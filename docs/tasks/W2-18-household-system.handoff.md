# W2-18 引き継ぎメモ

**この文書は PR 説明へ転記して削除する。**

## 却下した設計案(フェーズ1)

- **④の付け替えを `WorldDefinition` のフラグで切れるようにする案**(`IsExportEnabled` に倣う) — 採らない。GDD に無い調整軸が1つ増え、M0 の実測が「④を切った経済」になる。[GDD02 §8](../03-gdd/02-economy.md)-3(生産チェーンが止まらないか)は職業分布が動くことで観測が豊かになる、と GDD02b §4.2 が明言している。
  - **失われる保護**: 既存の60日検出器(`SmithNeverRunsOutOfToolsOverSixtyDays` / `ToolOffersNeverDisappearOverSixtyDays` など)が④の発火で赤になったとき、「④のせいか / 他の変更のせいか」を切り分けるスイッチが無い。
  - **代替手段はある**: 使い捨て worktree で `FullPipeline` から順3 を外せば同じ比較が取れる。**本体ツリーには書かない**(ADR-0013)。

- **担い手世帯数を手順2 のループ前にスナップショットする案** — 採らない。同職業の2戸が同じ日に3条件を満たすと両方が離脱し、GDD02b §4.2 が「構造的に防ぐ」と宣言した担い手 0(薪の売り手が消え、パンとビールが同時に止まる)が起きる。
  - **失われる保護**: 付け替えの結果が世帯 Id の走査順に依存する。**先の世帯の付け替えが、後の世帯の候補と `argmin` を動かす。** これは GDD02b §3.2 が資金について既に受け入れている順序依存と同種で、ADR-0002 が要求するのは「順を Id 昇順に固定すること」までである。代わりに「両方が離脱しない」ことをテスト #10(核心 C-3)が押さえる。

- **④の連日発火を抑える冷却期間(「N日連続で困窮したら付け替える」)** — 採らない。GDD02b §4.1 が「閾値が1つ増える」として既に却下しており、その却下理由は本タスクでも崩れていない(3条件はいずれも既にある状態である)。
  - **失われる保護**: 付け替えが毎日・往復に起きうる(A → B → A)。付け替え直後の世帯は新職業の入力を持たないので生産量 0・販売在庫 0 になり、フラグが立ち続ける限りゲートが毎日開く。GDD02b §4.2 は「付け替えが頻発するなら価格機構が働いていない兆候である」と書いており、**頻発そのものは観測対象であって異常ではない**。④のゲートを別の状態へ移すかは [#196](https://github.com/stama72/visionary/issues/196) が持つ(本 issue の後)。

- **`#37` の申し送り(必需の予算そのものが 0 の世帯が件数に数えられない)を本タスクで直す案** — 直す対象が既に無い。#97 が「購入量 0 の理由」(GDD02b §5.2)の固定順を実装した結果、流動資金 0 の世帯は現金上限 0 で `NoPurchaseReason.CashCap` に落ち、経路(1)で数えられる。実効価格が第 1 項も超える日に `MarketTerm` が勝つのは GDD02b §3.2 の「高すぎて買わなかったは資金不足ではない」「同点も 1 が勝つ」どおりであり、逆転ではない。**判定は issue のコメントに残した。**
  - **失われる保護**: なし(仕様の側が変わったのではなく、#37 当時に無かった実装が入った)。
