## 却下した設計案(フェーズ1)

- **最も具体的なテンプレートだけを候補にする(職業指定があれば共通を落とす)** — 職業別の台詞を1本足すたびに共通の台詞が全部消え、候補が減る。§6.2 #3 は候補の本数で決まるので、逆効果である。代償: 職業らしさは確率でしか出ない(共通の本数が多いと職業別が埋もれる)。本数の表で職業指定の下限を置いて補っている
- **台詞の使用履歴を `World` に入れる** — 状態ハッシュの凍結一覧(TDD01 §3.8)が動き、経済に効かない値で `vsim run` の比較が汚れる。代償: Godot(#47)が履歴を自分で持つ必要があり、`World` を保存・復元しても台詞の巡りは戻らない(M0 はセーブが無いので今は無害)
- **資料を JSON などの外部ファイルにする** — 読み込みの仕組みが Runner と Godot の両方に要り、列挙値の綴り違いが実行時まで分からない。C# のデータだけのファイルなら綴り違いはビルドで落ちる。代償: 開発者は台詞を直すたびにビルドする
- **世間話で自分の仕事の調子を語らせる** — Need の理由が漏れ、評価額の読み合い(GDD01 §3.6)の手がかりになる
- **取引の結果を `--gratitude` で1つに固定する** — 1回の出力で3段階と不成立を並べて読めない。代償: 巡らせ方の検査(#21)は Need の無い日が挟まるときしか落ちない
- **合成した入力で `dialogue-sample` を出す** — 開発者の決定4(実際に立つ Need を判定材料に反映する)
