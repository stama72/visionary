# W5-02 引き継ぎメモ

**この文書は PR 説明へ転記して削除する。**

## 却下した設計案(フェーズ1)

- **朝の中間値(需要・委託先・往復時間)を `TradePlanningSystem` のフィールドに持たせ、`TradeSystem` が参照する** — 夕方が World 以外から値を受け取ると、ハッシュが同じで夕方の振る舞いが違う世界が作れる(TDD01 §3.8 が計画と控えをハッシュに含めた前提が崩れる)。**失う保護: なし**(World から引き直すぶん、夕方に `Npcs[委託先].Rank` と区画列の再計算が1回ずつ増えるだけ)
- **往復時間の合計と委託先の労働力係数‰ も World の欄にする** — TDD01 §3.2 の計画の欄(委託先 NpcId・区画列・輸出フラグ)から一意に導けるので、欄を足すとハッシュの区分と TDD の両方を増やすだけになる。**失う保護**: 朝から夕方の間に委託先の階層が変わると、夕方の労働損失が朝の選択時と食い違う。M0 で階層を変える経路は無い(順3 は職業を付け替えるが階層は触らない)
- **夕方に `OpportunityCost.SelectErrandDelegate` を呼び直す** — 現行 `RunOneHouseholdsExport` の doc コメントが却下している形(朝と夕方で委託先が違う日がありうる、という契約を静かに作る)
- **時刻(6時・18時)を `WorldDefinition` のコンストラクタ引数にする** — 夕方のシステムの `Cadence` が定義ごとに変わり、設定ファイルで比較実験の約定時刻を動かせるようになる。**失う保護: なし**(W5 の調整は定数の書き換えで足りる)
- **控えを出力品目1つぶんのスカラーにする** — TDD01 §3.2 が「品目別」と書いている。スカラーにするとレシピが複数出力を持つ段で欄の形から変わる
- **朝の段4 にも Metrics の需要の3欄を書かせる** — `InputBlockedByFunds` は 1 の代入だけで 0 に戻らないので、朝の需要の 1 が夕方まで残る。プレイヤーが居る日に、買い物に使っていない需要が計数に混ざる
- **分割前との一致を状態ハッシュで比べる** — 新しい欄と、約定・観測の tick(0時 → 18時)でハッシュは必ず変わる。CSV と `summary.json` には tick が出ない(`CsvMetricsSink` を確認)ので、そちらのバイト一致で測る
