### 止まって報告 1 件(象限 I-b — 仕様の欠陥)

- **完了条件の `grep -rn 'GDD02 §9' src/ tests/` が 0 件にならない。** 表A が旧 `GDD02 §13.2` の行き先を `GDD02 §9.2` と定めているため、書き換え後に**正しい引用**が 2 件残る(`District.cs:29`、`WorldGeneratorTests.cs:300` = B-5)。この 2 件に grep が前方一致する。仕様「このタスクで特に効く規約」が本文で警告していた「`§6.2` の置換が `§6.2.1` を巻き込む」のと同じ境界の問題を、検証コマンド側が踏んでいる
- **推奨する訂正(フェーズ1 の判断)**: 完了条件を `grep -rnE 'GDD02 §9([^.0-9]|$)' src/ tests/` が 0 件、へ差し替える。表D が捕まえたいのは裸の旧 §9(季節との接続)だけで、`§9.2`(値として残っているもの)は対象外である。**表A・表B・表D の内容自体は正しく、書き換え結果を直す必要はない**

### 決めて報告 5 件

1. **継続引用の書式** — 分割後も同じ分冊に収まる場合(`GDD02 §6.2・§6.2.1` → `GDD02b §3・§3.2`)は 2 つ目を裸のまま圧縮し、分冊が割れる場合(`GDD02 §6.1・§9` → `GDD02b §1 / GDD02d §5`)だけ両方に文書名を書いた。**仕様の該当引用ブロックは「2つ目に文書名が無い形は保てない」と断定形だが、その理由は「分割で行き先が別の分冊へ割れるため」であり、割れない場合を除外する読みと整合する。フェーズ1 に確認させる価値がある1件**
2. 検出器から `bin/` `obj/` `.git/` を除外した(仕様は「拡張子で絞らない」としか言っておらず、ビルド生成物に触れていない)
3. 見出し収集ループで 2 語文字列を `set --` で空白分割する書き方を採った(等価な書き方が他にもある実装細部)
4. `LC_ALL` を明示せず、`§` が 1 文字として扱われることを Git Bash / ubuntu-latest の既定ロケールに委ねた
5. `awk` へ渡すファイルリストが空のとき標準入力待ちで固まるのを避け、`STALE 0 / UNRESOLVED 0` を出して `exit 0` するガードを足した(仕様に明記なし)
