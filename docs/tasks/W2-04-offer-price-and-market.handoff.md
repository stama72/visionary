# W2-04 引き継ぎメモ

**この文書は PR 説明へ転記して削除する。**

## 却下した設計案(フェーズ1)

- **値付けを `PricingSystem` として独立登録する** — `SimScheduler` が `Stream` の重複登録を拒む(共通乱数法が壊れる)ので、順5 に2つのシステムを置けない。`RandomStream` に 12 番を足す案も考えたが、[TDD01 §3.3](../04-tdd/01-sim-core-and-m0.md) が 12 を `OpportunityCost`・13 を `Metrics` に予約済みで、**パイプラインの順序と系統の値を一致させない**という同節の決定にも反する。`TradeSystem` 1本にして #37 が中を足す。
- **複数出力レシピの原価を「出力数量の合計」で割る** — 品目の価値差を無視した配分規則になり(「薪3 + 木炭1」で木炭が薪と同値になる)、しかも **GDD02 が持っていない規則がコードにだけ存在する**状態になる。`NotSupportedException` で落とす。**M0 の5レシピはすべて単一出力なので発火しない。** 配分規則が要るのは [GDD12](../03-gdd/12-countryside-and-fairs.md) の農村職業が戻る時点。
- **入力0件レシピの機会費用ベースの原価([GDD02 §8.1.1](../03-gdd/02-economy.md) の第2分岐)を今入れる** — 機会費用は順0 `OpportunityCost` の成果物で未実装、[GDD08 §9](../03-gdd/08-household-and-decision.md) の値もコードに無い。入れると「M0 で一度も実行されない式」と「調整軸2本(機会費用・可処分時間T)」を同時に抱える。`NotSupportedException` で落とし、[#51](https://github.com/stama72/visionary/issues/51) の時点で入れる。**この2件は開発者に確認して決めた。**
- **販売在庫0の日も `Market` に出品する**(在庫比0 → 係数1500‰ の高値が付く) — 売るものが無い「在庫のない店」が #37 の店選択の候補に載る。[GDD02 §8.1.1](../03-gdd/02-economy.md) が「前日に売り注文を出していない日」を明示的に想定しているので、出品しないほうが仕様に合う。在庫比の表の「販売在庫 0 → 1500‰」の行は**式の形を示す行であって出品される価格ではない**、という読みを仕様に書いた。
- **相場基準を `Market` から直接作る**(観測を経由しない) — 実装は短くなるが、**視界半径 R と保持期間が値付けから消える**。[GDD02 §8.1.1](../03-gdd/02-economy.md) が「有効な観測から作る」と決めており、[GDD06 §3.1](../03-gdd/06-trade-and-negotiation.md) の情報の摩擦(知識が単調に増えて中央の板にならないこと)が価格に効く経路そのものを失う。
- **`BankruptFloorPermille` と `MinCoefficientPermille` を1つの定数にまとめる** — [GDD02 §6.3](../03-gdd/02-economy.md) の「床の 500‰ は新しい係数ではない」は**値の由来**の説明であって、一方を動かしたら他方も動くという関係ではない。まとめると #28 が投げ売りの深さだけを調整できなくなる。
