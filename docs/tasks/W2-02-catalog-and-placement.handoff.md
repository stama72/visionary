## 却下した設計案(フェーズ1)

- **仕入れ移動平均を再帰形(前回値と新標本の加重平均)に確定させ、標本バッファを持たない形に固定する** — 採らない。[GDD02 §13.2](../03-gdd/02-economy.md) は「原価の**移動平均の窓**」と書いており、再帰形にするなら「平滑化重み‰」への訂正が要る。**窓か再帰かは原価の式そのものの性質であり、式を書く #35 が持つほうが正しい。** 代償は、#35 が窓付きを選ぶと標本バッファぶん状態が増えてハッシュと凍結検査がもう一度動くこと。**承知のうえで #33 は「初期値を書ける器」までに留める**(この判断は開発者に確認済み)
- **区画への職業割り当てを構成的に解く(衝突したら決定的に入れ替える)** — 採らない。棄却法(期待 1.125 回)より速いが、**入れ替え規則そのものが配置に偏りを入れる**(「最小の添字と入れ替える」なら若い区画に特定の職業が寄る)。加えて二重区画が複数ある一般の世帯数では終端性の証明が要る。**棄却法は上限 1000 回で明示的に失敗するので、満たせない定義が黙って回り続けない**
- **`vsim hash` を `WorldGenerator` へ差し替える** — 採らない。合成システム(`SyntheticLoadSystem` / `SyntheticDecaySystem`)は #34〜#39 が揃うまでのハッシュ検証手段であり、CLI の `--npcs` / `--households` / `--items` に依存している。**本物の配置と合成システムを混ぜると、回帰が出たときにどちらの側の回帰か切り分けられない。** 結果として `WorldGenerator` の呼び出し元は本タスクではテストだけになるが、これは死んだコードではなく #34 以降の入口である
- **品目 Id も `enum` にする** — 採らない。品目 Id は在庫(`int[]`)の**添字**として使われるので、`enum` にすると在庫に触れるたび `(int)` のキャストが入る。**職業は逆に世帯の欄として比較・代入される値なので `enum` が効く。** 分ける基準は「添字か、値か」
- **`WorldDefinition` を `static` な可変テーブルにする** — 採らない。#28 が値を差し替え、[TDD01 §4.1](../04-tdd/01-sim-core-and-m0.md) が JSON 設定を予定している。加えて **`static` な可変配列は `StateHasherCoverageTests` の凍結検査にも `StateHasher` にも2プロセス比較にも一切現れない**(同テストの doc コメントが警告している経路そのもの)
- **区画数を `WorldDefinition` の可変値にする** — 採らない。距離の式が 3×3 を前提にしているので、**式が黙って無視する設定値**が生まれる。[GDD02 §4.3](../03-gdd/02-economy.md) は 3×3 を決定として書いている
- **初期配置を固定にする(乱数を使わない)** — 採らない。配置が統制変数になる利点はあるが、[TDD01 §4.1](../04-tdd/01-sim-core-and-m0.md) の「条件あたり10反復」がすべて同じ地理を見ることになり、**[GDD02 §12-4](../03-gdd/02-economy.md)(区画間の価格差が消えない)が1つの配置に依存したままになる**。ADR-0002 の共通乱数法により A/B は同一シードなら同一配置で揃うので、統制は失われない(この判断は開発者に確認済み)

### 仕様を書く途中で自分の誤りを1件直した

**テスト13 を当初「`Distance` のテストで行優先/列優先の取り違えを捕まえる」と書いていたが、誤りである。** マンハッタン距離は転置に対して不変で、行優先 `(id/3, id%3)` と列優先 `(id%3, id/3)` は行と列を入れ替えただけなので `|Δ行| + |Δ列|` が完全に一致する。**「この実装ミスで落ちる」に書いたものが実際には落ちない**という、[docs/process/02](../process/02-task-spec.md) 規則1 が防ごうとしている型そのものだった。テストを #13(`RowOf`/`ColumnOf` を直接見る)と #14(加算か `max` か)の2本に割り、畳まない理由を仕様に残した。

## フェーズ3 へ — #28 に落とすもの

**2巡目レビューが報告対象外(象限II 相当)としたが、具体値がどのコミットにも残らないため転記する。**

`InitialAcquisitionCost` の**都市生産品**(小麦粉22 / 薪6 / パン16 / ビール30 / 工具60)は、[GDD02 §10.2](../03-gdd/02-economy.md) の `原価 < 外部買値 < 原価下限` を**現時点で満たしていない**。例: **小麦粉は原価 20 に対し外部買値 11**(工具も原価60 に対し外部買値29)。§10.2 はこの不等式を「値の調整範囲ではなく**成立条件**である」と書いており、破れると輸出が一度も発火せず §12-6 が構造的に不通過になる。

**本タスクの対象外であることは仕様が明示している**(「値の作り込み…検算と調整は #28」)。**#28 に「1次産品(0〜3)は §10.2 が固定済み・都市生産品(4〜8)のみ調整可」という前提つきで、この具体値を添えて落とすこと。**
