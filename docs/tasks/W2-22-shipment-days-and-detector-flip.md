## 前提 — 反転した検出器を正の向きへ戻す

[W2-16](W2-16-city-survival-detector.md) は「[#173](https://github.com/stama72/visionary/issues/173) の検出器は書いた時点で赤」を**反転して置く**ことで解いた。同仕様「終わり方」と「3. 検出器」が、戻し方まで先に決めてある:

- 30日のうち**違反日が1日以上あるシード** → **反転側**の `[InlineData]`
- 違反日が**0日のシード** → **正側**の `[InlineData]`
- **どちらかが空になったら、そのメソッドは書かない**(xUnit は `[InlineData]` の無い `[Theory]` をエラーにする)

**#210 決定ログ1 の実測**(使い捨て、HEAD `94ecc2c`、`WorldDefinition.M0`、シード 1/2/3/7/42・30日)**では、出荷日数 1 の下で条件1・条件2 の違反日が5シードとも0日になった。** 規則に当てはめると反転側2本は `[InlineData]` が空になり、メソッドごと消える。

**ただし割り振りを決めるのは実測であって、この仕様ではない。** implementer は W2-16 と同じ手順で自分で走らせ、`_output` の行を読み、**読んだ値に従って**割り振る(下の「実装の手順」)。上の実測は**期待であって前提ではない** — 違反日が残るシードがあれば、そのシードは反転側に残り、メソッドも残る。

### 向きが変わると、検出器が見るものが変わる

W2-16 の「6.1 反転した検出器が原理的に見ないもの」が、そのまま裏返る。

| 取り違えの向き | 反転側(`違反日 > 0`) | 正側(`違反日 == 0`) |
| -------------- | ---------------------- | --------------------- |
| **数え過ぎ**(違反日が消える) | **見る** | **見えない** |
| **数え落とし**(違反日が増える) | **見えない** | **見る** |
| **全滅**(母数が常に0) | 条件別の空振り防止が見る | 同左 |

**これは非対称の解消ではなく、死角の入れ替えである。** W2-16 の 6.1 は「向きが反転しきって条件1・2 にも正側が立てば、この非対称は自然に消える」と書いたが、**その一文は誤りである。** 同じことが条件3 で先に起きており、`ScanThirtyDays` の doc コメント「訂正(レビュー2巡目)」が既に逆を記録している — W2-17 が条件3 の反転側を削除した結果、**M-8(条件3 の判定を世帯在庫から工房在庫へ取り違える変異)は緑のまま通るようになった。**

**本タスクはこの入れ替えを引き受ける。構造的な留め具は足さない。** 代わりに次の2つをする。

1. **入れ替えを doc コメントに書く。**「守られている」と読ませないために、W2-16 の変異のうち**向きが変わって結論が変わる行**を明示する(下の「2. 条件1 の検出器」「3. 条件2 の検出器」)
2. **数え過ぎ方向を他のテストが見ているかを `mutator` で実測する**(下の V-2)。見ていれば、**それがどのテストかを** doc コメントに書く

**却下した案1: 条件1・2 にも反転側を残す。** 置けない — 実測で違反日0のシードしか残らない。人為的に悪い世界を組んで反転側を維持するのは、「素の M0 を30日回す」という検出器の題そのものを変える。

**却下した案2: 数え過ぎを留める assert を足す**(例「生産0 の世帯が1戸以上ある日が30日のうちにある」)。**データに乗った留め具になる。** #210 決定ログ1 の実測は day 29 の生産停止世帯 2〜4 戸だが、これは経済が良くなれば 0 になりうる値であり、**そのとき「退行」と同じ形の赤が出る。** `ScanThirtyDays` の doc コメントが 6.2 の等値 assert について同じ警告を既に持っている(「この検出器が測っている病理が進めば、保護は無言で消える」)。**失うもの**は上の表の「数え過ぎ」列であり、V-2 の実測がその穴の実際の大きさを測る。

### 日付の ±1 は、正の向きでは核心が見る

W2-16 の 6.2 の訂正は「等値 assert は ±1 のずれを**構造では守らない**。−1 方向で赤になるのはシード42 の1本だけで、それもデータに乗っている」と書いた。**正の向きではこの制約が外れる。**

核心が「30日すべてで都市内約定がある」を主張するので、**核心が緑である限り `DayIndex == 29` には必ず行がある。** 窓が −1 へずれれば day 30 の都市内約定が0件になって**核心自身が赤**になり、+1 へずれれば day 1 が0件になって同じく赤になる。**保護の前提は核心の成立そのものであり、核心が赤の日には保護も無い** — が、そのときは既に赤である。

**この改善は 6.4 の留め具(`FirstDayLabel` / `LastDayLabel` / `FirstScannedLedgerDayIndex` / `LastScannedLedgerDayIndex`)を置き換えない。** 4本はデータを1行も参照せずにループの形そのものを留めており、向きに依らない。**両方残す。**
