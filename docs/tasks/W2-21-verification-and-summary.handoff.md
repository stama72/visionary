## 却下した設計案(フェーズ1)

- **`summary.json` を CSV から読み戻して作る**(Runner が `economy.csv` などをパースする)— 採らない。整形済みの出力を読み戻すと、整数の再パースと列の対応づけが判定側にもう1本生まれ、実装量が倍になる。**失う保護**: 列名で引く経路が消えるので、**`CsvMetricsSink` のヘッダと判定が食い違っても機械が気付かない。** W2-20 別表 #30 が見ているのは「ヘッダと値の対応」までで、「ヘッダと**判定**の対応」は誰も見ていない。本タスクのテスト #38 が見るのは CSV の不変性であって名前ではない
- **`8-1a` の発散の帯を天井基準(床 × 2)まで狭める** — 採らない。[TDD01 §5.2](../04-tdd/01-sim-core-and-m0.md) の `[×0.1, ×10]` は既存の決定であり、狭めると `8-5b`(帯超えが連続30日)と役割が重なる。**失う保護**: 発散の検出が遅くなる(床の 10 倍に達するまで鳴らない)。**補っているのは `8-5b` が先に鳴ることだけである** — `8-5b` を外す変更が来たら `8-1a` の帯を見直す
- **変動係数(CV)を整数平方根で実装して残す** — 採らない。平方根は整数で書けるが「対数が**有意に**増加」の側が整数で書けず、片方だけ残すと式と散文が食い違う([02-task-spec](../process/02-task-spec.md) 規則5)。相対平均絶対偏差へ置き換えた。**失う保護**: 分散に基づく検定との比較可能性。M0 に比較相手が無いので実害は無い
- **判定を二値(緑 / 赤)にする** — 採らない。母数が消えた窓を緑とも赤とも読ませないために三値にした。**失う保護は無い**(増やした側)。**代償**は、下流(人の目と、後続の集計)が3状態を扱わなければならないこと

**`SPEC-OUTSIDE` の差し戻しを受けて、フェーズ1 がさらに2つ却下した**(下記「`SPEC-OUTSIDE` の内容」の3つの読みのうち2つ):

- **`First > 0` のガード(基準を先頭窓に固定し、0 なら偏差の枝を諦める)** — 採らない。**失う保護**: 床への張り付きから離脱して発散する経路(`0, 0, 300, 700, 1500`)で、**走行の残り全部で検出器が黙る。** 先頭窓が 0 になるのは [GDD02d §4.5](../03-gdd/02d-external-market-and-money.md) が予測する既定の状態なので、この穴は例外ではなく常態である
- **`Previous > 0`(直前の窓と比べる)** — 採らない。**失う保護**: 窓ごとの比較は「増え続けている」ではなく「増えた」を見るので、**1回の跳ねが発散になる。** 採ったのは「偏差‰ が 0 でない最初の窓を基準にする」形で、比較の相手を走行の中で1つに固定したまま退化を避けられる。**代償**: 基準窓から最後の窓まで単調非減少を要求するので、1窓でも下がればその走行で枝が沈黙する(§5.2 に残る穴として明記した)

## `SPEC-OUTSIDE` の内容(フェーズ1 への差し戻し)

**`8-1a` の偏差の枝が first = 0 で退化する。** [TDD01 §5.2](../04-tdd/01-sim-core-and-m0.md)「浮動小数点を呼び込む語を置き換える」は「連続する窓で単調非減少であり、かつ**最後の窓が最初の窓の 2 倍以上**」とだけ書いており、最初の窓の相対平均絶対偏差‰ が 0 のときの扱いを持たない。**0 は起こる** — 窓の全有効日で約定価格中央値が一定なら偏差は 0 であり、それは [GDD02d §4.5](../03-gdd/02d-external-market-and-money.md) が予測する「全売り手が床に張り付く定常状態」そのものである。

読みが3つあり、**どれも §5.2 の現行の条文から導けない**:

| 読み | 平坦なゼロ(`0, 0, 0`) | ゼロから立ち上がる発散(`0, 0, 300, 700, 1500`) |
| ---- | ---------------------- | ---------------------------------------------- |
| 条文どおり(ガード無し) | **赤**(`0 ≥ 0 × 2` が自明に真)。予測どおりの健全な定常状態が発散と報告される | 赤 |
| 実装が採った `First > 0` | 緑 | **緑**(最初の窓が 0 だと走行の残り全部で赤になれない。床への張り付きから離脱して発散する経路がまさにこの形) | 
| レビュアーの `Previous > 0` | 緑 | 赤 |

§5.2 は同じ形の偽陽性を `8-5c` では「**そこで赤を返すと、予測どおりの健全な状態が赤になる**」と明示して判定不能に落としている。偏差の枝にも同じ判断が要るが、**それは §5.2 に一文を足す決定であり、フェーズ2 の権限外である。**

**現在の実装は `First > 0` のガードを持ったまま緑で止めてある**(`VerificationAccumulator.cs` の偏差の枝)。訂正の際は、あわせて凍結仕様のテスト #6 と、1窓の走行で `8-1a` 緑を前提にしている #1・#4・#5 を見直す必要がある。
