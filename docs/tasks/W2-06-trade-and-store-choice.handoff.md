## 却下した設計案(フェーズ1)

- **統合テストで `StateHasher` の値を定数にピン留めする(黄金ハッシュ)** — #36 から引き継いだ配線10件(A〜J)は、どれもハッシュを変える。ピン留めすれば全件まとめて落とせる。**採らないのは、赤の意味が読めなくなるためである** — #28 が初期値を1つ動かすだけで赤くなり、「配線が壊れた」のか「値を変えた」のかを区別できない。**値に依存しない結果(嗜好が買われる / 知識が R の外へ広がる / 帳簿が突合する)で代替した**(テスト #20・#22・#23)。この理由は #28 が値を動かす限り生き続ける。
  - **却下理由の前提を再確認した(差し戻し後)。** 代替に挙げた4本のうち「耐久が買われる」は W2 では成立しないと判明し、テスト表から外した。**残る3本と新 #29 はいずれも値に依存しないので、却下理由は崩れていない** — 黄金ハッシュを採らない根拠は「赤の意味が読めなくなる」ことであり、代替の本数ではない。
- **「必需を資金不足で買えなかった」件数の記録を #39 へ回す** — 本タスクのスコープ(店の選択と帳簿の突合)には無い。**採らないのは、#39 が Trade の決済ループに配線を足すことになるためである** — #39 は `Household`(順3)のタスクであり、順5 を触らない。W2-05 で問題になった「仕様だけが守っている配線」を、フェーズをまたいでもう一度作ることになる。切り詰めが起きる場所でその場で数えるほうが、テストも同じ場所で書ける。

**フェーズ2 は一度 `IMPL-BLOCKED` で止まり、フェーズ1 が裁定して差し戻した。** 裁定の内容と実測はコミット `e9c6924` の本文が持つ(旧 #22 を #22 と #29 に分け、「工具が実際に買われる」を #38 の Exit Criteria へ移した)。
