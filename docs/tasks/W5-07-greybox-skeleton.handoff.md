## 却下した設計案(フェーズ1)

- **gdUnit4 でエンジン側を試す** — 試す価値のある論理を `Visionary.Presentation` に寄せたので、エンジン側に単体で試す対象が残らない。gdUnit4 の C# 版はテスト実行に Godot 本体を要し、パイプラインのフェーズ2 は Godot を叩けない(許可一覧に無い)。**失う保護: `Visionary.Game` のノードの配線は、コンパイルと煙試験(操作の経路を踏まない)しか守らない。** クリック → `Execute` の経路は人のプレイだけが見る
- **`Visionary.Game` に論理を置き、テストから Godot のアセンブリごと参照する** — `GodotSharp` は Godot 本体の上で動く前提で、xUnit から型の初期化を踏むと落ちる。CI(Ubuntu)の `sim` ジョブに Godot の依存を持ち込む。**失う保護: なし**(論理は `Presentation` で試す)
- **補間をシムに置く** — TDD01 §3.9 が経路の描き方を描画の側に置いている。シムに置くと時間割が tick の中の値を持ち、ハッシュの区分の議論が要る。**失う保護: なし**
- **#47 を1本の仕様で回す** — 歩行・会話メニュー・売買・感謝の演出・日誌・CI を1本にすると仕様が大きく、レビューの4巡で打ち切られる恐れが高い。**失う保護: 3本のあいだの配線(会話中に `Paused` を立てるなど)は、後続の仕様が拾うまで誰も見ない**
- **煙試験で移動コマンドも1回打つ** — 状態ハッシュを `vsim hash` と突き合わせる検査が成り立たなくなる(プレイヤーの状態が変わる)。**失う保護: 操作の経路の煙**(後続の仕様で決める)
