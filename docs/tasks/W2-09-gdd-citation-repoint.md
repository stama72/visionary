**本タスクは doc コメントの引用先だけを書き換える。式・規則・振る舞いは1行も変えない。** ビルドとテストの結果は着手前と完全に一致する。

## スコープ

**含む**:

1. `src/` と `tests/` の doc コメント・行コメントが引く GDD 節番号のうち、**現行の文書に見出しとして存在しない 112 件**(表A・表B)を現行の分冊と節番号へ書き換える
2. **番号は現行の文書にも存在するが、指している中身が変わった 8 件**(表D)を書き換える。これは機械では見つからないので、本仕様が列挙を持つ
3. 検出器 `scripts/check-doc-citations.sh` を新設する(§「検出器」)

**含まない**:

- **GDD / TDD 側の旧仕様の語**(実質コスト・原価下限・仕入れ間隔)**の書き換え** — #98 のフェーズ1 が持つ
- **コード内の旧仕様の語・旧規則の説明文の書き換え** — 表C に列挙し、**散文は1文字も直さない**。引き取り先の issue へ1行ずつ落とすのはフェーズ3 の仕事である
- CI ジョブの追加。検出器は手で叩くものとして置く(判断: 本 issue のフェーズ1)
- `docs/` 配下の編集(§「編集してよい文書」の1件を除く)

### 変えない既存コード(規則8)

**本タスクはコメントだけを触るので、「変えない」の単位は事実上すべての実行コードである。** 規則ごとの突き合わせは行っていない — 行うのは #98 / #38 / #39 / #40 / #41 であり、本タスクが引用先を直すことは**その突き合わせを済ませたことを意味しない。**

| 変えないコード(規則の単位) | 従う節(現行版) | 確認 |
| --------------------------- | --------------- | ---- |
| 本タスクが触るファイルの実行コードすべて | 各コメントの書き換え先(表A・表B・表D) | **未確認**。引用先を現行版へ向けただけで、コードが現行版に従うかは見ていない |
| 破産中フラグが駆動する値付けの分岐 | GDD02c §1.4 | **不一致**(表C-3〜5。コメントが旧②「原価下限を 500‰ へ下げる」のまま。#39 へ) |

### 2. 検出器 `scripts/check-doc-citations.sh`

**現行の GDD / TDD に見出しとして存在しない節を引く doc コメントを列挙する。** #101 の追随表を作る設計セッションが手で叩くためのもので、CI からは回さない(判断: 本 issue のフェーズ1。理由 — GDD 側だけを直す PR が通らなくなる代償を、いまは取らない)。

**言語は bash。** 実行環境は Git Bash(開発機)と ubuntu-latest(将来 CI へ載せるとき)。`awk` は GNU awk を前提にしてよい。

#### 入出力の契約

```
$ bash scripts/check-doc-citations.sh
src/Visionary.Sim/World/HouseholdState.cs:69<TAB>GDD02 §8.1.1        ← 標準出力。1件1行、path:line 昇順
...
STALE 112 / UNRESOLVED 35                                            ← 標準エラー。集計はこの1行だけ
$ echo $?
1                                                                     ← STALE が1件以上なら 1、0件なら 0
```

- **引数は取らない。** どのディレクトリから実行しても動く(スクリプト自身の位置からリポジトリルートを求める)

#### 継続引用の解決規則

`GDD02 §6.1・§9` の2つ目以降には文書名が無い。**同じ行で直前に現れた文書 Id を引き継ぐ。ただし、直前の引用と当該 `§` のあいだのテキストに `タスク仕様` / `ADR-` / `#<数字>` のいずれかが現れたら引き継がない。**

#### この検出器が見つけられないもの(**残る穴**)

- **番号が再利用された引用**(表D)。`GDD02 §9` は現行にも見出しとして在るので 0 件のまま通る。**節番号を振り直す変更をしたら、この検出器が 0 でも安心してはならない**

- **見出しの収集側が過剰に採る場合。** 上の3つと4つ目が引用側の限界であるのに対し、これは**照合相手の集合そのもの**の限界である。見出しの収集はコードフェンスを見ないので、**GDD / TDD のフェンス内に `## 3. …` のような行が入ると幻の節ができ、存在しない節への引用が 0 件のまま通る**(2026-09-20 実測で該当ゼロ。潜在)。**0 件は「引用先が実在する」ではなく「引用先が `^##〜###### <番号>` で始まる行として存在する」しか意味しない**
