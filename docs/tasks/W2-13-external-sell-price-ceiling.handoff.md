## 却下した設計案(フェーズ1)

- **`externalSellPriceBase[都市生産品] == 0` の検査を外す** — issue [#149](https://github.com/stama72/visionary/issues/149) の表 #3 の文言(「1次産品についてだけの検査に変える」)を素直に読むとこうなる。採らない理由は、**外した瞬間に表へ置いた値が黙って無視される**こと。都市生産品の外部売値は外部買値からの導出が正(GDD02d §3)なので、基準値の表に独立値を置ける形は二重定義になる。同じファイルの季節係数行が「都市生産品の行はすべて 1000(使わないが、黙って効く値を置かせない)」で同じ穴を塞いでおり、そちらと非対称にする理由が無い。**検査は残し、例外メッセージだけを現行の規則へ直す**(仕様 決定1)
- **`ExternalMarket.TryOfferPrice` を `int OfferPrice(...)` へ単純化する** — M0 では常に `true` を返すので `Try` の形が嘘になる、という読みは正しい。採らない理由は2つ。(1) 呼び出し側 `StoreChoice.cs:112` / `ErrandPlanner.cs:276` に波及し、issue が「変更不要で天井が働く」と書いた最小の差分から離れる。(2) [GDD11](../03-gdd/11-external-trade.md) が窓口を行商人へ置き換えると「その日は並ばない」が戻るので、`Try` の形は先で要る。**代わりに「M0 では常に true」を doc コメントで固定する**(仕様 決定2)
- **帯の検出器が上限を `definition.ExternalSellPrice(itemId, 季節)` から読む** — 導出と一致して読みやすいが、**交易マージン‰ を動かすと検出器の閾値が一緒に動く**。天井の値そのものを疑う変異(M-2)に対して無力になるので、リテラル `2` を検出器が自分で持つ(仕様 テスト #3)
- **帯の検出器の判定対象を `world.Market`(提示価格)のままにして閾値だけ 20 → 2 にする** — [GDD02 §8](../03-gdd/02-economy.md)-5 は提示価格が天井を上回ることを許しているので、仕様どおりの経済でも赤になる。**判定対象を約定価格(`world.Ledgers`)へ移すことが #120 の閉じる条件そのものである**

## 直さないと決めた指摘と、その理由

- **`MarketReference.TryBuyer` の `<remarks>` が「結論は `TrySeller` と同一」と書いている点**(3巡目の参考)。厳密には付帯部分が一致しない — `TrySeller` は自分の出力品目(都市生産品)で引くので #149 まで不活性だったが、`TryBuyer` は生産の入力(1次産品)で引くため **#149 以前から窓口の観測が入っていた**。**規範部分(取り込むのが現行仕様 / 変えない)は正しく、判断に影響しない**ため直さない
- **下の2件は issue へ落とす**(直さない)

## issue へ落とすもの(フェーズ3 が立てる)

1. **窓口から買った耐久が、翌日以降 床で窓口へ売り戻されうる環路**(2巡目の疑い1)。鍛冶が工具を天井で買うと `TradeSettlement.ExecuteImport` が `WorkshopInventory` へ入れ、これが `sellableStock` に乗る。閾在庫を超えれば床で輸出され、1個あたり床ぶんが都市から純流出する。**#149 以前は鍛冶が工具を買える相手がもう1戸の鍛冶だけ(都市内の移転)だったので、この環路は本タスクで初めて機械的に成立する。**
