## 却下した設計案(フェーズ1)

- **「行った区画で買った品目を需要リストから外す」([#98](https://github.com/stama72/visionary/issues/98) の本文の書き方)** — 採らず、差の相手(baseline)を「自区画 ∪ ここまでに行くと決めた区画」へ広げる形にした。外した場合、**3 つ目の区画がもっと安くてもその差を数えられない**。理由は [GDD06 §3](../03-gdd/06-trade-and-negotiation.md) に残した。
  **代償: issue の本文と仕様の字面が食い違う。** PR 説明で明示すること。issue を読んで実装を確かめる者は、外す規則が無いことを「実装漏れ」と読む。
  **追記(差し戻し後)。この却下理由が成り立つのは、訂正後の式(候補側も「既に居る区画」を含む)の上だけである。** 初版の式では「1 回目で最安になった品目は増分が 0 になって落ちる」も「3 つ目がもっと安ければその増分は残る」も成立しておらず、**却下理由に使った性質を、同じ文書の式が持っていなかった**([process/03](../process/03-corrections.md) 規則2 の逆向き — 前提が後から崩れたのではなく、最初から式が理由を実装していなかった)。却下の判断そのものは訂正後も妥当である。
- **`MarketReference` を見積もり価格に流用する** — 採らない。あちらは品目について畳んだ平均で、店ごとの差(外出の動機そのもの)が消える。
  **代償: 見積もり価格の経路が新しく 1 本増え、`MarketReference` と並走する。** どちらを呼ぶべきかの取り違えは例外を出さない。仕様の「見積もり価格は相場基準ではない」表がこれを押さえているが、**押さえているのは表だけで、機械は何も見ていない。**
- **`TrustScore` を実際に引いて [GDD06 §5](../03-gdd/06-trade-and-negotiation.md) の店の信用を組む** — 採らない([#44](https://github.com/stama72/visionary/issues/44))。応対店員が M0 に無く、平均の片側が定義できない。
  **代償: 呼び出し側が `trust: 0` の定数を 2 か所(段5a・段5b)に持つ。** 式は #5 が踏むが、**「呼び出し側が 0 以外を渡したときに何が起きるか」はどのテストも踏まない。** #44 は 2 か所とも直す必要があり、片方だけ直しても緑のまま通る。
- **1 次産品を需要リストから明示的に除外する** — 採らない。所在から引く店の候補が 0 件になるので、`ExternalBuyPrice`(1 次産品で投げる)には到達しない。
  **代償: 保証が `WorldDefinition.IsPrimaryItem` の定義(どのレシピも出力しない品目)に暗黙に依存する。** テスト #11 が例外が出ないことだけを押さえている。
- **目標在庫 0 の行を需要リストから外す規則に、テスト表の行を立てる** — 立てない。余剰が恒に 0 なので**外から観測できず、「この実装ミスで落ちる」を埋められない**([02-task-spec](../process/02-task-spec.md) 規則1)。
  **代償: 規則が doc コメントにしか残らない。** 次に読んだ者が「予算 > 0 だけで足りる」と外し、同時に別の変更が入ったときに誰も気付かない。

## `SPEC-OUTSIDE` の内容(3 回目・レビュー1 巡目の I-1 による)

### 2 つの節の字面だけで閉じる矛盾(コードを読まずに取れる)

| どこ | 何と書いてあるか |
| ---- | ---------------- |
| [GDD02b §5.2](../03-gdd/02b-consumption-and-household.md) | 「**耐久は耐久値で解き、`CeilDiv(購入量, N × 1000)` で個数に直す**(§2)」 |
| [GDD06 §3](../03-gdd/06-trade-and-negotiation.md) | `q = 線形解の購入量(GDD02b §5.2。ゲートを通した後の値)` / `w(s) = ApplyPermille(基礎値, 在庫圧力‰) ← いま1単位目に払ってもよい値` / `余剰_i = FloorDiv( q × (w(s) − p) , 2 )` |

**同じ `q` が、GDD02b では耐久値・GDD06 では「貨幣/1個」の相手として使われている。** `q × (w − p)` は耐久の行で「耐久値 × 貨幣/個」になり、比較相手の `Errand.Cost`(貨幣)と次元が合わない。個数へ直す変換(`CeilDiv(q, N × 1000)`)は購入の側(`TradeSystem.PurchaseQuantityInUnits`)にしか無い。

### 規模

M0 の `ToolDurabilityPerUnit` = 13,000。耐久の行は `BuyerDemand.Build` が全世帯に無条件で 1 行足し、目標在庫(親方世帯で 6,500)も予算も正なので需要リストに必ず残る。**工具が摩耗した日から、外出の価値は工具の行だけでほぼ決まる。**

## `SPEC-OUTSIDE` の内容(フェーズ2 の自己申告)

**[GDD06 §3](../03-gdd/06-trade-and-negotiation.md) の「外出 d の価値」の式が、同じ節の散文と食い違っている。散文が意図で、式が誤りである。**

### 現行の式(GDD06 §3、コードブロック内)

```
外出 d の価値 = Σ_i( 余剰_i(d の最安店) − 余剰_i(既に居る区画の最安店) ) − 外出の費用(d)
                 既に居る区画に店の無い品目は第2項を 0 とする
```

**候補側(第1項)が `{d}` 単独である。**

### なぜ 2 区画目が立たないか

1 周目が全候補中の argmax として区画 X を選んだとする。任意の Y について `価値₁(X) ≥ 価値₁(Y)`、すなわち

```
Σ余剰({Y}) − Σ余剰({X}) ≤ Cost(Y) − Cost(X)
```

2 周目で Y を評価するとき、baseline は `{自区画} ∪ {X}` に広がっており、最安を取る集合が広がるので価格は下がり **`余剰(i, {自区画,X}) ≥ 余剰(i, {X})`**。したがって

```
価値₂(Y) = Σ余剰({Y}) − Σ余剰({自区画,X}) − Cost(Y)
        ≤ Σ余剰({Y}) − Σ余剰({X})       − Cost(Y)
        ≤ ( Cost(Y) − Cost(X) )          − Cost(Y)   =  −Cost(X)  ≤ 0
```

**`Cost(X) > 0` なら厳密に負。** 品目構成にも距離にも価格にも依存しない。

### 節の中の他の記述はすべて複数回の外出を前提にしている

| 行 | 記述 |
| -- | ---- |
| §3 冒頭 | 「行く価値のある区画が2つあれば**2回行き**」 |
| §3 貪欲 | 「往復移動時間の**合計**が T を超える外出はしない」(1 回なら上限は無意味) |
| §3 論点「既に居る区画の店との差で数える」 | 「1回目で最安になった品目は**差が 0 になって**自動的に落ち、かつ**もっと安い3つ目の区画があればその差だけは残る**」 |
| §3 論点「労働損失は外出ごとに切り上げ」 | 「`Σ_d CeilDiv(…)`」「**2回に分けたほうが損失が大きくなる**」 |
| [GDD02a §2](../03-gdd/02a-production.md) | 「その日の外出**すべての**合計」 |

**とりわけ「差が 0 になって落ちる」は、現行の式では成り立たない。** d にその品目の店が無ければ第1項が 0 になり、差は 0 ではなく**負**(baseline の余剰ぶん丸ごと)になる。

### 訂正案(フェーズ1 が判断すること)

**候補側も baseline を含んだ集合にする。**

```
既に居る区画 = { 自区画 } ∪ { ここまでに行くと決めた区画 }
外出 d の価値 = Σ_i( 余剰_i( (既に居る区画 ∪ {d}) の最安店 ) − 余剰_i( 既に居る区画の最安店 ) ) − 外出の費用(d)
```

これで散文の 2 つの主張が両方そのまま成立する。「d が高ければ差 0」「3つ目がもっと安ければその差だけ残る」。現行の式の 2 行目(「既に居る区画に店の無い品目は第2項を 0 とする」)は不要になって吸収される。

**1 回目の外出では観測できない誤りである。** 1 回目は差が負でも「価値 ≤ 0 なら行かない」に吸収されるため、結果が一致する。2 区画目で初めて表面化する。
