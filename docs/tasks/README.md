# 実装タスク仕様と状態管理

設計セッションが実装エージェントに渡す作業指示と、進行中タスクの状態一覧。運用は [ADR-0004](../adr/0004-ai-driven-development-workflow.md) による。

## 状態一覧

| タスク                        | 状態       | ブランチ                    | worktree            |
| ----------------------------- | ---------- | --------------------------- | ------------------- |
| [W1-02: 系統別乱数ストリーム](W1-02-random-streams.md) | 進行中     | `feat/random-streams`       | `visionary/`(本体) |

W1 の残り(着手前・未採番): World と Clock/スケジューラ、決定論ハッシュと2プロセス検証。

状態は **進行中 / レビュー中 / 凍結 / 完了** の4つ。

### 状態遷移の規律

- **レビューを終えて初めて、次に取り組むタスクを選べる。** レビュー中を放置して新しいタスクを進行中にしない
- レビューが難航した、または前提として別タスクが必要だと判明したときは、**承認せずに凍結してよい**。デッドロックを避けるための逃げ道であり、使うことをためらわない
- 新しいタスクで**勝手にセッションを開かない**。まずメインセッションに相談し、専門性が違うと判断されたときだけサブセッションへ一時的に移る(その間メインは凍結)
- **メインに戻るときは、サブセッションのタスクを完了か凍結して閉じる**

### この表の更新について

**master へ直接コミットする。** worktree をまたいで共有する必要があり、ブランチ上で更新すると他のツリーからは古い表しか見えないため。ADR 番号の予約([docs/adr/README.md](../adr/README.md))と同じ扱い。

## タスク仕様の位置づけ

**使い捨て文書**として扱う(ADR-0004 論点2)。

- 実装完了(PRマージ)時点で**凍結**し、以後は更新しない
- 実装後の正は**コードと TDD**。この文書は当時の指示であって、現在の仕様ではない
- したがって実態合わせ改訂(TDD01 §5.4 W6)の対象外
- レビュアーエージェントは、この文書を「仕様との過不足」を判定する根拠に使う

書くのは「どう作るか」。「何を作るか」と「なぜそうするか」は GDD・TDD・ADR が持ち、ここでは**リンクするだけ**にする。ここに設計判断を書き始めたら、それは ADR か TDD に書くべき内容である。
