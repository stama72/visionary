# 実装タスク仕様

設計セッションが実装エージェントに渡す作業指示。運用は [ADR-0004](../adr/0004-ai-driven-development-workflow.md) と [ADR-0006](../adr/0006-issue-driven-task-management.md) による。

> **仕様の「書き方」は [docs/process/02-task-spec.md](../process/02-task-spec.md)、レビューの規律は [docs/process/01-review.md](../process/01-review.md) に移した。** 本書は置き場所・ファイル名・テンプレートを持つ。**状態は issue が持つ**(下記)。

## 状態は GitHub の issue が持つ

**この文書が状態一覧を持つ運用は廃止した**([ADR-0006](../adr/0006-issue-driven-task-management.md) 論点1)。進行中のタスク・優先順位・依存関係・凍結は [issue](https://github.com/stama72/visionary/issues) を見る。

**issue はブランチ非依存である。** そのため「一覧は master へ直接コミットする」という迂回([ADR-0004](../adr/0004-ai-driven-development-workflow.md) 帰結)も同時に不要になった。ADR 番号の予約は引き続き master へ直接コミットする。

### 進め方の規律

規律そのものは [ADR-0004](../adr/0004-ai-driven-development-workflow.md) 論点3 のまま。器だけが issue に変わった。

- **開発者の判断を要するタスクの WIP は 1。仕様が凍結済みの実装タスクに限り 2 本まで**([ADR-0006](../adr/0006-issue-driven-task-management.md) 論点4、[docs/process/04-issue-driven.md](../process/04-issue-driven.md))
- **レビューを終えて初めて、次に取り組むタスクを選べる。** レビュー中を放置して新しいタスクを進行中にしない
- レビューが難航した、または前提として別タスクが必要だと判明したときは、**承認せずに凍結してよい**。デッドロックを避けるための逃げ道であり、使うことをためらわない。**凍結は issue を閉じず、`blocked` ラベルと待っている issue 番号で表す**
- 新しいタスクで**勝手にセッションを開かない**。まずメインセッションに相談し、専門性が違うと判断されたときだけサブセッションへ一時的に移る(その間メインは凍結)
- **メインに戻るときは、サブセッションのタスクを完了か凍結して閉じる**

## タスク仕様の位置づけ

**使い捨て文書**として扱う(ADR-0004 論点2)。

- 実装完了(PRマージ)時点で**凍結**し、以後は更新しない
- 実装後の正は**コードと TDD**。この文書は当時の指示であって、現在の仕様ではない
- したがって実態合わせ改訂(TDD01 §5.4 W6)の対象外
- レビュアーエージェントは、この文書を「仕様との過不足」を判定する根拠に使う

書くのは「どう作るか」。「何を作るか」と「なぜそうするか」は GDD・TDD・ADR が持ち、ここでは**リンクするだけ**にする。ここに設計判断を書き始めたら、それは ADR か TDD に書くべき内容である。

## ファイル名

`W<段階>-<連番>-<スラッグ>.md` — 例: `W1-03-random-streams.md`

**「W」は週ではなく段階である**(TDD01 §5.4 の呼称を引き継いでいる)。期日は GitHub Milestone が持つ。

**ブランチ名には issue 番号を含める** — `feat/<issue番号>-<スラッグ>`。タスク仕様とブランチと issue の対応が名前だけで辿れる。

## 引き継ぎメモ

`W<段階>-<連番>-<スラッグ>.handoff.md` — タスク仕様と同じ名前に `.handoff` を挟む。

**フェーズをまたいで消える5件だけを持つ**([ADR-0009](../adr/0009-phase-scoped-sessions.md) 論点2)。何を書き、何を書かないかは [docs/process/05-phase-sessions.md](../process/05-phase-sessions.md) が持つ。

**使い捨て層。フェーズ3 で PR 説明へ転記し、同じブランチの最後のコミットで削除する。**

```markdown
# W1-03 引き継ぎメモ

**この文書は PR 説明へ転記して削除する。**

## 却下した設計案(フェーズ1)

- **<案>** — 採らない理由。<なぜその理由が今も生きているか>

## implementer の件数(フェーズ2)

- 止まって報告した件数: N 件
  - <内容を1行ずつ>
- 決めて報告した件数: M 件
  - <内容を1行ずつ>

## 直さないと決めた指摘(フェーズ2)

| 巡 | 象限 | 指摘 | 直さない理由 |
| -- | ---- | ---- | ------------ |

## 巡ごとの件数(フェーズ2)

| 巡 | 守備範囲 | 象限I | 象限II | 疑い |
| -- | -------- | ----- | ------ | ---- |

打ち切ったなら理由を1行。

## `mutator` の件数(フェーズ2)

- 当てた変異: N 件 / 期待と食い違った数: M 件
```

## テンプレート

以下をコピーして使う。

---

# W1-03: 系統別乱数ストリーム

| 項目     | 内容                           |
| -------- | ------------------------------ |
| issue    | #12                            |
| 根拠     | ADR-0002 論点2 / TDD01 §3.1   |
| ブランチ | `feat/12-random-streams`       |
| worktree | `visionary-random-streams/`    |

## スコープ

**含まない:** 後続タスクへ送るものと、既存コードのうち触らないもの。

**変えない既存コード**(規則8。[02-task-spec](../process/02-task-spec.md)「変えないと宣言する既存コード」)。単位はファイルではなく規則。「一致」と書けるのは現行版の節を読んで突き合わせたときだけで、していないなら「未確認」:

| 変えないコード(規則の単位) | 従う節(現行版) | 確認 |
| --------------------------- | --------------- | ---- |
|                             |                 | 一致 / 不一致(→ 本タスクで直す・#N へ)/ 未確認 |

## 作るもの

型とメソッドのシグネチャ水準まで書き、実装エージェントに設計判断を残さない。判断が必要だと気づいたら、実装に渡す前に設計セッションで決める。

- **各項目に TDD/GDD の該当箇所を引用する。** 引用できないものは新しい決定であり、先に TDD/GDD へ書く
- **「宣言のみでよい」と書かない。** フィールド一覧を書けないなら実装タスクではない
- **保証には残る穴を併記する。**「X で防ぐ。ただし Y は防げない」
- **順序・境界は具体例で固定する**

## 落ちるべき条件(テスト)

**この節が完了条件そのもの。** 目標は「通ること」ではなく「**壊したときに落ちること**」である。

「この実装ミスで落ちる」を埋められないテストは未完成であり、実装に渡さない。

**「核心」印を付けたら、当てる変異まで書く** — 場所・内容・期待(赤 / 緑)。**変異を選ぶのは仕様であり、測るのは [`mutator`](../../.claude/agents/mutator.md) である**([ADR-0013](../adr/0013-mutation-measurement-separated.md) / [02-task-spec](../process/02-task-spec.md)「変異テスト」)。印だけ付けると、選ぶ仕事が測る者へ落ちる。

| # | テスト | 検証内容 | この実装ミスで落ちる | 核心(当てる変異 / 期待) |
| - | ------ | -------- | -------------------- | ------------------------- |
| 1 |        |          |                      |                           |

## 編集してよい文書

worktree をまたいだ所有権の宣言。**ここに挙がっていない文書は触らない。**

- なし(コードとテストのみ)

## このタスクで特に効く規約

ADR-0002 の決定論規約のうち、このタスクで踏みやすいものだけを挙げる。**機械で捕まるものは書かない** — `BannedSymbols.txt` と `DeterminismConventionTests` がビルドとテストで止めるため、ここに書くとレビューの注意を無駄に割く。
