## 却下した設計案(フェーズ1)

- **`HouseholdState` に当日ぶんの欄を6本足す案** — `World` の区分1つ(`Metrics`)を採った。理由は [TDD01 §3.8](../04-tdd/01-sim-core-and-m0.md) の除外の理由を欄ごとに書かずに済むこと。**失われる保護**: `StateHasherCoverageTests.ExpectedSectionElementMembers` は `HouseholdState` の欄を1本ずつ凍結しており、欄を足すたびに「ハッシュに入れるか」を人に明示させる。区分にすると、**その強制が区分を足すこの1回だけになり、以後 `MetricsScratch` に欄を足しても凍結テストは何も言わない。** タスク仕様の「残る穴」に明記した
- **判定関数(#209)まで1本のタスクにする案** — 開発者の判断で2本に割った([決定ログ](https://github.com/stama72/visionary/issues/41#issuecomment-5796332682))。**失われる保護**: 列の定義と、それを消費する判定が別の PR になるので、**「この列で §8 の7項目が本当に判定できるか」を同じレビューで見られない。** #209 が列の不足を見つけたら #41 へ戻る往復が要る。割った理由(レビュー4巡上限)のほうが重いと判断した
- **帳簿を刈って 36,000日 の性能を作る案** — 採らず、`MarketReference.TryPreviousDaySettledPrice` の走査方向だけを直した。刈ると [TDD01 §3.8](../04-tdd/01-sim-core-and-m0.md) の `Ledgers` の契約が動き、決定論ハッシュの範囲が変わる。**失われる保護**: 帳簿は伸び続けるので、**経済が生き返った状態の 36,000日 ではメモリと `StateHasher` の1回ぶんの走査が線形に増える。** その形は誰も測っていない
- **区画別の列を `prices.csv` に畳む案**(`district_id = -1` を都市集計とする) — ファイルを増やさずに済むが、集計の単位が違う行が同じ表に混ざる。`districts.csv` を別に立てた
