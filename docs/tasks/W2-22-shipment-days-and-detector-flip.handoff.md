## 却下した設計案(フェーズ1)

- **条件1・2 にも反転側を残す**(人為的に悪い世界を組んで「1日以上止まる」を維持する) — **採らない。**「素の `WorldDefinition.M0` を30日回す」という検出器の題そのものが変わる。#210 決定ログ1 の実測では違反日0のシードしか残らないので、維持するには世界を悪く作るしかない。
  **却下で失う保護**: **数え過ぎ方向の取り違えを見る目**(W2-16 の M-1 = `ProductionRuns = Math.Max(1, runs)` が反転側を全5シードで赤にしていた)。正側ではこれが緑になる。**穴の実際の大きさは V-2 が測る** — `ProductionSystemTests` の `Assert.Equal(0, ...ProductionRuns)` 群が同じ変異を捕まえていれば、検出器が見なくても suite は見ている。
- **数え過ぎを留める assert を足す**(例「生産0 の世帯が1戸以上ある日が30日のうちにある」) — **採らない。** データに乗った留め具になる。#210 決定ログ1 の day 29 の生産停止世帯は 2〜4 戸だが、経済が良くなれば 0 になりうる値で、そのとき「退行」と同じ形の赤が出る。`ScanThirtyDays` の doc コメントが 6.2 の等値 assert について同じ警告を既に持っている。
  **却下で失う保護**: 上と同じ。**2案とも却下したので、条件1・2 の数え過ぎ方向は本タスクの後、検出器の外にしか無い。**
- **条件3 の構造的な留め具(M-8 = 世帯在庫と工房在庫の取り違え)を本タスクで塞ぐ** — **採らない。** #173 の持ち物として W2-17 が既に issue へ送っており、本タスクは #216(出荷日数と向きの反転)である。
  **却下で失う保護**: 条件3 は**いまも**「世帯在庫が全品目0」と「工房在庫が全品目0」を判別しない(2026-09-22 実測、`mutator`)。本タスクはこれを直さない。
