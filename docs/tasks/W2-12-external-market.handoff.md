## 却下した設計案(フェーズ1)

- **窓口を `World.Market` に実体化する** — [GDD02d §2.1](../03-gdd/02d-external-market-and-money.md) が決定として却下済み。`Market` のキーは売り手**世帯**であり、実体化すると決定論ハッシュに「`Market` は含める / 窓口は含めない」の二重定義が生まれる。**どちらに実装しても同一設定の2回実行は一致するので CI が検出しない** — 却下理由はこの「検出できなさ」に立っており、いまも生きている
- **窓口の当日価格を全世帯に見せる**(所在が公開なら価格も公開)— [GDD06 §3.1](../03-gdd/06-trade-and-negotiation.md) が「所在は公開、価格は距離 R の外からは見えない」と明記している。見せると隅の世帯が外部売値の季節変動を先読みでき、情報の摩擦が窓口の側から抜ける。代わりに未知価格の見積もりを **1** と決めた([GDD02d §2.2](../03-gdd/02d-external-market-and-money.md) に追記)
- **窓口の未知価格の見積もりを 0 にする** — 「最も楽観的な下限」としては 0 が自然だが、`BuyerBudget.Decide` と `TradeSettlement.FundsCap` が「実効価格は 1 以上」で投げる。**検査を緩める側に倒すと、床が 0 の品目で `PurchaseQuantity` の除算に到達する経路が開く**
- **輸出を段5a の外出の計画へ畳む** — 余剰はその日の世帯間取引が確定するまで決まらない([GDD02d §2.3](../03-gdd/02d-external-market-and-money.md)「確定したあと」)。畳むと持ち込む量を予測する別の規則が要る
- **`TradeSettlement.Execute` に `null` の売り手を通して窓口を表す** — 売り手側の在庫・資金・帳簿を動かす枝が `if (seller != null)` だらけになり、世帯間の約定の不変条件が読めなくなる。別メソッド2本(`ExecuteImport` / `ExecuteExport`)にした
- **`BandMultiplier` を実測に合わせて引き上げ、シードを足す** — 発散は [#120](https://github.com/stama72/visionary/issues/120) の守備範囲であり、本タスクで帯を緩めると #120 の検出器が先に鈍る。**シード1・20 倍のまま据え置き、実測を doc コメントに 1 行残す**
