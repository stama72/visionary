## 却下した設計案(フェーズ1)

- **校正 (c) の摩耗を 1 回あたりの摩耗費 `CeilDiv(工具の床 × 所要労働‰, N × 1000)` × 回数で数える** — 採らない。あれは 02c §2.3 の利潤上限のための保守的な丸めであり、現金の流出ではない。この形だと水車小屋番が −960/年(−3.6%)に見えて (c) を破り、値を動かして直そうとすると本当は釣り合っている収支を崩す。**失われる保護**: 利潤上限の摩耗費と (c) の摩耗が別の式になるので、片方の丸めを変えても他方のテストは落ちない
- **出荷目標在庫と入力の目標在庫を定数表のまま残す** — 採らない(02c §1.3 の理由: 所要労働‰ を動かしたとき物差しだけが古いまま残り、踏んでも気付けない)。**失われる保護**: 表なら値をテストで直接凍結できたが、導出では生産能力経由の 1 本になる。テスト #3 と #27 がその 1 本を踏む
- **`ErrandLaborLossPermille` を Production が読んだ後に 0 へ戻す** — 採らない。書き手を順5 の 1 か所にする(2 か所が書くと「どちらが最後か」が仕様になる)。**失われる保護**: #98 が外出の無い日に 0 を上書きし忘れると損失が翌日以降も残るが、本タスクのテストは捕まえない。#98 のテスト表に置く
- **初期在庫を 0 にして (d) の資金で初日に買わせる** — 採らない。0 から始めると初日の需要が全世帯で同位相になり、02b §5.4 が警告する売り手と買い手の同位相の振動を初日に叩き込む。工房在庫は D 日ぶん、世帯在庫は春の目標在庫にした。**失われる保護**: (d) の条件が初日に実際に効く経路が無くなる(テスト #25 は式の側だけを見る)
