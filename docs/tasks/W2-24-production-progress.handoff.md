## 却下した設計案(フェーズ1)

- **「増産できない」を順4 で労働力から計算し直す(今の実装を残す)** — 前日から持ち越した端数が見えないので、GDD02b §8「その日の生産能力が 0」と一致しない。鍛冶は外出した日の翌日に、持ち越しで完成できるのに Need が立つ。**失う保護: 無し**
- **「生産量 0 かつ 入力が足りている」から能力 0 を逆算する(欄を足さない)** — 入力も足りない日は、能力 0 か入力切れかが一意に決まらない(#218 全般1巡目 指摘3)。**失う保護: 無し。代償は欄が1つ増え、ハッシュに乗ること**
- **順1 から順4 へ `World` の外(システムのフィールド・`SimContext`)で渡す** — 状態が `World` の外に出てハッシュに乗らず、途中から再開した走行が別の Need を出す。**失う保護: 無し**
- **欄を1つにし、「労働を足した後・引く前の進捗」を持つ(持ち越しは翌日の順1 が前日の生産量から求め直す)** — TDD01 §3.2 の「生産の進捗‰(持ち越した端数)」と意味が食い違い、付け替えで 0 に戻す規則が「引く前の値を 0 にする」に変わる。**失う保護: 無し。代償は欄が1つ多いこと**
- **醸造の完了条件を 60日走行のまま読む**(61日走行で day 60 に生産がある / 60日走行で day 59 以上) — 前者は「最終稼働日」ではなく「最後の1日に作ったか」になり、一時的な停止(仕様)の日に当たると落ちる。後者は issue の物差し(day 60)を1日緩める。**90日走行を採った代償は、5シード × 90日の全走行がテストに1本増えること**(既存の 60日 × 5シードの全走行と同程度)
- **校正 (a) も年間実行回数で解き直す** — GDD02d §4.4 は「下の検算」((c))だけを年間実行回数で解くと書いている。(a) を日ごとの floor のまま残すと供給を下から見積もる十分条件になる。**失う保護: (a) が平均の供給で見たときの余裕(木材加工 1,444 回 vs 1,440 回など)を見ないこと。M0 の値では結論が変わらない**
