# TDD(技術設計書)分冊一覧

アーキテクチャと技術リスクの潰し込み。GDDと同じく「育てる文書」であり、マイルストーンごとに実態との乖離を見直す。エンジン・言語などの大きな決定は[ADR](../adr/)が正であり、TDDはそれを実装可能な設計に展開する。

## 執筆ルール

- 数値(閾値・性能目標)は初期値として書き、調整対象であることを明記する
- 「M0限りの仮置き」はプレースホルダであることを本文中で宣言し、正式化する分冊を指す
- 各分冊に「未決定事項」節を置き、判断待ちを可視化する
