> **本書が持つのは、売り手が並べる単価(提示価格)と、買い手が払える単価の上限(予算)である。** どちらも**1単位あたりの貨幣額**であり、相手が誰かに依らず決まる。いくつ買うか(数量)は予算と在庫から [02b](02b-consumption-and-household.md) の個別需要関数が決め、どこへ行きどの店で買うか(外出と実効価格)と妥結は [GDD06](06-trade-and-negotiation.md) が決める。原価と利潤の計測は [02a](02a-production.md)、外部価格と床の定義は [02d](02d-external-market-and-money.md) が持つ。
>
> **提示価格と予算は同じ材料から作る。** どちらも「相場基準」(自分の観測の平均)を軸に、売り手は在庫で係数を掛け、買い手は在庫で係数を掛けたうえで払える金で切る。**相場基準を持たない日の規則を別に持たない** — 売り手は床に落ち、買い手は現金上限だけが残る。**速さだけを変える** — 売り手は前日の値、買い手は保持期間の平均(§1.2)。

## 1. 提示価格(**決定**)

売り手が「いくらで並べるか」。妥結価格は [GDD06](06-trade-and-negotiation.md)(M0 では提示価格をそのまま妥結価格とする)。

```
在庫比‰   = CeilDiv( 1000 × 販売在庫 , 出荷目標在庫 )
価格係数‰ = clamp( 1500 − CeilDiv(在庫比‰, 2) , 500 , 1500 )
前日に自分の約定が無い日: 価格係数‰ = min( 価格係数‰ , 1000 )   ← §1.1「売れなかった日は値上げしない」
提示価格  = max( 床 , ApplyPermille(相場基準, 価格係数‰) )

床        = 外部買値                                     ← 02d §2.3。全区画で同じ
相場基準が無い日: 提示価格 = 床
```

- **床は原価ではなく外部買値である。** 手元の在庫の取得原価は埋没費用であり、値付けに入らない([GDD02 §5](02-economy.md) 帰結2)。窓口に持ち込める値より安く並べる理由が無い、という機会費用の床である。**床を下回る提示価格は投げ売りでも出ない**(§1.4)
- **床は「窓口が無限に床で買う」ことに立っている。** [GDD11](11-external-trade.md) で担い手が有限の需要を持つ NPC に変わると、提示価格の床・輸出の閾在庫・投げ売りの床がすべて柔らかくなる。M0 ではこの前提が成り立つ
- **床は 0 にならない。** 外部買値は正の定数([02d](02d-external-market-and-money.md))なので、財の投入が無い職業(原価 0)でも、相場基準が 0 に固定される経路は無い。**原価から床を作っていた旧版が抱えていた「0 が恒久に固定される」問題は、床の出所を変えたことで消えた**
- **原価は提示価格に使わない。** 原価の移動平均は利潤の計測のために残す([02a](02a-production.md))。**価格の経路から外れたので、仕入値が提示価格に跳ねる正のフィードバックは無い**

> **旧版の床は `ApplyPermille(原価, 1000 + 最低利幅‰)` だった。** 「原価割れで売らない」は現金と利潤の混同であり、しかも原価が外部買値を上回った工房の在庫を凍らせて輸出を止めていた([02d §2.3](02d-external-market-and-money.md))。**最低利幅‰ は値付けから消え、仕入上限(§2.3)へ移った** — 利幅は「これから作るか」の判断に効く量であって、「持っている物をいくらで売るか」には効かない。

### 1.1 価格係数

| 販売在庫 | 価格係数‰ | 意味 |
| -------- | --------- | ---- |
| 0 | 1500 | 品薄。相場の1.5倍 |
| 出荷目標在庫 | 1000 | **相場どおり** |
| 出荷目標在庫 × 2 以上 | 500 | 溢れている。相場の半値 |

**その品目について前日に自分の約定が1件も無かった売り手は、値上げしない。** その日のその品目の価格係数‰ は 1000‰ を超えない。**判定は (売り手 × 品目) ごとである** — 提示価格が (売り手 × 品目) ごとに決まるので、世帯単位で判定すると別の品目の約定が値上げを許してしまう(M0 は1世帯1出力なので差が出ず、踏んでも気付けない)。約定は帳簿(`Sale` の行)で数え、**窓口への輸出([02d §2.3](02d-external-market-and-money.md))も約定に含める** — §1.2 の「自分の前日の約定単価」と同じ母数である。

- **在庫比‰ が 1000 を下回っていても、売れていないなら相場より上へは出さない。** 品薄であること自体は、誰も払わなかった値を正当化しない
- **値下げ側には効かない。** 在庫が溢れている売り手の 500‰ はそのまま働く(`min` であって固定ではない)
- **破産中(§1.4)は 500‰ の固定が先に効く**ので、この規則は何もしない
- **捌けている売り手は制約を受けない。** 都市内で売れた日も、窓口へ輸出した日も約定である。**在庫が動いている売り手だけが値上げできる**

> **この規則が無いと、売れない売り手どうしの提示価格が等比的に発散する。** 売り手 A・B が同じ品目を出していて互いの提示価格しか観測できないとき、A の翌日の提示は B の前日の提示 × 係数A、B の翌日は A の前日 × 係数B である。**日次の公比は √(係数A × 係数B) / 1000 になり、係数の積が 1000² を超える限り、約定が1件も無くても発散する。** 売れず・作れずで販売在庫が凍った売り手は係数も凍るので、この積は恒久に 1000² を超えうる。
>
> **[§1.2](#12-相場基準) は「自分の前日の提示価格を錨にしない」と決めて1周期の自己ループを塞いでいたが、他者を経由する2周期は塞いでいなかった。** 実測([issue #120](https://github.com/stama72/visionary/issues/120) の決定ログ)では醸造2戸が係数 1194‰・1027‰ で凍り、公比 1.1075 で 120 日に 6 桁へ達した。**本規則は積の両側を 1000‰ 以下に抑えることで、この 2 周期を塞ぐ。**
>
> **却下した案。** (a) 相場基準の材料を約定単価の観測に変える — 観測0件の日が激増し、床に固定される売り手が増える。(b) **天井 = 輸入平価**(全品目に外部売値を置き、窓口が全品目を売る)— 床(外部買値)と対称で経済学的には最も正統だが、[02d](02d-external-market-and-money.md)「都市生産品は外部買値だけを持つ」の反転であり、窓口が全品目を無限に売る世界では都市内生産の希少性が消える。**この案は、担い手が有限の需要を持つ NPC に変わる [GDD11](11-external-trade.md) で再び候補になる。**

> **`価格係数‰` の式は減算の中に `CeilDiv` を持つため、式全体としては切り下げ方向になる(在庫比‰ が奇数のとき係数が1‰小さくなる)。これは意図的である。** 在庫比を切り上げてから引くことで、品薄側(在庫比が小さいとき)ではなく充足側(在庫比が大きいとき)に1‰の誤差が寄る。値付けが**品薄側へ偏る**ほうが [GDD02 §4.1](02-economy.md)(情報の摩擦)・[02b](02b-consumption-and-household.md)「不当価格はどこで成立するか」の設計意図に沿うため、[GDD01 §2.3](01-trust-and-conversation.md) の「全計算式切り上げ」の原則をここでは字面どおり在庫比‰ の算出にだけ適用し、係数全体には及ぼさない。

### 1.2 相場基準

**`相場基準` は、その品目についての有効な観測(`PriceObservation`)から作る。売り手と買い手で速さを変える。**

| | 材料 | 平均の規約 | 速さ |
| -- | ---- | ---------- | ---- |
| **買い手の予算**(§2.1) | 世帯主の**有効な記憶**(保持期間内の観測すべて。[GDD06 §3.1](06-trade-and-negotiation.md)) | 合計 ÷ 件数、[GDD01 §2.3](01-trust-and-conversation.md) の原則どおり切り上げ(`CeilDiv`) | **遅い**。保持期間(初期値 7 日)の移動平均 |
| **売り手の値付け**(§1) | 他の売り手ごとに**最新の1件** + **自分の前日の約定単価** | 同上 | **速い**。前日の値で決まる |

- **誰の観測かは世帯主(親方)である。** 知識は個人が持つ([TDD01 §3.2](../04-tdd/01-sim-core-and-m0.md) は `Knowledge` を NpcId 別とする)ので、世帯の誰の観測を読むかを決めないと値が定まらない。**買い物に行くのが徒弟でも、値付けと予算に使うのは世帯主の観測である**
- **有効な観測が0件なら相場基準は立たない**(提示価格は床に落ち、予算は現金上限だけが残る。§1・§2.1)。**0 を平均に混ぜるのではない**
- **売り手の自分の錨は前日の約定単価であり、提示価格ではない。** 売れなかった日の提示価格を翌日の基準にすると、誰も払わなかった値が自分の相場になる。前日に約定が無ければ加えない(0 を足すのではない)。完売した日は約定単価 = 提示価格なので、この規則は完売の側には効かず、売れ残った側にだけ効く。**約定単価は前日の全約定の合計 ÷ 数量(`CeilDiv`)で、窓口への輸出([02d §2.3](02d-external-market-and-money.md))も含める** — 帳簿は資金の増減と一致する規約([02b §3](02b-consumption-and-household.md))なので輸出も約定であり、含めないと「前日の約定」が帳簿から離れる。余剰を輸出した売り手は床寄りの値を錨にすることになるが、それは床に張り付いている売り手の実態と一致する
- **他の売り手の観測が1件も無いときは、自分の約定単価も使わない。** そのときは相場基準を立てず、床をそのまま提示価格にする(§1)。**これは日単位ではなく配置単位で恒久になりうる** — 同職業の2世帯は別区画に居て、視界は R = 1、記憶は保持期間(7日)で失効するので、相手が自分の外出先の隣接にも入らない配置では、その売り手は在庫に関係なく床に固定される
  - **旧版の却下理由は「自分だけを錨にすると純粋な自己ループが成立する」である。この理由は生きている。** かつてここには「買い手側の遅い相場基準で弱まっている(錨が誰であれ、売り手の値上げは買い手の受容 = 週平均の 1.8 倍で止まる)」と書いていたが、**上の囲みのとおり買い手の受容は公比の上限を作るだけで、値上げを止めない**([issue #120](https://github.com/stama72/visionary/issues/120))。自己ループを許すかどうかは、[§1.1](#11-価格係数) の「売れなかった日は値上げしない」が入った状態で改めて判断する。**判断は完売の枝で行うこと** — 約定が無い枝では §1.1 が錨の出所に関係なく値上げを止めるので、そこで見ると自己ループは安全に見える。**危ないのは完売が続く売り手が自分の約定単価(= 自分の提示価格)を錨にする枝であり、§1.1 はそこに効かない。** **M0 では規則を変えず、[GDD02 §8](02-economy.md) のメトリクスに「相場基準を持たない売り手日の割合」を置いて実測する。** 割合が大きければ、自分の約定単価だけを錨にすることを許す側へ戻る
- **[02d §2.3](02d-external-market-and-money.md) の輸出の閾在庫が使う相場基準は売り手のもの(速い側)である**

> **買い手を遅くすることは、発散の「速さ」に上限を与えるが、「水準」は固定しない。** 出荷目標在庫は日産の 3 日分なので、完売して当日の生産分だけ持つ売り手は在庫比 333‰、価格係数 1333‰ と読まれ、**完売が続く限り毎日 1.33 倍で上げる。** 買い手の基準が売り手と同じ速さ(前日の値)で動くと、買い手の受容(相場項 1.2 倍 × 在庫圧力 1.5 倍 = 前日の 1.8 倍)が毎日ついて行き、完売が止まらない。**買い手の基準を 7 日平均にすると、系全体が日次の公比 g で伸びるとき買い手が追随できるのは `Σ(k=1..7) g^−k ≥ 7 / 1.8` を満たす g までで、上限は g ≤ 1.173/日 である。**
>
> **これは上限であって歯止めではない。** 1 < g ≤ 1.173 の範囲がまるごと残るので、**系は「買い手がぎりぎり追随できる最大速度」で発散しうる。** [issue #120](https://github.com/stama72/visionary/issues/120) の実測(120日・3シード)の公比は 1.107〜1.166 で、いずれもこの上限の直下だった。**旧版はこの囲みを「複利発散の歯止め」と書いていたが、誤りである** — 期待した「売れ残り → 在庫比が上がる → 係数が落ちる」は、売れない売り手が資金を失って生産も止め、**在庫が増えないまま凍る**ときに起きない。**水準を止めるのは [§1.1](#11-価格係数) の「売れなかった日は値上げしない」である。§1.1 が完売の枝に効くのは、売れ残った日が1日でも入れば翌日に価格係数が 1000‰ へ落ちるからであり、在庫比が上がるのを待たない** — 旧版が期待した「売れ残り → 在庫比が上がる → 係数が落ちる」より1段速い。**ただし止まる水準は経路依存である**(最初に売れ残りが起きた水準で止まる)。初期値の近傍で止まる保証は §1.1 からは出ない。**そして §1.1 はラチェットの停止であって復元力ではない** — 両方の売り手が 1000‰ で頭打ちになると公比は 1.0 になり、その水準で凍る。下げるのは在庫比(在庫が積み上がれば 500‰ まで落ちる)だけである。
>
> **代償が2つある。** 第一に、旧版が「売り手ごとに最新の1件」で避けていた「よく見る売り手ほど重みが増す」偏りを買い手側で受け入れる。第二に、値下がり時には買い手の基準が高いまま残り、買い手には安く見えて買い溜めが起きる — これは意図した挙動([02b](02b-consumption-and-household.md))だが、**保持期間を周期とする振動が残る可能性がある。** [GDD02 §8](02-economy.md)-1 で実測する。
>
> **この公比の上限は 保持期間(7日)・許容乖離(1200‰)・在庫圧力の上限(1500‰)の3つから決まる**(上の `Σ` の式の解であって、3つの積ではない)。保持期間は知識モデルの値([GDD06 §3.1](06-trade-and-negotiation.md))であり、情報の摩擦の都合で動かすと**発散の速さの上限が黙って動く**。この絡みを [GDD02 §9.2](02-economy.md) に記す。**価格の水準そのものの天井はここには無い** — 床は外部買値(§1)、水準の歯止めは [§1.1](#11-価格係数) が持つ。

> **売り手側に自分の錨を含めるのは、売り手2世帯のあいだの交互振動モードを消すためである。** 互いの前日価格だけを錨にすると遷移行列の固有値が ±√(k_A·k_B) になり、**高値の日と安値の日が交互に続く**。自分を含めると行列の行が同一になり、この固有値が 0 に落ちる。**この導出は線形近似の下でのみ成り立つ** — 両売り手の価格係数が同一で、その日在庫が動かないという近似に立っている。残留する交互成分がどれだけあるかは実測でしか分からない([GDD02 §8](02-economy.md)-1)。

### 1.3 販売在庫と出荷目標在庫

**`販売在庫` は、工房在庫のうち売り注文として `Market` に出している分である。生産職では自分のレシピの出力在庫の全量がこれにあたる**(出力を手元に残す規則を M0 では置かない)。 在庫は世帯在庫(消費財)と工房在庫(生産の入出力)の2本に分かれる([GDD08 §2.2](08-household-and-decision.md) / [TDD01 §3.2](../04-tdd/01-sim-core-and-m0.md))が、**販売在庫はそのどちらとも別の切り口であり、工房在庫の部分集合である** — 生産の入力として抱えている分は売りに出ていない。§1.4 の投げ売りも④のゲート([02b](02b-consumption-and-household.md))も [02d §2.3](02d-external-market-and-money.md) の輸出も、**届くのは販売在庫だけである**。

**`出荷目標在庫` は日産から導く。** [02a §4](02a-production.md) の入力の目標在庫と同じ形である。

```
出荷目標在庫 = 生産能力(実行回数。労働力は損失を引く前の合計、設備係数 1000‰ で評価。02a §4) × 出力数量 × 出荷日数        出荷日数 = 3(初期値。§3)
```

> **実際の生産量からではなく生産能力から導く。** 実績で導くと、生産が停止している工房で導出元が 0 になり、在庫比‰ の分母が消える。生産能力は労働力と設備から決まるので、停止中の工房も「まだ目標に届いていない」と正しく判定される。旧版はこの零除算を避けるために定数表にしていたが、定数のままだと校正表([02d §4.4](02d-external-market-and-money.md))の所要労働‰ を動かしたときに在庫比の物差しだけが古いまま残り、それは踏んでも気付けない。**入力の目標在庫と同じ導出にして、同じ値(生産能力)から動くようにする。**

### 1.4 破産中の売り手

**破産中フラグ([02b](02b-consumption-and-household.md))が立っている売り手は、価格係数‰ を 500 に固定する。** 在庫圧力を無視して相場の半値で並べ、在庫を現金に換える。

```
破産中: 提示価格 = max( 床 , ApplyPermille(相場基準, 500) )
```

- **床は破らない。** 半値が床を下回るなら床で並べる。床は窓口の値なので、それより安く都市内に並べる理由は破産中でも無い — 同じ在庫を窓口に持ち込めば床の値で現金になる([02d §2.3](02d-external-market-and-money.md))
- **したがって投げ売りの余地は「相場の半値」と「床」の間にしかない。** 相場が床の 2 倍を下回っていれば、破産中でも提示価格は床のままで、この分岐は何もしない。**困窮の段階②を独立した段階として残すか、輸出(床で捌く)に吸収するかは [02b](02b-consumption-and-household.md) が決める**

> **旧版の②は「原価下限を 500‰ に下げる」だった。** 床が原価から外部買値に変わったので、下げる対象が無くなった。半値の意味(在庫を早く現金にする)だけを価格係数の固定として残す。

## 2. 予算(**決定**)

**予算は買い手が1単位に払える上限であり、1つの世帯・1つの(用途, 品目)について1つである。** 店ごとの事情(信用・提示価格)と外出の費用は入れない — それは実効価格と外出の費用であり、[GDD06 §2](06-trade-and-negotiation.md) が持つ。**購入条件は「その日に居る区画の店のうち実効価格が最も安い店で、その実効価格が予算以下」**である。移動は外出ごとに払い、店ごとの単価には乗せない([GDD06 §2・§3](06-trade-and-negotiation.md))。

### 2.1 統一形

```
予算 = min( ApplyPermille(相場項, 在庫圧力‰) , 現金上限 , 利潤上限 )

相場項    = ApplyPermille( 相場基準 , 許容乖離‰ )                 ← 相場基準(§1.2、買い手側)が無ければこの項は無い
在庫圧力‰ = 500〜1500。目標在庫の 2 倍超で 0([02b §5.1](02b-consumption-and-household.md))
現金上限  = FloorDiv( 用途に使える資金 , max(1日分の数量, 1) )      ← 常にある。資金は下表の母数
利潤上限  = 生産の入力にだけある(§2.3)。計算できない日は無い

無い項は min から落とす。3 項とも無いことは無い(現金上限は常にある)
在庫圧力‰ が掛かるのは相場項だけである ── 現金上限にも利潤上限にも掛からない
```

| 用途 | 相場項 | 用途に使える資金(母数) | 1日分の数量 | 利潤上限 | M0 の品目 |
| ---- | ------ | ---------------------- | ----------- | -------- | --------- |
| 必需 | あり | 流動資金 | 1日消費量(世帯合計) | — | パン・薪 |
| 耐久 | あり | 流動資金 − 必需の取り置き | **1 個**(1日分は 1 個未満) | — | 工具 |
| 生産の入力 | あり | 流動資金 − 必需の取り置き | 1日の投入量(生産能力 × 必要数量) | **あり**(§2.3) | 穀物・木材・鉄鉱石・木炭・小麦粉・薪 |
| 嗜好 | あり | 流動資金 − 必需の取り置き − 運転資金 = **余剰資金** | 1日消費量 | — | ビール |

```
必需の取り置き = Σ_(必需の消費, 品目)( 目標在庫 × 相場基準[前日] )       ← 持ちたい在庫を今の相場で買い揃える金
運転資金       = Σ_(生産の入力, 品目)( 目標在庫 × 相場基準[前日] )       ← 同上。定義と規約は 02b
相場基準が無い品目は加算しない。母数が負なら 0
```

**役割は2つに分かれる。相場項が「いくらなら妥当か」、現金上限が「1日分を買える金があるか」である。**

- **数量を決めるのは相場項である。** [02b §5.2](02b-consumption-and-household.md) の個別需要関数は、**在庫圧力を掛ける前の相場項**を基礎値に置き、実効価格との比から購入量を解く。在庫が少ないほど高くまで買い、安ければ買い溜める。**基礎値に在庫圧力を掛けてはならない** — 在庫圧力は線形解の形そのものに既に入っており(到達在庫が予想在庫と一致する価格が `相場項 × 在庫圧力‰` である)、基礎値にも掛けると二重に効く
- **予算の第 1 項は、その線形解が「何も買わない」と答える価格そのものである。** `ApplyPermille(相場項, 在庫圧力‰)` は `到達在庫 = 予想在庫` となる実効価格に一致するので、第 1 項だけを見る限りゲートは線形解の言い換えにすぎない。**それでも min の第 1 項として明示するのは、現金上限・利潤上限と同じ土俵で比べるためと、丸めと clamp(500‰ の下限・2000‰ 超の 0)がある以上ゲートが実際に効く帯が残るためである**
- **現金上限はゲートである。** 「その用途に使える金で 1 日分が買えない」なら数量は 0、買えるなら数量は相場項が決める。**上限は在庫圧力の外側にある** — 切羽詰まって相場の 1.5 倍を出す気があっても、払えない値は払えない。**単価が高すぎるかどうかの判断は相場項だけが持ち、現金上限は持たない** — 2 つの役割を 1 つの比率に載せると、どちらの役割の値としても調整できなくなる
- **母数の段階が資金の優先順位である。** 必需は流動資金の全額から払える。工具と入力は「食料の取り置きを除いた残り」から、嗜好は「さらに運転資金を除いた余剰」からしか払えない。**先に守るものほど母数が大きい。** 決済の走査順(必需 → 耐久 → 入力 → 嗜好。[02b](02b-consumption-and-household.md))はこれと同じ順である
- **相場基準が無い日は相場項が落ち、現金上限だけが残る。** 旧版はこれを「フォールバック」という別の規則で持っていたが、統一形では min の帰結である。**相場を知らない世帯は、その用途に使える金を 1 日分の数量で割った額までなら払ってしまう** — これが不当価格の発生源であり([02b](02b-consumption-and-household.md)「不当価格はどこで成立するか」)、情報の摩擦が価格に現れる正規の経路である。初期観測を配って塞がない
- **在庫圧力を 1000‰ で頭打ちにしていた旧版の理由は消えた。** 旧版は「1000‰ を超えると派生需要(利益が出る上限)を超えて買う」ことを恐れていたが、利潤上限が min の外側で切るので、在庫圧力がいくら上がっても上限は超えない

> **貨幣から需要への経路は現金上限が担う。** 都市の貨幣が減れば流動資金が細り、母数の小さい用途から順にゲートが閉じて需要が落ちる。逆に貨幣が溜まれば開く。[02d §4.2](02d-external-market-and-money.md) の自動調節は、M0 ではこの経路だけで働く。**価格の上昇そのものの歯止めは現金上限ではなく、§1.2 の買い手側の遅い相場基準が担う。**

### 2.2 母数がなぜ段階なのか

- **嗜好を余剰資金にするのは、黒字倒産を防ぐためである。** 流動資金をそのまま母数にすると、明日の仕入に要る金がそのまま遊興費の原資になる。運転資金を先に取り置き、残りからしか嗜好に回さない。**困窮の段階①(嗜好を諦める)はこの帰結であり、規則としては実装しない**([02b](02b-consumption-and-household.md))
- **工具と入力を「流動資金 − 必需の取り置き」にするのは、生産のために食料を切らさないためである。** 取り置きが無いと、入力を買った翌日にパンが買えず、破産中フラグが「仕入の順序」で立つ。取り置きは目標在庫 × 相場基準なので新しい軸は増えず、**薪の目標在庫が季節で動くぶん、冬は取り置きが増える** — 冬支度の現金版である
- **必需を流動資金の全額にするのは、生活の継続を最後まで守るためである。** ここを余剰資金に倒すと、困窮した世帯が食料を買えなくなる
- **工具を入力より先に置くのは、工具が 10 日に 1 個の安い支出で入力の効率を倍にするからである**([02a](02a-production.md) の設備係数)。工具が無くても生産は止まらないが半減する。入力を先に買って工具を諦めるより、工具を先に買って入力を減らすほうが翌日の生産が多い
- **取り置きも運転資金も、現在の在庫を差し引かない。** 差し引くと在庫が満ちた日に母数が跳ねて嗜好に流れ、翌日の仕入で資金が尽きる。「常時寝かせておく額」である([02b](02b-consumption-and-household.md))

### 2.3 利潤上限 — 生産の入力にだけある

**「作って売れば利幅が残る」値でしか入力を買わない。** 利潤の側の判断はここに集約される([GDD02 §5](02-economy.md))。

```
見込み収益     = 提示価格_出力[前日] × 出力数量               ← レシピ1回の実行あたり
許容原価合計   = floor( 見込み収益 × 1000 ÷ (1000 + 最低利幅‰) ) − 摩耗費[1回あたり](02a)
相場での原価   = Σ_k( 相場基準_k × 必要数量_k )                 k はレシピの全入力
利潤上限_j     = floor( 許容原価合計 × 相場基準_j ÷ 相場での原価 )   入力 j の 1単位あたり

次のいずれかなら利潤上限は無い(min から落ちる):
    提示価格_出力[前日] が無い(初日、前日に売り注文を出していない)
    いずれかの入力 k の相場基準が無い(相場での原価が定義できない)
    許容原価合計 ≤ 0
```

- **意味は「レシピが相場でどれだけ儲かるかの比率で、各入力の相場を伸縮する」である。** `利潤上限_j = 相場基準_j × (許容原価合計 ÷ 相場での原価)` と読める。相場で作って利幅が残るなら比率は 1 以上で、相場項(許容乖離‰)のほうが先に効く。**残らないなら比率は 1 未満で、相場より安くしか買わない → 仕入が細る → 生産が減速する → 出力の在庫が減る → 出力の提示価格が上がる → 比率が戻る。** これが原材料価格の下流への転嫁であり、1日遅れの負のフィードバックである
- **配分は相場基準に比例させる。** 複数入力(パン = 小麦粉 + 薪)で許容原価をどう分けるかは、各入力の相場 × 必要数量の比で分ける。**すべての除算を切り下げる**ので、各入力の上限 × 必要数量を合計しても許容原価合計を超えない(整数の性質)。`ApplyPermille` を経由すると入力ごとに切り上がって合計が超えうるので、‰ を挟まず直接比例配分する
- **1入力のレシピでは `利潤上限 = floor(許容原価合計 ÷ 必要数量)` に一致する**
- **前日の出力提示価格を使う。** 当日の値を使うと、予算 → 仕入 → 在庫 → 提示価格 → 予算が同一 tick で循環する([GDD08 §6.3](08-household-and-decision.md) の1日遅延の成層化)
- **入力のどれかに相場が無ければ利潤上限ごと落とす。** 一部の入力だけで按分すると、観測できた入力が「本来2入力で分けるはずだった上限」を丸ごと受け取る。落とせば現金上限だけが残り、その日は「相場を知らない世帯」と同じ扱いになる。**視界 R = 1 では、パン屋から水車小屋番と木材加工がともに見えない日が普通に起きる** — 塞がず、情報の摩擦として残す
- **摩耗費を先に引く。** 工具代を回収できない仕入は利益が出ていない([GDD02 §5](02-economy.md) 帰結3)。1回あたりの摩耗費は [02a](02a-production.md) が持つ

> **旧版の「派生需要」は、この値を上限ではなく基礎値にしていた。** 基礎値にすると在庫圧力が掛かる前の値が利潤で決まり、相場より安く買える日でも買い溜めが起きず、逆に「派生需要 → 仕入値 → 原価 → 提示価格 → 翌日の派生需要」という正のフィードバック経路ができていた。**上限にすれば、数量は相場項が決め、利潤は買ってよいかのゲートだけを担う。** 経路も、原価が提示価格から外れたことで消えた(§1)。

### 2.4 M0 の機会費用

**機会費用は職業 × 階層の固定値とする**(算出方式は [GDD08 §5](08-household-and-decision.md)、M0 スコープと階層係数は [GDD08 §9](08-household-and-decision.md))。外出の費用([GDD06 §2](06-trade-and-negotiation.md))がこれを使う。**基準値は 5 職業とも 20(貨幣/1時間)** — [GDD08 §5.1](08-household-and-decision.md) の定義「親方の1日粗利 ÷ 可処分時間 12」を [02d §4.4](02d-external-market-and-money.md) の校正表に当てると、校正 (c) が各職業の粗利を生活費 + 摩耗と同じ約 250 に揃えるので、5 職業とも 21 前後になる。徒弟は階層係数 200‰ で 4。旧値 {5, 6, 6, 4, 8} は初期の粗利が小さい前提で置いた暫定値だった

構造(予算と費用の分離、統一形の min、在庫圧力の線形解)は M0 から入れる。**構造を先に固定し、値の由来を後から差し替える**のは季節係数([02d §5](02d-external-market-and-money.md))と同じやり方である。
