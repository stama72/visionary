## 0. この文書の位置づけ

信用システムと会話システムは、本作のUSP「信用が資本になる」と「情報を足で稼ぐ」を実装する中核であり、**コアループの2工程(歩く・聞く / 商う)を直接支える**。両者は不可分(会話が信用を生み、信用が会話の内容を変える)なため、1つの分冊にまとめる。

数値はすべて**初期値であり、M0〜M2の調整対象**である。ここで固定したいのは数値ではなく、システムの構造と依存関係。

## 1. 設計方針

1. **会話それ自体に意味を持たせる**。情報を得るための手段としてだけの会話は作業になる。話しかける・話を聞く行為そのものが信用という蓄積を生むことで、会話が目的にもなる
2. **信用は中世商業のリアリティである**。掛け売り・手形・評判で回っていた当時の商業を、メカニクスとして再現する。ファンタジーの好感度システムではなく、経済の構成要素として設計する
3. **効果は4点に限定する**。信用が「なんとなく色々に効く」状態は、プレイヤーが因果を追えずGuild 3化する。効き先を絞り、プレイヤーが「信用を上げると何が起きるか」を明確に予測できるようにする
4. **シミュレーションへの組み込みは段階的に**。まずプレイヤー⇔NPC間で成立させ、NPC同士への拡張は制御可能性を確認してから行う(§2.6)

## 2. 信用システム

### 2.1 データモデル

```
TrustScore
  from    : NpcId           // 信用を寄せる側
  to      : ActorId         // 信用を寄せられる側(プレイヤー or NPC)
  value   : int  [0, 100]   // 信用スコア
  lastMet : Tick            // 最後に接触したtick
```

- v1.0の必須スコープは `to = プレイヤー` のみ。`to = NPC` はフルスコープ(§2.6)
- NPC 100体 × プレイヤー = 100レコード。フルスコープでも 100×100 = 10,000レコードで、疎行列として保持すれば問題ない規模

### 2.2 信用が影響する4つの効果

**この4つ以外に信用を効かせない。** 拡張したくなった場合はこの表に追記し、影響の全体像を1箇所で把握できる状態を保つ。

| # | 効果 | 内容 | 実装上の形 |
|---|------|------|-----------|
| 1 | **取引相手の選好** | 同条件なら信用のある相手から買う。多少高くても信用を優先する | NPCの購買評価で実効価格 `p' = p × (1 - α × trust/100)` を用いる(α初期値0.2 = 信用MAXで実質2割引の魅力) |
| 2 | **交渉価格の幅** | 信用があるほど価格交渉で動かせる幅が広い | 交渉可能レンジ `±(base + β × trust/100)`%(base 3%, β 12% → 信用MAXで±15%) |
| 3 | **掛け売りの可否** | 信用が一定以上で後払い・信用取引が解禁。上限額も信用に比例 | Tier「常連」以上で解禁。与信枠 `= γ × trust`(γ初期値は通貨単位で調整) |
| 4 | **情報開示の深さ** | 信用に応じて話す内容が深くなる。世間話→相場の実数→他人の事情→秘密 | 会話トピックの解禁条件(§3.2) |

### 2.3 信用の増減

| 行為 | 変化 | 備考 |
|------|------|------|
| 挨拶・雑談 | +1 | **1日1回まで**。連打による稼ぎを封じる |
| 話を聞く(ニーズの傾聴) | +2 | ニーズを最後まで聞いた時。同一ニーズにつき1回 |
| ニーズの充足 | +5〜+20 | ニーズの緊急度・規模に比例 |
| 約束の履行 | +5〜+15 | 期日内。期日ぎりぎりは減額 |
| プレゼント | +2〜+8 | 相手のニーズに合致するほど大きい([idea/001](../idea/001-コアループ.md) §4.2) |
| **約束の不履行** | **−15〜−30** | 期日超過・放棄。獲得より損失を大きくする(§2.4) |
| 不当な価格での売りつけ | −5〜−15 | 相場からの乖離幅に比例。**相手が乖離に気づける場合のみ**(§4の知識モデルに依存) |
| 期間経過による減衰 | **TODO(§2.5)** | 設計判断が必要 |

### 2.4 非対称性の原則

**信用は築くのに時間がかかり、失うのは一瞬。** 上表で不履行のペナルティ(−15〜−30)を単発の獲得(+1〜+20)より大きく設定しているのはこのため。これは中世商業のリアリティであると同時に、「約束を軽く扱えない」という緊張感がゲームプレイの重みを作る。

ただし**回復不能にはしない**。信用0に落ちても、時間と誠実な取引で再建できる余地を残す(プレイヤーが詰む状態を作らない)。

### 2.5 【要決定】信用の減衰モデル

**この判断は「作業感」の問題に直結するため、起案者が決める。**

長期間会わないNPCの信用が下がるかどうか。3案あり、それぞれ体験が大きく変わる:

- **案1:減衰なし**。一度築いた信用は永続。プレイヤーは新規開拓に集中できるが、「一度上げれば終わり」で関係の維持という遊びが消える
- **案2:一律減衰**(例:30日会わないと −1/週)。定期的に顔を出す動機が生まれるが、**NPCが増えるほど巡回が義務になり、まさに「作業」化するリスク**。Stardew Valleyはこの問題を抱えている
- **案3:上限の減衰**(スコア自体は下がらないが、しばらく会わないと効果1〜4の適用が段階的に鈍る。再会話1回で即時回復)。維持コストを「巡回」ではなく「思い出したときに一声かける」程度に抑える折衷案

決定したら本節を結論で置き換え、§2.3の該当行を埋めること。

### 2.6 スコープとフォールバック

| 段階 | 内容 | 判定 |
|------|------|------|
| **必須** | プレイヤー⇔NPC間の信用。効果1〜4すべて | v1.0必須 |
| **フルスコープ** | NPC同士の信用も経済シミュレーションに組み込み、取引相手選好・交渉価格に反映 | M0で制御可能性を検証 |
| **フォールバック** | フルスコープが破綻した場合、NPC同士の信用は廃し、プレイヤー関連の取引条件と会話発生条件のみに縮小 | M0で判定 |

フルスコープの懸念は**バランス調整の困難さ**:信用が取引相手選好に効くと、経済が「最適な取引相手」ではなく「関係の履歴」で回り始め、価格形成が意図せず硬直または発散しうる。M0のヘッドレス実行で、信用ありモデルとなしモデルの価格系列を比較して判断する。

## 3. 会話システム

### 3.1 会話の構造

会話はトピック選択式。自由入力やフルボイスの分岐ドラマは作らない(工数)。

```
会話開始 → トピック一覧提示 → 選択 → 応答 → (トピック一覧に戻る) → 終了
```

| トピック | 解禁条件 | 得られるもの |
|---------|---------|------------|
| 挨拶 | 常時 | 信用+1(1日1回)、相手の機嫌・近況の断片 |
| 世間話 | 常時 | 街の噂、天候・行事の情報 |
| ニーズを聞く | Tier「顔見知り」以上 | **ニーズの開示**(§3.2)。信用+2 |
| 商談(売る/買う) | 常時(条件は信用依存) | 取引。交渉幅・掛け売りは効果2・3に従う |
| 相場を尋ねる | Tier「常連」以上 | 品目の価格情報(§4の知識に加算) |
| 他人のことを聞く | Tier「信頼する相手」以上 | 他NPCのニーズ・事情・紹介 |
| 依頼の報告 | 依頼受注中 | 約束の履行判定 |

### 3.2 ニーズの開示

**ニーズは手書きクエストではなく、シミュレーション状態から発生する**([idea/001](../idea/001-コアループ.md) §1)。会話は、シムの内部状態を人間の言葉として開示するインターフェースである。

```
シム状態(在庫不足/金銭不足/労働力不足/建設意欲/イベント/病気…)
    ↓ ニーズ生成
Need { 種別, 対象NPC, 品目, 数量, 期限, 緊急度, 理由 }
    ↓ 台詞化(§3.3)
「うちの娘が来月結婚するんだが、花嫁衣装の布が手に入らなくてね」
```

信用Tierによって開示の深さが変わる:
- 顔見知り:ニーズの存在と品目のみ(「布が要る」)
- 常連:数量・期限・予算まで(「来月までに3反、200まで出せる」)
- 信頼する相手:背景・事情まで(「実は蓄えが乏しくて、掛けで頼めないか」)

### 3.3 台詞生成パイプライン

**全NPCに手書き台詞は不可能**(NPC 100体 × ニーズ種別 × 状況)。テンプレート+パラメータ差し込みで生成する。

```
DialogueTemplate
  needType   : NeedType      // ニーズ種別
  occupation : Occupation    // 職業(パン屋、鍛冶屋…)
  personality: Personality   // 性格(寡黙、饒舌、卑屈、尊大…)
  trustTier  : TrustTier     // 信用段階
  text       : string        // "{item}が{qty}ばかり要るんだ。{deadline}までに何とかならんか"
```

- 差し込みパラメータ:`{item} {qty} {deadline} {budget} {reason} {npcName} {playerTitle}`
- **手書きは主要NPCに限定**:領主/市参事会、司教・修道女、主要な取引先数名。ストーリーを担うキャラクターのみ
- 品質リスク:テンプレートは繰り返しが目立つと世界が死ぬ。同一条件に複数バリエーションを持たせ、ランダムではなく**未使用のものを優先**して選ぶ(反復感の軽減)

**このパイプラインの品質はM0の検証項目**(企画書 §6 / コンセプトシート GO判断)。テンプレートで「人間らしさ」が出せない場合、NPC数を削って手書き比率を上げる方向に縮小する。

### 3.4 場所・状態による会話の変化

[idea/001](../idea/001-コアループ.md) §4.2・[idea/002](../idea/002-都市.md) §1 より:

| 要因 | 効果 |
|------|------|
| 酒場 | 酔ったNPCは信用Tierを1段階上として振る舞う(口が軽くなる)。翌日は覚えていない場合あり |
| 商人のオフィス訪問 | Tier「常連」以上で解禁。商談の成功率・交渉幅にボーナス |
| 私的な食事への招待 | Tier「信頼する相手」以上。深い情報と大口案件の入口 |
| 服装 | 身分の高いNPCは相応の身なりを要求(会話自体を拒否)。「行商人の服」は通行人からの声かけを誘発 |
| 教会 | 信用・コミュニケーションについての助言(チュートリアル的機能) |

## 4. 情報の非対称性(知識モデル)

信用の効果4「情報開示の深さ」が意味を持つ前提として、**プレイヤーは全知の相場表を持たない**。

```
PriceObservation
  item     : ItemId
  location : LocationId
  price    : int
  observedAt: Tick     // 観測時刻(鮮度)
  source   : Direct | Heard   // 自分で見たか、聞いた話か
```

- プレイヤーの「相場感」は観測記録の集合であり、鮮度が落ちた情報は不確実なものとして表示する(具体的なUI表現は別分冊)
- NPC側も同型の知識を持つ。これにより効果2(交渉)と§2.3の「不当な価格」判定が成立する——**相手が相場を知らなければ、高く売りつけても信用は下がらない**(そして後で気づかれれば下がる)
- この非対称性こそが「情報を足で稼ぐ」というUSPの実体

## 5. ニーズ解決フロー(コアループとの接続)

[idea/001](../idea/001-コアループ.md) §1.1で定義された流れを、本システムの用語で再記述する:

1. **耳を傾ける**(会話:ニーズを聞く)→ Need の開示、信用+2
2. **考える**(プレイヤーの判断)→ 手持ち/仕入れ/誰かに作らせるかの選択
3. **キーパーソンを探す**(会話:他人のことを聞く、街歩き)→ 供給者の発見。信用Tierが探索効率を左右する
4. **関係を築く**(会話・取引の積み重ね)→ 供給者側の信用を上げる
5. **説得する**(商談・交渉)→ 効果2・3が効く
6. **履行する** → 信用+5〜+20、都市の状態が変化

**この6工程が本作の「クエスト」であり、そのすべての工程で信用が効く。** 信用システムはコアループの装飾ではなく、骨格である。
