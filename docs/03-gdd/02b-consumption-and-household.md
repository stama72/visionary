## 1. 日次消費

| 品目 | 消費者 | 量 | 分類 |
| ---- | ------ | -- | ---- |
| パン | 全 NPC | 家族規模に比例 | **必需** |
| 薪 | 全 NPC | 季節で変動 | **必需**(冬に急増) |
| ビール | 全 NPC | 階層で変動 | **嗜好** |
| 工具 | 工房 | 生産で摩耗([02a §3](02a-production.md)) | **耐久** |

**必需・嗜好・耐久の分類が価格形成に効く**([02c §2](02c-price-and-budget.md))。必需は価格が上がっても買う(需要が硬直的)、嗜好は諦める(弾力的)。**奢侈の分類も式としては持つ**([02c §2.1](02c-price-and-budget.md))が、**M0 に該当する品目は無い** — ワイン・香辛料は [GDD11](11-external-trade.md) が持つ。

#### 1日消費量(初期値)

**1人1日あたりの個数。階層ごとに持つ。** 上表の「家族規模に比例」は構成員ぶんを足すこと、「階層で変動」は行が階層で違うことを指す。

| 品目 | 親方 | 職人 | 徒弟 | 季節係数 |
| ---- | ---- | ---- | ---- | -------- |
| パン | 1 | 1 | 1 | 掛からない |
| 薪 | 2 | 2 | 2 | **掛かる**([02d §5](02d-external-market-and-money.md)。値は [GDD03 §2](03-seasons-and-city.md)) |
| ビール | 1 | 1 | 0 | 掛からない |

- **減らすのは世帯在庫であって工房在庫ではない。** 薪は消費財でも生産の入力でもある([GDD02 §2.2](02-economy.md))ため、2本の在庫([TDD01 §3.2](../04-tdd/01-sim-core-and-m0.md))のどちらから引くかを決めておく必要がある。生産の入力としての薪は [02a §1](02a-production.md) が工房在庫から引く。**§1.1 の自家消費は工房在庫を減らすが、それは消費ではなく移動である** — 引く先を決めるこの規則は変わらない
- **徒弟のビールが0なのは、徒弟が給金を持たないためである**([GDD10 §1](10-employment.md)。嗜好は諦められる、§5.3)。職人は M0 に居ない([GDD02 §2.4](02-economy.md))が、階層の行は先に埋めておく
- **職人・主婦・子どもを含む階層の一覧は [02a §2](02a-production.md) が持つ。** 本表が持つのは M0 の `NpcRank` の3階層だけである

**季節係数は構成員ごとに適用して切り上げ、それから世帯で合計する。** 丸めが入るので順序が結果を変える。例: 親方+徒弟の世帯が夏(400‰)に消費する薪は `ApplyPermille(2, 400) = 1` の2人ぶんで **2** である。

> **M0 の初期値ではどちらの順序でも一致する**(基礎量2が偶数で、係数を掛けた積が 1000 で割り切れるか、切り上げが同じ側に倒れるため)。**一致しなくなるのは基礎量が奇数のとき** — 基礎量1・係数500‰・2人なら、構成員ごとなら 1+1 = **2**、世帯合計に先に掛けると `ApplyPermille(2, 500) = 1` である。**基礎量は [GDD02 §9.2](02-economy.md) の調整対象なので、いま一致していることに頼らない。**

**在庫が足りないときの消費の規則**: **在庫は 0 で下げ止まり、負にならない。** 足りなかったぶんは繰り越さず、その日の不足として §8 の Need(在庫不足)になるだけである。**M0 では飢餓・健康・死亡をモデル化しない**(NPC は不死、[GDD02 §7](02-economy.md))ので、不足が蓄積する変数を持たない。

> **この規則が無いと §5.2 が壊れる。** 在庫が負に振れると `購入量 = max(0, 到達在庫 − 予想在庫)` が負在庫の絶対値ぶん膨らみ、それが §3 の資金上限で毎日切り詰められて**破産中フラグが恒久的に立つ**。(§5.1 の在庫圧力‰ は 1500‰ で頭打ちなので、そちらは発散しない。)

### 1.1 自家消費 — 自分の生産物を世帯在庫へ移す(**決定**)

**工房在庫にある自分の生産物を、消費の直前に世帯在庫へ移す。** これが無いと、**世帯が消費できるのは買ったものだけになり、パン屋はパンを抱えたまま飢える**([issue #174](https://github.com/stama72/visionary/issues/174) の実測: シード1・60日で、パン屋 h1 の世帯在庫[パン]が 0 の日に工房在庫[パン]が 15〜16 ある)。

**これは移動であって取引ではない。貨幣は動かず、帳簿にも記帳しない**(§3「帳簿は資金の増減と一致する」を破るため)。**2本の在庫の分離(§1)は変えない。**

```
対象品目 = 自分のレシピの出力品目
目標日数 = 必需の目標在庫の日数[品目] + 嗜好の目標在庫の日数[品目]        (§2)

目標在庫 = Σ( 消費量[d] )   d = 今日 … 今日 + 目標日数 − 1                (§2 の先読み)
移動量   = min( 販売在庫[品目] , max( 0 , 目標在庫 + 今日の消費量 − 世帯在庫[品目] ) )

工房在庫[品目] −= 移動量
世帯在庫[品目] += 移動量
```

- **位置は順2 消費の直前である**([TDD01 §3.3](../04-tdd/01-sim-core-and-m0.md))。順1 生産の直後ではない。**「消費を終えたあとに目標在庫へ届く量」を移す規則は、消費の直前でしか書けない**
- **水準が「消費後に目標在庫ちょうど」(販売在庫が足りる日)なのは、§5.1 の予想在庫がそこを読むからである。** 段4 の需要は順2 の後の世帯在庫を予想在庫として読む([TDD01 §3.3](../04-tdd/01-sim-core-and-m0.md) 段4)。予想在庫 = 目標在庫 なら在庫圧力‰ は 1000 になり、§5.2 の到達在庫が目標在庫に一致して**購入量が 0 になる** — **パン屋は自分のパンを買いに行かない。** 消費の前に目標在庫へ届く量にすると予想在庫が `目標在庫 − 1日消費量` になり、パン屋は相場の 1.17 倍まで払って他のパン屋からパンを買う
  - **安い日に買い溜める経路は閉じない。** 実効価格が基礎値を下回れば到達在庫は目標在庫を超える(§5.2 の検算表)ので、自家消費できる世帯も安ければ買う。**閉じるのは「相場どおりの値段で自分の生産物を買う」経路だけである**
  - **目標在庫は今日ぶんを含む**(§2 の先読みは `d = 今日` から始まる)ので、移動後の世帯在庫は買い手が段4 で積む水準より1日ぶん多い。**代償は「その1日ぶんが市場に出ない」ことだけで、翌日の生産で戻る** — 木材加工の薪でいえば冬でも 8 個であり、日産 36 個の前では見えない
- **販売在庫を上限に取る**([02c §1.3](02c-price-and-budget.md))。工房在庫を直に読まない。**自家消費は販売在庫を通る6本目の経路である** — 直読みすると、鍛冶の工具の留保(1個)を素通りする経路が1本増える。**M0 では対象3品目の留保量がすべて 0 なので数値は変わらない**が、留保が値を持つ品目が現れた日に黙って外れるのを防ぐ
- **移した量はその日の売り注文に出ない。** 順2 は順5 より前なので、段1 が販売在庫を読む時点で移動は済んでいる。**順序の帰結であり、別の規則を足していない**
- **用途で分岐しない。** 必需(パン・薪)も嗜好(ビール)も同じ式で移す。醸造が自分のビールを飲むことになり、**嗜好は余剰資金で買うという規律(§3.1)が醸造のビールにだけ効かなくなる**が、分岐を足すと「なぜ用途で違うのか」を本節が答える必要が生じ、**「足すのは移動だけである」という本節の性格が崩れる**。中近世の醸造が自分のビールを飲まない理由も無い
- **耐久(工具)と、世帯が消費しない品目(小麦粉)は、対象から外す条件を置かなくても移らない。** この2品目は**目標日数も当日の消費量も 0** であり(§1 の1日消費量の表にも §2 の目標在庫の表にも行が無い)、`max( 0 , 0 + 0 − 世帯在庫 )` が 0 を返す。**目標日数が 0 であることだけでは足りない** — 消費表に行がある品目の目標日数だけを 0 にすれば、当日の消費量ぶんだけ移る。**M0 にその組み合わせは無い。** 絞り込みを規則として書かないのは、書くとそれを守るテストが書けないためである(外しても値が変わらない)。**工具を移してはならない理由は別にある** — 耐久の目標在庫(§2)は工房在庫に対するものであり、世帯在庫へ移すと [02a §3](02a-production.md) の設備係数が見る在庫が減って生産が止まる
- **必需の取り置き(§3.1)は、移した在庫のぶん自然に縮む。** 取り置きは目標在庫と予想在庫の差を数える(§3.1)ので、自家消費で世帯在庫を目標まで満たした品目は取り置きに残らない。**自家供給できる品目を取り置きから外す規則は置かない** — 品目で分岐しなくても、在庫で差し引けば同じ結果になる([issue #185](https://github.com/stama72/visionary/issues/185) は §3.1 の差し引きに含まれた)

## 2. 目標在庫(**決定**)

**目標在庫は用途 × 品目ごとに持つ。** 在庫圧力(§5.1)、取り置きと運転資金(§3)、外出先の選択の目標購入量([GDD06 §3](06-trade-and-negotiation.md))がすべてこれを参照する。

| 用途 | 目標在庫(初期値) | 単位 | 所在 |
| ---- | ------------------ | ---- | ---- |
| 必需 | 薪: 1週間分(1日消費量は季節変動)。パン: 3日分 | 個 | 本節 |
| 嗜好 | ビール: 1日分 | 個 | 本節 |
| 耐久 | 工具: 耐久値の 500‰ × 階層係数 | 耐久値(‰人日) | 本節 |
| 生産の入力 | 1日の投入量 × 緩衝日数 D(3) | 個 | [02a §4](02a-production.md) |

**目標在庫は「N日 × 現在の1日消費量」ではなく、「今後 N 日に消費する予定の量の合計」とする。**

```
目標在庫 = Σ( 消費量[d] )      d = 今日 … 今日 + N − 1
```

**`消費量[d]` は日ごとに季節係数を適用して切り上げた整数であり、それを足す。** 合計してから切り上げるのではない。薪のように季節係数が掛かる品目では、丸め順で結果がずれる。

- **季節の境をまたぐと自然に前倒しで積み上がる。** 冬が近づくにつれ薪の目標在庫が滑らかに上がり、在庫圧力が上がり、予算が増える — **冬支度が規則ではなく帰結として現れる**
- 季節変動しない品目(パン)では `N × 1日消費量` と一致する。**式が分岐しない**

> **§5.1 が現在庫の側で既に採っている「買い物に行く時点で予想される在庫」と、同じ発想を比較の反対側(目標)に当てたものである。** 両側が先読みになっても**調整軸は増えない** — 変わるのは N の意味だけで、N は元から品目ごとの調整軸である。
>
> **当日の季節の消費量をそのまま使うと、冬に入った瞬間に全世帯の目標在庫が同時に跳ねる。** §5.2 が警告する「売り手と買い手の在庫圧力が同位相で動く」振動を、季節が毎年4回叩き込むことになる。

**M0 が式のまま毎日評価するのは必需と嗜好である。** 生産の入力の目標在庫は [02a §4](02a-production.md)(1日の投入量 × 緩衝日数 D)が持つ。耐久は持ち方を決めておかないと、実装が別の答えを出す。

| 用途 | M0 での持ち方 | 単位 |
| ---- | ------------- | ---- |
| 必需・嗜好 | 上の先読み(「N日分」)をそのまま毎日評価する | 個 |
| 耐久 | `ApplyPermille( ApplyPermille(N × 1000, 500‰) , 階層係数‰[世帯主] )` | **耐久値(‰人日)** |

- **耐久の在庫も目標在庫も耐久値(‰人日)で数える**([02a §3](02a-production.md)「工具在庫 × N × 1000 − 累積摩耗」)。**購入量(§5.2)も耐久値で解き、`CeilDiv(購入量, N × 1000)` で個数に直す** — 半端な耐久値は買えず、切り上げは [GDD01 §2.3](01-trust-and-conversation.md) の全体規約と一致する
- **階層係数は世帯主(親方)のものを採る。** 耐久財を買うのは世帯であり([GDD08 §2.2](08-household-and-decision.md))、耐久の現金上限の母数を世帯の資金にした理由(徒弟が自分の財布を持たない)は**世帯の資金から買えること**であって、徒弟が別枠の目標在庫を持つことではない。**「階層が高いほど複数個を持とうとする」は、階層の違う世帯主が現れる [GDD10](10-employment.md) で効く**
- **M0 の耐久財は工具だけである**([GDD02 §9.1](02-economy.md))。1個あたりの耐久値は [02a §3](02a-production.md) の `N × 1000` そのものなので、品目ごとの表を持たない

## 3. 家計(**世帯単位**)

**家計の主体は個人ではなく世帯である**([GDD08 §2](08-household-and-decision.md))。

```
日次: 流動資金 += 販売収入 − 仕入支出 − 生活費
```

- **流動資金と帳簿(取引履歴)は世帯が持つ。** 帳簿は**資金の増減と一致するため**、個人別に持つと突合できない
- **すべて int**。比率係数は千分率(‰)の整数([ADR-0002](../adr/0002-time-model-and-determinism.md))
- **`生活費` は必需の消費のための支出そのものである。** 別建ての固定費ではなく、`Trade` で必需品を買った代金を指す
- **週次の給金は M0 に無い**(雇用は [GDD10](10-employment.md))。**季節次の税も M0 に無い**([GDD09](09-treasury-and-tax.md))

> **W1 の `World` は流動資金を `NpcState` に持たせている**([TDD01 §3.2](../04-tdd/01-sim-core-and-m0.md))。**世帯単位へ移すのは W2 の作業であり、決定論ハッシュ([TDD01 §3.8](../04-tdd/01-sim-core-and-m0.md))の区分が変わる。** 区分の設計は [TDD01 §3.2「経済主体は世帯である」](../04-tdd/01-sim-core-and-m0.md)が持つ。

### 3.1 取り置き・運転資金・余剰資金(**決定**)

**予算の現金上限([02c §2.1](02c-price-and-budget.md))の母数は用途で段階になる。** 必需は流動資金の全額、耐久と生産の入力は「必需の取り置き」を除いた残り、嗜好・奢侈はさらに「運転資金」を除いた余剰資金である。流動資金をそのまま全用途の母数にすると、**今日の必需と仕入の買い足しに要る金がそのまま遊興費の原資になる。** 段が守るのは**その日の買い足し**であって、翌日分の蓄えではない(下記)。

```
必需の取り置き = Σ_(必需の消費, 品目) ( max(0, 目標在庫[品目] − 予想在庫[品目]) × 相場基準[品目][前日] )
運転資金       = Σ_(生産の入力, 品目) ( max(0, 目標在庫[品目] − 予想在庫[品目]) × 相場基準[品目][前日] )
               予想在庫は §5.1 と同じ値(必需は世帯在庫、生産の入力は工房在庫)
               相場基準が無い品目は加算しない(下記)

耐久・入力に使える資金 = max( 0 , 流動資金 − 必需の取り置き )
余剰資金               = max( 0 , 流動資金 − 必需の取り置き − 運転資金 )
```

- **新しい調整軸は1つも増えない。** `目標在庫` は §2 が既に用途 × 品目ごとに持っており、**そこに「何日ぶん持ちたいか」が入っている。取り置きも運転資金も「持ちたい在庫に届くまで、今の相場で買い足すのに要る額」である。**
- **翌日分と冬支度の現金は取り置かない。** 前日に目標まで満たした世帯では、段4 の予想在庫は `目標在庫 − 1日消費量` なので、取り置きは**その日の消費1日分 × 相場 = 当日の支払い額**に縮む。運転資金も当日の仕入代金になる。薪の目標在庫が季節で動く日には、その差ぶんの買い足し額が乗るだけで、冬の前に現金を寄せる働きは無い。**蓄えを持たせる案(買い足し額 + 翌日の消費1日分)は採らなかった**([#218](https://github.com/stama72/visionary/issues/218) 決定ログ5)— 嗜好の母数が1日分細る。冬や価格の跳ねはその日のうちに困窮へ伝わる
- **走査の単位は品目ではなく(用途, 品目)の組である。** `目標在庫` は用途別にしか定義されていない。**薪はパン屋・醸造にとって生産の入力であると同時に家庭の必需でもあり、在庫も2本に分かれている**([TDD01 §3.2](../04-tdd/01-sim-core-and-m0.md))。取り置きは必需の薪、運転資金は入力の薪を数える
- **現在の在庫を差し引く。** 差し引かないと、在庫を買った現金と、同じ在庫のための取り置きが二重に数えられる。**在庫を目標まで揃えた世帯ほど、手元の現金が減ったうえで同じ額を控除される** — 嗜好と入力の母数が構造的に 0 へ寄る。実測では取り置きが残高を恒久的に上回って入力の母数が 0 に張り付き([issue #30](https://github.com/stama72/visionary/issues/30)、day 20 に全10戸)、余剰資金が 72 以上ある世帯は day 5 以降 10戸中 1〜4戸で、ビールの都市内の約定は校正の 10/日 に対して 2〜3/日だった。**醸造は全シードで day 7〜13 に止まって戻らなかった**([issue #218](https://github.com/stama72/visionary/issues/218))
  - **旧版は差し引かない理由を「在庫が満ちた日に母数が跳ねて嗜好に流れ、翌日の仕入で資金が尽きる(黒字倒産の周期的な振動)」としていた。これは実測で出なかった**(#218、5シード・60日、全世帯日。比較の両側とも [02a §1](02a-production.md) の進捗‰ の下): 差し引くと、入力が資金で止まった世帯日は 27.7% → 11.7%、止まる/再開するの切り替わりは 4.4 → 3.9 回/世帯、必需が資金で止まった世帯日は 5.5% → 0.6% に下がった。**跳ねた母数が流れる先は嗜好だけで、嗜好の購入量は目標在庫の2倍(ビール2日分)で頭打ちになる**(§5.2 の到達在庫の上側 clamp)ので、跳ねた日に流れる額は小さい。**この実測は 60日で、季節の段差([#172](https://github.com/stama72/visionary/issues/172))と冬の薪の目標在庫の増加をまたいでいない**
- **前向きの量であることが要点である。** 過去 N 日の実支出の移動平均で定義すると、**支出できていない世帯ほど必要額が小さく出る** — 困窮して仕入を止めた世帯ほど「運転資金は要らない」と判定され、**余剰資金が大きく出て嗜好に回る**。目標在庫も予想在庫も過去の支出に依存しないのでこの縮退が起きない
- **前日の相場基準を使う。** 当日の値を使うと、予算が当日の支出に依存し、その支出が予算から決まる日内の循環になる([GDD08 §6.3](08-household-and-decision.md) の1日遅延の成層化)。**本書のすべての `相場基準` は前日までの有効な観測から作る**
- **相場基準が無い品目は加算しない。** 現金上限で代用すると、現金上限は流動資金の関数なので**取り置きが流動資金の関数になり、`余剰資金 = 流動資金 − …` が自己参照する**。加算しないぶん取り置きは小さめに出るが、**それは「相場を知らない品目のぶんは取り置かない」という素直な意味になる**
- **除算は現れない。** 在庫の差(整数)× 相場基準(整数)の総和であり、丸めの向きを決める必要が無い

> **醸造の赤字は、必需品が床の上にあるぶんの再分配である。** [02d §4.3](02d-external-market-and-money.md) (c) は床価格で収支 ≈ 0 に校正しているので、床で売る醸造の赤字は買う側の上乗せに一致する — 実勢の薪 13・パン 71 では、パン (71 − 54) × 2 = 34、薪 (13 − 10) × (家計 約4.5 + 入力 6) ≈ 31 で約 −65/日(能力どおり 6 回実行しても約 −68/日)。**出力が床に張り付く職業(ビール、2倍余剰の工具)が、必需品を作る職業へ払い続ける形であり、鍛冶も同じ上乗せを負う**([#219](https://github.com/stama72/visionary/issues/219))。必需品が床を離れる原因は外出の労働損失が (a) の余裕を食うことで、損失の平均は校正に入っていない([#222](https://github.com/stama72/visionary/issues/222))。**本節の差し引きが効くのはビールの側だけである** — 都市内の買い手を厚くしてビールを床から浮かせる。 差し引かなかった旧版ではその買い手が 2〜3/日 に細り、醸造は全シードで止まった。差し引くとビールの都市内の約定は 5.4〜6.0/日 になり、醸造は各シード1戸が day 96〜149 まで稼働した(#218、[02a §1](02a-production.md) の進捗‰ と併用)。**もう1戸は各シードで day 9〜16 に止まる**(都市内の約定 6/日 は1戸の能力に届く量である)。[GDD02 §8](02-economy.md)-3 が醸造について見る。

### 3.2 購入の資金上限と走査順(**決定**)

**どの購入も、支払額が世帯の流動資金を超えてはならない。**

```
買える数量 = min( §5.2 の購入量 , FloorDiv( 流動資金 , その店の実効単価 ) )
             ← 切り下げる。切り上げると1単位多く買えて流動資金が負に落ちる
切り詰めた結果 1単位も買えなかった購入を「資金不足で買えなかった」と呼ぶ

世帯内の購入は次の順に決済する(流動資金を共有するので順序が結果を変える。ADR-0002):
    必需 → 耐久 → 生産の入力 → 嗜好    同じ用途の中では 品目 Id 昇順([GDD02 §2.2](02-economy.md))
```

**走査順を固定するのは、資金が世帯内の共有資源だからである。** [02c §2](02c-price-and-budget.md) の予算は**単価の上限**であって総額の上限ではない(§7)。**資金の上限がある以上、どの購入が切り詰められるかが順序で決まり、それが破産中フラグ → ②の値付け → ④の付け替え → [GDD02 §8](02-economy.md)-2 の判定まで波及する。**

**順序は [02c §2.1](02c-price-and-budget.md) の母数の段階と同じである** — 先に守るものほど母数が大きく、先に決済する。**耐久(工具)を入力より先に置くのは、10 日に 1 個の安い支出で入力の効率が倍になるからである**([02a §3](02a-production.md))。

**必需を先に決済するのは、フラグの意味を保つためである。** 嗜好品を先に買って必需品が切り詰められる順序を許すと、「資金不足で必需品が買えなかった」が**買い物の順序の関数**になり、困窮の指標として読めなくなる。

**「高すぎて買わなかった」は資金不足ではない。** §5.2 が予算(第 1 項 `ApplyPermille(基礎値, 在庫圧力‰)`・現金上限・利潤上限の min。[02c §2.1](02c-price-and-budget.md))を超える実効価格で購入量を 0 にした場合は、そもそも切り詰めが起きていないので上の定義に当たらない。**フラグが拾うのは「買う判断をしたが払えなかった」だけである** — ここを緩めると、価格が跳ねた日に全世帯のフラグが立ち、②が一斉に発動する**価格ショックの検出器**になってしまう。

**ただし必需の現金上限で購入量が 0 になった場合も、資金不足に数える。** 現金上限は「その用途に使える金で 1 日分が買えるか」のゲートである([02c §2.1](02c-price-and-budget.md))。必需でこれが閉じることは、「必需品を 1 単位も買えない」という §3.3 の意味そのものである。**したがって資金不足は2つの経路で起きる**: (1) 現金上限のゲートで購入量が 0 になった、(2) 資金上限の切り詰めで 0 になった。**(2) は必需にも残る** — 必需は薪(Id 5)とパン(Id 6)の2品目で、予算は購入前に全世帯ぶん一括で確定する([TDD01 §3.3](../04-tdd/01-sim-core-and-m0.md) 段4)ので、冬の薪を目標の2倍まで買った後にパンが資金上限で 0 に切られる経路がある。**その状態こそ困窮であり、どちらの経路も同じフラグに数える。** 第 1 項が実効価格を下回って買わなかった(前段落)のと区別するのは、購入量 0 を決めたのがどの項かである。**判定の順と、同点をどちらに倒すかは §5.2「購入量 0 の理由」が持つ**

**買った品の行き先は用途で決まる。** 必需・嗜好の消費は**世帯在庫**へ、生産の入力と耐久(工具)は**工房在庫**へ入る([GDD08 §2.2](08-household-and-decision.md) / [TDD01 §3.2](../04-tdd/01-sim-core-and-m0.md) の2本の在庫)。**走査の単位が(用途, 品目)の組である**([02c §2.1](02c-price-and-budget.md))以上、行き先も用途で決まる — 品目だけで振り分けると、暖房用に買った薪が工房在庫に入り、**生産用の薪の在庫圧力が下がって仕入が止まる**。

**「資金不足で買えなかった」件数は、その日のうちに世帯の状態として記録する**([TDD01 §3.2](../04-tdd/01-sim-core-and-m0.md))。§3.2 のフラグを立てるのは順3 の `Household` だが、切り詰めが起きるのは順5 の `Trade` の中だけであり、**帳簿には残らない** — 記帳されるのは成立した約定だけで、「買えなかった」は行として現れない。順3 は順5 より前にあるので、**読む時点でその欄はまだ前日の値である**。§3.2 の「前日の購入結果を評価する」は、欄を1つ持つだけで順序の帰結として成立する。

### 3.3 破産中フラグ(**決定**)

```
破産中フラグ(世帯の状態。1ビット):
    立つ:  前日、必需品を「資金不足で買えなかった」購入が1つ以上あった
    降りる: 前日、そのような購入が1つも無かった

②(投げ売り)と④のゲートは、どちらもフラグが立っている「状態」で駆動する
```

**評価するのは前日の購入結果である。** 購入が起きるのは `Trade`([TDD01 §3.3](../04-tdd/01-sim-core-and-m0.md) 順5)で、フラグの更新は `Household`(順3)、すなわちその日の購入より前にある。**当日の結果で立てようとすると、②(順5 の値付けでフラグを読む)が同一 tick 内で循環する。** [GDD08 §6.3](08-household-and-decision.md) の1日遅延の成層化・[GDD06 §3.1](06-trade-and-negotiation.md) の「予算は当日の観測を反映しない」と同じ扱いにする。

**「流動資金が尽きた」を残高 0 とは読まない。** 上の規則のとおり、**必需品を1単位も買えない**ことがその意味である。**[GDD02 §8](02-economy.md)-2 の (a)「必需の購入が資金で止まった世帯の割合」が測るのは、このフラグが立っている状態である。**

> **このフラグを「食えない世帯」と呼ばない。** **フラグが見ているのは在庫ではなく現金である。** §5.2 の判定順(相場 → 利潤上限 → 現金上限。同点は先の項が勝つ)から、現金上限で 0 になるには `流動資金 < 基礎値 × 1日分の数量` が要る — **在庫が目標に満ちていても、その品の1日分を相場で買う金が無ければ立つ。** 薪(外部買値 10・2人世帯で1日分4個)なら流動資金 40 未満である。逆に言えば**在庫が尽きているかどうかをフラグは見ない**ので、名前を定義より強い側へ振ると、§8-2 (a) の数字が「この割合の世帯が飯を食えていない」と読まれる。**フラグが言えるのは「必需の購入が資金で止まった」までである。**

> **フラグは「事業が回らない」ことを拾わない。拾わせない。** 必需は買えるが生産の入力が買えない世帯 — 資金が細った鍛冶の典型 — ではフラグが立たず、②にも④にも進まない。**これは仕様である**([issue #30](https://github.com/stama72/visionary/issues/30) 懸念2 の決着、決定4)。**判定条件を生産・仕入の資金不足まで広げない理由は3つある** — (1) ②(投げ売り)は「廃業の前日に在庫を現金化する」段階(§4.1)であり、**実測で生産が止まった世帯日が 66〜72%、入力の資金不足はそれ以上になりうる**(#30 決定4)ので、常態化して段階の意味が壊れる、(2) **入力側のフラグは必需側より強く価格に反応する** — 入力の母数は `max(0, 流動資金 − 必需の取り置き)`(§3.1)なので、**必需の価格が上がると実効価格が上がると同時に母数が縮み、入力のゲートは必需より低い価格で閉じる。** §3.2 が絞り込みで避けた「価格ショックの検出器」に、増幅された形で戻る。**さらにループが正に閉じる** — 入力が買えず生産が落ちる → 都市内のパン・薪の供給が減る → 必需の相場基準が上がる → 取り置きが膨らむ(#30 の実測)。**母数が縮むことは取り置きが正である限り成り立つ。入力のゲートが必需より低い価格で閉じるのは、必需の在庫が目標を1日分以上割った世帯である**(取り置きが在庫を差し引くため。§3.1)。価格が跳ねると不足量が広がるので、増幅の場面ではこの条件は満たされやすい、(3) 「困窮」の意味が「必需が買えない世帯」から「事業が回らない世帯」へ変わり、§8-2 の閾値を置き直すことになる。**入力の購入が資金で止まったことは [GDD02 §8](02-economy.md)-2 の (b) が別に測る。生産が止まったことは §8-3 が、止まった理由は Need(生産の入力切れ。§8)が持つ。**
>
> **④(廃業)がフラグで駆動されている以上、この決着は「事業が死んでも廃業しない」ことを含む。** ②の意味を保つためにフラグを狭く保つことと、④が立ち直れない世帯へ届くことは、1ビットの上では両立しない。**④を別のゲートへ移すかは [#196](https://github.com/stama72/visionary/issues/196) が持つ**(②が実際に発火するまで実測が取れないため、#39 の後)。
>
> **自家消費(§1.1)はこの見落としを広げる方向に効く。** 必需を自分で作れる世帯は必需の購入そのものが減るので、フラグの入力も減る。**#30 決定4 の実測(5シード・30日)では、必需を自家供給できる4戸のフラグ日が 1.7〜11.7%、できない6戸が 15.6〜28.3% だった。** 指標を購入行動に載せている以上、購入せずに満たす経路が増えるたびに (a) の射程は狭まる — **(a) を単独で「困窮」と読まないこと。** **フラグは②④を駆動する状態でもあるので、この非対称は測定だけでなく行動にも出る** — 自家供給できる職業だけが投げ売りも廃業もしない。**長期の職業分布への影響は [#197](https://github.com/stama72/visionary/issues/197) が持つ。**

> **「店を1つも知らないから買えなかった」は破産ではない。** それは [GDD06 §3.1](06-trade-and-negotiation.md) が **在庫不足 / 遠方在庫**の Need に割り当てた状態である(§8 の理由コードも「金銭不足 / 困窮」と別である)。**上の条件が資金の項だけを見ているので、これは自動的に除かれる** — 店を知らなければ購入そのものが起きず、切り詰めも発生しない。

**破産しても世帯は解体しない。** §4 の段階はすべて世帯の行動であり、④の職業付け替えでも構成員はそのまま残る。

> **②の投げ売りの対象は販売在庫である。** 在庫は世帯在庫(消費財)と工房在庫(生産の入出力)の2本に分かれる([GDD08 §2.2](08-household-and-decision.md) / [TDD01 §3.2](../04-tdd/01-sim-core-and-m0.md))。**世帯在庫の食料と薪まで投げ売ると翌日に困窮が深まるだけ**であり、換金の対象にならない。**工房在庫のうち②が届くのは、売り注文が出ている分(= 販売在庫、[02c §1](02c-price-and-budget.md))だけである** — ②は提示価格の分岐なので、売りに出していない生産の入力には効かない。

## 4. 困窮と破産(**決定**)

資金の不足で必需品が買えなくなったとき(**判定の規範は §3.2 の破産中フラグ**)、**段階的に対応する**:

| 段階 | 行動 | M0 での形 |
| ---- | ---- | --------- |
| ① | 嗜好品・奢侈品を諦める | **[02c §2.1](02c-price-and-budget.md) の余剰資金の帰結。** 規則としては実装しない(下記) |
| ② | **在庫を投げ売る**(相場の半値で並べ、残りは床で窓口へ) | **`Trade`(順5)の提示価格の分岐**([02c §1.4](02c-price-and-budget.md))と、**その日の輸出の閾在庫を 0 にする**([02d §2.3](02d-external-market-and-money.md)) |
| ③ | **掛けで買う**(信用が要る) | **M0 スコープ外。**[GDD01](01-trust-and-conversation.md) 効果2「与信」/ [GDD06 §6](06-trade-and-negotiation.md) |
| ④ | 廃業して職業を変える | **`Household`(順3)の職業付け替え**(下記) |

**破産は退場ではなく職業の変更である。** これは中世都市のリアリティであると同時に、**プレイヤーが救う余地を残す**設計である。v1.0 では③で信用システムが経済的な意味を持ち、④が雇用([GDD10](10-employment.md))と接続する。

> **①は規則ではない。** 余剰資金(流動資金 − 必需の取り置き − 運転資金。§3)が嗜好・奢侈の現金上限の母数なので、**流動資金が必要運転資金に近づくだけで嗜好の予算は 0 へ向かう**。困窮の判定を待たずに支出が絞られるので、①を別の処理として実装する必要はない。表に残しているのは段階の並びを示すためである。

### 4.1 ①〜④の実行位置(**決定**)

**`Household`(順3)で実行するのは ④ だけである。②は `Trade`(順5)の値付けと輸出の中で、フラグを読んで分岐する。**

```
Trade(順5)の中で、破産中フラグが立っている売り手は:
    提示価格の価格係数‰ を 500 に固定する(床は破らない)          02c §1.4
    その日の輸出の閾在庫を 0 にする(閾在庫を超えた在庫は床で窓口へ)  02d §2.3

Household(順3)の日次処理。
  **手順ごとに全世帯を Id 昇順で回す。世帯ごとに 1→2 を回すのではない。**
  **M0 の順3 では金が動かない** — 給金(GDD10)・税(GDD09)・掛け売り(③)がいずれも無く、
  仕入の支払いは順5 の約定がその場で行う(§3.2)。固定支出の支払いがこの位置に入るのは
  ③を足したときである。**流動資金は順3 に入る前に確定している。**

  1. 破産中フラグの更新(§3.2。前日の購入結果から)

  2. ④へ進む条件(3つすべて):
       a. 破産中フラグが立っている
       b. 販売在庫が尽きている              ← ②で換金できるものが無い
       c. 生産量が 0 かつ 入力から作れる回数が 0(入力切れ。02a §1)   ← 立ち直れない
        → 下記 §4.2 の付け替えを実行する

     ※ b だけでは足りない。販売在庫 0 は「売れ残りが尽きた」だけでなく
       「その日完売した」にも成立するので、**完売した健全な世帯が1日の資金不足で廃業する**。
       c が「立ち直れないこと」を表す
     ※ b を工房在庫にしてはならない。生産の入力は売り注文に出ていないので ② では現金化できず、
       工房在庫でゲートすると「鉄鉱石を抱えたまま木炭を買えない鍛冶」が永久に ④ に到達しない
     ※ c は入力切れだけを見る。「生産量が 0」だけにすると、進捗‰ が所要労働‰ に届かない日
       (02a §1・§2)も立つ。M0 では鍛冶で、外出の損失の累計が 1300‰ を越えるたび —
       平均損失 ÷ 1300 ≈ 8.5〜15% の日 — に起き、入力を持って毎日作っている破産中の鍛冶が
       労働が1日足りないだけで廃業する(#218 決定ログ6)。入力から作れる回数は順1 の後の
       工房在庫から求める(順3 までに入力の在庫は動かない)
```

**②を順3 の手順にしてはならない。** 投げ売りは `Market` への書き込みであり、順5 の値付け([02c §1](02c-price-and-budget.md)、全売り手ぶんを一括で書く)と**同じ場所に二重に書くことになる**。順3 で書くと、順5 が同日中に上書きして投げ売りが無効化されるか、[TDD01 §3.2](../04-tdd/01-sim-core-and-m0.md) が「更新前の `Market` の値が**前日の提示価格**である」と宣言した値が当日の投げ売り価格に化けて相場基準の入力を汚す。**フラグを読んで値付け側で分岐すれば、書き込みは1か所のままである。**

> **「段階的に対応する」を手順の並びで表さない。** フラグが立った世帯に ①〜④ を一息に適用すると、**最初の破産日に必ず廃業まで到達し**、②で立ち直る余地が構造的に消える。**破産がただちに廃業を意味しない**ことが、§4.2 の「付け替えが頻発するなら価格機構が働いていない兆候である」という観測の前提である。
>
> **段階を進める条件に新しい調整軸を足していない。** 3条件はいずれも既にある状態である — フラグ(§3.2)、販売在庫([02c §1.3](02c-price-and-budget.md))、生産量 0([02a §1](02a-production.md))。**「N日連続で困窮したら廃業」とすると閾値が1つ増える**ので採らなかった。

> **②は輸出に吸収し、独立した段階としては書かない**([issue #30](https://github.com/stama72/visionary/issues/30) 決定)。**②に床があるのは、床が外部買値だからである。** 旧版は床が原価だったので「原価下限を外すと相場 × 500‰ の半減ループで 1 まで崩落する」ことを恐れ、原価の半分を床にしていた。**いまの床は窓口の値であり、投げ売りは「都市内では半値、残りは全量を窓口へ」という意味になる。** 相場が床の 2 倍を下回っていれば都市内の値は床のままで、②の実体は「その日の在庫をすべて床で現金化する」だけである。**§4.2 の条件 b(販売在庫が尽きている)は、②が発火した翌日にはほぼ必ず成立する** — ②は「立ち直る余地」というより「廃業の前日に在庫を現金に換える」段階である。**買い手が視界外(R=1)や予算不足で在庫が捌けなくても、輸出が閾在庫を無視して残りを床へ流すので在庫は同日中に尽きる** — ②に無期限に留まる世帯は存在せず、④への遷移を最終的にゲートするのは条件 c(入力切れで生産量 0)だけである(旧issue #30 の懸念1はこれで解消する)。[GDD02 §8](02-economy.md)-5(床を下回る提示価格が継続しない)は、②が床を破っていないことを併せて確かめる。

### 4.2 ④の付け替え(**決定**)

**M0 では雇用を実装しない**([GDD10](10-employment.md))ため、「他所に雇われる」接続先が存在しない。**M0 に限り、破産した世帯の職業を、担い手の最も薄い職業へ付け替える。**

```
その職業の担い手が自世帯だけなら → 付け替えない(職業を維持する)
そうでなければ:
    候補 = 都市5職業([GDD02 §2.4](02-economy.md))から自職業を除いたもののうち、
           破産世帯の区画に既に同職業の世帯が無いもの([GDD02 §2.4](02-economy.md)「同職業2世帯は別区画」を破らない候補)
    候補が空なら → 候補 = 除外前の全職業(区画の重複を許容する。品目の供給停止のほうが優先度が低いため)
    付け替え先 = argmin( その職業の担い手世帯数 )  over 候補
                 同値のときは職業 Id 昇順
```

**「最後の1世帯は付け替えない」が供給の消滅を構造的に防ぐ。** [GDD02 §2.4](02-economy.md) は「1品目につき売り手2世帯」を M0 の成立条件としているが、**付け替えを無条件にすると両方の木材加工世帯が離脱して薪の売り手が消え、パンとビールが同時に止まる** — [GDD02 §2.4](02-economy.md) が「最初から存在しない」と警告した状態を、破産処理が実行時に作ってしまう。担い手の薄い職業へ流す `argmin` と併せて、職業分布は均等へ戻る方向に働く。

**ただし防いでいるのは担い手 0 だけであり、2 → 1 への減少は防がない。** 担い手が1世帯になった品目は市中価格が1つしか存在しなくなるので、**[GDD02 §8](02-economy.md)-4(区画間の価格差)はその品目について偽陰性を返す**([GDD02 §2.4](02-economy.md) と同じ理由)。**[GDD02 §8](02-economy.md)-4 は職業分布と併せて読む** — 差が消えたのか、比べる相手が居なくなったのかを区別する必要がある。

**候補を区画で絞るのは [GDD02 §2.4](02-economy.md) の構造制約を保つためである。** 担い手世帯数だけで付け替え先を選ぶと、破産世帯の区画にたまたま既に同職業の世帯があった場合、**[GDD02 §2.4](02-economy.md) が成立しないと言った配置(同職業2世帯が同一区画)を実行時に作ってしまう** — [GDD02 §8](02-economy.md)-4 がその品目について偽陰性を返す。候補が尽きたときだけ例外的に許容する。

**価格や原価から決めない。** 一見「最も儲かっている職業へ」が自然だが、整数除算では比が潰れて `argmax` が事実上「職業 Id 昇順」に退化する。**担い手世帯数は `World` から直接数えられ、除算も価格観測も要らない。** これは NPC の意思決定ではなく、**空いた親方の座を割り当てる世界側の処理**である(史実ではギルドが親方昇格を統制していた → 分冊07)。

- **世帯は解体しない。** 世帯主の職業が変わるだけである。**販売在庫は②の投げ売りで既に現金化されているが、生産の入力として抱えていた工房在庫は残る**(②は売り注文にしか効かない、§3.2)。M0 では旧職業の入力を売りに出す経路が無いので滞留する
- **生産の進捗‰([02a §1](02a-production.md))は 0 に戻す。** 旧職業のレシピの仕掛品であり、所要労働‰ の違う新しいレシピへ持ち越すと存在しない仕掛品で完成する
- **流動資金は補填しない。** 貨幣量を外から増やすと [02d](02d-external-market-and-money.md) の自動調節と [GDD02 §8](02-economy.md)-6 の判定が濁る
- 同値の処理を Id 昇順で固定するのは列挙順規約([ADR-0002](../adr/0002-time-model-and-determinism.md))による

> **M0 に救済経路を置かないのは、置くと測定器が濁るからである。** [GDD02 §8](02-economy.md)-2(困窮世帯の割合)と [GDD02 §8](02-economy.md)-6(貨幣総量)は、「経済が回っているか」ではなく「救済の強さ」の関数になりうる。**M0 の目的は測定であって救済ではない。**「資金が尽きた鍛冶が止まり [GDD02 §8](02-economy.md)-3 が落ちる」ことは、**W2 で得たい観測そのものである。**
>
> **v1.0 では③(掛け売り)と質屋・両替商が再建の役割を担う。** 与信と雇用が揃えば、別途の救済機構は要らない。
>
> 職業分布が動くため [GDD02 §8](02-economy.md)-3(生産チェーンが止まらないか)の観測が豊かになる。**逆に付け替えが頻発するなら、価格機構が働いていない兆候である。**

## 5. 買い手の在庫圧力と個別需要関数(**決定**)

### 5.1 在庫圧力

**売り手の価格係数([02c §1.1](02c-price-and-budget.md))の鏡像である。** 在庫が目標より少なければ相場より高くまで買い、多ければ安くしか買わない。

```
在庫比‰   = CeilDiv( 1000 × 予想在庫 , 目標在庫 )
在庫圧力‰ = 在庫比‰ ≤ 2000 ? clamp( 1500 − CeilDiv(在庫比‰, 2) , 500 , 1500 ) : 0
```

| 予想在庫 | 在庫圧力‰ | 意味 |
| -------- | --------- | ---- |
| 0 | 1500 | 尽きかけ。相場の1.5倍まで払う |
| 目標在庫 | 1000 | **相場どおりなら目標在庫まで買う** |
| 目標在庫 × 2 | 500 | 溢れている。半値なら買う |
| 目標在庫 × 2 超 | **0** | 買わない |

- **両側で1つの概念である。** 売り手は在庫が多ければ提示価格を下げ、買い手は在庫が多ければ払う上限を下げる。調整軸は品目ごとの目標在庫だけで済む(上限倍率 2 は固定なので軸にならない)
- **目標在庫の下側にも傾きがある。** 旧版は目標在庫以下で 1000‰ に据え置いていたが、それでは在庫が尽きかけた世帯の緊急性が予算に現れず、必需の需要が価格に対して完全に非弾力になっていた。**売り手側と同じ 500〜1500‰ の線形にすることで、尽きかけの世帯が相場より高く払う「正当な緊急性」(§6)が式に現れる**
- **2 倍を超えたら 0 にする。** 売り手側は 500‰ で止まるが、買い手側を 500‰ で止めると「半値なら無限に買う」ことになり、溜め込みが縮退する。腐敗を明示的に入れずに済ませているのはこの上限である(§5.4)
- **1000‰ を超えることを禁じていた旧版の理由は消えた。** 「派生需要(利益が出る上限)を超えて買う」ことを恐れていたが、利潤上限と現金上限は在庫圧力の外側で切る([02c §2.1](02c-price-and-budget.md))ので、圧力がいくら上がっても超えない
- **丸めの向きは売り手側と同じ**(在庫比‰ を切り上げ、係数全体としては切り下げ方向)。買い手側では充足側に 1‰ の誤差が寄る
- **目標在庫が 0 の (用途, 品目) は在庫圧力も 0 である**(在庫比‰ の除算をしない)。「1単位も持ちたくない」であって「尽きかけ」ではない。**この組は [GDD06 §3](06-trade-and-negotiation.md) の需要リスト(外出の計画)にも入れない** — §5.2 の到達在庫が 0 に clamp されるので余剰は恒に 0 であり、行き先の候補にだけ現れて何も動かさない

#### 買い物に行く時点の予想在庫を使う

**在庫圧力の計算には、現時点の在庫ではなく「買い物に行く時点で予想される在庫」を使う。**

```
予想在庫 = 現在庫 − (買い物までに予定されている消費・生産投入)
```

> **これが時間の摩擦([GDD02 §4](02-economy.md))の正しい表現である。** 買い物に行くまでに食事や生産を予定しているなら、そのぶん予想在庫が減り、在庫圧力が上がり、予算が増える — **「在庫を切らす前に店へ行けない」状況が、緊急性として自然に価格へ現れる。**
>
> **待ち時間を費用として数えてはならない。** 待っている間は他の仕事ができるので、実際に時間が奪われるわけではない。摩擦は**偽の費用**ではなく**本物の緊急性**として表す。

**M0 では `予想在庫 = 現在庫` になる(**決定**)。** [TDD01 §3.3](../04-tdd/01-sim-core-and-m0.md) のパイプラインは順1 生産・順2 消費の**後**に順5 取引を置くので、**買い物の時点で「これから予定されている消費・生産投入」が残っていない**。引き算の位置は式に残すが、M0 で引く量は 0 である。**日内スケジュール(食事は朝、買い物は昼)を入れたときに初めて値が入る。**

### 5.2 個別需要関数 — 線形解

**判定基準はその商品を買う**前**の在庫量である。** 2単位目以降は、直前までの購入分を加えた在庫量で在庫圧力を算出する。**ただし式は線形なので、反復せずに一度で購入量を解ける。**

```
基礎値 = 相場項(02c §2.1。**在庫圧力を掛ける前**)。相場項が無い日は窓口の当日価格(下記)
予算   = min( ApplyPermille(基礎値, 在庫圧力‰) , 現金上限 , 利潤上限 )        ← 02c §2.1

実効価格 > 予算  → 購入量 0     ← ゲート
それ以外:
    到達在庫 = clamp( 3 × 目標在庫 − CeilDiv( 2 × 目標在庫 × 実効価格 , 基礎値 ) , 0 , 2 × 目標在庫 )
    購入量   = max( 0 , 到達在庫 − 予想在庫 )
```

検算:

| 実効価格 | 到達在庫 | 意味 |
| ---------- | -------- | ---- |
| = 基礎値 × 1.5 | 0 | 在庫が 0 でなければ買わない |
| = 基礎値 | 目標在庫 | 相場どおりなら目標在庫まで買う |
| = 基礎値 × 1/2 | 目標在庫 × 2 | **安ければ買い溜める**(上限) |

- **これが個別需要関数である。** 引数は目標在庫・予想在庫・基礎値・実効価格の4つで、いずれも観測可能な状態か既存の値である。**式を仮定しているのではなく、在庫圧力の線形から導いている**
- **在庫圧力が掛かるのは予算の第 1 項だけである。** 現金上限・利潤上限を超える実効価格では、在庫がいくら少なくても 0 — 切羽詰まっても払えない金は払えない([02c §2.1](02c-price-and-budget.md))。**第 1 項に在庫圧力を掛けるのは §5.1 の表の 1500‰ の行(「尽きかけ。相場の1.5倍まで払う」)を到達可能にするためである** — 掛けないと予算が相場項(相場の 1.2 倍)で頭打ちになり、在庫が 0 の世帯も 1.2 倍までしか払えず、表の行が死ぬ
- **相場項が無い日は、窓口の当日価格を基礎値に使う(決定)。** 都市生産品は**外部買値**(= 床。季節に依らない)、1次産品は**当日の外部売値**(季節係数を掛けた後。[GDD02d §3・§5](02d-external-market-and-money.md))。そうしないと基礎値が無く、線形解が立たない。**相場を知らない日でも「いくつ買うか」は世界価格で決まる** — 実効価格が基礎値に等しければ目標在庫ちょうど、1.5 倍なら 0、半値なら 2 倍まで買う(上の検算表のとおり)
  - **当日値であって基準値ではない。** 基準値を使うと、高い季節は取り崩し・安い季節は積み増しという**季節の数量応答**が出る([02d §5](02d-external-market-and-money.md)「次の収穫までの在庫繰りがゲームになる」)。**M0 では採らない** — 相場を知らない日にだけ効く応答は、相場基準を持つ日との境目で段差になる。**滑らかな季節応答は基準値ではなく移動平均で作るべきもの**であり、[#172](https://github.com/stama72/visionary/issues/172) が持つ
  - **予算の第 1 項も基礎値で立てる**([02c §2.1](02c-price-and-budget.md))。相場項が無い日に第 1 項ごと落とすと、**ゲートと線形解の零点の一致が壊れる** — `ApplyPermille(基礎値, 在庫圧力‰)` は到達在庫が予想在庫に一致する実効価格そのもの(**実数では恒等式**。整数では下の但し書き)なので、第 1 項を落とすと「ゲートは開いているのに線形解が 0 を返す」帯ができ、**購入量 0 の理由が記録されない**(下記「購入量 0 の理由」の3分岐が網羅でなくなる)
    - **一致が恒等なのは実数の上だけである。** 在庫圧力‰ は切り下げ方向に丸まる(§5.1)ので、**ゲートは線形解の零点より 1 だけ手前で閉じうる** — その帯では「ゲートが閉じたが、線形解なら 1 買えた」が起きる。発火には `基礎値 × 丸め残り‰ ÷ 1000 ≥ 1 + 基礎値 ÷ (2 × 目標在庫)` が要り、丸め残りは 1‰ 未満なので **基礎値 1000 以上 かつ 目標在庫 500 以上**が同時に要る。**M0 では到達しない** — 相場項が無い日の基礎値は最大 290(工具の外部買値)で、目標在庫が 500 を超えるのは耐久の行(耐久値で 6500)だけであり、その行の基礎値が 290 だからである(2026-09-22 に M0 の全 (基礎値, 目標在庫, 予想在庫) を当てて反例 0 を確認した。[issue #170](https://github.com/stama72/visionary/issues/170))。**相場項がある日はこの決定の前から同じ丸めであり、帯は広がっていない。**
  - **したがって、相場を知らない世帯が払いうる上限は `1.5 × 基礎値` である。** 在庫が 0 でもこれを超える値では1単位も買わない。**旧版はここを現金上限(床の 20 倍を超える)と書いていたが、誤りだった** — 線形解の零点は基礎値の側にあり、現金上限はそこまで届かない
  - **窓口で都市生産品を買うかどうかは `交易マージン‰ < 在庫圧力の上限‰ − 1000`(= 500)で決まる。** `外部売値 < 1.5 × 外部買値` と同値である。**現在値 1000‰ はこの外側なので、相場を知らない買い手は窓口から都市生産品を買わない。** 交易マージン‰([02d §3](02d-external-market-and-money.md))も在庫圧力の上限([02-economy.md](02-economy.md) §9.2 が「発散の公比の上限を決める」と書いている値)も、**この境界を決める値だとはそれぞれの節に書かれていない。** 片方を動かすと [issue #120](https://github.com/stama72/visionary/issues/120) の初日の一撃が戻る
  - **旧版は現金上限を基礎値にしていた。これは誤りだった。** 基礎値が資金なので `実効価格 ÷ 基礎値` が 0 に近づき、**到達在庫が上側 clamp(目標在庫の 2 倍)に張り付く**。需要が価格について 0 次同次([02c §1.2](02c-price-and-budget.md) の囲みが系の性質として名指ししているもの)であることをやめ、**資金について 1 次同次になる** — 開放小国の輸入需要が世界価格ではなく手持ち現金で決まる形である。[issue #120](https://github.com/stama72/visionary/issues/120) の実測では、**全世帯が同時に相場を知らない初日に、都市の貨幣 24,000 のうち 20,240(84.3%)が1日で窓口へ流出した。** 窓口価格を基礎値にすると 816(96% 減)になる
  - **[02c §2.1](02c-price-and-budget.md) が「現金上限に2つの役割を載せるな」と既に禁じていた。** 旧版は同じ節の中で、単価の判断(評価)と払えるか(ゲート)の両方を現金上限に載せていた。**この箇条書きはその自己矛盾を解いたものである**
  - **窓口価格は知識ではなく物差しである。** 相場基準が立たない日に売り手が床をそのまま提示価格にする([02c §1](02c-price-and-budget.md))のと対称で、どちらも観測を要求しない。**「どの店へ行くか」の見積もり([GDD06 §3](06-trade-and-negotiation.md))は知識に依存し、そちらは変えていない** — 1次産品の見積もりの下限 1([02d §2.2](02d-external-market-and-money.md))はそのまま残る。**依存するのは「いくつ買うか」だけである**
  - **ゲートは `min(第 1 項, 現金上限, 利潤上限)` である。** 第 1 項が基礎値で立つので、旧版の「ゲートは基礎値と同じ値で閉じる」(基礎値 = 現金上限だった頃の言い方)はもう成り立たない。**払えない金は払えないという役割は現金上限が持ち続ける**ので、[02d §4.2](02d-external-market-and-money.md) の貨幣から需要への自動調節は変わらない
  - **単価の側の不当価格は残るが、幅は狭まる**(§6 の経路1)。相場を知らない世帯が払いうるのは `1.5 × 基礎値` までであり、**現金上限までではない。** 経路1 の帯が経路2(在庫圧力が上限に張り付いた正当な緊急性)とほぼ重なるので、**[GDD01 §6](01-trust-and-conversation.md) 検証項目5 の誤爆率(2を1と誤判定する率)は、切り分けが原理的に難しくなる方向へ動く**
  - **初期観測を配って塞ぐ案は採らない。** [GDD06 §3.1](06-trade-and-negotiation.md) が既に却下しており、**#120 の実測でも効かなかった** — 観測の有効性は「前日まで」(差 1 日以上、[02c §1.2](02c-price-and-budget.md))なので、エポックに配った観測は初日にまだ有効にならない。効かせるにはその境界規則に例外が要る
- **耐久は耐久値で解き、`CeilDiv(購入量, N × 1000)` で個数に直す**(§2)
- **最終的な購入量は §3.1 の資金上限でさらに切り詰められる**

#### 購入量 0 の理由(**決定**)

**ゲートで 0 になったとき、min のどの項が閉じたかを残す。** §3.2 の破産中フラグが「資金不足で買えなかった」を現金上限の経路でだけ数えるために要る。

```
理由は次の順に判定し、最初に当たったものを採る:
    1. 相場      実効価格 > ApplyPermille(基礎値, 在庫圧力‰)   ← 基礎値は常にあるので条件は1つ
                 (相場項が無い日の基礎値は窓口の当日価格。§5.2)
    2. 利潤上限  利潤上限があり、かつ 実効価格 > 利潤上限
    3. 現金上限  実効価格 > 現金上限
どれにも当たらなければゲートは開いている(理由は無い)
```

- **argmin(最も小さい項)ではなく、この固定順の最初に当たった項を採る。** 第 1 項と現金上限がともに実効価格を下回る日に argmin を採ると、現金上限のほうが小さいというだけで「資金不足」に数えられる。**しかしその世帯は、金が無限にあっても第 1 項で買わなかった** — それは困窮ではなく §3.2 が名指しした「高すぎて買わなかった」である。**同点も 1 が勝つ**(狭い側に倒す)
- **この順でなければ、破産中フラグが価格ショックの検出器に化ける。** 価格が跳ねた日は多くの世帯で第 1 項も現金上限も同時に閉じるので、argmin だと全世帯のフラグが立ち、②の投げ売りが一斉に発動する(§3.2)
- **利潤上限が必需に現れることは無い**(生産の入力にしかない。[02c §2.1](02c-price-and-budget.md))ので、1 と 2 の順はフラグには効かない。それでも順を固定するのは、プレイヤーに見せる「なぜ買わなかったか」(§5.4)を走査順や丸めで揺らさないためである
- **店を1つも知らない・売り手の在庫が尽きた は、この理由に入れない。** どちらもゲートに到達しておらず、資金不足でもない(§3.3 の囲み)。Need の側が拾う(§8)

### 5.3 個別需要関数は明示的、集計需要曲線は創発する

**各世帯は §5.2 の需要関数を持つ。** 価格が下がれば「買う世帯」も「1世帯あたりの量」も増えるので、**集計レベルの需要曲線は自動的に右下がりになる** — これは書かずに創発させる。

- **個体の需要関数を「持たせない」のではない。** 旧版は「個体に需要関数を導入すると価格の因果が式の中に隠れて追えなくなる」として個別需要関数の存在を否定していたが、§5.2 の線形解はまさに個別需要関数である。**方針2(観測可能性)が要求するのは、関数が無いことではなく、引数がすべて観測可能で、式が線形で、プレイヤーが「なぜ買わなかったか」を追えることである**
- **仮定するのは個体の規則であり、集計の形ではない。** 需要曲線の形(弾力性)を外から与えることはしない。在庫分布と相場観の分布から出てくる形が、その日の需要曲線である
- 必需品の必要量は固定で、払えなければ §4 へ。嗜好は在庫圧力が 0 または予算を超えたら買わない。耐久は摩耗したときだけ需要が立つ。**「量が価格に連続的に応答する」のは目標在庫と 2 倍の間の在庫の持ち方であり、消費量そのものではない**(§5.5)

### 5.4 得られるものと代償

| 利点 | 内容 |
| ---- | ---- |
| **買い溜めと買い控え** | **商人ゲームの中核行動が NPC 側にも生まれる。** プレイヤーの投機([02d §5](02d-external-market-and-money.md))に市場が応答する |
| 概念が増えない | 売り手側([02c §1](02c-price-and-budget.md))と同じ機構 |
| **価格の安定**(**在庫のある者に限る**) | 必需品の需要が完全非弾力だと供給不足時に価格が青天井になる。**在庫のある者が買い控えることで需要が自動的に減る。** ただし**買えなかった者には逆向きに働く**(下記の囲み)。価格の水準そのものを止めるのは [02d §3](02d-external-market-and-money.md) の天井である |
| 貯蔵性が意味を持つ | 貯まる品目(薪)と貯まらない品目(パン)の差が経済に効く |
| 会話の素材 | 「うちはまだ薪があるからね」。**買わない理由をプレイヤーに説明できる** |

| 代償 | 対応 |
| ---- | ---- |
| 溜め込みの縮退 | **目標在庫の2倍を超えると在庫圧力が 0 になる(§5.1)。** 腐敗を明示的に入れずに済む([GDD02 §9](02-economy.md)) |
| 在庫を置く場所が要る | 世帯在庫と工房在庫の2本([GDD08 §2.2](08-household-and-decision.md) / [TDD01 §3.2](../04-tdd/01-sim-core-and-m0.md))。**W1 の `NpcState.Inventory` は W2 で廃止**し、`HouseholdState` へ移す |
| **振動の増幅** | 売り手と買い手の在庫圧力が同位相で動くと「安い→買い溜め→在庫増→買い控え→売れない→さらに安く」が起きうる。買い手の相場基準を遅くしたこと([02c §1.2](02c-price-and-budget.md))が保持期間を周期とする振動を足す可能性もある。**[GDD02 §8](02-economy.md)-1 の安定性検証で見る** |

> **在庫圧力は、必需品の品不足が続くあいだ正のフィードバックになる。** 3つが重なる: (1) 必需の母数は**流動資金の全額**([02c §2.1](02c-price-and-budget.md) の表)なので、現金上限が最後に閉じる。(2) 消費量は外生(§1。需要破壊は §5.5 で未実装)なので、買えなかった世帯の予想在庫は減る一方である。(3) 予想在庫が減ると在庫圧力は 1000‰ から **1500‰ へ上がる**。
>
> **つまり買えなかった世帯は、翌日もっと高く払い(予算 1.2 × 相場基準 → 1.8 × 相場基準)、もっと多く買おうとする**(§5.2 の `購入量 = 到達在庫 − 予想在庫` の予想在庫が小さい)。需要曲線は上へも右へも動く。**上の表の「価格の安定」が働くのは在庫のある者だけで、品不足が続くと全世帯が予想在庫 0 の側へ寄り、集計需要は 1.8 倍へ収束していく。**
>
> **これは在庫圧力の欠陥ではなく、上側の錨が無いことの現れだった。** §5.1 が「尽きかけの世帯が相場より高く払う正当な緊急性」と書いたとおり、個体の規則としては正しい。**帯が閉じた([02d §3](02d-external-market-and-money.md))いまは、この経路も天井で頭を打つ** — 1.8 倍が床の 2 倍を超えた日、買い手は窓口を選ぶ。出所は [issue #120](https://github.com/stama72/visionary/issues/120) の決定ログ(2巡目)。

### 5.5 需要破壊 — 消費量が在庫に応答する仕組みの置き場

**M0 の消費量は定数である**(§1)。§5.2 の需要関数が価格に応じて変えるのは「いくつ買うか」であり、「いくつ食べるか」ではない。**したがって、供給が構造的に不足したとき、実際の消費が減るのは在庫が底をついてからである。** それまでは緩やかに在庫を取り崩す振る舞いを表現できるだけで、マクロの負のフィードバック(価格上昇 → 消費減)は起きない。最終的に需給の不均衡を直すのは、誰かが破産して不足している職業へ付け替わること(§4.2)だけである。

**在庫の減少が消費の減少につながる「需要破壊」は、本節の拡張として置く。** 形は決めていない — 在庫が目標を下回った日に消費量を減らす(配給)、価格が高い日に嗜好の消費を飛ばす、などが候補である。**M0 に入れるかは、[GDD02 §8](02-economy.md) の検証項目が校正([02d §4.3](02d-external-market-and-money.md))だけで通るかで判断する。** 通るなら M0 では入れず、通らないならここへ戻る。

## 6. 不当価格はどこで成立するか

予算を相場基準にすると、NPC は相場から離れた値を「買わない」だけになる。では [GDD01 §4.5](01-trust-and-conversation.md) の不当価格はどこで起きるか。**2つの経路が残る**:

**1 の実体は、相場項の代わりに窓口の当日価格が基礎値に入ることである**([02c §2.1](02c-price-and-budget.md) / §5.2)。相場基準が無い日は、その世帯にとっての「相場」が窓口の値になり、**在庫が尽きかけていれば その 1.5 倍までなら払ってしまう。** **旧版はこれを「現金上限まで払う」と書いていたが、誤りだった**([issue #120](https://github.com/stama72/visionary/issues/120))— 予算の第 1 項は落ちず、現金上限はそこまで届かない。**摩擦の幅は資金次第の青天井ではなく、窓口価格の 1.5 倍で固定である。**

1. **相場観が古い、または無い**(情報の摩擦、[GDD02 §4](02-economy.md))。新しく来た NPC、久しく買っていない品目では `PriceObservation` が薄い。そのとき高値を掴み、**後から相場を観測して「あれは不当だった」と気づく** — [GDD02 §4.5](02-economy.md) の「取引tick近傍の観測入手による気づき」そのものである
2. **在庫が尽きかけて在庫圧力が最大(1500‰)になっている**。これは**正当な緊急性**であり、プレイヤーが「足元を見る」余地でもある

**1が誤爆の源であり、2は仕様である。** [GDD01 §6](01-trust-and-conversation.md) 検証項目5 の誤爆率は、**2を1と誤判定する率**として測る。

> **不当価格が「困窮という異常時」ではなく「情報の非対称という平常時の構造」から生まれることが重要である。** 本作の USP「情報を足で稼ぐ」に直結する。

## 7. 予算と費用の役割分担(**重要**)

**便益と費用を分ける。**

| | 予算(払える上限) | 費用(実効価格と外出の費用) |
| -- | ------------------ | ---------- |
| **何を表すか** | **便益**。その品をどれだけ欲しいか | **費用**。手に入れるのに実際いくらかかるか |
| **決まり方** | 需要のみ(基礎値 × 在庫圧力、現金上限と利潤上限で切る。[02c §2.1](02c-price-and-budget.md)) | 実効価格(提示価格 + 信用による割引。店ごと)と外出の費用(区画ごと、外出ごとに1回) |
| **いくつあるか** | **1つ** | 実効価格は店ごと、外出の費用は区画ごと |
| **どこが持つか** | **本書 [02c §2](02c-price-and-budget.md)** | **分冊06** |

**購入条件**:

```
その日に居た区画(自区画と行った区画)の店のうち、信用を考慮した実効価格が最も安く、
かつ その実効価格が予算以下 であるとき、その店で買う
```

> **旧版は機会費用による上乗せを予算の側に入れていた。誤りである。** 外出の費用にも機会費用が入るため**二重計上**になり、かつ「行き先ごとに異なるもの」を「1つしかない予算」に混ぜていた。**便益と費用の分離が正しい**([process/03](../process/03-corrections.md) 規則6 — 却下理由ではなく設計そのものの訂正)。
>
> **時間の摩擦は §5.1 の予想在庫へ、空間の摩擦は分冊06 の外出の労働損失へ**、それぞれ1か所だけに置く。
>
> **予算の中の資金は「1日分を買えるか」のゲートだけである**([02c §2.1](02c-price-and-budget.md) 現金上限)。総額の制約は §3.1 が購入量の側で掛ける。**「予算が足りない」と「資金が足りない」は別の事象であり、§3.2 の破産中フラグが拾うのは後者だけである。**

## 8. Need への接続

不足は [GDD01 §3.2](01-trust-and-conversation.md) の Need として表面化する。**Need が経済とコアループの結節点である。**

| 発生源 | Need 種別 | 理由コード |
| ------ | --------- | ---------- |
| 生産の入力切れ([02a §1](02a-production.md)) | 在庫不足 | 生産停止 |
| 必需品が買えない(§4) | 金銭不足 | 困窮 |
| 労働力不足([02a §2](02a-production.md)) | 労働力不足 | 増産できない |
| 設備の摩耗([02a §3](02a-production.md)。工具が尽きて設備係数が 500‰ に落ちた) | 在庫不足 | 工具切れ |
| 区画をまたぐ運搬が要る([GDD02 §4](02-economy.md)) | 在庫不足 | 遠方在庫 |

> **これが [TDD01 §3.6](../04-tdd/01-sim-core-and-m0.md) の仮決め「`Need.TypeCode` / `ReasonCode` を enum にする」への答えである。** 上表の左2列が種別、右列が理由コードの初期集合になる。

### 8.1 M0 の発生条件・数量・失効(**決定**)

**Need は毎日 [TDD01 §3.3](../04-tdd/01-sim-core-and-m0.md) 順4 で組み直す。** その日に条件を満たす組だけが立ち、満たさなくなった組はその日に消える — **これが失効である。** 期限による失効も、連続日数を数えるカウンタも置かない(調整軸を増やさない。§4.1 が④の条件に対して採ったのと同じ向き)。

**`(対象世帯, 理由コード, 品目)` が Need の同一性である。** 同じ組が立ち続けている間は同じ Need であり、**Id は変わらない**(Id を持たせる理由は [TDD01 §3.6](../04-tdd/01-sim-core-and-m0.md))。**一度失効した組が後日また立ったら、それは別の Need である**(新しい Id を採る)。

| 理由コード | 立つ条件(順4 の時点) | 品目 | 数量 |
| ---------- | ---------------------- | ---- | ---- |
| 生産停止 | **当日の生産量(実行回数)が 0** かつ **工房在庫[入力 j] < 必要数量_j**([02a §1](02a-production.md)) | その入力 j(足りない入力ごとに1件) | `必要数量_j − 工房在庫[j]`(個。レシピを1回実行するのに足りない量) |
| 困窮 | **破産中フラグが立っている**(§3.3)かつ **当日の消費不足量[i] が正**(§1)。**i は必需品に限る**(§2 の必需の目標在庫の日数が正である品目) | その必需品 i | 当日の消費不足量[i](個) |
| 増産できない | **その日の生産能力が 0**(進捗‰ < 所要労働‰。[02a §1・§2](02a-production.md)) | 自レシピの出力品目 | `所要労働‰ − 進捗‰`(**‰人日**。その日の労働を足した後の進捗) |
| 工具切れ | **工具在庫が 0**(設備係数‰ が 500 に落ちている。[02a §3](02a-production.md)) | 工具 | 1(個。設備係数‰ を 1000 に戻すのに要る最小在庫) |
| 遠方在庫 | **前日、その品目を1個も買えず、かつその日の予想在庫が目標在庫を下回っていた**([GDD06 §3.1](06-trade-and-negotiation.md)) | その品目 | `目標在庫 − 予想在庫`(個。耐久は §5.2 と同じ換算で個数へ直す) |

**数量の単位は理由コードによって違う。** 4つは品目の個数だが、**増産できないだけが ‰人日である** — 労働は品目ではないので個数で表せない。**品目の欄に自レシピの出力品目を置くのは、足りないのは労働だが作れないのはその品目だからである**(M0 のレシピは出力1件。[GDD02 §2.3](02-economy.md) が複数出力を許すので、複数出力を入れるときはここを決め直す)。

**困窮を破産中フラグだけで立てない。** フラグが見ているのは現金であって在庫ではない(§3.3)ので、フラグだけで立てると「在庫は目標に満ちているが、その品の1日分を相場で買う金が無い」世帯にも Need が立つ。**Need は不足の表面化である**([GDD01 §3.2](01-trust-and-conversation.md))から、実際に食えなかったこと(当日の消費不足量)と併せて初めて立てる。**狭い側に倒している** — フラグが立った世帯のうち一部にしか立たない。**したがって「困窮の Need の件数」は [GDD02 §8](02-economy.md)-2 (a) の代わりにならない。** (a) が測るのはフラグそのものである。

**嗜好の消費不足は困窮にしない。** 当日の消費不足量は必需にも嗜好にも立つ(§1 の1日消費量が正の品目すべて)が、§4 の段階①が「嗜好品・奢侈品を諦める」を**困窮の入口**に置いている以上、嗜好が欠けたことを困窮の信号にすると段階の並びが逆さになる。

**この1本だけが前日の値と当日の値を混ぜる。** 破産中フラグは構造上つねに前日の購入結果であり(§3.3)、消費不足量は当日の順2 が書いた値である。**順4 の時点で読める最新がそれぞれこれだから**であって、揃えるために片方を遅らせることはしない。帰結は「今日から食えなくなった世帯の Need は明日立つ」である。

**遠方在庫も前日の購入結果を読む。** 購入が起きるのは順5 なので、順4 が読む欄には前日の値が入っている — フラグ(§3.3)と同じ順序の帰結である。**条件の2つはどちらも順5 がその日の値で判定して書く**(§5.1 の予想在庫は買い物より前の値である)。**順4 は判定し直さない** — し直すと、買い物で増えた在庫を見て「下回っていない」と読み、同じ規則が2か所で食い違う。

**同じ品目に理由の違う Need が同時に立つことを許す。** 台詞化([GDD01 §3.3](01-trust-and-conversation.md))は理由で分岐するので、畳むと「工具が摩耗した」と「工具が買えなかった」が区別できなくなる。**畳まないぶん Need の件数は増えるが、M0 の上限は 10世帯 × 9品目 × 5理由である。**

**期限と緊急度は M0 では 0 に固定する。** 読み手が無い — 開示([GDD01 §3.2](01-trust-and-conversation.md))は W3 以降、約束の基本値 B([GDD01 §2.8](01-trust-and-conversation.md))は順6 が未実装である。**失効を期限で駆動しないので、0 のままでも Need が滞留することはない。** 読み手を足す段でここを決め直す。

**M0 に Need を履行する主体は居ない**(行商人・運送労働者は [GDD11](11-external-trade.md))。**Need は「まだ届いていない」という信号として立つだけでよい。**
