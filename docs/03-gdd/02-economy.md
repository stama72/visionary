## 1. 設計方針

1. **経済は摩擦のためにある。** これが第一原理である。NPC が完璧に動く経済ではプレイヤーの価値がゼロになる。[idea/008](../idea/008-NPCと職業.md) §3.1 の「AI職人は工房から動かない」を**仕様として明文化する**(§4)
2. **観測可能性を最優先する。** The Guild 3 化(観測不能な複雑さ)の回避は企画段階からの制約である。プレイヤーが「なぜこの価格なのか」を追えなくなった時点で、経済の精巧さは価値を失う。**追えなくなる複雑さは、面白さの有無に関わらず入れない**
3. **閉じた経済にしない。** 都市の外を明示的にモデル化する(§10)。閉じた系は貨幣量が固定され、価格の絶対水準が動かせない
4. **NPC は満足化する。最適化しない。** 最適化する NPC はプレイヤーの介在余地を消し、かつ挙動が読めなくなる
5. **数値は初期値。** 構造と依存関係だけを固定する

## 2. 品目とレシピ

### 2.1 構成(**決定**)

**3層・最大2段・21品目。** 層と段を区別する:

- **層** = 品目の位置(1次産品 / 中間財 / 最終財)。**3層に固定する**
- **段** = 1次産品からの変換回数。**制約すべきはこちら**。段が深いほど価格の因果が追えなくなる(方針2)

品目数を増やしても段が浅ければ因果は追える。逆に段が深いと品目数が少なくても追えない。**したがって品目数は20程度まで増やし、段は2に抑える。**

> **段は「品目をどの層に置くか」で調整できる。** 木炭は当初 `木材→薪→木炭` の中間財としたため工具が3段になったが、**1次産品(農村の炭焼き)に置き直すと工具は1段になる**(§2.2)。史実に沿わせた結果として制約も満たした例である。

**都市の賑わいは、品目ではなく職業で出す。** 生産以外の職業(サービス業・物流業・貿易商)を置くことで、レシピを増やさずに都市の味が出る(§3)。

| **木炭** | **金属加工のみ**(工具・武器・甲冑) | **農村から**(炭焼き) | **農村からの搬入が途絶える(=季節性)** |

**故障モードが違うことに価値がある。** 単一の隘路より、2つの独立した供給不安があるほうが、プレイヤーの介入機会が多様になる。冬の暖房需要(§9)は薪だけを圧迫し、木炭には効かない。

> **「肉」が1次品であること。** 肉屋は都市内の職業だが、家畜の購入を明示的にモデル化しない(抽象化する)。レシピを持たず肉と皮を産出する、という扱いにする。**モデル化すると家畜という品目と牧畜という職業が要り、段が増える。**
>
> **貿易専用品目(塩・ワイン・香辛料)は都市内で作れない。** 供給は港(§10.4)のみである。**外部依存が構造的に発生する品目**を持つことで、貿易商の存在意義と、港が止まったときの緊張が生まれる。

#### 木炭は1次産品である(**決定**)

**中世の炭焼きは森の奥深くで原木を蒸し焼きにする作業であり、都市内の工房で行うものではない。** したがって木炭は、きこりや鉱夫と同じく**農村から持ち込まれる1次産品**として扱う(§3.3)。

**この置き方が3つの問題を同時に解く**:

1. **史実性。** 製鉄・鍛造には木炭が要る。薪では温度が足りず不純物も多い。「炭が切れた鍛冶屋」は [idea/008](../idea/008-NPCと職業.md) §3.1 が挙げた場面そのものである
2. **段数。** 中間財(`木材→薪→木炭`)に置くと工具が3段になるが、**1次産品に置けば `鉄鉱石 + 木炭 → 工具` は1段**である。§2.1 の制約を満たす
3. **対称性。** 金属加工3種(工具・武器・甲冑)がすべて `鉄鉱石 + 木炭` で揃う

> **v0.2 では木炭を廃し、金属加工の燃料を薪に統一していた。** 廃した理由は「段が3になる」「燃料が2種で対称性が崩れる」だったが、**どちらも木炭を中間財に置いたことの帰結**であり、1次産品に置き直すと両方とも消える。**却下理由の前提が、置き場所を変えたことで崩れた**([process/03](../process/03-corrections.md) 規則6)。

### 2.3 レシピの形

```
レシピ = { 出力[(品目, 数量)], 入力[(品目, 数量)], 所要労働 }
```

- **出力は複数を許す**(肉屋 → 肉 + 皮)
- **1レシピ1段**。中間財を経ずに原料から最終財を作る近道は置かない
- 数量はすべて int。歩留まり・端数は**切り上げ**([GDD01](01-trust-and-conversation.md) §2.3 の全体規約)
- **入力を持たないレシピを許す**(肉屋)。1次品の産出がこれにあたる

### 2.4 M0 のサブセット(**決定**)

**§2.2 の21品目・§3 の21職業は v1.0 の目標仕様である。M0 では 11品目・都市6職業・農村4職業で走らせる。**

**理由は規模の噛み合わせである。** 9区画 × 1〜2世帯(§4.3)では世帯が最大18しか無く、都市16職業では**1品目1売り手**になる。`Market` は「品目 × 売り手 → 提示価格」なので、売り手が1人なら市中価格が1つしか存在せず、**§12-4「区画間の価格差が消えない」が消えるのではなく最初から存在しない**。[GDD06 §3](06-trade-and-negotiation.md) の店の選択も比較対象を持たない。**1品目につき売り手2世帯を別区画に置けることが、サブセットの大きさを決めている。**

**ただしこれが当てはまるのは都市の世帯が売る7品目**(都市生産の小麦粉・薪・パン・ビール・工具と、貿易商が扱う塩・ワイン)**である。** 1次産品4品目(穀物・木材・木炭・鉄鉱石)は農村世帯が中心区画でのみ売るので、区画差は生じない。**§12-4 は都市で生産される5品目で判定する**(塩・ワインは貿易商2世帯の区画にしか並ばず、価格差は距離ではなく供給元の単一性から来るため)。

**M0 の下限は [GDD06 §3.1](06-trade-and-negotiation.md) の観測の広がりが担う。** 「その日に居た区画から距離 R 以内」で観測が生まれるので、**買い物に行くこと自体が知識を外へ広げる**。知っている店が0件でも Need(遠方在庫)が立つだけで、数日のうちに自然に解消する。**履行の主体は要らない。**

**都市6職業 × 2世帯 = 12世帯。** 9区画に1〜2世帯で収まる。これに農村世帯が加わる。

**同じ職業の2世帯は必ず別の区画に置く。これは値ではなく構造の制約である。** §4.3 の密度(1区画1〜2世帯)だけでは同居を防げず、同居すると当該品目の売り手が1区画に集まって区画差が消える。**M0 では職人世帯を置かない** — 世帯は親方・主婦・子ども・徒弟で構成し、[GDD08 §2.1](08-household-and-decision.md) の「職人は別世帯」は雇用(§7.3)とともに v1.0 へ送る。

**さらに、鍛冶1世帯と貿易商1世帯は、中心区画(Id 4)に隣接する区画(Id 1/3/5/7)のいずれかに置く(構造の制約)。** 農村世帯の来訪先は中心区画に固定され、視界半径 R=1 では隣接区画までしか知覚が届かない(下記)。工具は §5.3 で必ず摩耗するため、鍛冶・貿易商のどちらにも来訪中の農村世帯から到達できないと、農村世帯は§10.5サイクル3の購入(工具・塩)を永久に行えず、工具切れが生産チェーン全体を恒久的に止める。**中心の隣接区画に最低1世帯ずつ置けば、この失敗配置を構造的に排除できる。**

**農村は4職業 × 2世帯 = 8世帯。** 都市12世帯と合わせて20世帯になる。

**季節市は視界半径の明示的な例外である。** 農村世帯の来訪は**定期市**であり、中世都市では開催が公的に周知されていた。**1次産品の売り注文だけは、開催中に限り距離によらず全世帯の「今日の知覚」([GDD06 §3.1](06-trade-and-negotiation.md))に含まれる。** これは記憶ではなく知覚の例外であり、**当日から買える**(そうでなければ下の註記が前提にする「木材加工が搬入日に木材を仕入れられる」が成立しない)。同時に見た売り注文は通常どおり観測(`PriceObservation`)としても記録されるので、市が閉じたあとは保持期間([GDD06 §3.1](06-trade-and-negotiation.md))の範囲で記憶として残る。1次産品の `相場基準`(§8.1.1)は観測の平均なので、ここを取り違えると値付けが変わる。

**季節市は3日間開催する(初期値。§14)。開催日は農村職業ごとの定数オフセットで決める(v0.16 で構造を追加)。**

```
農村職業 j の季節市 = 季節の初日 + 開催日オフセット[j] から 3日間
開催日オフセット[農民 / きこり / 炭焼き / 鉱夫] = 0 / 0 / 0 / 0   ← 初期値。全品目が同時に立つ

値域(構造の制約): 0 ≤ 開催日オフセット ≤ 季節日数 − 開催日数 (= 30 − 3 = 27)
```

**値域は値ではなく構造の制約である。** 市が季節境界をまたぐと、季節次の納税(§6.2.1)と財政の季節口座(§10.6 の「残り日数」)の区切りと噛み合わなくなる。

「季節に一度」(§10.5)だけでは1日だけの開催とも読め、その場合は農村世帯が同日中に来訪・換金・納税・購入まで済ませられるかが移動時間(§4.3)との兼ね合いで詰まりうる。**3日間あれば、来訪初日に売れなくても翌日以降に売り直せる**。

> **オフセットを構造として持たせるのは、市をずらすかどうかが実験でしか決まらないためである。** 農村4職業はそれぞれ1品目を売る(§2.4)ので、**職業ごとのオフセットはそのまま品目ごとの開催日になる**。初期値を全 0 にしておけば挙動は同時開催のままであり、**値を変えるだけで比較実験ができる** — 財政の日次購入を on/off の実験軸にしたのと同じやり方である(§14)。
>
> **ずらす動機は2つある。** ゲーム側では、市というイベントが季節に1回まとめて来るより数日おきに来るほうが、プレイヤーの関与点が増える。シミュレーション側では、**各職業の仕入支出の波と農村世帯からの需要が分散する** — 現行の同時開催では、全1次産品の供給と農村8世帯の購買力が年4回の同じ3日間に集中する。**どちらが §12-1(価格の安定)を通しやすいかは実測でしか分からない。**
>
> **保持期間の構造制約(GDD06 §3.1「来訪間隔より長い」)はオフセットを入れても変わらない。** 各品目の来訪間隔は依然として1季(30日)である。

> **例外を置かないと、生産チェーンの根が初期配置の運で切れる。** 1次産品は中心区画で季節に一度しか並ばない。視界 R = 1 では隅の4区画(Id 0/2/6/8)から中心は距離2で見えず、**その日にたまたま近所へ買い物に行った世帯しか観測できない**。木材加工が隅に置かれれば木材を知る経路が無く、**薪が止まり、パンとビールが同時に止まる**(§12-3 が構造的に不通過)。
>
> **普段の店の情報の摩擦は R = 1 のまま保たれる。** 例外は1次産品の売り注文だけであり、都市生産品と貿易品は従来どおり足で稼ぐ。

**農村世帯の区画Id は「農村」を表す専用の値で固定する。** 来訪中だけ中心区画(Id 4)を距離の起点として扱う。**来訪しているかどうかは暦から決まる**(季節に一度、§10.5)ので状態ではなく、[TDD01 §3.2](../04-tdd/01-sim-core-and-m0.md) の「区画Id は不変」も §3.8 のハッシュ根拠も揺らがない。**§4.3 の世帯密度(1区画1〜2世帯)は都市世帯にだけ適用する。**

**来訪中の農村世帯の距離の起点は中心(Id 4)である。** 農村世帯は買い手でもある(§10.5 の来訪サイクル3)ため、視界([GDD06 §3.1](06-trade-and-negotiation.md))と移動時間(§4.3)の起点が要る。**来訪していない期間は買い物をしない。**

| 加工 | パン屋 | 小麦粉+薪→パン | 必需品の供給。**止まると都市が困窮する** |
| 加工 | 醸造 | 穀物+薪→ビール | |
| 加工 | 肉屋 | →肉+皮 | 1次品の都市内供給 |
| 加工 | 木材加工 | 木材→薪 | **薪の唯一の供給者。** 止まると暖房とパンが同時に止まる |

| **商業** | 貿易商 | — | **港での大口取引を担う(§10.4)。スプレッドが都市内の利益になる** |

**サービス業は「最終財を買って在庫にしない」ことに意味がある。** 都市内に最終財の需要の受け皿があると、パン屋・醸造・肉屋の生産が家計消費だけに依存しなくなり、価格が安定しやすい。**サービスそのものは品目として持たない**(在庫も価格も持たない)ため、品目数は増えない。

### 3.3 農村の職業

**都市の外に住み、季節に一度だけ都市に来る**(§10.5)。

| 職業 | 産出 |
| ---- | ---- |
| 農民 | 穀物 |
| きこり | 木材 |
| **炭焼き** | **木炭** |
| 鉱夫 | 鉄鉱石 |
| 羊飼い | 羊毛 |

**1次産品(肉・皮を除く)は都市で生産されない。** 都市は加工と商業に特化する。これは史実的にも正確であり、**原料在庫が季節で大きく振れる**という設計([idea/008](../idea/008-NPCと職業.md) §1.5、§9)を成立させる。

### 3.4 粒度(**決定**)

**都市16職業 + 農村5職業 = 21職業。経済的な役割が異なるものだけを分ける。** ただし**これは v1.0 の目標仕様であり、M0 で走らせるのは §2.4 のサブセット(都市6 + 農村4)である**。 [idea/008](../idea/008-NPCと職業.md) はより細かい区分を挙げている(海上貿易商とスパイス貿易商の分離、金銀細工師、道化師など)が、経済的役割が重複するものは統合した。

**職業の追加は品目の追加より安い。** レシピを持たない職業(サービス・物流・商業)は品目数も段数も増やさないため、方針2の観測可能性を損なわない。**粒度を上げる拡張は、M0 後の「賑わいが足りない」という所感に応じて足す。**

> **従業員の扱い(決定)**: 商業・サービスにも**親方/職人/徒弟の枠組みを適用する**。別の職業としては扱わない。生産物が無い職種では熟練度が「信用の上がりやすさ」と仕事の割り振りに効く。詳細は [GDD08 §3.3](08-household-and-decision.md)。

## 4. 摩擦 — プレイヤーの価値の源泉

**本書で最も重要な節。** [idea/008](../idea/008-NPCと職業.md) §3.1 を仕様化する。

| 摩擦 | NPC の制約 | プレイヤーの機会 | 実装上の要点 |
| ---- | ---------- | ---------------- | ------------ |
| **空間** | 職人は工房のある区画から動かない。生産物は自分の区画にしか並ばない | 区画をまたぐ運搬でサヤを抜く | **都市を 3×3 の9区画に分け**、価格差の単位にする(§4.3)。**区画ごとに価格が違う** |
| **時間** | 職人が買い出しに行くのは1日1回・決まった時刻だけ。入力が切れても即座には補充しない | 「今すぐ要る」に応えて割増で売る | 生産システムは入力不足で**停止する**。停止は Need を生む |
| **情報** | NPC は自分が観測した価格しか知らない([GDD01 §4.1](01-trust-and-conversation.md)) | 相場を知っていること自体が資本 | 既に GDD01 が設計済み。**02 はそれを経済的に意味あるものにする側** |

### 4.1 摩擦を消してはならない

**この3つを効率化する施策は、すべて本作の価値を削る。** 具体的には以下を作らない:

- NPC 同士の自動的な物流(きこりが木材加工へ木材を届ける)
- 全 NPC が共有する市場価格表(中央の板)。**ただし2つの明示的な例外がある**: ①1次産品の季節市(§2.4)— 定期市は公的に周知される行事であり、**11品目中4品目に限って**距離によらず見える。②財政の購入(§10.6)— NPC ではなく**世界側の主体**であり、徴税網が全区画に及ぶという設定的根拠を持つ。**この2つを「一貫性のために」他へ広げてはならない**
- 入力切れを即座に解消する自動発注

**逆に言えば、経済の「効率が悪い」ことは不具合ではなく仕様である。** レビューや調整でここを「改善」しないよう、本節を根拠として参照すること。

### 4.2 ただし、詰みは作らない

摩擦が強すぎて都市が餓死しては困る。**下限として、運送労働者(§3.2)と行商人(§10.3)が最低限の流通を担う。** プレイヤーが何もしなくても都市は回るが、**遅く・高く回る**。プレイヤーはその差分を取る。

**運送労働者は「遅い」ことが仕様である。** 依頼を受けてから運ぶまでに日数がかかり、運賃も高い。速さと安さで勝つのがプレイヤーである。

> **M0 では行商人も運送労働者も入れない**(§2.4)。下限は [GDD06 §3.1](06-trade-and-negotiation.md) の**観測の広がり**が担う — 買い物に行くこと自体が知識を外へ広げるので、「知っている店が0件」は一時的にしか続かない。**Need(遠方在庫)は立つが、M0 では履行する主体を置かない。**

### 4.3 区画と距離(**決定**)

**9区画を 3×3 のグリッドとして扱い、区画間の距離はマンハッタン距離とする。**

```
距離(a, b) = |行(a) − 行(b)| + |列(a) − 列(b)|      ← 0〜4
移動時間   = 距離 × 1区画あたりの移動時間(初期値 1時間) × 2   ← 往復
```

- **区画 Id は行優先で 0〜8。** Id から行・列が定まるので、距離表というデータを持たない
- 距離は**視界半径 R** にも使う([GDD06 §3.1](06-trade-and-negotiation.md))。**起点は「その日に居た区画」であって自宅とは限らず**、1次産品の季節市はこの半径の例外である(§2.4)。**R は値ではなく構造であり、実データを見て調整する軸ではない**
- 距離は実質コストに乗る([GDD06 §2](06-trade-and-negotiation.md))。**これが空間の摩擦の唯一の数値表現である**
- 買い手の区画は世帯の区画、店の区画は売り手の工房の区画

> **隣接グラフや 9×9 の距離行列を持たないのは、調整軸を増やさないためである**(方針2)。距離行列なら36個の軸が増え、**区画間の価格差が「機構の帰結」か「距離表の設定」かを切り分けられなくなる** — §12-4 がまさにその価格差を判定に使う以上、これは致命的である。
>
> 城壁・川・門といった不整形をグリッドで表せないのは承知の上である。**M0 の目的は価格機構の検証であって都市の地理ではない。** 複数都市(§14)へ進むときに再訪する。

#### 世帯は区画を移らない(**決定**)

**世帯の区画は初期配置で決まり、以後変わらない。**

- **世帯密度は 1区画あたり1〜2世帯。** 同じ職業が1区画に詰まって競合することがなく、かつ空区画も出ない薄さである
- 世帯の区画Id は不変。`Household` の定数であって状態ではない

> **移住を許すとホテリングの法則で全世帯が中心区画に集まる。** 中心は全区画への距離が最小なので実質コスト([GDD06 §2](06-trade-and-negotiation.md))で有利になり、周辺に留まる動機が無い。**集まった瞬間に §4 の空間の摩擦が消滅し、§12-4「区画間の価格差が消えない」が構造的に不通過になる。**
>
> **決定論の側でも効く。** 区画Id が不変なら「どの世帯がどこに居るか」は状態ではなくなり、移動判定の順序やタイミングが状態ハッシュ([TDD01 §3.8](../04-tdd/01-sim-core-and-m0.md))に乗らない。§12-4 は**価格機構の帰結だけ**を見ることになる。

#### 立地のコントラストは徒弟の移動で表す(**方向の決定**)

**都心と周辺で条件が違うこと自体はリアルであり、消したくない。** 世帯を動かさずにそれを表現する担い手は**徒弟**である。

- 立地の良い工房は徒弟を集め、条件の悪い工房は徒弟を手放す。**動くのは世帯ではなく人手**
- 徒弟が増えれば労働力(§7.1)が増え、生産量で立地の差が現れる
- 機会費用の低い徒弟が居ることは、遠い店が候補に入ることでもある([GDD08 §7.2](08-household-and-decision.md))

> **M0 では入らない。** §7.3 で雇用を実装しないと決めており、徒弟の移動は雇用の一部である。**M0 の初期配置で徒弟数を固定し、立地の差は価格差としてのみ現れる。** ここは v1.0 の方向の宣言であって、W2 の作業ではない。

## 5. 生産

### 5.1 日次の生産

各生産者は日次で、自分のレシピについて:

1. 入力在庫が足りるか判定する
2. 足りれば生産量ぶん消費して出力を在庫に加える
3. 足りなければ**停止**し、不足している入力について Need を生成する(§8.4)

生産量は `min(入力から作れる量, 生産能力)`。生産能力は労働力と設備で決まる(§5.2、§7)。

### 5.2 労働力(**決定**)

**労働は入力の一種として扱う。** レシピの `所要労働`(出力1単位あたりに必要な労働力‰。1000‰ = 親方1人日相当)に対し、その工房に従事する世帯構成員の**労働力係数‰の合計**(労働力合計‰)が生産量の上限を決める。

**労働力係数‰(初期値)**:

| 階層 | 係数‰ |
| ---- | ----- |
| 親方 | 1000 |
| 職人 | 800 |
| 徒弟 | 300 |
| 主婦 | 300 |
| 子ども | 100 |

**主婦・子どもも家業を手伝う分の労働力として数える。** M0 では家事・時間配分を分けて計算しない([GDD08 §9](08-household-and-decision.md))ため、家業に振り向けられる時間の按分を行わず、**工房を持つ世帯の構成員全員の労働力係数‰をそのまま合算する。** これは M0 限定の単純化であり、時間配分を入れる v1.0 では [GDD08 §4.2](08-household-and-decision.md) のとおり実際に家業へ充てた時間の比率を乗じる形に戻す。

```
労働力合計‰       = Σ( その工房を持つ世帯の構成員の労働力係数‰ )
生産能力(単位数)   = floor( ApplyPermille(労働力合計‰, 設備係数‰(§5.3)) ÷ 所要労働‰ )
生産量             = min( 入力から作れる量, 生産能力(単位数) )
```

**この除算は切り下げる。** [GDD01 §2.3](01-trust-and-conversation.md) の全計算式切り上げの原則の**意図的な例外**である — 端数の労働力では1単位を完成できないため、切り上げると存在しない労働力で生産したことになる。

**これにより [GDD08 §4.2](08-household-and-decision.md)「1時間あたり出力」の式は M0 では使わない。** あの式はレシピに無い `標準出力/時間` を要求し、かつ時間配分(M0 では入れない)を前提にしている。GDD08 §4.2 は熟練度・時間配分を入れる v1.0 のための式として残し、**M0 の生産量は本節の式が正**とする([GDD08 §9](08-household-and-decision.md) の該当行はこの節を参照する形へ改める)。

これにより「労働力不足」が [GDD01 §3.2](01-trust-and-conversation.md) の Need 種別として自然に発生する(労働力合計‰ が所要労働‰ に満たない場合)。

### 5.3 設備の摩耗(**決定**)

**摩耗を入れる。ただし確率ではなく決定的に**(生産N回で工具1個を消費)。乱数を増やさないぶん因果が追える。

**設備係数‰(§5.2)は M0 では二値とする。** 稼働可能な工具在庫が1個以上あれば 1000‰、無ければ 0‰(生産停止。Need「工具切れ」、§8.4)。**摩耗度に比例して連続的に下がる形は v1.0 の拡張とする** — 段階を増やすと調整軸が増え、方針2(観測可能性)に対して M0 では過剰である。

耐久財の需要が内生的に湧く経路は、経済の自立性にとって重要である。工具を買えない工房は生産能力が落ち、それが Need になる(§8.4)。

> **摩耗する耐久財を工具のみに限っている**のは意図的なスコープ制約である。農具・ツルハシ・厨房設備なども同型に扱えるが、品目と調整軸が増える。将来の拡張候補として §14 に置く。

## 6. 消費と家計

### 6.1 日次消費

| 品目 | 消費者 | 量 | 分類 |
| ---- | ------ | -- | ---- |
| パン | 全 NPC | 家族規模に比例 | **必需** |
| 薪 | 全 NPC | 季節で変動 | **必需**(冬に急増) |
| 塩 | 全 NPC | 少量・一定 | **必需**(輸入依存) |
| ビール | 全 NPC | 階層で変動 | 嗜好 |
| ワイン・香辛料 | 上位階層のみ | 少量 | **奢侈** |
| 衣服・靴 | 全 NPC | 摩耗したとき | 耐久 |

**必需・嗜好・奢侈・耐久の4分類が価格形成に効く**(§8.2)。必需は価格が上がっても買う(需要が硬直的)、嗜好・奢侈は諦める(弾力的)。

**在庫が足りないときの消費の規則(v0.16 で明文化)**: **在庫は 0 で下げ止まり、負にならない。** 足りなかったぶんは繰り越さず、その日の不足として [§8.4](#84-need-への接続) の Need(在庫不足)になるだけである。**M0 では飢餓・健康・死亡をモデル化しない**(NPC は不死、§11.1)ので、不足が蓄積する変数を持たない。

> **この規則が無いと、塩で確実に踏む。** §6.1 の自給規則(下記)はパン・薪を都市経済から外すが、**塩は都市でしか手に入らないので農村8世帯が各季およそ16日間尽きる**(§14 で issue #8 へ送った未決の帰結)。在庫が負に振れると §8.2.3 の `購入量 = max(0, 到達在庫 − 予想在庫)` が負在庫の絶対値ぶん膨らみ、それが上の資金上限で毎日切り詰められて**破産中フラグが恒久的に立つ**。(§8.2.2 の在庫圧力‰ は目標在庫以下で 1000‰ に張り付くので、そちらは発散しない。)

**農村世帯の来訪期間外の必需品消費は自給として扱い、都市の需要にならない(v0.16 で追加)。** 農村世帯が都市で買い物をできるのは季節に一度の3日間だけである(§2.4「来訪していない期間は買い物をしない」・§10.5)。**上の表を農村32体にそのまま適用すると、日次消費は毎日進むのに補充の機会が30日に3日しか無い** — パン(目標在庫3日分)も薪も、残り27日は在庫が尽きたまま消費を続けることになり、**在庫の意味が定義されない**(整数の在庫が負になるか、消費が黙って失敗する)。

**したがって農村世帯は、農村で自給できる財(パン・薪)を都市で買わず、その消費を都市の在庫・需要として扱わない。** 都市の需要になるのは、**都市でしか手に入らない財(塩・工具)、滞在中および帰路の食料(パン)、そして滞在中の嗜好品(ビール)**である(§10.5 の来訪サイクル3と同じ集合)。

> **これは困窮(§6.3)の偽陽性の問題ではない。** 本書の破産は**金銭**で判定する(§6.2.1「流動資金が尽き、必需品が買えない」)ので、資金を持ったまま市から離れている農村世帯は破産にはならない。**壊れるのは在庫と消費の側であり、§12-2(困窮世帯の割合)ではなく §12-3(生産チェーン)と §8.2.2(在庫圧力)の入力である。**

> **塩については同じ問題が残っている。** 塩は都市でしか手に入らない必需品で、買い手側の目標在庫は2週間分(§8.2.1)、来訪間隔は30日である。**自給に倒せないので、各季およそ16日間、農村8世帯の塩が尽きる。** 農村世帯の目標在庫を来訪間隔ぶんに取るのが素直な解だが、**それは §8.2.1 の目標在庫に「世帯の種別」という新しい次元を入れることになる**ため、本書では決めない。**買う品目と数量の詰め(滞在中のパンの日数・塩の目標在庫の取り方・そもそも農村世帯を世帯として持ち続けるか)は W2 のスコープ切り分け([issue #8](https://github.com/stama72/visionary/issues/8))へ送る**(§14)。**本節が確定させるのは「自給できる財の来訪期間外の消費は都市経済に現れない」という一点だけである。**

> **塩を必需にしたことの帰結**: 都市内で作れない必需品ができる。**港が止まると全 NPC が困る。** 貿易の重要性が体感される設計である。

### 6.2 家計(**世帯単位**)

**家計の主体は個人ではなく世帯である**([GDD08 §2](08-household-and-decision.md))。

```
日次:   流動資金 += 販売収入 − 仕入支出 − 生活費
週次:   流動資金 −= 給金(雇用している場合)
季節次: 流動資金 −= 税
```

- **流動資金と帳簿(取引履歴)は世帯が持つ。** 帳簿は**資金の増減と一致するため**、個人別に持つと突合できない
- 世帯 = 親方 + 主婦 + 子ども + 徒弟。**職人は自分の家計を持つので別世帯**([GDD08 §2.1](08-household-and-decision.md))
- **すべて int**。税率・給金は千分率(‰)の整数([ADR-0002](../adr/0002-time-model-and-determinism.md))
- 税は領主・教会へ。**ただし都市外へ消えるのではなく還流させる**(§10.6)

> **W1 の `World` は流動資金を `NpcState` に持たせている**([TDD01 §3.2](../04-tdd/01-sim-core-and-m0.md))。**世帯単位へ移すのは W2 の作業であり、決定論ハッシュ([§3.8](../04-tdd/01-sim-core-and-m0.md))の区分が変わる。** 区分の設計は [TDD01 §3.2「経済主体は世帯である」](../04-tdd/01-sim-core-and-m0.md)が持つ。

#### 6.2.1 課税と破産の主体(**決定**)

**どちらも世帯である。** 資金が世帯にしか無い以上、払えるのも払えなくなるのも世帯である。

| | 単位 | 標準 |
| -- | ---- | ---- |
| 税(季節次) | 世帯 | **`ApplyPermille(流動資金, 税率‰)`** = 切り上げ付きの 流動資金 × 税率‰ ÷ 1000 |
| 破産(§6.3) | 世帯 | **資金の不足で必需品を1単位も買えなかった**(下記「破産中フラグ」が規範。残高 0 のことではない) |

**流動資金への比例課税を採るのは、税が自己制限的だからである。** 資金ゼロの世帯は 0 を払うので、**税が直接破産を誘発しない**。切り上げ規約([GDD01 §2.3](01-trust-and-conversation.md))により資金が 1 以上の世帯は最低 1 を払うが、**自己制限性は「資金ゼロなら 0」で保たれる**。§10.7 の自動調節と §12-6 の判定「**税率を上げても貨幣量が枯渇に向かわない**」は、この自己制限性を前提にしている。

> **世帯あたり定額の戸別賦課にすると §12-6 が成立しない。** 定額は資金の無い世帯を機械的に破産へ押し出すため、判定が「枯渇しない」ではなく「税率次第で枯渇する」に変わる。**税率を調整不能な地雷にしないという §12-6 の目的そのものを失う。**
>
> **残る歪みは許容する。** 比例課税は課税時点の現金保有量に依存するので、投げ売り(§6.3②)の直後に換金した世帯が重く当たる。中世都市として不自然ではなく、M0 では調整軸を増やさないことを優先する。

**破産は「状態」と「その立ち上がり」を区別する(v0.16 で明確化)。**

**まず、購入には資金の上限がある(v0.16 で明文化)。**

```
どの購入も、支払額が世帯の流動資金を超えてはならない。
    買える数量 = min( §8.2.3 の購入量 , FloorDiv( 流動資金 , その店の実効単価 ) )
                 ← 切り下げる。切り上げると1単位多く買えて流動資金が負に落ちる
    切り詰めた結果 1単位も買えなかった購入を「資金不足で買えなかった」と呼ぶ

世帯内の購入は次の順に決済する(流動資金を共有するので順序が結果を変える。ADR-0002):
    必需 → 生産の入力 → 耐久 → 嗜好 → 奢侈    同じ用途の中では 品目 Id 昇順(§2.4)
```

**走査順を固定するのは、資金が世帯内の共有資源になったからである。** v0.15 までは品目ごとの予算が互いに独立で(§8.2 の予算は**単価の上限**であって総額の上限ではない)、買う順序が結果を変えなかった。**資金の上限を入れた時点で、どの購入が切り詰められるかが順序で決まり、それが破産中フラグ → ②の値付け → ④の付け替え → §12-2 の判定まで波及する。**

**必需を先に決済するのは、フラグの意味を保つためである。** 嗜好品を先に買って必需品が切り詰められる順序を許すと、「資金不足で必需品が買えなかった」が**買い物の順序の関数**になり、困窮の指標として読めなくなる。

**「高すぎて買わなかった」は資金不足ではない。** §8.2.3 が `実質コスト > 基礎値` で購入量を 0 にした場合は、そもそも切り詰めが起きていないので上の定義に当たらない。**フラグが拾うのは「買う判断をしたが払えなかった」だけである** — ここを緩めると、価格が跳ねた日に全世帯のフラグが立ち、②が一斉に発動する価格ショックの検出器に戻る。

**これは本書に無かった規則である。** 資金制約が書かれていたのは §10.4 の貿易商の仕入(「流動資金を負にしない」)だけで、**必需品の購入には上限が無かった** — §8.2 の予算は §8.2.5 のとおり**便益**であり、資金も距離も含まない(費用側は実質コストへ分離してある)。v0.15 まではこの欠落が何も駆動していなかったが、**§6.3 ⑤ が「破産」を発火条件にしたことで荷重が掛かった。**

```
破産中フラグ(世帯の状態):
    立つ:  前日、必需品を「資金不足で買えなかった」購入が1つ以上あった
    降りる: 前日、そのような購入が1つも無かった

②(投げ売り)と④のゲートは、どちらもフラグが立っている「状態」で駆動する
```

**評価するのは前日の購入結果である。** 購入が起きるのは `Trade`([TDD01 §3.3](../04-tdd/01-sim-core-and-m0.md) 順5)で、フラグの更新は `Household`(順3)、すなわちその日の購入より前にある。**当日の結果で立てようとすると、②(順5 の値付けでフラグを読む)が同一 tick 内で循環する。** [GDD08 §6.3](08-household-and-decision.md) の1日遅延の成層化・[GDD06 §3.1](06-trade-and-negotiation.md) の「予算は当日の観測を反映しない」と同じ扱いにする。

**「流動資金が尽き」を残高 0 とは読まない。** 上の規則のとおり、**必需品を1単位も買えない**ことがその意味である。

> **「店を1つも知らないから買えなかった」は破産ではない。** それは [GDD06 §3.1](06-trade-and-negotiation.md) が **在庫不足 / 遠方在庫**の Need に割り当てた状態である(§8.4 の理由コードも「金銭不足 / 困窮」と別である)。**上の条件が資金の項だけを見ているので、これは自動的に除かれる** — 店を知らなければ購入そのものが起きず、切り詰めも発生しない。
>
> **資金の項を落とすと、塩が破産処理を毎季叩き起こす。** §6.1 のとおり塩は自給に倒せず、農村8世帯の塩は各季およそ16日間尽きる。**「必需品が手に入らなかった日に立つ」と書くと、そのあいだ8世帯のフラグが立ち続け**、④の職業付け替えと⑤の貸付が毎季発動する。§12-2 の困窮世帯割合と貸付件数が構造的なノイズで埋まり、**債務残高のある世帯では1回しかない債権放棄(§6.3 ⑤)を偽の立ち上がりが消費する。** 保持期間(GDD06 §3.1)は来訪間隔より長いので「知っている店が0件」では塞がらない — **塞いでいるのは資金の項そのものである。**

**§12-2 が測る「困窮状態」は、この破産中フラグが立っている状態を指す。**

**`生活費`(§6.2 の日次式)は、必需の消費のための支出そのものである。** 別建ての固定費ではなく、`Trade` で必需品を買った代金を指す。したがって `必要運転資金`(§8.2.1)の「必需の消費」の項が、そのまま生活費ぶんの手当てになっている。

**立ち上がり(前日は降りていて今日立った)を取る必要はない。** v0.16 の草稿は財政からの貸付(⑤)を持ち、その債権放棄を立ち上がりで駆動していたが、**⑤は M0 から撤回した**(§6.3)。②も④のゲートも状態だけを見るので、**フラグは1ビットで足りる。**

**破産しても世帯は解体しない。** §6.3 の①〜④はすべて世帯の行動であり、④の職業付け替えでも構成員はそのまま残る。

> **②の投げ売りの対象は販売在庫である(v0.16 で訂正)。** 在庫は世帯在庫(消費財)と工房在庫(生産の入出力)の2本に分かれる([GDD08 §2.2](08-household-and-decision.md) / [TDD01 §3.2](../04-tdd/01-sim-core-and-m0.md))。**世帯在庫の食料と薪まで投げ売ると翌日に困窮が深まるだけ**であり、換金の対象にならない。**工房在庫のうち②が届くのは、売り注文が出ている分(= 販売在庫、§8.1.1)だけである** — ②は提示価格の分岐なので、売りに出していない生産の入力には効かない。§6.3 の④のゲートもこの範囲で定める。

### 6.3 困窮と破産(**決定**)

資金の不足で必需品が買えなくなったとき(**判定の規範は §6.2.1 の破産中フラグ**)、**段階的に対応する**:

| 段階 | 行動 | 接続先 |
| ---- | ---- | ------ |
| ① | 奢侈品・嗜好品を諦める | **§8.2.1 の余剰資金**(規則ではなく帰結。下記) |
| ② | **在庫を投げ売る**(原価下限を割ってでも) | §8.1 の例外。**破産中フラグが立っている間の値付けの帰結**(下記) |
| ③ | **掛けで買う**(信用が要る) | [GDD01](01-trust-and-conversation.md) 効果2「与信」/ 質屋・両替商(§3.2) |
| ④ | 廃業して他所に雇われる | §7(雇用) |

**破産は退場ではなく職業の変更である。** これは中世都市のリアリティであると同時に、**プレイヤーが救う余地を残す**設計である。③で信用システムが経済的な意味を持ち、④で雇用と接続する。

> **①は v0.16 で規則ではなくなった。** §8.2.1 の余剰資金(流動資金 − 必要運転資金)が嗜好・奢侈の予算の母数になったため、**流動資金が必要運転資金に近づくだけで嗜好・奢侈の予算は 0 へ向かう**。困窮の判定を待たずに支出が絞られるので、段階①を別の処理として実装する必要はない。表に残しているのは段階の並びを示すためである。

> **④で職業を維持された世帯には、M0 では資金の回復経路が無い。** 下記「M0 での④の扱い」は、供給の消滅を防ぐために「最後の1世帯」と「中心隣接の唯一の担い手」を職業維持で保護するが、②は在庫が尽きれば効かず、③は M0 スコープ外である。**v0.16 の草稿はここに財政からの貸付(⑤)を置いたが、撤回して issue #8 へ送った**(下記)。

> ④はプレイヤーの店の従業員供給源にもなる(分冊04)。

#### M0 での④の扱い(**決定**)

**M0 では雇用を実装しない**(§7.3)ため、④の「他所に雇われる」接続先が存在しない。**M0 に限り、破産した世帯の職業を、担い手の最も薄い職業へ付け替える。**

```
その職業の担い手が自世帯だけなら → 付け替えない(職業を維持する)
破産世帯が鍛冶または貿易商かつ中心隣接区画(Id 1/3/5/7、§2.4)にあり、
かつ自世帯以外に同職業で中心隣接区画にいる世帯が無いなら → 付け替えない(職業を維持する)
そうでなければ:
    候補 = 同じ側の職業(都市世帯なら都市6、農村世帯なら農村4)から自職業を除いたもの
           のうち、破産世帯の区画に既に同職業の世帯が無いもの(§2.4「同職業2世帯は別区画」を破らない候補)
    候補が空なら → 候補 = 除外前の全職業(区画の重複を許容する。品目の供給停止のほうが優先度が低いため)
    付け替え先 = argmin( その職業の担い手世帯数 )  over 候補
                 同値のときは職業 Id 昇順
```

**候補を区画で絞るのは §2.4 の構造制約を保つためである。** §2.4 は「同じ職業の2世帯は必ず別の区画に置く。これは値ではなく構造の制約である」としており、担い手世帯数だけで付け替え先を選ぶと、破産世帯の区画にたまたま既に同職業の世帯があった場合、**§2.4 が成立しないと言った配置(同職業2世帯が同一区画)を実行時に作ってしまう** — §12-4(区画間の価格差が消えない)がその品目について偽陰性を返す。候補が尽きたときだけ例外的に許容する。

**中心隣接の鍛冶・貿易商を最後の1つにしない。** §2.4 が「鍛冶1世帯と貿易商1世帯は中心隣接区画に置く」という構造制約を持つのは、来訪中の農村世帯(視界 R=1 の起点は中心区画)が工具・塩を買えなくなることを防ぐためである。**区画で絞る規則(上記)だけでは、中心隣接の担い手そのものが破産で職業を離れる事態を防げない**(区画の重複は避けられても、その区画に誰も鍛冶/貿易商が居なくなりうる)。担い手が2世帯以上いても、中心隣接の1世帯が唯一の中心隣接担い手なら維持する。

**価格や原価から決めない。** 一見「最も儲かっている職業へ」が自然だが、整数除算では比が潰れて `argmax` が事実上「職業 Id 昇順」に退化する。**これだけで決定を支えるのに十分である。** 「市場全体の完全情報が要り NPC の意思決定として不自然」という理由も挙げられるが、これは §4.1 の情報の摩擦(NPC の視界)についての制約であり、この処理自体は次の段落のとおり**世界側の処理**(財政の日次購入(§10.6)と同じ扱い)なので、その制約の対象ではない。**除算の退化という1つの理由で決定は揺るがない。**

**担い手世帯数は `World` から直接数えられ、除算も価格観測も要らない。** これは NPC の意思決定ではなく、**空いた親方の座を割り当てる世界側の処理**である(史実ではギルドが親方昇格を統制していた → 分冊07)。

> **「最後の1世帯は付け替えない」が供給の消滅を構造的に防ぐ。** §2.4 は「1品目につき売り手2世帯」を M0 の成立条件としているが、**付け替えを無条件にすると両方の木材加工世帯が離脱して薪の売り手が消え、パンとビールが同時に止まる** — §2.4 が「最初から存在しない」と警告した状態を、破産処理が実行時に作ってしまう。担い手の薄い職業へ流す `argmin` と併せて、職業分布は均等へ戻る方向に働く。

- **世帯は解体しない。** 世帯主の職業が変わるだけである。**販売在庫は②の投げ売りで既に現金化されているが、生産の入力として抱えていた工房在庫は残る**(②は売り注文にしか効かない、§6.2.1)。M0 では旧職業の入力を売りに出す経路が無いので滞留する(§14)
- **都市世帯は都市職業の中でだけ移る。** 農村世帯は区画を持たない(§2.4)ので、都市職業に就くと居場所が定義できない
- **流動資金は補填しない。** 貨幣量を外から増やすと §10.7 の自動調節と §12-6 の判定が濁る。**財政からの貸付は §12-6 の貨幣総量を動かさないが**(財政残高も世帯の流動資金もその構成要素である)、**別の理由で M0 から外した**(下記)
- 同値の処理を Id 昇順で固定するのは列挙順規約([ADR-0002](../adr/0002-time-model-and-determinism.md))による

> **これは M0 限定の簡易版であり、④の構造「破産は退場ではなく職業の変更である」を雇用なしで満たすためのものである。** v1.0 では §7 の雇用市場を通り、「解雇された職人が供給プールに戻って別の親方に雇われる」形になる。**構造(職業が変わる)は同じで、経路だけが違う。**
>
> 職業分布が動くため §12-3(生産チェーンが止まらないか)の観測が豊かになる。**逆に付け替えが頻発するなら、価格機構が働いていない兆候である。**

#### M0 での①〜④の実行位置(**決定**。v0.16 で新設)

**①と②は「手順」ではなく状態の帰結である。`Household`(順3)で実行するのは ④ だけである。**

| 段階 | どこで起きるか | 形 |
| ---- | -------------- | -- |
| ① 嗜好・奢侈を諦める | §8.2.1 の予算計算 | **余剰資金が 0 へ向かう帰結。** 破産を待たずに効く |
| ② 投げ売り | **`Trade`(順5)の提示価格の決定**(§8.1.1) | **破産中フラグが立っている世帯は、原価下限を `原価 × 500‰` へ下げる**(外すのではない。下記) |
| ③ 掛けで買う | — | M0 スコープ外 |
| ④ 職業付け替え | **`Household`(順3)** | 下記の手順 |

**②を順3 の手順にしてはならない。** 投げ売りは `Market` への書き込みであり、順5 の値付け(§8.1.1、全売り手ぶんを一括で書く)と**同じ場所に二重に書くことになる**。順3 で書くと、順5 の `max(原価下限, …)` が同日中に上書きして投げ売りが無効化されるか、[TDD01 §3.2](../04-tdd/01-sim-core-and-m0.md) が「更新前の `Market` の値が**前日の提示価格**である」と宣言した値が当日の投げ売り価格に化けて §8.1.1 の `相場基準` の入力を汚す。**フラグを読んで値付け側で分岐すれば、書き込みは1か所のままである。**

```
Trade(順5)の提示価格の決定(§8.1.1)の中で:
    破産中フラグが立っている売り手は、原価下限を「外す」のではなく 500‰ に下げる
        提示価格 = max( ApplyPermille( 原価 , 500 ) ,
                        ApplyPermille( 相場基準 , 価格係数‰ ) )
        通常時の第1項は ApplyPermille(原価, 1000 + 最低利幅‰)(§8.1.1)

Household(順3)の日次処理。
  **手順ごとに全世帯を Id 昇順で回す。世帯ごとに 1→2 を回すのではない。**
  **TDD01 §3.3 順3 の固定支出(仕入・給金・税)の支払いを済ませてから 1 を始める** —
  流動資金が確定していないと 余剰資金 も破産の判定も決まらない。

  1. 破産中フラグの更新(§6.2.1。前日の購入結果から)

  2. ④へ進む条件(3つすべて):
       a. 破産中フラグが立っている
       b. 販売在庫(§8.1.1)が尽きている          ← ②の投げ売りで換金できるものが無い
       c. 事業が再開できない                      ← 生産職なら生産停止(§5.1、入力切れ)、
                                                    貿易商なら仕入不能(§10.4、資金が仕入単価未満)
        → 下記「M0 での④の扱い」の付け替えを実行する

     ※ b だけでは足りない。販売在庫 0 は「売れ残りが尽きた」だけでなく
       「その日完売した」「その日は売り注文を出していない」にも成立するので、
       **完売した健全な世帯や、閉場中の農村世帯(売り注文は季節市の3日間だけ)が
       1日の資金不足で廃業する**。c が「立ち直れないこと」を表す
     ※ b を工房在庫にしてはならない。生産の入力は売り注文に出ていないので ② では現金化できず、
       工房在庫でゲートすると「鉄鉱石を抱えたまま木炭を買えない鍛冶」が永久に ④ に到達しない
```

> **「段階的に対応する」を手順の並びで表さない。** フラグが立った世帯に ①〜④ を一息に適用すると、**最初の破産日に必ず廃業まで到達し**、②で立ち直る余地が構造的に消える。§6.3 冒頭が「段階的に対応する」と書き、下の註記が「付け替えが頻発するなら価格機構が働いていない兆候である」と観測に意味を与えているのは、**破産がただちに廃業を意味しない**ことが前提である。
>
> **段階を進める条件に新しい調整軸を足していない。** 3条件はいずれも既にある状態である — フラグ(§6.2.1)、販売在庫(§8.1.1)、生産停止(§5.1)・仕入不能(§10.4)。**「N日連続で困窮したら廃業」とすると閾値が1つ増える**ので採らなかった。
>
> **④の前提は「販売在庫が尽きている」までしか言えない。** ④が発動するのは売るものが無くなった世帯に限られるが、**生産の入力として抱えている工房在庫は②では現金化できない**(②は提示価格の分岐であり、売り注文が出ているのは販売在庫だけである、§8.1.1)。**付け替え後も旧職業の入力在庫はそのまま残る** — M0 では新職業のレシピで使わない品目を売りに出す経路が無いので滞留する(§14 へ送る)。§6.2.1 の「②の投げ売りの対象は工房在庫である」は**販売在庫**の誤りであり、本版で訂正した。

> **投げ売りに床を置くのは、原価下限を完全に外すと提示価格が 1 まで崩落するためである。** v0.16 で `相場基準` に自分の前日の提示価格が入った(§8.1.1)。投げ売りする売り手は在庫が捌けずに積んでいる側なので `価格係数‰ = 500` であり、他の売り手の価格を Q とすると `P[t] ≈ (P[t-1] + Q) / 4` で**不動点が Q/3**、同一品目の売り手が同時にフラグを立てれば毎日半減して `ApplyPermille` の切り上げが効く 1 まで落ちる。**§8.1.1 が「原価下限が消えて半減ループに歯止めがなくなる」と警告した状態を、②が自ら作ることになる。**
>
> **床の 500‰ は新しい係数ではない。** §8.1.1 の `価格係数‰` の clamp の下限と同じ値を使う。**「投げ売りとは、最低利幅を諦めて原価の半分まで下げること」**という意味になり、§12-5(原価を下回る提示価格が**継続**しない)は引き続き「困窮が長引いていないか」を測る指標として働く — 数値的な崩落ではなく経済的な理由で落ちる。

#### ⑤(財政からの運転資金貸付)は M0 に入れない(**決定**。v0.16 で撤回)

**v0.16 の草稿は、④で職業を付け替えられなかった世帯へ財政が運転資金を貸す経路(⑤)を新設していた。** ④の付け替えは供給の消滅を防ぐために「最後の1世帯」と「中心隣接の唯一の担い手」を職業維持で保護するが、**保護された世帯には資金の回復経路が無い**(②は在庫が尽きれば効かず、③は M0 スコープ外)。⑤はその穴を塞ぐ意図だった。

**レビューの過程で、⑤が意図した相手に届かないことが分かった。**

- **貿易商に届かない。** 貸付額は `必要運転資金 − 流動資金` で、`必要運転資金` の走査範囲は「生産の入力」と「必需の消費」である(§8.2.1)。**貿易商はレシピを持たない**ので塩・ワインの仕入資金が1枚も入らない — 仕入量を決めるのは §8.1.1 の `出荷目標在庫`(売り手側の軸)であって §8.2.1 の目標在庫ではない。貸されるのは家計の必需分だけで、しかも §10.4 の仕入式が翌日その全額を塩に変えるため、当日また必需品が買えなくなる
- **債権放棄がほぼ発火しない。** 放棄の判定を④のゲート(販売在庫が尽きている)の配下に置いたが、貸付で立ち直った世帯は**再び倒れた日には販売在庫を持っている**のが普通である。在庫が捌けた頃にはフラグは状態であって立ち上がりではないので、「債務残高 > 0 なら貸さない」に落ちる

**正味の効果は「保護された鍛冶への1回限りの救済」だけであり、持ち込む機構(債務残高・債権放棄済みフラグ・返済・状態と立ち上がりの区別・順3 の多段パス)に見合わない。** したがって **M0 のスコープ切り分け([issue #8](https://github.com/stama72/visionary/issues/8))へ送る**(§14)。

> **前提として、貸し手である財政(§10.6)そのものが M2 相当のスコープである。** 税・財政・外部経済との接続は、M0 が見たい「信用なしで価格が安定するか」([TDD01 §5.4](../04-tdd/01-sim-core-and-m0.md))より一段上の層にあり、**issue #8 の M0 仕様策定でさらに先送りになる可能性が高い。** ⑤は財政の存在に全面的に依存しているので、**財政ごと動く公算が大きい。本小節と §14 が残すのは方向性の記録であって、確定した仕様ではない。**

> **撤回しても W2 は着手できる。** 残る穴(中心隣接の鍛冶・貿易商の資金回復経路が無い)は **v0.15 が疑いとして持ったまま W2 着手可としていたもの**であり、状態がそこへ戻るだけである。**シミュレーションを起動できなくする種類の欠落ではなく、観測で現れる失敗モードである。**
>
> **むしろ救済経路を先に入れるほうが測定器を濁らせる。** §12-2(困窮世帯の割合)と §12-6(貨幣総量)は、「経済が回っているか」ではなく「財政の救済力」の関数になりうる。**M0 の目的は測定であって救済ではない** — §2.4 が運送労働者を外したときと同じ判断基準である。「資金が尽きた鍛冶が止まり §12-3 が落ちる」ことは、**W2 で得たい観測そのものである。**
>
> **v1.0 では③(掛け売り)と質屋・両替商が同じ役割を担う。** 雇用と与信が揃えば、財政を貸し手にする必要はない。

**したがって、破産中フラグは1ビットの状態でよい。** ②(値付けでの原価下限の引き下げ)も④のゲートも**状態**で駆動するので、前日との比較(立ち上がり)を取る必要がない。`債務残高` と `債権放棄済みフラグ` も持たない。

## 7. 雇用

### 7.1 構造

**親方 / 職人 / 徒弟** の3階層([idea/008](../idea/008-NPCと職業.md) §1.4.1 のギルド構造)。

- 工房を持てるのは親方のみ
- 職人は週次で給金を受け取る。徒弟は食住のみ(給金なし)
- **労働力係数‰の値は §5.2 が持つ**(親方1000 / 職人800 / 徒弟300 / 主婦300 / 子ども100、初期値)。ここでは重複させない

### 7.2 雇用の増減

- 生産が需要に追いつかない状態が続くと、親方は職人か徒弟を雇おうとする(Need「労働力不足」)
- 資金が続かなければ解雇する。解雇された職人は §6.3 ④の供給プールに戻る

### 7.3 スコープ(**決定**)

**v1.0 の目標仕様としては本節を採るが、M0 では雇用を実装しない。** **固定するのは労働力である** — 雇用の増減が無いので世帯の構成員と階層が変わらず、労働力の合計が動かない。M0 で見たいのは価格機構であり、雇用は変数を増やすだけである。

> **設備は固定しない。** 工具は摩耗し(§5.3)、設備係数が動くので生産量も動く([GDD08 §4.2](08-household-and-decision.md))。**工具は §2.4 のサブセットで唯一の耐久財**であり、耐久の予算(§8.2.1 の `min`)と「工具切れ」の Need(§8.4)を検証する唯一の経路なので、ここを固定すると M0 の検証項目が1本落ちる。

**ただしデータモデルには雇用関係を最初から持たせる。** 後付けは `World` の区分追加になり、決定論ハッシュの更新([TDD01 §3.8](../04-tdd/01-sim-core-and-m0.md))が要るため。

## 8. 価格形成

### 8.1 提示価格(**決定**)

売り手が「いくらで並べるか」。妥結価格は分冊06。

**在庫圧力 + 原価下限**を v1.0 の基準線とする:

```
提示価格 = max( ApplyPermille(原価, 1000 + 最低利幅‰) , 在庫圧力調整後の価格 )
```

- **原価は移動平均**とする。直近仕入値だと一度の高値づかみで提示価格が跳ねる

#### 8.1.1 更新式(**決定**)

```
在庫比‰   = CeilDiv( 1000 × 販売在庫 , 出荷目標在庫 )
価格係数‰ = clamp( 1500 − CeilDiv(在庫比‰, 2) , 500 , 1500 )
提示価格  = max( ApplyPermille(原価, 1000 + 最低利幅‰) ,
                 ApplyPermille(相場基準, 価格係数‰) )

原価 = 財の投入がある職業 → CeilDiv( Σ_j(入力 j の仕入れ移動平均単価 × 必要数量_j) , 出力数量 )
       財の投入が無い職業 → ApplyPermille( 機会費用_親方(1時間あたり) × 可処分時間T, 所要労働‰ )
```

**財の投入がある職業の原価は「出力1単位あたり」に正規化する。** 複数入力(パン=小麦粉+薪、ビール=穀物+薪、工具=鉄鉱石+木炭)は仕入れ移動平均単価 × 必要数量の合計を、出力数量で割って1単位分に均す。**この除算は切り上げる**(GDD01 §2.3 の原則どおり。切り上げても提示価格が上がる方向にしか効かず、§8.1「原価は移動平均」の保守性と整合する — §5.2・派生需要の「保証を守るため切り下げる」例外とは向きが逆であることに注意)。

**財の投入が無い職業の原価は、世帯主(親方)の機会費用を使う。** [GDD08 §9](08-household-and-decision.md) の機会費用は職業 × 階層の値だが、原価という「その職業の基準値」を出すには代表値が要る。**親方(階層係数1000‰)を採る** — GDD08 §9 の機会費用の値そのものが職業別の基準値に階層係数を掛ける形であり、親方は階層係数1000‰なので「職業別の基準値」と一致する。`所要労働‰`(§5.2、1000‰ = 親方1人日相当)と単位を揃えるため、機会費用(1時間あたり)に**可処分時間T**([GDD08 §3.1](08-household-and-decision.md)、初期値12時間)を掛けて「1人日あたりの金銭価値」に変換してから `ApplyPermille` で所要労働ぶんに按分する。

| 販売在庫 | 価格係数‰ | 意味 |
| -------- | --------- | ---- |
| 0 | 1500 | 品薄。相場の1.5倍 |
| 出荷目標在庫 | 1000 | **相場どおり** |
| 出荷目標在庫 × 2 以上 | 500 | 溢れている。相場の半値 |

> **`価格係数‰` の式は減算の中に `CeilDiv` を持つため、式全体としては切り下げ方向になる(在庫比‰ が奇数のとき係数が1‰小さくなる)。これは意図的である。** 在庫比を切り上げてから引くことで、品薄側(在庫比が小さいとき)ではなく充足側(在庫比が大きいとき)に1‰の誤差が寄る。値付けが**品薄側へ偏る**ほうが§4.1(情報の摩擦)・§8.2.4(不当価格が起き得る場所)の設計意図に沿うため、GDD01 §2.3 の「全計算式切り上げ」の原則をここでは字面どおり在庫比‰ の算出にだけ適用し、係数全体には及ぼさない。

**財の投入が無い職業の原価は、投入した労働の機会費用である。** 農村4職業(農民・きこり・炭焼き・鉱夫)はレシピに入力を持たないので、財の移動平均としての原価が **0** になる。素直に適用すると初回の来訪日に提示価格が 0 になり、**1次産品を売るのは農村世帯だけなので他の農村世帯の `相場基準` も 0 にしかならず、0 が恒久に固定される** — そこから小麦粉と薪の原価が移動平均で 0 へ向かい、原価下限が消えて `相場基準 × 500‰` の半減ループに歯止めがなくなる。

**労働だけが投入されているなら、それが原価である。** 機会費用は職業 × 階層の定数([GDD08 §9](08-household-and-decision.md))で**必ず正**なので 0 にならず、所要労働はレシピが持つ(§2.3)。**新しい概念も新しい調整軸も増えない。**

> **判別子は「レシピに入力があるか」ではなく「レシピの入力として、または転売のために仕入れた財があるか」である。** 貿易商のレシピ欄も `—` だが、港で仕入れるので**原価は正**である(§10.4)。レシピの形で分岐すると貿易商の原価下限が仕入値と無関係になり、**在庫が積んだ日に必ず仕入値未満で並べる** — §12-5「原価を下回る提示価格が継続しない」が構造的に不通過になり、貿易商2世帯が損失を垂れ流して §12-7(塩が品切れしない)も壊れる。**農村4職業が§10.5サイクル3で工具を購入することは、この判別子を揺らさない** — 工具は農村4職業のレシピの入力ではなく消費される耐久財(§5.3)であり、原価の対象である「販売する品目の仕入」には当たらない。
>
> **外部市場の帯(§10.4)は錨に使えない。** 帯があるのは港が扱う品目だけで、**木炭には帯が無い**(木炭は農村から来る、§2.2)。§12-1 は既にこの理由で対象品目を「M0 で港に接続する塩・ワインのみ」に絞ってある(§10.4)。

**`出荷目標在庫` は品目 × 職業ごとの定数(設定値)である。** 買い手側の目標在庫(§8.2.1 が薪1週間・パン3日と与えているもの)と同じ扱いで、**産出量から導出しない**。

> **導出をやめた理由。** 「1日あたりの産出量 × 回転日数」とすると、産出を当日の実績で取れば生産停止日(§5.1)に 0 になって零除算([`IntegerMath`](../../src/Visionary.Sim/Numerics/IntegerMath.cs))を起こし、**品薄が最も深刻な日に最安値を付ける**。定格で取れば「定格とは何か」の定義が要り、[GDD08 §4.2](08-household-and-decision.md) の生産性(M0 でも設備係数で動く)を含むかで再び 0 に近づく。**貿易商の「1日あたりの仕入量」に至ってはどこにも定義が無い。**
>
> **定数にすれば零除算も定義の依存も消え、買い手側と対称になる。** 農村世帯のように季節に一度しか売らない職業では目標在庫を1季ぶんに取る — **定数なので品目ごとに素直に置ける。**

**売り手が使う `相場基準` には、自分がその品目に出している売り注文を含める(v0.16 で変更)。**

```
観測されている他の売り手 = 世帯主(親方)の有効な観測([GDD06 §3.1](06-trade-and-negotiation.md))に現れる、
                          当該品目の自世帯以外の売り手世帯。
                          同じ売り手を複数日ぶん観測していても、採るのは最新の1件だけ(売り手ごとに1つ)

他の売り手が0件のとき:
    相場基準は無い → 原価下限がそのまま提示価格になる(§8.2.7)

他の売り手が1件以上のとき:
    価格の集合 = { 他の売り手ごとの最新の観測価格 }
               ∪ { 自分の前日の提示価格 }   ← 昨日この品目を売りに出していた場合のみ。
                                              出していなければ集合に足さない(0 を足すのではない)
    相場基準(売り手) = CeilDiv( 価格の集合の総和 , 集合の要素数 )
```

**「自分の前日の提示価格」は存在しない日がある。そのとき集合に加えないだけで、式は分岐しない。** `Market` は疎構造([TDD01 §3.2](../04-tdd/01-sim-core-and-m0.md))なので、売りに出していない日は自分のエントリが無い。少なくとも4経路で起きる:

| 経路 | 頻度 |
| ---- | ---- |
| **農村世帯の季節市の初日**(§2.4。開催3日間しか売り注文を出さない) | **毎季・農村8世帯で必ず** |
| §6.3 ④の職業付け替えの直後(昨日は別の品目を売っていた) | 破産のたび |
| 販売在庫が尽きて売り注文が消えていた世帯 | 随時 |
| 仕入前の貿易商(§10.4) | 随時 |

> **欠損を 0 として混ぜてはならない。** 混ぜると相場基準が要素数ぶん薄まり、本節が下で警告している「**0 が恒久に固定され、原価下限が消えて半減ループに歯止めがなくなる**」経路に、今度は自分の項から入る。**農村世帯では毎季必ず通る**ので、[GDD06 §3.1](06-trade-and-negotiation.md) が保持期間を「来訪間隔より長い」と構造制約にした目的(季節市の相場基準が消えないこと)が、自分の項についてだけ毎季崩れることになる。

**同じ売り手の観測は最新の1件に絞る(売り手ごとに1つ)。** 保持期間([GDD06 §3.1](06-trade-and-negotiation.md))は来訪間隔より長いので、同じ売り手を何日ぶんも観測している状態が普通に起きる。**レコード単位で平均すると、よく見る売り手ほど重みが増す**うえ、下の遷移行列の導出(1日前の値だけで決まる1次の差分方程式)も成り立たなくなる。

**使うのは世帯主(親方)の観測である。** 知識は個人が持ち世帯内で帰宅時に共有される([GDD08 §8.1](08-household-and-decision.md))が、**売り手としての値付けは世帯の行動なので代表者が要る**。§8.1.1 が原価としての機会費用に親方を代表値として採ったのと同じ理由・同じ相手を使う。

§8.2.1 が買い手側で掛ける**許容乖離‰ は掛けない** — あれは買い手が「いくらまで出すか」の緩みであって、売り手の値付けには関係しない。

**平均は `CeilDiv( 総和 , 件数 )` とし、平均をとる集合は「売り手ごとに最新の観測1件」とする。** 買い手側(§8.2.1・§8.2.7)も売り手側(§8.1.1)も同じである — 保持期間([GDD06 §3.1](06-trade-and-negotiation.md))は来訪間隔より長いので同じ売り手を何日ぶんも観測している状態が普通に起き、**レコード単位で平均するとよく見る売り手ほど重みが増す**。 切り上げ規約([GDD01 §2.3](01-trust-and-conversation.md))の既定どおりで、例外扱いにしない。**この規約は本書のすべての `相場基準` に共通して適用する**(§8.1.1・§8.2.1・§8.2.7・§10.6)。[TDD01 §4](../04-tdd/01-sim-core-and-m0.md) の `prices.csv` が出力する**約定価格の中央値は別物である** — あれは分布の要約であって値付けの入力ではない。

> **自分の売り注文を含めるのは、売り手2世帯間の交互振動を消すためである。** 売り手 A・B の価格係数を k とすると、自分を除いた場合の遷移は `P_A[t] = k_A·P_B[t-1]`、`P_B[t] = k_B·P_A[t-1]` であり、遷移行列の固有値は **±√(k_A·k_B)** — **符号が交互に入れ替わるモードが生きている**。A と B が価格だけを毎日入れ替えても両者の在庫は動かないので、**在庫圧力のフィードバックがこのモードを減衰させない**。自分を含めて平均を取ると行列の行が同一になり、この固有値が **0 に落ちる**。
>
> **[GDD06 §3.1](06-trade-and-negotiation.md) が「自分の売り注文は自分の観測に入れない」とした却下理由(複利で発散する)は誤っていた。** 両者が品薄(k = 1500‰)なら、**自分を除いても** 2日で `k_A·k_B` = 2.25 倍、すなわち1日あたり 1.5 倍で複利発散する。自分を除いて防げるものは何も無く、**交互振動モードが1つ増えるだけだった**([process/03](../process/03-corrections.md) 規則6 — 木炭と同じ型)。複利発散を実際に止めているのは、価格が買い手の予算(§8.2)を超えて売れなくなり、在庫が積んで `価格係数‰` が 500‰ 側へ落ちる経路のほうである。
>
> **「他の売り手の観測が0件のときは自分も使わない」が、GDD06 の懸念の有効な部分を残している。** 視界 R = 1(GDD06 §3.1)では相手の売り手が見えない日が普通に起きる。そこで自分だけを錨にすると、**純粋な自己ループ(品薄の売り手が毎日1.5倍を掛ける)**が本当に成立する。混ぜる相手が居るときだけ混ぜる。
>
> **中央値をやめて平均にしたのは、下側中央値が「安いほうへのラチェット」になるためである。** 旧規約(昇順 `CeilDiv(件数, 2)` 番目)は偶数件で下側を採るので、自分を含めて2件なら `相場基準 = min(自分, 相手)` になる。交互振動は同じく消えるが、**品薄側(k = 1500‰)の値上げ信号が過剰側(k = 500‰)に潰され**、錨が `min(k_A, k_B)` で下がり続ける。平均なら錨は `(k_A + k_B) / 2` で動かず、売り手2人の提示価格の差だけが残る — **§12-4(区画間の価格差が消えない)が見たいのはこちらである**。増える除算は1つ(`CeilDiv`)。
>
> **買い手側(§8.2.1)の `相場基準` には自分の売り注文を含めない。** 含めるのは §8.1.1 の値付けだけである。パン屋がパンの買い手でもある(§6.1)といった重なりで、自分の売値が自分の必需の予算を決める経路を作らない。

**`販売在庫` は工房在庫のうち売りに出している分である。** 生産職では生産の出力、貿易商では港で仕入れた商品。**即時消費で在庫を持たない職業(v1.0 のサービス業、§3.2)はそもそも `Market` に売り注文を出さない**(値付けの対象にならない)。M0 のサブセットにはこの型の職業は無い(§2.4「落としたもの」)。

**係数の 500〜1500 は固定であり軸にならない。** ただし**出荷目標在庫は買い手側の目標在庫とは別の調整軸である** — 1品目あたり売り手側と買い手側で2軸になる。§8.2.2 の「調整軸は品目ごとの目標在庫だけで済む」は**買い手側の内部での話**であって、両側を合わせた数ではない。

> **買い手側と「同じ関数」ではない。概念の鏡像である。** 買い手の在庫圧力は目標在庫以下で 1000‰ に張り付く(§8.2.2 が「基礎値の意味を壊さないため」と明記)。**売り手側で同じ形にすると、在庫ゼロでも相場どおりの値付けになり、品薄が価格に出ない。** 売り手側は目標在庫を中心に対称な直線にする。

**新しい状態は増えない。「自分の前日の提示価格」は `Market` が既に持っている**([TDD01 §3.2](../04-tdd/01-sim-core-and-m0.md) — `Market` は品目 × 売り手世帯の提示価格である)。今日の更新で上書きされる前の値がそれに当たる。

**ただし「全売り手が読み終えてから書く」という順序が構造の制約になる(v0.16 で追加)。** 売り手ごとに読んでは書くと、世帯 Id の小さい売り手の当日価格を Id の大きい売り手が同一 tick 内で参照してしまい、**処理順が結果を変える**(ADR-0002 の列挙順規約に違反する)。**その日の提示価格は全売り手ぶんを前日の `Market` から算出し、そのあとで一括して書き込む。** [GDD08 §6.3](08-household-and-decision.md) が機会費用に採った1日遅延の成層化と同じ規律である。

> **v0.15 までは「状態を持たないことが要点である」としていた。** 式が前日の提示価格を参照する以上この主張は成り立たないが、**保持すべき新しい場所は増えていない**。旧版が状態を避けた理由のうち「初日の初期提示価格を決める必要が出る」は、上の0件ルールが解いている — 初日は他の売り手の観測が0件なので相場基準そのものが立たず、原価下限がそのまま提示価格になる。**初期配置で与えるのは、依然として初期在庫の取得原価だけでよい。**

**相場基準が無いとき**(初日、他の売り手の観測が0件のとき、および観測が失効した品目)**は原価下限がそのまま提示価格になる**(§8.2.7 の売り手側)。`max` の第2項が消えるだけで、式は分岐しない。

> **ステップ更新(前日価格を ±X‰ 動かす)は引き続き採らない。** 状態を1つ持つこと自体は上記で受け入れたが、**ステップ更新は前日価格の積分器**であり、相場基準の平均(低域通過フィルタ)とは向きが逆である。ステップ幅という調整軸が増え、**§8.2.3 が警告する「売り手と買い手の在庫圧力が同位相で動く」振動を、慣性が増幅する。**

**原価下限には例外がある。** §6.3 ② の投げ売りでは**原価を下回る**。困窮した売り手は換金を優先するためである。

> **これは仕様であって不具合ではない。** M0 検証項目(§12-5)は「原価を下回る提示価格が**継続**しない」を見るのであって、「一度も起きない」を見るのではない。**投げ売りはプレイヤーにとって好機であり、経済の緊張の表現でもある。**

**相場観の参照(自分の `PriceObservation` を見て他店に追随する)は、§8.1.1 で既定経路になった。** 差し替え点ではない — `max` の第2項 `ApplyPermille(相場基準, 価格係数‰)` がそれである。情報の摩擦が価格に直結する反面、追随が振動を生みうるため、**M0 の安定性判定(§12-1)を通せるかは未知であり、そこが最初に崩れる候補である。**

### 8.2 予算(**決定**)

**予算は需要だけで決まる。** 店ごとの事情(距離・信用・提示価格)は入れない — それは**実質コスト**であり、分冊06 が持つ(§8.2.5)。

```
予算 = 用途別の基礎値 × 買い手の在庫圧力‰ ÷ 1000
```

**予算は1つ。実質コストは店ごとに異なる。** 買うのは「実質コストが最も安い店」で、かつ「その実質コストが予算以下」のときである。

#### 8.2.1 用途別の基礎値と目標在庫

| 用途 | 基礎値 | 目標在庫(初期値) |
| ---- | ------ | ------------------ |
| **生産の入力** | **派生需要**(出力の見込み売値から逆算) | 1日分の使用量 × 仕入れ間隔(日) |
| **必需の消費** | **相場基準**(自分の `PriceObservation` の平均 × 許容乖離‰。§8.1.1 の平均の規約) | 薪: 1週間分(1日消費量は季節変動、§9)<br>パン: 3日分<br>塩: 2週間分 |
| **嗜好・奢侈の消費** | **予算比率**(**余剰資金** × 比率‰。階層で変える。下記「運転資金と余剰資金」) | 肉: 1日分<br>ビール: 1日分<br>ワイン: 1週間分<br>香辛料: 1週間分 |
| **耐久の消費** | **min(相場基準, 予算比率)**(予算比率の母数は**流動資金**。下記) | 靴 / 衣服 / 工具: **耐久値の500‰ × 階層係数** |

**基礎値の意味**:

- **生産の入力**: 利益が出る値段でしか買わない
- **必需**: 余程の急騰でない限り相場に追随し、目標在庫まで買う。安ければさらに買い溜める
- **嗜好・奢侈**: 肉とビールは嗜好(酒場でも提供される)。ワインと香辛料は奢侈
- **耐久**: **`min` を取ることが要点である。** 相場を知っていても資金がなければ買えず、資金があっても相場より高くは買わない

> **耐久財に予算比率を入れたのは、徒弟が自分の財布を持たないため**([GDD08 §2.1](08-household-and-decision.md))。世帯の流動資金の一定比率(初期値10‰)までなら買える、とすることで**徒弟も靴を買える**。同じ条件を全階層に適用する。

**耐久財の在庫は「個数」ではなく「耐久値」である。** 時間経過と生産で摩耗し([§5.3](#53-設備の摩耗決定))、在庫が減る。目標在庫が `耐久値の500‰ × 階層係数` なので、**最下層の NPC は製品寿命の半分で目標在庫に達し、在庫圧力が 1000‰ になる**。階層が高いほど複数個を持とうとする。

##### 運転資金と余剰資金(**決定**。v0.16 で新設)

**嗜好・奢侈の予算の母数は流動資金ではなく余剰資金である。** 流動資金をそのまま母数にすると、**明日の仕入に要る金がそのまま遊興費の原資になり、黒字倒産(資金繰りだけを原因とする破産)が起きる。**

```
必要運転資金 = Σ_(用途,品目) ( 目標在庫[用途,品目] × 相場基準[品目][前日] )
               走査するのは (生産の入力, 品目) と (必需の消費, 品目) の組すべて
               相場基準が無い品目は加算しない(下記)

余剰資金     = max( 0 , 流動資金 − 必要運転資金 )

嗜好・奢侈の基礎値 = ApplyPermille( 余剰資金 , 用途別の予算比率‰ )
```

- **新しい調整軸は1つも増えない。** `目標在庫` は §8.2.1 の表が既に用途 × 品目ごとに持っており、**そこに「何日ぶん持ちたいか」が入っている** — 在庫回転期間を別の軸として持つ必要がない。**必要運転資金は「持ちたい在庫を今の相場で買い揃えるのに要る額」である**
- **走査の単位は品目ではなく(用途, 品目)の組である。** `目標在庫` は用途別にしか定義されていない(§8.2.1 の表)。**薪はパン屋・醸造にとって生産の入力であると同時に家庭の必需でもあり、在庫も2本に分かれている**([TDD01 §3.2](../04-tdd/01-sim-core-and-m0.md)「薪のように消費財でも生産入力でもある品目では、1本の在庫では目標在庫が一意に決まらない」)。品目単位で畳むとどちらの目標在庫を採るかが実装任せになり、**生産用の薪が運転資金から丸ごと落ちて、この変更が防ぐはずの黒字倒産が生産世帯でだけ戻る**
- **現在の在庫は差し引かない。** 「これから買い揃えるのに要る額」にすると、在庫が満ちた日に必要運転資金が 0 に落ちて余剰資金が跳ね、嗜好・奢侈に流れ、翌日の仕入で資金が尽きる — **黒字倒産が周期的に戻る**。必要運転資金は毎日の差額ではなく、**在庫を回し続けるために常時寝かせておく額**である(§14 に構造の帰結として記録した)
- **前向きの量であることが要点である。** 過去 N 日の実支出の移動平均で定義すると、**支出できていない世帯ほど必要額が小さく出る** — 困窮して仕入を止めた世帯ほど「運転資金は要らない」と判定され、**余剰資金が大きく出て嗜好・奢侈に回る**。目標在庫は実績に依存しないのでこの縮退が起きない
- **前日の相場基準を使う。** 当日の値を使うと、予算が当日の支出に依存し、その支出が予算から決まる日内の循環になる([GDD08 §6.3](08-household-and-decision.md) の1日遅延の成層化)。**これは §8.2.1 の必需の基礎値と同じ時点である** — [GDD06 §3.1](06-trade-and-negotiation.md)「予算は当日の観測を反映しない。前日までの観測から計算する」が予算全体に掛かっており、`必要運転資金` もその一部である。**本書のすべての `相場基準` は前日までの有効な観測から作る**
- **相場基準が無い品目は加算しない。§8.2.7 のフォールバックを使ってはならない。** フォールバックは `ApplyPermille(流動資金, 比率‰)` なので、**必要運転資金が流動資金の関数になり、`余剰資金 = 流動資金 − 必要運転資金` が自己参照する**。加算しないぶん必要運転資金は小さめに出るが、**それは「相場を知らない品目のぶんは取り置かない」という素直な意味になる**
- **除算は現れない。** 目標在庫(整数)× 相場基準(整数)の総和であり、丸めの向きを決める必要が無い
- **必需(§8.2.1・§8.2.7 のフォールバック 50‰)と耐久(`min` の予算比率側 10‰)の母数は流動資金のままである。** ここを余剰資金に倒すと、**困窮した世帯が食料を買えなくなり、困窮した鍛冶が工具を買えず設備係数(§5.3)が 0 に落ちて恒久停止する** — §14 が疑いとして挙げている失敗モードを、この変更自体が作ってしまう。**守りたいのは「生産と生活の継続」であり、工具はその継続そのものである**
- **生産の入力(派生需要)も母数を持たない**(下記のとおり出力の見込み売値から逆算する)ので影響を受けない

> **§6.3 ①「奢侈品・嗜好品を諦める」が、離散的な段階ではなく連続的な帰結になる。** 流動資金が必要運転資金に近づくほど余剰資金が 0 へ向かい、嗜好・奢侈の予算が自然に消える。**困窮の判定を待たずに支出が絞られる**ので、①を別の規則として書く必要がなくなった(§6.3 の表を書き換えた)。

> **農村世帯では必要運転資金が小さくなる。** レシピに入力を持たないので「生産の入力」の項がゼロになり、必需も都市で買うのは塩と滞在中のパンだけである(§6.1)。**手持ちの多くが余剰資金として扱われるが、これは意図した挙動である** — 収穫を売った農民が市で散財するのは中世都市の定期市の姿であり、醸造(ビール)の需要源にもなる。予算比率‰ が上限として効くので使い切りにはならない。

##### 派生需要の算出(**決定**)

**生産の入力の基礎値は、出力の見込み売値から逆算した「利益が出る上限単価」である。** レシピが複数入力を持つ場合(パン=小麦粉+薪、ビール=穀物+薪、工具=鉄鉱石+木炭)、その上限を入力どうしでどう配分するかを定義する。

```
見込み収益        = 提示価格_出力[前日] × 出力数量
許容原価合計       = floor( 見込み収益 × 1000 ÷ (1000 + 最低利幅‰) )

観測が無い入力 j(相場基準_j[前日] が計算できない)には、按分に加える前に
    派生需要(入力 j の基礎値) = ApplyPermille( 流動資金, 必需の予算比率‰ )    ← §8.2.7 のフォールバックそのもの
    フォールバック仕入見込み_j = 派生需要(入力 j の基礎値) × 必要数量_j
を確定し、按分の対象から外す。

残余原価合計 = max( 0, 許容原価合計 − Σ_{フォールバックに落ちた j} フォールバック仕入見込み_j )
    ← フォールバック入力のぶんを先に差し引く。按分対象(J)に全額を渡さない

残った(観測がある)入力の集合を J とする:
    入力 j∈J の見込み単価配分 = 相場基準_j[前日] × 必要数量_j
    入力 j∈J の配分予算       = floor( 残余原価合計 × 見込み単価配分_j ÷ Σ_{k∈J} 見込み単価配分_k )
    派生需要(入力 j の基礎値)  = floor( 入力 j の配分予算 ÷ 必要数量_j )

J が空(全入力が観測無し、または提示価格_出力[前日] 自体が無い)なら、
全入力についてフォールバックのみを使う(按分の式を評価しない。残余原価合計も使わない)。
```

- **フォールバック入力のぶんを先に差し引くのは、按分に残った入力へ全額を渡さないためである。** 差し引かないと、観測できた入力だけが「本来2入力で分けるはずだった上限」を丸ごと受け取り、その日の入力購入の合計に事実上の上限が無くなる — `最低利幅‰` の保証(下記)が、観測が部分的に欠けた日にだけ破れることになる
- **入力が1つしかないレシピ**(水車小屋番・木材加工)で J が非空なら `Σ_{k∈J} = 見込み単価配分_j` なので、`派生需要 = floor(残余原価合計 ÷ 必要数量)` に一致する(このケースはフォールバック対象が無いので `残余原価合計 = 許容原価合計`)
- **すべての除算を切り下げる。** `floor(A × w_j ÷ W)` を J 内で合計すると必ず `A`(= `残余原価合計`)以下になる(整数の性質)。J 内の合計とフォールバック入力の合計を足しても `許容原価合計` を超えない。**途中で ‰ 表現の按分比を経由すると、切り上げヘルパー `ApplyPermille` が入力ごとに端数を切り上げてしまい、合計が `許容原価合計` を超えうる**(実現利幅が `最低利幅‰` を下回る)。§5.2 と同じ「保証を壊さない側に丸める」例外であり、**ここでは中間に ‰ を挟まず直接比例配分する**ことで二重丸めを避けている
- **前日の観測を使うのは §8.2.7・[GDD08 §6.3](08-household-and-decision.md) と同じ1日遅延の成層化である。** 当日の価格を参照すると同一tick内で循環する
- **観測が無い入力を按分から外すのは、零除算(`Σ_{k∈J} = 0`)と恒久停止を同時に塞ぐためである。** M0 の視界半径 R=1(GDD06 §3.1)では、パン屋から見て水車小屋番・木材加工がともに距離2以上に居ることが普通に起きる。全入力が観測無しなら按分そのものを評価せず、**初日に限らずいつでも**フォールバックへ倒す — §8.2.7 の表の「生産の入力」行はこの規則に合わせて「影響を受けない」ではなく「**入力ごとに観測の有無で決まる**」と読む
- 新しい調整軸は増えない。**`最低利幅‰` は既存(§8.1)、配分予算は完全に導出値、フォールバックは §8.2.7 の必需の予算比率‰ を流用する**

##### 目標在庫の「N日分」は先読みで数える(**決定**)

**目標在庫は「N日 × 現在の1日消費量」ではなく、「今後 N 日に消費する予定の量の合計」とする。**

```
目標在庫 = Σ( 消費量[d] )      d = 今日 … 今日 + N − 1
```

**`消費量[d]` は日ごとに季節係数を適用して切り上げた整数であり、それを足す。** 合計してから切り上げるのではない。薪のように季節係数が掛かる品目では、丸め順で結果がずれる(N が2週間なら最大で N 単位)。

- **季節の境をまたぐと自然に前倒しで積み上がる。** 冬が近づくにつれ薪の目標在庫が滑らかに上がり、在庫圧力が上がり、予算が増える — **冬支度が規則ではなく帰結として現れる**
- 季節変動しない品目(パン・塩)では `N × 1日消費量` と一致する。**式が分岐しない**
- これが §14 の「季節変動する薪の1日消費量の定義が要る」への回答である。**定義すべきは1日消費量ではなく、目標在庫の数え方だった**

> **§8.2.2 が現在庫の側で既に採っている「買い物に行く時点で予想される在庫」と、同じ発想を比較の反対側(目標)に当てたものである。** 両側が先読みになっても**調整軸は増えない** — 変わるのは N の意味だけで、N は元から品目ごとの調整軸である。
>
> **当日の季節の消費量をそのまま使うと、冬に入った瞬間に全世帯の目標在庫が同時に跳ねる。** §8.2.3 が警告する「売り手と買い手の在庫圧力が同位相で動く」振動を、季節が毎年4回叩き込むことになる。

#### 8.2.2 買い手の在庫圧力(**式を確定**)

**上限倍率は2倍固定とする。**

```
在庫 ≤ 目標在庫:
    在庫圧力‰ = 1000

目標在庫 < 在庫 ≤ 目標在庫 × 2:
    在庫圧力‰ = CeilDiv( 1000 × (2 × 目標在庫 − 在庫) , 目標在庫 )

在庫 > 目標在庫 × 2:
    在庫圧力‰ = 0
```

変動幅は **0〜1000‰**。目標在庫までは 1000‰ で据え置き、そこから線形に 0 まで落ちる。

> **上限を 1000‰ に固定し、目標在庫まで据え置くことが重要である。** 基礎値を「安定して機能する信頼できる値」に保つため。
>
> **1000‰ を超えられるようにすると**、原材料では派生需要(利益が出る上限)を超えて買うことになり、**赤字の原価で仕入れが発生する**。奢侈品でも予算比率が後から変動してしまう。**基礎値の意味が壊れる。**

**これは §8.1 の売り手側在庫圧力の鏡像である。** 売り手は在庫が多ければ提示価格を下げ、買い手は在庫が多ければ予算を下げる。**両側で1つの概念**であり、調整軸は品目ごとの目標在庫だけで済む(上限倍率は固定なので軸にならない)。

##### 買い物に行く時点の予想在庫を使う

**在庫圧力の計算には、現時点の在庫ではなく「買い物に行く時点で予想される在庫」を使う。**

```
予想在庫 = 現在庫 − (買い物までに予定されている消費・生産投入)
```

> **これが時間の摩擦(§4)の正しい表現である。** 買い物に行くまでに食事や生産を予定しているなら、そのぶん予想在庫が減り、在庫圧力が上がり、予算が増える — **「在庫を切らす前に店へ行けない」状況が、緊急性として自然に価格へ現れる。**
>
> **待ち時間を費用として数えてはならない。** 待っている間は他の仕事ができるので、実際に時間が奪われるわけではない。摩擦は**偽の費用**ではなく**本物の緊急性**として表す。

#### 8.2.3 複数単位を買う場合

**判定基準はその商品を買う**前**の在庫量である。** 2単位目以降は、直前までの購入分を加えた在庫量で在庫圧力を算出する。

**ただし式は線形なので、反復せずに一度で購入量を解ける。** 実装はこちらを推奨する:

```
実質コスト > 基礎値            → 購入量 0
実質コスト ≤ 基礎値:
    到達在庫 = 2 × 目標在庫 − CeilDiv( 目標在庫 × 実質コスト , 基礎値 )
    購入量   = max( 0, 到達在庫 − 予想在庫 )
```

検算:

| 実質コスト | 到達在庫 | 意味 |
| ---------- | -------- | ---- |
| = 基礎値 | 目標在庫 | 相場どおりなら目標在庫まで買う |
| = 基礎値 × 1/2 | 目標在庫 × 1.5 | **安ければ買い溜める** |
| > 基礎値 | — | 買わない |

##### 需要曲線は創発する。書かない

各買い手の予算が在庫で下がるなら、**集計レベルの需要曲線は自動的に右下がりになる** — 価格が下がれば「買う人」も「1人あたりの量」も増えるためである。

**したがって個体に需要関数を持たせない。** 個体の意思決定は上の線形解だけで、方針4(満足化)と方針2(観測可能性)を保てる。**需要曲線を仮定するのではなく創発させるのが、エージェントベースの正しい使い方である。**

| 概念が増えない | 売り手側(§8.1)と同じ機構 |
| **価格の安定** | 必需品の需要が完全非弾力だと供給不足時に価格が青天井になる。**在庫のある者が買い控えることで需要が自動的に減る** |
| 貯蔵性が意味を持つ | 貯まる品目(薪・塩)と貯まらない品目(パン・肉)の差が経済に効く |

| 代償 | 対応 |
| ---- | ---- |

**腐敗は M0 では入れない**(§14)。

#### 8.2.4 不当価格はどこで成立するか

予算を相場基準にすると、NPC は相場から離れた値を「買わない」だけになる。では [GDD01 §4.5](01-trust-and-conversation.md) の不当価格はどこで起きるか。**2つの経路が残る**:

1. **相場観が古い、または無い**(情報の摩擦、§4)。新しく来た NPC、久しく買っていない品目では `PriceObservation` が薄い。そのとき高値を掴み、**後から相場を観測して「あれは不当だった」と気づく** — §4.5 の「取引tick近傍の観測入手による気づき」そのものである
2. **在庫が尽きかけて予算が最大(1000‰)になっている**。これは**正当な緊急性**であり、プレイヤーが「足元を見る」余地でもある

**1が誤爆の源であり、2は仕様である。** [GDD01 §6](01-trust-and-conversation.md) 検証項目5 の誤爆率は、**2を1と誤判定する率**として測る。

> **不当価格が「困窮という異常時」ではなく「情報の非対称という平常時の構造」から生まれることが重要である。** 本作の USP「情報を足で稼ぐ」に直結する。

#### 8.2.5 予算と実質コストの役割分担(**重要**)

**便益と費用を分ける。**

| | 予算(払える上限) | 実質コスト |
| -- | ------------------ | ---------- |
| **何を表すか** | **便益**。その品をどれだけ欲しいか | **費用**。手に入れるのに実際いくらかかるか |
| **決まり方** | 需要のみ(基礎値 × 在庫圧力) | 提示価格 + 信用による割引 + 移動の機会費用 |
| **いくつあるか** | **1つ** | **店ごとに1つずつ** |
| **どこが持つか** | **本書 §8.2** | **分冊06** |

**購入条件**:

```
信用を考慮した実質コストが他のどの店よりも安く、
かつ その実額が予算以下 であるとき、その店で買う
```

> **v0.3 は機会費用による上乗せを予算の側に入れていた。誤りである。** 実質コストにも機会費用が入るため**二重計上**になり、かつ「店ごとに異なるもの」を「1つしかない予算」に混ぜていた。**便益と費用の分離が正しい**([process/03](../process/03-corrections.md) 規則6 — 却下理由ではなく設計そのものの訂正)。
>
> **時間の摩擦は §8.2.2 の予想在庫へ、空間の摩擦は分冊06 の移動の機会費用へ**、それぞれ1か所だけに置く。

#### 8.2.6 M0 でどこまで実装するか(**決定**)

**機会費用は職業 × 階層の固定値とする**(算出方式は [GDD08 §5](08-household-and-decision.md)、M0 スコープと階層係数は [GDD08 §9](08-household-and-decision.md))。

構造(予算と実質コストの分離、在庫圧力、線形解)は M0 から入れる。**構造を先に固定し、値の由来を後から差し替える**のは §9(季節係数)と同じやり方である。

#### 8.2.7 相場観が無いときの予算(**決定**)

**相場基準は自分の `PriceObservation` の平均から出る**(§8.2.1・§8.1.1 の平均の規約)。観測が1件も無ければ計算できない。**これは初日だけの問題ではない** — 保持期間を過ぎた品目、久しく買っていない品目でも起きる(§8.2.4)。したがって初期観測を配るのではなく、**規則として定義する**。

```
相場基準が計算できないとき:
    基礎値 = ApplyPermille( 流動資金 , 用途別の予算比率‰ )
```

| 用途 | 観測ゼロ時の基礎値 |
| ---- | ------------------ |
| 生産の入力 | **入力ごとに、その入力の観測が無ければ影響を受ける**(§8.2.1「派生需要の算出」)。初日(出力自体の前日価格が無い)はすべての入力がこれに該当する。観測がある入力は他人の観測を要さず、前日の出力価格から逆算する |
| **売り手の提示価格**(§8.1.1) | **原価下限がそのまま提示価格になる。** `max` の第2項が消えるだけで式は分岐しない |
| 必需の消費 | **予算比率へフォールバックする**(初期値 50‰) |
| 嗜好・奢侈の消費 | **影響を受けない。** 元から予算比率(母数は**余剰資金**、§8.2.1) |
| 耐久の消費 | `min(相場基準, 予算比率)` の相場基準側が落ち、**予算比率のみになる**(既存の 10‰。母数は**流動資金**、§8.2.1) |

**新しい機構を持ち込んでいない。** 既に §8.2.1 の表にある「予算比率」へ倒すだけであり、増える調整軸は必需品の比率‰ の1つである。**生産の入力のフォールバック**(§8.2.1「派生需要の算出」)も同じ式を流用する — `基礎値 = ApplyPermille(流動資金, 必需の予算比率‰)` を観測の無い入力ごとの基礎値とし、新しい比率‰ は増やさない。**初日に限らない** — 保持期間切れや視界の外にある入力(GDD06 §3.1)でも、その入力だけこの規則に落ちる。観測がある入力は通常どおり按分される。

> **この規則は §8.2.4 の不当価格の発生源そのものである。** 相場を知らない NPC は「流動資金の範囲でなら払ってしまう」ので、**高値を掴み、後から相場を観測して気づく**。フォールバックを穴埋めとしてではなく、**情報の摩擦が価格に現れる正規の経路**として置いている。
>
> **初期観測を配らないのはこのためである。** 配ると初日だけ穴が塞がり、保持期間で観測が失効した NPC が後から同じ穴に落ちる。**規則にすれば初日を特別扱いせずに済む。**

**買い手がそもそも店を1つも知らない場合は、予算ではなく Need になる** → [GDD06 §3.1](06-trade-and-negotiation.md)。

### 8.3 需要の表現

**需要曲線は作らない。** NPC は「必要量」と「払える上限」(§8.2)を持つだけで、価格に応じて量を連続的に変えることはしない(方針4)。

- 必需品: 必要量は固定。払える上限まで買う。買えなければ §6.3 へ
- 嗜好・奢侈品: 払える上限を超えたら**買わない**(量は0か固定量)
- 耐久財: 摩耗したときだけ需要が立つ

これで十分に価格は動く(在庫が捌けなければ売り手が下げ、買い手は在庫が満ちれば買い控える)。**個体に需要関数を導入すると、価格の因果が式の中に隠れて追えなくなる**(方針2)。

**集計レベルの需要曲線は §8.2.4 の在庫圧力から創発する。書かない。**

### 8.4 Need への接続

不足は [GDD01 §3.2](01-trust-and-conversation.md) の Need として表面化する。**Need が経済とコアループの結節点である。**

| 発生源 | Need 種別 | 理由コード |
| ------ | --------- | ---------- |
| 生産の入力切れ(§5.1) | 在庫不足 | 生産停止 |
| 必需品が買えない(§6.3) | 金銭不足 | 困窮 |
| 労働力不足(§7.2) | 労働力不足 | 増産できない |
| 設備の摩耗(§5.3) | 在庫不足 | 工具切れ |
| 区画をまたぐ運搬が要る(§4) | 在庫不足 | 遠方在庫 |

> **これが [TDD01 §3.6](../04-tdd/01-sim-core-and-m0.md) の仮決め「`Need.TypeCode` / `ReasonCode` を enum にする」への答えである。** 上表の左2列が種別、右列が理由コードの初期集合になる(§13)。

## 9. 季節との接続

[GDD03 §2](03-seasons-and-city.md)(季節が経済に効く形)は未着手。**本書が先に値を決めると二重管理になる。**

| 何を | どちらが持つか |
| ---- | -------------- |
| 季節係数の**構造**(どのレシピ・どの消費が季節に依存するか) | **本書** |
| 季節係数の**値**と、季節そのものの定義 | **GDD03** |

構造だけ本書で決める:

- **生産の季節性**: 1次産品のみ季節係数を持つ。中間財・最終財は持たない(工房は屋内)
- **消費の季節性**: 薪のみ季節係数を持つ
- **農村からの搬入は季節に一度**(§10.5)。これが季節性の最大の担い手である
- 係数は千分率の整数。**GDD03 が値を持つ**

> 穀物が秋にしか穫れず、農民が季節に一度しか来ないなら、**次の搬入までの在庫繰りがゲームになる。保存と投機**は本作の商人像と非常に相性がよい。ただし1年=120日(30日/季)という短さで成立するかは要検証。

## 10. 貨幣と都市の外(**改稿**)

### 10.1 なぜここが最重要か

[GDD01 §6](01-trust-and-conversation.md) の M0 検証項目2 は「長期実行して価格が発散・硬直しないか」である。**この判定を通せるかは、貨幣のソースとシンクの設計でほぼ決まる。**

- **完全に閉じた系**(貨幣総量が一定): 価格の絶対水準が動かない
- **シンクだけがある系**(税が都市外へ消えるのみ): 貨幣が枯渇し、全 NPC が困窮する

**税を入れた時点で、対応するソースが必須になる。**

### 10.2 決定:外部市場(A)と財政還流(B)を併用する

- **A(外部市場)** — 都市外との交易が貨幣のソース兼シンクになり、同時に**価格の上下限**を与える
- **B(財政還流)** — 税収を都市内に還流させ、**シンクそのものを小さくする**

**併用する。** A だけでは税が一方的な流出になり、B だけでは価格の上下限が無くなる。

### 10.3 A-1:行商人(陸路)

- **幅広い品目を少量**扱う
- 各区画を巡回し、都市内の提示価格で売買する
- **スプレッドが大きい**(買値と売値の差)。行商人と取引すると必ず損をする
- **§4.2 の「詰みは作らない」の実装**。プレイヤーが何もしなくても最低限は流通するが、遅く・高い

### 10.4 A-2:港(海路)

- **限られた品目を大量**に扱う: 穀物・木材・鉄鉱石・塩・ワイン・香辛料
- **スプレッドが小さい**。大口取引の効率を表現する
- **貿易専用品目(塩・ワイン・香辛料)の唯一の供給源**
- **都市内の貿易商(§3.2)が取引した分は、スプレッドが都市内の利益になる**

> **最後の点が重要である。** 港のスプレッドは、貿易商が介在すれば都市内に残り、介在しなければ外部へ出る。**貿易商を育てること自体が都市の富を増やす**という構造になり、プレイヤーが貿易商になる動機にもなる。

**外部価格は季節でゆっくり動く。急変させない**(プレイヤーが読めなくなる)。品目ごとに帯の幅が違う — 鉄鉱石は外部依存が強く帯が狭い、パンは都市内財なので港では扱わない。

#### M0 での港・貿易商の実装(**決定**)

**§2.4 のサブセットで港に接続するのは塩とワインだけである。** 穀物・木材・鉄鉱石は農村世帯が都市内価格で直接供給する(§10.5)ので、M0 では港を経由しない — **v1.0 の目標仕様(この3品目も港と接続する)への接続は、輸出経路とあわせて先送りする**(§14)。

**貿易商2世帯は、日次で以下を行う**:

```
販売在庫(塩 or ワイン) < 出荷目標在庫(§8.1.1) のとき:
    仕入単価   = 外部価格帯の上限値
    仕入数量   = min( 出荷目標在庫 − 販売在庫 , floor(流動資金 ÷ 仕入単価) )
    販売在庫  += 仕入数量
    流動資金  -= 仕入単価 × 仕入数量
```

- **仕入数量は流動資金の範囲に切り詰める。** 資金が足りない日は目標在庫まで届かなくても仕入を打ち切る — §6.3 の困窮・破産の判定(「必需品が買えない」)と矛盾しない形にするため、流動資金を負にしない
- **仕入は外部価格帯の上限値で行う。** M0 には輸出が無いため、§10.4 冒頭の「貿易商が介在すればスプレッドが都市内に残る」は成立しない — **港のスプレッド(帯の下限〜上限)そのものは M0 では都市外に出たままである。** 都市内に残るのは `最低利幅‰` だけであり、貿易商の利益はこの利幅が担う(v1.0 で輸出を追加すると、下限での売り経路が加わりスプレッドの取り込みが機能する)
- **外部価格帯(初期値。調整対象、§14)**:

  | 品目 | 帯 |
  | ---- | -- |
  | 塩 | 8〜12 |
  | ワイン | 40〜60 |

- 提示価格は §8.1.1 の通常式に従う(原価 = 仕入れの移動平均)。貿易商の原価下限は §8.1.1 が既に「財の投入がある職業」側に分類している

**輸出は M0 に入れない。** §2.4 のサブセットが持つ2つの貿易品目(塩・ワイン)はどちらも「輸入のみ」(§2.4)であり、都市生産品(小麦粉・薪・パン・ビール・工具)はすべて都市内消費財で港では扱わない品目である。**したがって M0 には輸出経路が構造的に存在しない** — §10.7 の正貨流出入メカニズムは v1.0 で穀物・木材・鉄鉱石の輸出を追加してから機能する。M0 の貨幣還流は §10.6 の財政支出が担う。

### 10.5 農民 NPC は「内部 NPC」である(**重要な区別**)

[idea/008](../idea/008-NPCと職業.md) §1.5 の農村職業(§3.3)は、**行商人とはまったくの別物である。** 混同すると設計が壊れる。

| | 行商人・港 | 農民 NPC |
| -- | ---------- | -------- |
| 価格 | **外部市場の固定価格帯** | **都市内の提示価格** |
| 頻度 | 常時(行商)/ 随時(港) | **季節に一度** |
| 性格 | 都市の外の経済 | **都市経済の一部** |

**農民 NPC の1回の来訪サイクル**:

1. 生産物(穀物・木材・**木炭**・鉄鉱石・羊毛)を都市に持ち込み、**都市内の提示価格で換金する**
2. **納税する**
3. 残った資金で都市の物資(衣服・靴・工具・塩)を購入し、消費する

**M0 では §2.4 のサブセットに従い、持ち込むのは穀物・木材・木炭・鉄鉱石、購入するのは工具・塩・パン・ビールである**(羊毛・衣服・靴はサブセット外)。**パンは滞在中と帰路の分だけであり、薪は買わない** — 農村で自給できる財は都市で買わない(§6.1)。**来訪先は中心区画(Id 4)に固定する**(§2.4)。**3日間の開催(§2.4)の中で、1〜3のサイクルを1日ごとに順に行う**(初日に売って納税し、残り2日で購入する)。1日で3工程すべてを終える必要はない。

**この構造が2つの役割を果たす**:

- **1次産品の供給源。** 都市は1次品(肉・皮を除く)を生産しない(§3.3)
- **貨幣シンクの相殺。** 農民の生産は**ゼロから資源を生む**。それが都市内価格で換金され、納税で吸われ、残りが都市の最終財の需要になる。**税で消えた貨幣が、農村の生産を通じて都市に戻る**

> **なぜ「内部」と呼ぶか。** 農民が外部市場価格ではなく都市内価格で取引するため、**都市の価格変動が農民の購買力に直接効く**。都市の物価が上がれば農民は買い控え、下がれば買う。閉じたフィードバックの内側にいる。

### 10.6 B:財政還流

**税収はできるだけ都市内に還流させ、シンクを小さく保つ。**

**財政政策として、好況時に貯め、不況時に支出を拡大する。** これにより景気変動が緩和される。

主要な支出先:

| 支出 | 需要が向かう先 |
| ---- | -------------- |
| **建設事業** | 大工の賃金 + 資材(木材・薪) |
| **衛兵** | 賃金 + **武器・甲冑**(M0 では賃金と生活費のみ、下記) |
| 領主・聖職者自身の消費 | 奢侈品(ワイン・香辛料)、衣服 |

> **これが §2.2 で武器・甲冑を加えた理由である。** 市民は武器を買わない。**領主が衛兵に装備させることが唯一の需要源**であり、武器職人の存在は財政支出に依存する。**財政が縮むと武器職人が困窮する** — 経済の連関が体感される設計である。
>
> 建設事業も同様に、大工と木材加工に需要を作る。**不況時の支出拡大が、最も困窮しやすい職業を支える**構造になっている。

#### M0 での財政の実装(**決定**。レビュー6巡目で全面改訂)

**§2.4 のサブセットには大工・衛兵・領主・聖職者という職業も世帯も無い。** §10.6 が挙げる支出先はいずれも購買を実行する主体を欠いており、このままでは税(§6.2.1)がシンクとして流出するだけで戻らない(§10.1 が自ら「シンクだけがある系は貨幣が枯渇する」と警告した構成そのものになる)。**M0 では財政を、世帯ではない `World` 側の主体として直接実装する。**

**税収の還流だけでは貨幣のソースにならない。** 財政残高は税(徴収時点で既に世帯間の貨幣を動かしただけ)を溜めて配るだけなので、**系全体の貨幣総量は変えない**。一方 §10.4 の貿易商は塩・ワインを外部価格帯の上限で仕入れるため、**輸出が無い M0 では貨幣が恒常的に外へ流出する**(§10.4)。**したがって財政には、税収とは別に、都市外からの定期収入(補助金)を持たせる** — これは v1.0 で輸出経路(穀物・木材・鉄鉱石の余剰を港へ売る)を実装したときに置き換える**明示的な M0 限定のプレースホルダ**である(TDD01 §3.6 の仮決めと同じ性質)。

```
財政残高(World の区分。世帯ではない。在庫・帳簿・区画を持たない)

季節次:
    財政残高 += その季節に徴収した税の合計(§6.2.1 と同じ処理から)
    財政残高 += 外部補助金(初期値。M0 限定のプレースホルダ。§14)

季節次:
    支出予算   = ApplyPermille( 財政残高, 還流率‰(初期値800) )
    財政残高  -= 支出予算
    建設口座   = min( ApplyPermille(支出予算, 400), 支出予算 )
    衛兵口座   = min( ApplyPermille(支出予算, 400), 支出予算 − 建設口座 )
    領主口座   = 支出予算 − 建設口座 − 衛兵口座          ← 残差。`min` により負にならない
    各口座をさらに下表の対象品目へ均等に分割する(端数は品目 Id 昇順に1ずつ乗せる)

日次(Trade システム([TDD01 §3.3](../04-tdd/01-sim-core-and-m0.md) 順5)の中で、世帯間取引が確定したあとに実行する):
    残り日数 = その季節の残り日数(今日を含む)
    各(口座, 品目)の組について:
        品目口座残高が 0 なら何もしない
        日次上限   = CeilDiv( 品目口座残高, 残り日数 )                     ← 季節内で均す。初日に使い切らせない
        相場基準_財政 = 今日 Market に並ぶ当該品目の全売り手の提示価格の平均(§8.1.1 の平均の規約に従う。個人の観測を経由しない)
        留保単価   = ApplyPermille( 相場基準_財政, 許容乖離‰(§8.2.1) )    ← 既存の係数を流用。新しい軸を増やさない
        対象売り手 = 提示価格 ≤ 留保単価 である当該品目の売り手全員(世帯Id昇順)
        対象売り手が空なら購入しない(日次上限は消化されず、品目口座残高にそのまま残る)
        日次上限を対象売り手へ均等に配分する(端数は世帯Id昇順に1ずつ乗せる) — 最安値だけを浚わない
        各売り手への購入量 = min( 配分額 ÷ その売り手の提示価格(floor), その売り手の販売在庫 )
        実支出額(この(口座,品目)の合計) を求め、品目口座残高 -= 実支出額 (日次上限ではなく実支出額を引く。
            買えなかった分は品目口座残高に残り、翌日以降に繰り越す — 貨幣を消さない)
        買った代金は売り手世帯の流動資金へ加算し、通常の取引と同じく帳簿に記帳する
        (買い手は「財政」という特別な世帯外 Id を使う)
    その季節のうちに使い切れなかった品目口座残高は次季の財政残高へ繰り戻す(消えない)

```

- **貨幣総量(§12-6)には品目口座残高も含める。** `貨幣総量 = Σ世帯の流動資金 + 財政残高 + Σ品目口座残高`。季節次に財政残高から口座へ資金が移るだけで、貨幣は消えも生まれもしない — §12-6 の判定式(§12 の表)をこの定義に更新した
- **留保単価と対象売り手の均等配分は、財政が「区画間の価格差を潰す裁定者」になることへの歯止めとして設計したが、有効性は未検証である。** 最安値の売り手だけを毎日浚うと §12-4 が判定する区画間の価格差を財政自身が消しうる。`許容乖離‰` による歯止めが効く範囲(価格差がどこまで広がると歯止めが利かなくなるか)は値に依存し、GDD では決着しない。**W2 のタスク仕様で、財政の日次購入を on/off できる実験軸として実装し、§12-4 の判定を両条件で比較すること**(§14)
- **日次上限は季節内での支出の平滑化を目的とするが、1次産品(木材)のように売り注文が季節市の数日間しか立たない品目とは相性が悪い。** そのため**建設事業の対象品目は薪のみとする**(木材は外す)。薪は都市内(木材加工)で毎日供給されるため、日次上限の前提(毎日買える)と噛み合う

| 支出 | 配分比‰(初期値) | M0 での対象品目(均等分割) |
| ---- | ---------------- | -------------------------- |
| 建設事業 | 400 | **薪のみ**(木材は季節市の数日間しか売られず日次上限と噛み合わないため対象から外した。下記)。大工を職業として置かない(§2.4)ため、購入のみで賃金は発生しない |
| 衛兵 | 400 | **パン・ビール・塩。** **酒場は M0 に無い**(§2.4「落としたもの」)ため、既存品目を直接買う形にした。装備需要(武器・甲冑)は§2.4のサブセットに無いので入れない |
| 領主・聖職者自身の消費 | 200(残差) | **ワイン**(奢侈)。品目が1つなので分割しない |

> **v1.0 の武器・甲冑・衣服・香辛料・大工の賃金・衛兵の賃金は、対応する職業(分冊07・分冊04)を入れてから復元する。** 構造(税収の一定割合を還流させる)は変えず、宛先だけを M0 の主体に合わせて差し替えた。**外部補助金は v1.0 で不要になる**(輸出が代わりにソースを担うため)。

### 10.7 自動調節メカニズム

**v1.0 の目標仕様**(A・B併用)では、以下の負のフィードバックが働く:

```
税による通貨量の減少
  → 購買力の低下
  → 物価の下落
  → 輸出競争力の向上(都市内価格が外部価格帯の下限に近づく)
  → 輸出の促進
  → 貿易黒字
  → 通貨量の回復
```

**これは正貨流出入メカニズム(price-specie-flow)そのものである。** 歴史的にも実在した調節機構であり、**外部価格帯という「神の値」を、経済的に正当な錨として使える**ことを意味する。

さらに A は**分業の利益**をもたらす:

- 余剰生産能力がある品目 → **輸出で稼ぐ**
- 不足する品目 → **輸入でコストを抑える**

**その結果、都市内の職業構成のばらつきが「個性」として残せる。** 全職業が均等に揃っていなくても、貿易が凸凹を埋める。これは都市ごとの性格づけ(将来の複数都市)にも繋がる。

#### M0 での自動調節(**決定**)

**M0 には輸出経路が無い**(§10.4)ため、上の price-specie-flow は機能しない。**M0 で実際に働く負のフィードバックは §10.6 の財政(税の還流 + 外部補助金)だけである**:

```
税による通貨量の減少
  → 財政残高の増加(徴税分 + 外部補助金)
  → 季節次の支出予算(財政残高 × 還流率‰)の増加
  → 建設事業・衛兵(パン・ビール・塩の直接購入)・領主消費への購入増
  → 該当世帯の流動資金の回復
```

**外部補助金が無いと、この経路は §10.4 の輸入シンクを相殺できない。** 財政が税だけを溜めて配るなら系全体の貨幣総量は変わらないので、貿易商の塩・ワイン仕入で流出する分だけ純減する。**これは price-specie-flow より単純だが、それだけ壊れにくい。** 依存する経路が財政の1本だけであり、貿易収支という測定の難しい量を経由しない。**§12-6 の判定基準はこれに合わせて改める**(下記)。v1.0 で輸出経路を追加したときに、外部補助金を廃し、両方の負のフィードバックが並走する形へ戻す。

## 11. NPC の一生(**決定**)

### 11.1 M0 では NPC は不死とする

**世代交代は v1.0 の課題とし、M0 では実装しない。**

**根拠となる整理**: [GDD01 §6](01-trust-and-conversation.md) 検証項目2 の 36,000日は、**300年の物語ではなく価格機構の耐久試験である。** 混同すると人口動態が M0 のスコープに引きずり込まれる。耐久試験に人口動態は要らない。

**検証地平は 36,000日のまま据え置く**([TDD01 §5.4](../04-tdd/01-sim-core-and-m0.md) の判定基準を変更しない)。

> **短縮は残された調整弁である。** 発散・硬直が起きるなら数十年で兆候が出るはずなので、原理的には 3,600日(30年)でも検証は成立する。**W2 の調整サイクルが実測で遅すぎた場合に限り、短縮を再検討する。** 先回りして基準を緩めない。

### 11.2 世代交代を入れる場合の波及(参考)

v1.0 で入れるなら以下が連動する。**M0 では触らない。**

- 信用([GDD01 §2.1](01-trust-and-conversation.md))は死亡でリセットされる。長期の信用関係が失われる痛みがゲームになる
- 相続で資産と工房が引き継がれる。徒弟→職人→親方の昇格が生きる
- 決定論ハッシュ([TDD01 §3.8](../04-tdd/01-sim-core-and-m0.md))の区画が増える

| 4 | **摩擦が残っているか** | **都市で生産される5品目(小麦粉・薪・パン・ビール・工具)の区画間の価格差が消えない。** 消えていれば §4 の摩擦が実装されていない。1次産品は農村世帯が中心区画でのみ売るので対象外(§2.4) |
| 5 | 原価下限が効いているか | 原価を下回る提示価格が**継続**しない(§8.1。投げ売りによる一時的な下回りは正常) |
| 6 | **自動調節が働くか** | **貨幣総量(Σ世帯の流動資金 + 財政残高 + Σ品目口座残高、§10.6)が長期的に減少し続けない。** 財政残高や支出予算の増加だけでは測らない — それらは税率を上げれば機械的に増えるので、貨幣が実際に枯渇していても通ってしまう。**M0 では税は世帯↔財政の内部移転であり総量を動かさないため、この項目が実質的に測っているのは「外部補助金(§10.6)が貿易商の輸入流出を相殺できているか」である。** 税率を動かす実験としては v1.0 で輸出経路が入ってから貿易黒字と併せて見るほうが意味を持つ |
| 7 | 貿易依存品が枯れないか | 塩(必需・輸入のみ)が長期に品切れしない(§6.1) |
| 8 | **知識が広がるか** | **「知っている店が0件」の世帯の割合が、初期の過渡期を過ぎて高止まりしない**([GDD06 §3.1](06-trade-and-negotiation.md))。M0 は行商人も運送労働者も置かず、**観測の広がりだけが摩擦の下限**(§4.2)なので、これが働かないと #7 が落ちる。**#7 と分けて測ることで、原因が貿易収支か知識の伝播かを切り分けられる** |

**#4 が本書固有の判定である。** 価格が安定していても区画差が消えていたら、それは「プレイヤーのいらない経済」であり、**経済として成功でもゲームとして失敗**である。

**#6 は §10.7 の機構が机上の理屈で終わっていないかを見る。** 自動調節を設計に組み込んだ以上、それが実際に働くことを確かめないと、税率が調整不能な地雷になる。

- [ ] **片方の売り手だけが投げ売っても、相手の錨が下がる。** ②の提示価格は `Market` に書かれ、他の売り手の `PriceObservation` に入り、翌日の彼らの `相場基準`(平均、§8.1.1)の1項になる。売り手が2世帯しかいない M0 では `(投げ売り価格 + Q) / 2` まで下がるので、**健全な側の提示価格も原価下限へ押し付けられうる**。§8.1.1 の崩落の導出は「同時にフラグを立てた場合」しか扱っていない。§12-4・§12-5 で見る
- [ ] **交互振動モードが「消えた」という導出は線形近似の下でのみ成り立つ。** §8.1.1 の「自分を含めて平均を取ると行列の行が同一になり固有値が 0 に落ちる」は、**両売り手の `価格係数‰` が同一で、その日在庫が動かない**という近似に立っている。実際の k は在庫で毎日動くので行が完全に同一になるのは瞬間だけであり、**残留する交互成分がどれだけあるかは実測でしか分からない**。§12-1 で見る
- [ ] **破産中フラグは世帯単位の1ビットなので、②はその世帯が売る全品目の原価下限を同時に下げる。** 貿易商なら塩とワインが同時に投げ売りになる。**品目ごとに困窮を持つ設計もありうる**が、困窮は資金の状態であって品目の状態ではないので世帯単位を採った。奢侈(ワイン)まで投げ売る挙動が §12-1・§12-5 にどう出るかは実測する
- [ ] **売り手2世帯が同時に品薄のときの共通モードの発散は残っている。** v0.16 で自分の売り注文を相場基準に含めたことにより、**交互振動モード(遷移行列の固有値 ±√(k_A·k_B))は消えた**(§8.1.1)。残るのは両者が同時に品薄のときの共通モード(利得 `(k_A + k_B) / 2`、最大 1.5/日)であり、**これは自分を除いていた v0.15 でも同じ大きさで存在していた**。止めているのは値付けの式ではなく、価格が買い手の予算(§8.2)を超えて売れなくなり在庫が積む経路である。**§12-1 の安定性検証で実測する。** **併せて、派生需要(§8.2.1)が作る別経路の正のフィードバック**(派生需要 → 仕入値 → 原価の移動平均 → 提示価格 → 翌日の派生需要)**も同じ検証で見る**
- [ ] **§4.2「詰みは作らない」は M0 では観測の広がり(§12-8)という未検証の機構1本に委ねられている。** §12-8 が落ちた場合の代替(視界半径 R を上げる、行商人を暫定的に戻すなど)が未定
- [ ] **中心隣接の鍛冶が④で職業を維持され続けると、工具の供給が恒久的に止まりうる。** §6.3 は中心隣接の唯一の担い手を職業維持で保護するが、**M0 にはその世帯の資金回復経路が無い**(②は販売在庫が尽きれば効かず、③は M0 スコープ外、⑤は撤回した)。鍛冶2世帯がこの経路を順に辿ると、工具の生産者が「資金が尽きて動かない1世帯」だけになり、設備係数(§5.3、二値)がいずれ全工房で 0‰ に落ちて §12-3 が壊滅的に不通過になりうる。**これは観測で現れる失敗モードであり、W2 で実測する**
- [ ] **財政の「世帯外 Id」の割り当て方と帳簿記帳の範囲が未定。** Id は非負 int(TDD01 §3.2)で、既存の世帯 Id と衝突しない値を予約する必要がある。「通常の取引と同じく帳簿に記帳する」が売り手側だけの記帳を指すのか、財政側にも何らかの記録を残すのかは未定
- [ ] **実装が `CeilDiv` 同様の `FloorDiv` ヘルパーを持つか。** §5.2(生産能力)・§8.2.1(派生需要の許容原価合計・配分予算)・**§6.2.1(資金上限による購入量の切り詰め)**・§10.4(貿易商の仕入数量)・§10.6(財政の購入量)が「切り下げが正しい」と明記した除算を複数導入した。**GDD06 §2 の移動費は `CeilDiv` のままである**(切り上げが正しい側)。裸の `/` 演算子で書かせると、個々の除算が切り上げ規約の例外かどうかがレビューでしか判別できなくなる(reviewer.md 観点1と同型のリスク)
- [ ] **破産中フラグの条件が「必需品を買えない」に限られており、生産の停止を拾わない。** §6.2.1 のフラグは**必需品の購入が資金不足で切り詰められた日**に立つ。したがって **必需品は買えるが仕入(生産の入力)には足りない世帯 — 資金が細った鍛冶・貿易商の典型 — はフラグが立たず、②(投げ売り)にも④(付け替え)にも到達しない**。販売在庫が尽きれば生産も仕入も止まり、工具や塩の供給が消える(§12-3・§12-7)。**判定条件を生産・仕入の資金不足まで広げるべきかは W2 のタスク仕様で判断する。** 広げると §12-2 の「困窮世帯」の意味が「食えない世帯」から「事業が回らない世帯」に変わるので、判定基準(§12-2 の閾値)とセットで決める必要がある
- [ ] **④の付け替え後に残る旧職業の工房在庫(生産の入力)の扱いが未定。** ②は売り注文にしか効かないので入力在庫は現金化されず、付け替え後も残る。新職業のレシピで使わない品目は M0 では売りに出す経路が無く滞留する。**貨幣総量(§12-6)は動かないので測定は壊れない**が、在庫という実物が死蔵される。売りに出せるようにするか、付け替え時に処分するかは W2 で決める
- [ ] **§5.2 の `ApplyPermille(労働力合計‰, 設備係数‰)` は設備係数が二値(1000/0)の M0 では安全だが、v1.0 で摩耗を連続化すると、切り下げるべきと明記した式の内側に切り上げヘルパーが残る。** M0 では実害が無いため放置している
- [ ] **財政の留保単価(§10.6)が §12-4 の区画間価格差を汚さないかは未検証である。** `許容乖離‰` の値次第で、価格差が一定以上広がると財政が安い側からしか買わなくなり、最安値だけを浚っていた元の問題に戻りうる。**GDD では決着させず、財政の日次購入を on/off できる実験軸として W2 で実装し、§12-4 を両条件で比較すること**
- [ ] **建設口座の対象を薪のみに絞ったことの妥当性。** 木材(1次産品、季節市の数日間のみ流通)を対象から外したことで、建設事業が木材加工の需要源にならなくなった。§10.6 冒頭の「建設事業も…木材加工に需要を作る」という v1.0 目標との差分をどう埋めるか(1次産品向けに季節単位で均す規則を別途持つ、など)は未定
