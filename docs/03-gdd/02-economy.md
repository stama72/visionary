## 1. 設計方針

1. **経済は摩擦のためにある。** これが第一原理である。NPC が完璧に動く経済ではプレイヤーの価値がゼロになる。[idea/008](../idea/008-NPCと職業.md) §3.1 の「AI職人は工房から動かない」を**仕様として明文化する**(§4)
2. **観測可能性を最優先する。** The Guild 3 化(観測不能な複雑さ)の回避は企画段階からの制約である。プレイヤーが「なぜこの価格なのか」を追えなくなった時点で、経済の精巧さは価値を失う。**追えなくなる複雑さは、面白さの有無に関わらず入れない**
3. **閉じた経済にしない。** 都市の外を明示的にモデル化する(§10)。閉じた系は貨幣量が固定され、価格の絶対水準が動かせない
4. **NPC は満足化する。最適化しない。** 最適化する NPC はプレイヤーの介在余地を消し、かつ挙動が読めなくなる
5. **数値は初期値。** 構造と依存関係だけを固定する

## 2. 品目とレシピ

### 2.1 構成(**決定**)

**3層・最大2段・21品目。** 層と段を区別する:

- **層** = 品目の位置(1次産品 / 中間財 / 最終財)。**3層に固定する**
- **段** = 1次産品からの変換回数。**制約すべきはこちら**。段が深いほど価格の因果が追えなくなる(方針2)

品目数を増やしても段が浅ければ因果は追える。逆に段が深いと品目数が少なくても追えない。**したがって品目数は20程度まで増やし、段は2に抑える。**

> **段は「品目をどの層に置くか」で調整できる。** 木炭は当初 `木材→薪→木炭` の中間財としたため工具が3段になったが、**1次産品(農村の炭焼き)に置き直すと工具は1段になる**(§2.2)。史実に沿わせた結果として制約も満たした例である。

**都市の賑わいは、品目ではなく職業で出す。** 生産以外の職業(サービス業・物流業・貿易商)を置くことで、レシピを増やさずに都市の味が出る(§3)。

**燃料は2系統ある。用途が分かれ、供給経路も分かれる。**

| 燃料 | 用途 | 供給 | 止まる条件 |
| ---- | ---- | ---- | ---------- |
| **薪** | 家庭の暖房、食品加工(パン・ビール) | **都市内**(木材加工が木材から作る) | 木材の搬入が途絶える / 木材加工が止まる |
| **木炭** | **金属加工のみ**(工具・武器・甲冑) | **農村から**(炭焼き) | **農村からの搬入が途絶える(=季節性)** |

**故障モードが違うことに価値がある。** 単一の隘路より、2つの独立した供給不安があるほうが、プレイヤーの介入機会が多様になる。冬の暖房需要(§9)は薪だけを圧迫し、木炭には効かない。

> **「肉」が1次品であること。** 肉屋は都市内の職業だが、家畜の購入を明示的にモデル化しない(抽象化する)。レシピを持たず肉と皮を産出する、という扱いにする。**モデル化すると家畜という品目と牧畜という職業が要り、段が増える。**
>
> **貿易専用品目(塩・ワイン・香辛料)は都市内で作れない。** 供給は港(§10.4)のみである。**外部依存が構造的に発生する品目**を持つことで、貿易商の存在意義と、港が止まったときの緊張が生まれる。

#### 木炭は1次産品である(**決定**)

**中世の炭焼きは森の奥深くで原木を蒸し焼きにする作業であり、都市内の工房で行うものではない。** したがって木炭は、きこりや鉱夫と同じく**農村から持ち込まれる1次産品**として扱う(§3.3)。

**この置き方が3つの問題を同時に解く**:

1. **史実性。** 製鉄・鍛造には木炭が要る。薪では温度が足りず不純物も多い。「炭が切れた鍛冶屋」は [idea/008](../idea/008-NPCと職業.md) §3.1 が挙げた場面そのものである
2. **段数。** 中間財(`木材→薪→木炭`)に置くと工具が3段になるが、**1次産品に置けば `鉄鉱石 + 木炭 → 工具` は1段**である。§2.1 の制約を満たす
3. **対称性。** 金属加工3種(工具・武器・甲冑)がすべて `鉄鉱石 + 木炭` で揃う

> **v0.2 では木炭を廃し、金属加工の燃料を薪に統一していた。** 廃した理由は「段が3になる」「燃料が2種で対称性が崩れる」だったが、**どちらも木炭を中間財に置いたことの帰結**であり、1次産品に置き直すと両方とも消える。**却下理由の前提が、置き場所を変えたことで崩れた**([process/03](../process/03-corrections.md) 規則6)。

### 2.3 レシピの形

```
レシピ = { 出力[(品目, 数量)], 入力[(品目, 数量)], 所要労働 }
```

- **出力は複数を許す**(肉屋 → 肉 + 皮)
- **1レシピ1段**。中間財を経ずに原料から最終財を作る近道は置かない
- 数量はすべて int。歩留まり・端数は**切り上げ**([GDD01](01-trust-and-conversation.md) §2.3 の全体規約)
- **入力を持たないレシピを許す**(肉屋)。1次品の産出がこれにあたる

### 2.4 M0 のサブセット(**決定**)

**§2.2 の21品目・§3 の21職業は v1.0 の目標仕様である。M0 では 11品目・都市8職業・農村4職業で走らせる。**

**理由は規模の噛み合わせである。** 9区画 × 1〜2世帯(§4.3)では世帯が最大18しか無く、都市16職業では**1品目1売り手**になる。`Market` は「品目 × 売り手 → 提示価格」なので、売り手が1人なら市中価格が1つしか存在せず、**§12-4「区画間の価格差が消えない」が消えるのではなく最初から存在しない**。[GDD06 §3](06-trade-and-negotiation.md) の店の選択も比較対象を持たない。**1品目につき売り手2世帯を別区画に置けることが、サブセットの大きさを決めている。**

**ただしこれが当てはまるのは都市で売られる7品目**(小麦粉・薪・パン・ビール・工具・塩・ワイン)**である。** 1次産品4品目(穀物・木材・木炭・鉄鉱石)は農村世帯が中心区画でのみ売るので、区画差は生じない。**§12-4「区画間の価格差が消えない」は都市生産品で判定する。**

| 1次 | 穀物 | — | 生産の入力 |
| 1次 | 木材 | — | 生産の入力 |
| 1次 | 鉄鉱石 | — | 生産の入力 |
| 1次 | 木炭 | — | 生産の入力(金属加工専用) |
| 中間 | 小麦粉 | 穀物 → | 生産の入力 |
| 中間 | 薪 | 木材 → | **必需**(家庭の暖房)+ 生産の入力(パン・ビール) |

| 最終 | ビール | 穀物 + 薪 → | **嗜好** |

**§8.2.1 の予算の4つの決まり方がすべて残っている** — 派生需要(1次〜中間)、相場基準(パン・薪・塩)、予算比率(ビール・ワイン)、`min` の耐久(工具)。**どれか1つでも対応する品目を落とすと、その式が W2 で一度も実行されない。**

**燃料2系統も残る** — 薪は都市内(木材加工)、木炭は農村(炭焼き)。故障モードが違うことが §2.2 の柱であり、木炭を落とすと工具そのものが作れない。

**都市8職業 × 2世帯 = 16世帯。** 9区画に1〜2世帯で収まり、**NPC 約48体**になる。これに農村世帯が加わる。

**同じ職業の2世帯は必ず別の区画に置く。これは値ではなく構造の制約である。** §4.3 の密度(1区画1〜2世帯)だけでは同居を防げず、同居すると当該品目の売り手が1区画に集まって区画差が消える。**M0 では職人世帯を置かない** — 世帯は親方・主婦・子ども・徒弟で構成し、[GDD08 §2.1](08-household-and-decision.md) の「職人は別世帯」は雇用(§7.3)とともに v1.0 へ送る。

**農村は4職業 × 2世帯 = 8世帯。** 都市16世帯と合わせて24世帯になる。

**職業 Id は上の表の順に 0〜11**(都市8 → 農村4)。§6.3 と [GDD08 §9](08-household-and-decision.md) の「同値なら職業 Id 昇順」はこの採番による。

**農村世帯は区画を持たない。** 都市の外に住み、季節に一度だけ(§10.5)**中心区画(Id 4)に来訪して売る**。中心は全区画から最大距離2であり、1次産品が都市全体から等しく届く位置になる。**来訪先を中心に固定するのは本節の決定である**(§10.5 は来訪サイクルだけを持つ)。

## 3. 職業(**新設**)

**理由**: 職業 = レシピ + 家計 + 雇用階層であり、3つとも本書の §2・§6・§7 が持つ。レシピを持たない職業(商業・サービス・物流)も、**経済における役割**として定義される以上ここに属する。

| 加工 | 紡ぎ手 | 羊毛→毛糸 | |
| 加工 | 仕立て屋 | 毛糸→衣服 | |
| 加工 | 皮職人 | 皮→なめし皮 | |
| 加工 | 靴職人 | なめし皮→靴 | |
| 加工 | 鍛冶 | 鉄鉱石+木炭→工具 | 生産設備の供給 |
| 加工 | 武器職人 | 鉄鉱石+木炭→武器/甲冑 | **需要源は領主(衛兵)のみ**(§10.6) |
| **商業** | 貿易商 | — | **港での大口取引を担う(§10.4)。スプレッドが都市内の利益になる** |
| **商業** | 質屋・両替商 | — | 困窮 NPC への与信(§6.3③)。**信用システムの NPC 側の担い手** |
| **物流** | 運送労働者 | — | **区画間の運搬。摩擦の下限を担う**(§4.2) |
| **サービス** | 酒場の主人 | パン+ビール+肉→(即時消費) | **最終財の大口需要者。** 在庫にならない |
| **サービス** | 宿屋 | 薪+パン+ビール→(即時消費) | 同上。行商人・貿易商が客 |

**サービス業は「最終財を買って在庫にしない」ことに意味がある。** 都市内に最終財の需要の受け皿があると、パン屋・醸造・肉屋の生産が家計消費だけに依存しなくなり、価格が安定しやすい。**サービスそのものは品目として持たない**(在庫も価格も持たない)ため、品目数は増えない。

### 3.3 農村の職業

**都市の外に住み、季節に一度だけ都市に来る**(§10.5)。

| 職業 | 産出 |
| ---- | ---- |
| 農民 | 穀物 |
| きこり | 木材 |
| **炭焼き** | **木炭** |
| 鉱夫 | 鉄鉱石 |
| 羊飼い | 羊毛 |

**1次産品(肉・皮を除く)は都市で生産されない。** 都市は加工と商業に特化する。これは史実的にも正確であり、**原料在庫が季節で大きく振れる**という設計([idea/008](../idea/008-NPCと職業.md) §1.5、§9)を成立させる。

### 3.4 粒度(**決定**)

**都市16職業 + 農村5職業 = 21職業。経済的な役割が異なるものだけを分ける。** ただし**これは v1.0 の目標仕様であり、M0 で走らせるのは §2.4 のサブセット(都市8 + 農村4)である**。 [idea/008](../idea/008-NPCと職業.md) はより細かい区分を挙げている(海上貿易商とスパイス貿易商の分離、金銀細工師、道化師など)が、経済的役割が重複するものは統合した。

**職業の追加は品目の追加より安い。** レシピを持たない職業(サービス・物流・商業)は品目数も段数も増やさないため、方針2の観測可能性を損なわない。**粒度を上げる拡張は、M0 後の「賑わいが足りない」という所感に応じて足す。**

> **従業員の扱い(決定)**: 商業・サービスにも**親方/職人/徒弟の枠組みを適用する**。別の職業としては扱わない。生産物が無い職種では熟練度が「信用の上がりやすさ」と仕事の割り振りに効く。詳細は [GDD08 §3.3](08-household-and-decision.md)。

## 4. 摩擦 — プレイヤーの価値の源泉

**本書で最も重要な節。** [idea/008](../idea/008-NPCと職業.md) §3.1 を仕様化する。

| 摩擦 | NPC の制約 | プレイヤーの機会 | 実装上の要点 |
| ---- | ---------- | ---------------- | ------------ |
| **空間** | 職人は工房のある区画から動かない。生産物は自分の区画にしか並ばない | 区画をまたぐ運搬でサヤを抜く | **都市を 3×3 の9区画に分け**、価格差の単位にする(§4.3)。**区画ごとに価格が違う** |
| **時間** | 職人が買い出しに行くのは1日1回・決まった時刻だけ。入力が切れても即座には補充しない | 「今すぐ要る」に応えて割増で売る | 生産システムは入力不足で**停止する**。停止は Need を生む |
| **情報** | NPC は自分が観測した価格しか知らない([GDD01 §4.1](01-trust-and-conversation.md)) | 相場を知っていること自体が資本 | 既に GDD01 が設計済み。**02 はそれを経済的に意味あるものにする側** |

### 4.1 摩擦を消してはならない

**この3つを効率化する施策は、すべて本作の価値を削る。** 具体的には以下を作らない:

- NPC 同士の自動的な物流(きこりが木材加工へ木材を届ける)
- 全 NPC が共有する市場価格表(中央の板)
- 入力切れを即座に解消する自動発注

**逆に言えば、経済の「効率が悪い」ことは不具合ではなく仕様である。** レビューや調整でここを「改善」しないよう、本節を根拠として参照すること。

### 4.2 ただし、詰みは作らない

摩擦が強すぎて都市が餓死しては困る。**下限として、運送労働者(§3.2)と行商人(§10.3)が最低限の流通を担う。** プレイヤーが何もしなくても都市は回るが、**遅く・高く回る**。プレイヤーはその差分を取る。

**運送労働者は「遅い」ことが仕様である。** 依頼を受けてから運ぶまでに日数がかかり、運賃も高い。速さと安さで勝つのがプレイヤーである。

> **M0 では下限を運送労働者だけが担う**(§2.4)。行商人は入れないため、[GDD06 §3.1](06-trade-and-negotiation.md) の Need(遠方在庫)を履行する主体は運送労働者である。**ヘッドレス実行にプレイヤーは居ないので、ここが唯一の履行経路になる。**

### 4.3 区画と距離(**決定**)

**9区画を 3×3 のグリッドとして扱い、区画間の距離はマンハッタン距離とする。**

```
距離(a, b) = |行(a) − 行(b)| + |列(a) − 列(b)|      ← 0〜4
移動時間   = 距離 × 1区画あたりの移動時間(初期値 1時間) × 2   ← 往復
```

- **区画 Id は行優先で 0〜8。** Id から行・列が定まるので、距離表というデータを持たない
- 距離は**視界半径**にも使う。買い手が見える店の範囲は距離 R 以内([GDD06 §3.1](06-trade-and-negotiation.md)、初期値 R = 1)
- 距離は実質コストに乗る([GDD06 §2](06-trade-and-negotiation.md))。**これが空間の摩擦の唯一の数値表現である**
- 買い手の区画は世帯の区画、店の区画は売り手の工房の区画

> **隣接グラフや 9×9 の距離行列を持たないのは、調整軸を増やさないためである**(方針2)。距離行列なら36個の軸が増え、**区画間の価格差が「機構の帰結」か「距離表の設定」かを切り分けられなくなる** — §12-4 がまさにその価格差を判定に使う以上、これは致命的である。
>
> 城壁・川・門といった不整形をグリッドで表せないのは承知の上である。**M0 の目的は価格機構の検証であって都市の地理ではない。** 複数都市(§14)へ進むときに再訪する。

#### 世帯は区画を移らない(**決定**)

**世帯の区画は初期配置で決まり、以後変わらない。**

- **世帯密度は 1区画あたり1〜2世帯。** 同じ職業が1区画に詰まって競合することがなく、かつ空区画も出ない薄さである
- 世帯の区画Id は不変。`Household` の定数であって状態ではない

> **移住を許すとホテリングの法則で全世帯が中心区画に集まる。** 中心は全区画への距離が最小なので実質コスト([GDD06 §2](06-trade-and-negotiation.md))で有利になり、周辺に留まる動機が無い。**集まった瞬間に §4 の空間の摩擦が消滅し、§12-4「区画間の価格差が消えない」が構造的に不通過になる。**
>
> **決定論の側でも効く。** 区画Id が不変なら「どの世帯がどこに居るか」は状態ではなくなり、移動判定の順序やタイミングが状態ハッシュ([TDD01 §3.8](../04-tdd/01-sim-core-and-m0.md))に乗らない。§12-4 は**価格機構の帰結だけ**を見ることになる。

#### 立地のコントラストは徒弟の移動で表す(**方向の決定**)

**都心と周辺で条件が違うこと自体はリアルであり、消したくない。** 世帯を動かさずにそれを表現する担い手は**徒弟**である。

- 立地の良い工房は徒弟を集め、条件の悪い工房は徒弟を手放す。**動くのは世帯ではなく人手**
- 徒弟が増えれば労働力(§7.1)が増え、生産量で立地の差が現れる
- 機会費用の低い徒弟が居ることは、遠い店が候補に入ることでもある([GDD08 §7.2](08-household-and-decision.md))

> **M0 では入らない。** §7.3 で雇用を実装しないと決めており、徒弟の移動は雇用の一部である。**M0 の初期配置で徒弟数を固定し、立地の差は価格差としてのみ現れる。** ここは v1.0 の方向の宣言であって、W2 の作業ではない。

## 5. 生産

### 5.1 日次の生産

各生産者は日次で、自分のレシピについて:

1. 入力在庫が足りるか判定する
2. 足りれば生産量ぶん消費して出力を在庫に加える
3. 足りなければ**停止**し、不足している入力について Need を生成する(§8.4)

生産量は `min(入力から作れる量, 生産能力)`。生産能力は労働力と設備で決まる(§5.2、§7)。

### 5.2 労働力

**労働は入力の一種として扱う。** レシピの `所要労働` に対して、その工房の労働力(親方 + 職人 + 徒弟)が足りなければ生産量が下がる。

これにより「労働力不足」が [GDD01 §3.2](01-trust-and-conversation.md) の Need 種別として自然に発生する。

### 5.3 設備の摩耗(**決定**)

**摩耗を入れる。ただし確率ではなく決定的に**(生産N回で工具1個を消費)。乱数を増やさないぶん因果が追える。

耐久財の需要が内生的に湧く経路は、経済の自立性にとって重要である。工具を買えない工房は生産能力が落ち、それが Need になる(§8.4)。

> **摩耗する耐久財を工具のみに限っている**のは意図的なスコープ制約である。農具・ツルハシ・厨房設備なども同型に扱えるが、品目と調整軸が増える。将来の拡張候補として §14 に置く。

## 6. 消費と家計

### 6.1 日次消費

| 品目 | 消費者 | 量 | 分類 |
| ---- | ------ | -- | ---- |
| パン | 全 NPC | 家族規模に比例 | **必需** |
| 薪 | 全 NPC | 季節で変動 | **必需**(冬に急増) |
| 塩 | 全 NPC | 少量・一定 | **必需**(輸入依存) |
| ビール | 全 NPC | 階層で変動 | 嗜好 |
| ワイン・香辛料 | 上位階層のみ | 少量 | **奢侈** |
| 衣服・靴 | 全 NPC | 摩耗したとき | 耐久 |

**必需・嗜好・奢侈・耐久の4分類が価格形成に効く**(§8.2)。必需は価格が上がっても買う(需要が硬直的)、嗜好・奢侈は諦める(弾力的)。

> **塩を必需にしたことの帰結**: 都市内で作れない必需品ができる。**港が止まると全 NPC が困る。** 貿易の重要性が体感される設計である。

### 6.2 家計(**世帯単位**)

**家計の主体は個人ではなく世帯である**([GDD08 §2](08-household-and-decision.md))。

```
日次:   流動資金 += 販売収入 − 仕入支出 − 生活費
週次:   流動資金 −= 給金(雇用している場合)
季節次: 流動資金 −= 税
```

- **流動資金と帳簿(取引履歴)は世帯が持つ。** 帳簿は**資金の増減と一致するため**、個人別に持つと突合できない
- 世帯 = 親方 + 主婦 + 子ども + 徒弟。**職人は自分の家計を持つので別世帯**([GDD08 §2.1](08-household-and-decision.md))
- **すべて int**。税率・給金は千分率(‰)の整数([ADR-0002](../adr/0002-time-model-and-determinism.md))
- 税は領主・教会へ。**ただし都市外へ消えるのではなく還流させる**(§10.6)

> **W1 の `World` は流動資金を `NpcState` に持たせている**([TDD01 §3.2](../04-tdd/01-sim-core-and-m0.md))。**世帯単位へ移すのは W2 の作業であり、決定論ハッシュ([§3.8](../04-tdd/01-sim-core-and-m0.md))の区分が変わる。** 区分の設計は [TDD01 §3.2「経済主体は世帯である」](../04-tdd/01-sim-core-and-m0.md)が持つ。

#### 6.2.1 課税と破産の主体(**決定**)

**どちらも世帯である。** 資金が世帯にしか無い以上、払えるのも払えなくなるのも世帯である。

| | 単位 | 標準 |
| -- | ---- | ---- |
| 税(季節次) | 世帯 | **`ApplyPermille(流動資金, 税率‰)`** = 切り上げ付きの 流動資金 × 税率‰ ÷ 1000 |
| 破産(§6.3) | 世帯 | 流動資金が尽き、必需品が買えない |

**流動資金への比例課税を採るのは、税が自己制限的だからである。** 資金ゼロの世帯は 0 を払うので、**税が直接破産を誘発しない**。切り上げ規約([GDD01 §2.3](01-trust-and-conversation.md))により資金が 1 以上の世帯は最低 1 を払うが、**自己制限性は「資金ゼロなら 0」で保たれる**。§10.7 の自動調節と §12-6 の判定「**税率を上げても貨幣量が枯渇に向かわない**」は、この自己制限性を前提にしている。

> **世帯あたり定額の戸別賦課にすると §12-6 が成立しない。** 定額は資金の無い世帯を機械的に破産へ押し出すため、判定が「枯渇しない」ではなく「税率次第で枯渇する」に変わる。**税率を調整不能な地雷にしないという §12-6 の目的そのものを失う。**
>
> **残る歪みは許容する。** 比例課税は課税時点の現金保有量に依存するので、投げ売り(§6.3②)の直後に換金した世帯が重く当たる。中世都市として不自然ではなく、M0 では調整軸を増やさないことを優先する。

**破産しても世帯は解体しない。** §6.3 の①〜④はすべて世帯の行動であり、④の職業付け替えでも構成員はそのまま残る。

> **②の投げ売りの対象は工房在庫である。** 在庫は世帯在庫(消費財)と工房在庫(生産の入出力)の2本に分かれる([GDD08 §2.2](08-household-and-decision.md) / [TDD01 §3.2](../04-tdd/01-sim-core-and-m0.md))。**世帯在庫の食料と薪まで投げ売ると翌日に困窮が深まるだけ**であり、換金の対象にならない。

### 6.3 困窮と破産(**決定**)

流動資金が尽き、必需品が買えなくなったとき、**段階的に対応する**:

| 段階 | 行動 | 接続先 |
| ---- | ---- | ------ |
| ① | 奢侈品・嗜好品を諦める | §6.1 の分類 |
| ② | **在庫を投げ売る**(原価下限を割ってでも) | §8.1 の例外 |
| ③ | **掛けで買う**(信用が要る) | [GDD01](01-trust-and-conversation.md) 効果2「与信」/ 質屋・両替商(§3.2) |
| ④ | 廃業して他所に雇われる | §7(雇用) |

**破産は退場ではなく職業の変更である。** これは中世都市のリアリティであると同時に、**プレイヤーが救う余地を残す**設計である。③で信用システムが経済的な意味を持ち、④で雇用と接続する。

> ④はプレイヤーの店の従業員供給源にもなる(分冊04)。

#### M0 での④の扱い(**決定**)

**M0 では雇用を実装しない**(§7.3)ため、④の「他所に雇われる」接続先が存在しない。**M0 に限り、破産した世帯の職業を、担い手の最も薄い職業へ付け替える。**

```
その職業の担い手が自世帯だけなら → 付け替えない(職業を維持する)
そうでなければ:
    付け替え先 = argmin( その職業の担い手世帯数 )
                 over 同じ側の職業(都市世帯なら都市8、農村世帯なら農村4)から自職業を除いたもの
                 同値のときは職業 Id 昇順
```

**価格や原価から決めない。** 一見「最も儲かっている職業へ」が自然だが、M0 のサブセットでは成立しない — 農村4職業は入力を持たないので**原価が 0** になり、酒場の主人は**出力品目を持たない**(即時消費)。整数除算では比が潰れて `argmax` が事実上「職業 Id 昇順」に退化する。**そして最も重く、「市中価格の中央値」を引くには市場全体の完全情報が要り、§4.1 の情報の摩擦と §8.2.7(自分の `PriceObservation` しか使えない)に正面から反する。**

**担い手世帯数は `World` から直接数えられ、除算も価格観測も要らない。** これは NPC の意思決定ではなく、**空いた親方の座を割り当てる世界側の処理**である(史実ではギルドが親方昇格を統制していた → 分冊07)。

> **「最後の1世帯は付け替えない」が供給の消滅を構造的に防ぐ。** §2.4 は「1品目につき売り手2世帯」を M0 の成立条件としているが、**付け替えを無条件にすると両方の木材加工世帯が離脱して薪の売り手が消え、パンとビールが同時に止まる** — §2.4 が「最初から存在しない」と警告した状態を、破産処理が実行時に作ってしまう。担い手の薄い職業へ流す `argmin` と併せて、職業分布は均等へ戻る方向に働く。

- **世帯は解体しない。** 世帯主の職業が変わるだけで、工房の在庫は②の投げ売りで既に現金化されている
- **都市世帯は都市職業の中でだけ移る。** 農村世帯は区画を持たない(§2.4)ので、都市職業に就くと居場所が定義できない
- **流動資金は補填しない。** 貨幣量を外から増やすと §10.7 の自動調節と §12-6 の判定が濁る
- 同値の処理を Id 昇順で固定するのは列挙順規約([ADR-0002](../adr/0002-time-model-and-determinism.md))による

> **これは M0 限定の簡易版であり、④の構造「破産は退場ではなく職業の変更である」を雇用なしで満たすためのものである。** v1.0 では §7 の雇用市場を通り、「解雇された職人が供給プールに戻って別の親方に雇われる」形になる。**構造(職業が変わる)は同じで、経路だけが違う。**
>
> 職業分布が動くため §12-3(生産チェーンが止まらないか)の観測が豊かになる。**逆に付け替えが頻発するなら、価格機構が働いていない兆候である。**

## 7. 雇用

### 7.1 構造

**親方 / 職人 / 徒弟** の3階層([idea/008](../idea/008-NPCと職業.md) §1.4.1 のギルド構造)。

- 工房を持てるのは親方のみ
- 職人は週次で給金を受け取る。徒弟は食住のみ(給金なし)
- 労働力: 親方1.0 / 職人0.8 / 徒弟0.3(初期値)

### 7.2 雇用の増減

- 生産が需要に追いつかない状態が続くと、親方は職人か徒弟を雇おうとする(Need「労働力不足」)
- 資金が続かなければ解雇する。解雇された職人は §6.3 ④の供給プールに戻る

### 7.3 スコープ(**決定**)

**v1.0 の目標仕様としては本節を採るが、M0 では雇用を実装しない。** **固定するのは労働力である** — 雇用の増減が無いので世帯の構成員と階層が変わらず、労働力の合計が動かない。M0 で見たいのは価格機構であり、雇用は変数を増やすだけである。

> **設備は固定しない。** 工具は摩耗し(§5.3)、設備係数が動くので生産量も動く([GDD08 §4.2](08-household-and-decision.md))。**工具は §2.4 のサブセットで唯一の耐久財**であり、耐久の予算(§8.2.1 の `min`)と「工具切れ」の Need(§8.4)を検証する唯一の経路なので、ここを固定すると M0 の検証項目が1本落ちる。

**ただしデータモデルには雇用関係を最初から持たせる。** 後付けは `World` の区分追加になり、決定論ハッシュの更新([TDD01 §3.8](../04-tdd/01-sim-core-and-m0.md))が要るため。

## 8. 価格形成

### 8.1 提示価格(**決定**)

売り手が「いくらで並べるか」。妥結価格は分冊06。

**在庫圧力 + 原価下限**を v1.0 の基準線とする:

```
提示価格 = max( 原価 × (1 + 最低利幅‰) , 在庫圧力調整後の価格 )
```

- **原価は移動平均**とする。直近仕入値だと一度の高値づかみで提示価格が跳ねる

#### 8.1.1 更新式(**決定**)

```
出荷目標在庫 = 1日あたりの産出量(仕入れて売る職業は仕入量)× 回転日数 N

出荷目標在庫 = 0 のとき:
    提示価格 = ApplyPermille(原価, 1000 + 最低利幅‰)      ← 在庫比を計算しない

それ以外:
    在庫比‰   = CeilDiv( 1000 × 販売在庫 , 出荷目標在庫 )
価格係数‰ = clamp( 1500 − CeilDiv(在庫比‰, 2) , 500 , 1500 )
提示価格  = max( ApplyPermille(原価, 1000 + 最低利幅‰) ,
                 ApplyPermille(相場基準, 価格係数‰) )
```

| 販売在庫 | 価格係数‰ | 意味 |
| -------- | --------- | ---- |
| 0 | 1500 | 品薄。相場の1.5倍 |
| 出荷目標在庫 | 1000 | **相場どおり** |
| 出荷目標在庫 × 2 以上 | 500 | 溢れている。相場の半値 |

**売り手が使う `相場基準` は自分の `PriceObservation` の中央値そのものである。** §8.2.1 が買い手側で掛ける**許容乖離‰ は掛けない** — あれは買い手が「いくらまで出すか」の緩みであって、売り手の値付けには関係しない。

**`販売在庫` は工房在庫のうち売りに出している分である。** 生産職では生産の出力、貿易商では港で仕入れた商品、酒場では即時消費なので在庫を持たない(値付けの対象にならない)。**在庫を持たない職業はそもそも `Market` に売り注文を出さない。**

**出荷目標在庫 = 0(在庫を持たない職業、または産出がゼロの日)では在庫比を計算しない。** `CeilDiv` は零除算で例外を投げる([`IntegerMath`](../../src/Visionary.Sim/Numerics/IntegerMath.cs))。

**係数の 500〜1500 は固定であり軸にならない。** ただし**回転日数 N は買い手側の目標在庫とは別の調整軸である** — 1品目あたり売り手側と買い手側で2軸になる。§8.2.2 の「調整軸は品目ごとの目標在庫だけで済む」は**買い手側の内部での話**であって、両側を合わせた数ではない。

> **買い手側と「同じ関数」ではない。概念の鏡像である。** 買い手の在庫圧力は目標在庫以下で 1000‰ に張り付く(§8.2.2 が「基礎値の意味を壊さないため」と明記)。**売り手側で同じ形にすると、在庫ゼロでも相場どおりの値付けになり、品薄が価格に出ない。** 売り手側は目標在庫を中心に対称な直線にする。

**状態を持たないことが要点である。** 前日の提示価格を参照せず、毎日「工房在庫・相場基準・原価」から作り直す。**したがって初日の初期提示価格を決める必要がない** — 初期配置で与えるのは初期在庫の**取得原価**だけでよい。

**相場基準が無いとき**(初日、および観測が失効した品目)**は原価下限がそのまま提示価格になる**(§8.2.7 の売り手側)。`max` の第2項が消えるだけで、式は分岐しない。

> **ステップ更新(前日価格を ±X‰ 動かす)を採らなかった理由。** 前日価格という状態を持つと初日の初期値を別に決める必要があり、ステップ幅という調整軸も増える。**そして §8.2.3 が警告する「売り手と買い手の在庫圧力が同位相で動く」振動を、慣性が増幅する。**

**原価下限には例外がある。** §6.3 ② の投げ売りでは**原価を下回る**。困窮した売り手は換金を優先するためである。

> **これは仕様であって不具合ではない。** M0 検証項目(§12-5)は「原価を下回る提示価格が**継続**しない」を見るのであって、「一度も起きない」を見るのではない。**投げ売りはプレイヤーにとって好機であり、経済の緊張の表現でもある。**

**相場観の参照(自分の `PriceObservation` を見て他店に追随する)は、§8.1.1 で既定経路になった。** 差し替え点ではない — `max` の第2項 `ApplyPermille(相場基準, 価格係数‰)` がそれである。情報の摩擦が価格に直結する反面、追随が振動を生みうるため、**M0 の安定性判定(§12-1)を通せるかは未知であり、そこが最初に崩れる候補である。**

### 8.2 予算(**決定**)

**予算は需要だけで決まる。** 店ごとの事情(距離・信用・提示価格)は入れない — それは**実質コスト**であり、分冊06 が持つ(§8.2.5)。

```
予算 = 用途別の基礎値 × 買い手の在庫圧力‰ ÷ 1000
```

**予算は1つ。実質コストは店ごとに異なる。** 買うのは「実質コストが最も安い店」で、かつ「その実質コストが予算以下」のときである。

#### 8.2.1 用途別の基礎値と目標在庫

| 用途 | 基礎値 | 目標在庫(初期値) |
| ---- | ------ | ------------------ |
| **生産の入力** | **派生需要**(出力の見込み売値から逆算) | 1日分の使用量 × 仕入れ間隔(日) |
| **必需の消費** | **相場基準**(自分の `PriceObservation` の中央値 × 許容乖離‰) | 薪: 1週間分(1日消費量は季節変動、§9)<br>パン: 3日分<br>塩: 2週間分 |
| **嗜好・奢侈の消費** | **予算比率**(流動資金 × 比率‰。階層で変える) | 肉: 1日分<br>ビール: 1日分<br>ワイン: 1週間分<br>香辛料: 1週間分 |
| **耐久の消費** | **min(相場基準, 予算比率)** | 靴 / 衣服 / 工具: **0.5個分の耐久値 × 階層** |

**基礎値の意味**:

- **生産の入力**: 利益が出る値段でしか買わない
- **必需**: 余程の急騰でない限り相場に追随し、目標在庫まで買う。安ければさらに買い溜める
- **嗜好・奢侈**: 肉とビールは嗜好(酒場でも提供される)。ワインと香辛料は奢侈
- **耐久**: **`min` を取ることが要点である。** 相場を知っていても資金がなければ買えず、資金があっても相場より高くは買わない

> **耐久財に予算比率を入れたのは、徒弟が自分の財布を持たないため**([GDD08 §2.1](08-household-and-decision.md))。世帯の流動資金の一定比率(初期値10‰)までなら買える、とすることで**徒弟も靴を買える**。同じ条件を全階層に適用する。

**耐久財の在庫は「個数」ではなく「耐久値」である。** 時間経過と生産で摩耗し([§5.3](#53-設備の摩耗決定))、在庫が減る。目標在庫が `0.5個分 × 階層` なので、**最下層の NPC は製品寿命の半分で目標在庫に達し、在庫圧力が 1000‰ になる**。階層が高いほど複数個を持とうとする。

##### 目標在庫の「N日分」は先読みで数える(**決定**)

**目標在庫は「N日 × 現在の1日消費量」ではなく、「今後 N 日に消費する予定の量の合計」とする。**

```
目標在庫 = Σ( 消費量[d] )      d = 今日 … 今日 + N − 1
```

**`消費量[d]` は日ごとに季節係数を適用して切り上げた整数であり、それを足す。** 合計してから切り上げるのではない。薪のように季節係数が掛かる品目では、丸め順で結果がずれる(N が2週間なら最大で N 単位)。

- **季節の境をまたぐと自然に前倒しで積み上がる。** 冬が近づくにつれ薪の目標在庫が滑らかに上がり、在庫圧力が上がり、予算が増える — **冬支度が規則ではなく帰結として現れる**
- 季節変動しない品目(パン・塩)では `N × 1日消費量` と一致する。**式が分岐しない**
- これが §14 の「季節変動する薪の1日消費量の定義が要る」への回答である。**定義すべきは1日消費量ではなく、目標在庫の数え方だった**

> **§8.2.2 が現在庫の側で既に採っている「買い物に行く時点で予想される在庫」と、同じ発想を比較の反対側(目標)に当てたものである。** 両側が先読みになっても**調整軸は増えない** — 変わるのは N の意味だけで、N は元から品目ごとの調整軸である。
>
> **当日の季節の消費量をそのまま使うと、冬に入った瞬間に全世帯の目標在庫が同時に跳ねる。** §8.2.3 が警告する「売り手と買い手の在庫圧力が同位相で動く」振動を、季節が毎年4回叩き込むことになる。

#### 8.2.2 買い手の在庫圧力(**式を確定**)

**上限倍率は2倍固定とする。**

```
在庫 ≤ 目標在庫:
    在庫圧力‰ = 1000

目標在庫 < 在庫 ≤ 目標在庫 × 2:
    在庫圧力‰ = CeilDiv( 1000 × (2 × 目標在庫 − 在庫) , 目標在庫 )

在庫 > 目標在庫 × 2:
    在庫圧力‰ = 0
```

変動幅は **0〜1000‰**。目標在庫までは 1000‰ で据え置き、そこから線形に 0 まで落ちる。

> **上限を 1000‰ に固定し、目標在庫まで据え置くことが重要である。** 基礎値を「安定して機能する信頼できる値」に保つため。
>
> **1000‰ を超えられるようにすると**、原材料では派生需要(利益が出る上限)を超えて買うことになり、**赤字の原価で仕入れが発生する**。奢侈品でも予算比率が後から変動してしまう。**基礎値の意味が壊れる。**

**これは §8.1 の売り手側在庫圧力の鏡像である。** 売り手は在庫が多ければ提示価格を下げ、買い手は在庫が多ければ予算を下げる。**両側で1つの概念**であり、調整軸は品目ごとの目標在庫だけで済む(上限倍率は固定なので軸にならない)。

##### 買い物に行く時点の予想在庫を使う

**在庫圧力の計算には、現時点の在庫ではなく「買い物に行く時点で予想される在庫」を使う。**

```
予想在庫 = 現在庫 − (買い物までに予定されている消費・生産投入)
```

> **これが時間の摩擦(§4)の正しい表現である。** 買い物に行くまでに食事や生産を予定しているなら、そのぶん予想在庫が減り、在庫圧力が上がり、予算が増える — **「在庫を切らす前に店へ行けない」状況が、緊急性として自然に価格へ現れる。**
>
> **待ち時間を費用として数えてはならない。** 待っている間は他の仕事ができるので、実際に時間が奪われるわけではない。摩擦は**偽の費用**ではなく**本物の緊急性**として表す。

#### 8.2.3 複数単位を買う場合

**判定基準はその商品を買う**前**の在庫量である。** 2単位目以降は、直前までの購入分を加えた在庫量で在庫圧力を算出する。

**ただし式は線形なので、反復せずに一度で購入量を解ける。** 実装はこちらを推奨する:

```
実質コスト > 基礎値            → 購入量 0
実質コスト ≤ 基礎値:
    到達在庫 = 2 × 目標在庫 − CeilDiv( 目標在庫 × 実質コスト , 基礎値 )
    購入量   = max( 0, 到達在庫 − 予想在庫 )
```

検算:

| 実質コスト | 到達在庫 | 意味 |
| ---------- | -------- | ---- |
| = 基礎値 | 目標在庫 | 相場どおりなら目標在庫まで買う |
| = 基礎値 × 1/2 | 目標在庫 × 1.5 | **安ければ買い溜める** |
| > 基礎値 | — | 買わない |

##### 需要曲線は創発する。書かない

各買い手の予算が在庫で下がるなら、**集計レベルの需要曲線は自動的に右下がりになる** — 価格が下がれば「買う人」も「1人あたりの量」も増えるためである。

**したがって個体に需要関数を持たせない。** 個体の意思決定は上の線形解だけで、方針4(満足化)と方針2(観測可能性)を保てる。**需要曲線を仮定するのではなく創発させるのが、エージェントベースの正しい使い方である。**

##### 得られるものと代償

| 利点 | 内容 |
| ---- | ---- |
| **買い溜めと買い控え** | **商人ゲームの中核行動が NPC 側にも生まれる。** プレイヤーの投機(§9)に市場が応答する |
| 概念が増えない | 売り手側(§8.1)と同じ機構 |
| **価格の安定** | 必需品の需要が完全非弾力だと供給不足時に価格が青天井になる。**在庫のある者が買い控えることで需要が自動的に減る** |
| 貯蔵性が意味を持つ | 貯まる品目(薪・塩)と貯まらない品目(パン・肉)の差が経済に効く |
| 会話の素材 | 「うちはまだ薪があるからね」。**買わない理由をプレイヤーに説明できる** |

| 代償 | 対応 |
| ---- | ---- |
| 溜め込みの縮退 | **上限倍率2倍で在庫圧力が 0 になる。** 腐敗を明示的に入れずに済む |
| 在庫を置く場所が要る | 世帯在庫と工房在庫の2本([GDD08 §2.2](08-household-and-decision.md) / [TDD01 §3.2](../04-tdd/01-sim-core-and-m0.md))。**W1 の `NpcState.Inventory` は W2 で廃止**し、`HouseholdState` へ移す |
| **振動の増幅** | 売り手と買い手の在庫圧力が同位相で動くと「安い→買い溜め→在庫増→買い控え→売れない→さらに安く」が起きうる。**§12-1 の安定性検証で見る** |

**腐敗は M0 では入れない**(§14)。

#### 8.2.4 不当価格はどこで成立するか

予算を相場基準にすると、NPC は相場から離れた値を「買わない」だけになる。では [GDD01 §4.5](01-trust-and-conversation.md) の不当価格はどこで起きるか。**2つの経路が残る**:

1. **相場観が古い、または無い**(情報の摩擦、§4)。新しく来た NPC、久しく買っていない品目では `PriceObservation` が薄い。そのとき高値を掴み、**後から相場を観測して「あれは不当だった」と気づく** — §4.5 の「取引tick近傍の観測入手による気づき」そのものである
2. **在庫が尽きかけて予算が最大(1000‰)になっている**。これは**正当な緊急性**であり、プレイヤーが「足元を見る」余地でもある

**1が誤爆の源であり、2は仕様である。** [GDD01 §6](01-trust-and-conversation.md) 検証項目5 の誤爆率は、**2を1と誤判定する率**として測る。

> **不当価格が「困窮という異常時」ではなく「情報の非対称という平常時の構造」から生まれることが重要である。** 本作の USP「情報を足で稼ぐ」に直結する。

#### 8.2.5 予算と実質コストの役割分担(**重要**)

**便益と費用を分ける。**

| | 予算(払える上限) | 実質コスト |
| -- | ------------------ | ---------- |
| **何を表すか** | **便益**。その品をどれだけ欲しいか | **費用**。手に入れるのに実際いくらかかるか |
| **決まり方** | 需要のみ(基礎値 × 在庫圧力) | 提示価格 + 信用による割引 + 移動の機会費用 |
| **いくつあるか** | **1つ** | **店ごとに1つずつ** |
| **どこが持つか** | **本書 §8.2** | **分冊06** |

**購入条件**:

```
信用を考慮した実質コストが他のどの店よりも安く、
かつ その実額が予算以下 であるとき、その店で買う
```

> **v0.3 は機会費用による上乗せを予算の側に入れていた。誤りである。** 実質コストにも機会費用が入るため**二重計上**になり、かつ「店ごとに異なるもの」を「1つしかない予算」に混ぜていた。**便益と費用の分離が正しい**([process/03](../process/03-corrections.md) 規則6 — 却下理由ではなく設計そのものの訂正)。
>
> **時間の摩擦は §8.2.2 の予想在庫へ、空間の摩擦は分冊06 の移動の機会費用へ**、それぞれ1か所だけに置く。

#### 8.2.6 M0 でどこまで実装するか(**決定**)

**機会費用は職業 × 階層の固定値とする**(算出方式は [GDD08 §5](08-household-and-decision.md)、M0 スコープと階層係数は [GDD08 §9](08-household-and-decision.md))。

構造(予算と実質コストの分離、在庫圧力、線形解)は M0 から入れる。**構造を先に固定し、値の由来を後から差し替える**のは §9(季節係数)と同じやり方である。

#### 8.2.7 相場観が無いときの予算(**決定**)

**相場基準は自分の `PriceObservation` の中央値から出る**(§8.2.1)。観測が1件も無ければ計算できない。**これは初日だけの問題ではない** — 保持期間を過ぎた品目、久しく買っていない品目でも起きる(§8.2.4)。したがって初期観測を配るのではなく、**規則として定義する**。

```
相場基準が計算できないとき:
    基礎値 = ApplyPermille( 流動資金 , 用途別の予算比率‰ )
```

| 用途 | 観測ゼロ時の基礎値 |
| ---- | ------------------ |
| 生産の入力 | **影響を受けない。** 派生需要は自分の出力の提示価格から逆算するので、他人の観測を要さない |
| **売り手の提示価格**(§8.1.1) | **原価下限がそのまま提示価格になる。** `max` の第2項が消えるだけで式は分岐しない |
| 必需の消費 | **予算比率へフォールバックする**(初期値 50‰) |
| 嗜好・奢侈の消費 | **影響を受けない。** 元から予算比率 |
| 耐久の消費 | `min(相場基準, 予算比率)` の相場基準側が落ち、**予算比率のみになる**(既存の 10‰) |

**新しい機構を持ち込んでいない。** 既に §8.2.1 の表にある「予算比率」へ倒すだけであり、増える調整軸は必需品の比率‰ の1つである。

> **この規則は §8.2.4 の不当価格の発生源そのものである。** 相場を知らない NPC は「流動資金の範囲でなら払ってしまう」ので、**高値を掴み、後から相場を観測して気づく**。フォールバックを穴埋めとしてではなく、**情報の摩擦が価格に現れる正規の経路**として置いている。
>
> **初期観測を配らないのはこのためである。** 配ると初日だけ穴が塞がり、保持期間で観測が失効した NPC が後から同じ穴に落ちる。**規則にすれば初日を特別扱いせずに済む。**

**買い手がそもそも店を1つも知らない場合は、予算ではなく Need になる** → [GDD06 §3.1](06-trade-and-negotiation.md)。

### 8.3 需要の表現

**需要曲線は作らない。** NPC は「必要量」と「払える上限」(§8.2)を持つだけで、価格に応じて量を連続的に変えることはしない(方針4)。

- 必需品: 必要量は固定。払える上限まで買う。買えなければ §6.3 へ
- 嗜好・奢侈品: 払える上限を超えたら**買わない**(量は0か固定量)
- 耐久財: 摩耗したときだけ需要が立つ

これで十分に価格は動く(在庫が捌けなければ売り手が下げ、買い手は在庫が満ちれば買い控える)。**個体に需要関数を導入すると、価格の因果が式の中に隠れて追えなくなる**(方針2)。

**集計レベルの需要曲線は §8.2.4 の在庫圧力から創発する。書かない。**

### 8.4 Need への接続

不足は [GDD01 §3.2](01-trust-and-conversation.md) の Need として表面化する。**Need が経済とコアループの結節点である。**

| 発生源 | Need 種別 | 理由コード |
| ------ | --------- | ---------- |
| 生産の入力切れ(§5.1) | 在庫不足 | 生産停止 |
| 必需品が買えない(§6.3) | 金銭不足 | 困窮 |
| 労働力不足(§7.2) | 労働力不足 | 増産できない |
| 設備の摩耗(§5.3) | 在庫不足 | 工具切れ |
| 区画をまたぐ運搬が要る(§4) | 在庫不足 | 遠方在庫 |

> **これが [TDD01 §3.6](../04-tdd/01-sim-core-and-m0.md) の仮決め「`Need.TypeCode` / `ReasonCode` を enum にする」への答えである。** 上表の左2列が種別、右列が理由コードの初期集合になる(§13)。

## 9. 季節との接続

[GDD03 §2](03-seasons-and-city.md)(季節が経済に効く形)は未着手。**本書が先に値を決めると二重管理になる。**

| 何を | どちらが持つか |
| ---- | -------------- |
| 季節係数の**構造**(どのレシピ・どの消費が季節に依存するか) | **本書** |

## 10. 貨幣と都市の外(**改稿**)

### 10.1 なぜここが最重要か

[GDD01 §6](01-trust-and-conversation.md) の M0 検証項目2 は「長期実行して価格が発散・硬直しないか」である。**この判定を通せるかは、貨幣のソースとシンクの設計でほぼ決まる。**

- **完全に閉じた系**(貨幣総量が一定): 価格の絶対水準が動かない
- **シンクだけがある系**(税が都市外へ消えるのみ): 貨幣が枯渇し、全 NPC が困窮する

**税を入れた時点で、対応するソースが必須になる。**

### 10.2 決定:外部市場(A)と財政還流(B)を併用する

- **A(外部市場)** — 都市外との交易が貨幣のソース兼シンクになり、同時に**価格の上下限**を与える
- **B(財政還流)** — 税収を都市内に還流させ、**シンクそのものを小さくする**

**併用する。** A だけでは税が一方的な流出になり、B だけでは価格の上下限が無くなる。

### 10.3 A-1:行商人(陸路)

- **幅広い品目を少量**扱う
- 各区画を巡回し、都市内の提示価格で売買する
- **スプレッドが大きい**(買値と売値の差)。行商人と取引すると必ず損をする
- **§4.2 の「詰みは作らない」の実装**。プレイヤーが何もしなくても最低限は流通するが、遅く・高い

### 10.4 A-2:港(海路)

- **限られた品目を大量**に扱う: 穀物・木材・鉄鉱石・塩・ワイン・香辛料
- **スプレッドが小さい**。大口取引の効率を表現する
- **貿易専用品目(塩・ワイン・香辛料)の唯一の供給源**
- **都市内の貿易商(§3.2)が取引した分は、スプレッドが都市内の利益になる**

> **最後の点が重要である。** 港のスプレッドは、貿易商が介在すれば都市内に残り、介在しなければ外部へ出る。**貿易商を育てること自体が都市の富を増やす**という構造になり、プレイヤーが貿易商になる動機にもなる。

**外部価格は季節でゆっくり動く。急変させない**(プレイヤーが読めなくなる)。品目ごとに帯の幅が違う — 鉄鉱石は外部依存が強く帯が狭い、パンは都市内財なので港では扱わない。

### 10.5 農民 NPC は「内部 NPC」である(**重要な区別**)

[idea/008](../idea/008-NPCと職業.md) §1.5 の農村職業(§3.3)は、**行商人とはまったくの別物である。** 混同すると設計が壊れる。

| | 行商人・港 | 農民 NPC |
| -- | ---------- | -------- |
| 価格 | **外部市場の固定価格帯** | **都市内の提示価格** |
| 頻度 | 常時(行商)/ 随時(港) | **季節に一度** |
| 性格 | 都市の外の経済 | **都市経済の一部** |

**農民 NPC の1回の来訪サイクル**:

1. 生産物(穀物・木材・**木炭**・鉄鉱石・羊毛)を都市に持ち込み、**都市内の提示価格で換金する**
2. **納税する**
3. 残った資金で都市の物資(衣服・靴・工具・塩)を購入し、消費する

**M0 では §2.4 のサブセットに従い、持ち込むのは穀物・木材・木炭・鉄鉱石、購入するのは工具・塩・パン・ビールである**(羊毛・衣服・靴はサブセット外)。**来訪先は中心区画(Id 4)に固定する**(§2.4)。

**この構造が2つの役割を果たす**:

- **1次産品の供給源。** 都市は1次品(肉・皮を除く)を生産しない(§3.3)
- **貨幣シンクの相殺。** 農民の生産は**ゼロから資源を生む**。それが都市内価格で換金され、納税で吸われ、残りが都市の最終財の需要になる。**税で消えた貨幣が、農村の生産を通じて都市に戻る**

> **なぜ「内部」と呼ぶか。** 農民が外部市場価格ではなく都市内価格で取引するため、**都市の価格変動が農民の購買力に直接効く**。都市の物価が上がれば農民は買い控え、下がれば買う。閉じたフィードバックの内側にいる。

### 10.6 B:財政還流

**税収はできるだけ都市内に還流させ、シンクを小さく保つ。**

**財政政策として、好況時に貯め、不況時に支出を拡大する。** これにより景気変動が緩和される。

主要な支出先:

| 支出 | 需要が向かう先 |
| ---- | -------------- |
| **建設事業** | 大工の賃金 + 資材(木材・薪) |
| **衛兵** | 賃金 + **武器・甲冑**(M0 では賃金と生活費のみ、下記) |
| 領主・聖職者自身の消費 | 奢侈品(ワイン・香辛料)、衣服 |

> **これが §2.2 で武器・甲冑を加えた理由である。** 市民は武器を買わない。**領主が衛兵に装備させることが唯一の需要源**であり、武器職人の存在は財政支出に依存する。**財政が縮むと武器職人が困窮する** — 経済の連関が体感される設計である。
>
> 建設事業も同様に、大工と木材加工に需要を作る。**不況時の支出拡大が、最も困窮しやすい職業を支える**構造になっている。

#### M0 での支出先(**決定**)

**§2.4 のサブセットには武器・甲冑・衣服・香辛料が無い。** 支出先を差し替えないと税収の行き場が減り、**§12-6 の自動調節の検証が痩せる**:

| 支出 | M0 での需要先 |
| ---- | ------------- |
| 建設事業 | **資材(木材・薪)のみ。** 大工を職業として置かない(§2.4) |
| 衛兵 | **賃金 + 生活費(パン・ビール・塩)。** 装備需要は無い |
| 領主・聖職者自身の消費 | **ワイン**(奢侈) |

**還流の総額は変えない。** 変えるのは向かう先だけであり、§10.7 の負のフィードバックは同じに働く。

### 10.7 自動調節メカニズム

A と B を併用すると、以下の負のフィードバックが働く:

```
税による通貨量の減少
  → 購買力の低下
  → 物価の下落
  → 輸出競争力の向上(都市内価格が外部価格帯の下限に近づく)
  → 輸出の促進
  → 貿易黒字
  → 通貨量の回復
```

**これは正貨流出入メカニズム(price-specie-flow)そのものである。** 歴史的にも実在した調節機構であり、**外部価格帯という「神の値」を、経済的に正当な錨として使える**ことを意味する。

さらに A は**分業の利益**をもたらす:

- 余剰生産能力がある品目 → **輸出で稼ぐ**
- 不足する品目 → **輸入でコストを抑える**

**その結果、都市内の職業構成のばらつきが「個性」として残せる。** 全職業が均等に揃っていなくても、貿易が凸凹を埋める。これは都市ごとの性格づけ(将来の複数都市)にも繋がる。

## 11. NPC の一生(**決定**)

### 11.1 M0 では NPC は不死とする

**世代交代は v1.0 の課題とし、M0 では実装しない。**

**根拠となる整理**: [GDD01 §6](01-trust-and-conversation.md) 検証項目2 の 36,000日は、**300年の物語ではなく価格機構の耐久試験である。** 混同すると人口動態が M0 のスコープに引きずり込まれる。耐久試験に人口動態は要らない。

**検証地平は 36,000日のまま据え置く**([TDD01 §5.4](../04-tdd/01-sim-core-and-m0.md) の判定基準を変更しない)。

> **短縮は残された調整弁である。** 発散・硬直が起きるなら数十年で兆候が出るはずなので、原理的には 3,600日(30年)でも検証は成立する。**W2 の調整サイクルが実測で遅すぎた場合に限り、短縮を再検討する。** 先回りして基準を緩めない。

### 11.2 世代交代を入れる場合の波及(参考)

v1.0 で入れるなら以下が連動する。**M0 では触らない。**

- 信用([GDD01 §2.1](01-trust-and-conversation.md))は死亡でリセットされる。長期の信用関係が失われる痛みがゲームになる
- 相続で資産と工房が引き継がれる。徒弟→職人→親方の昇格が生きる
- 決定論ハッシュ([TDD01 §3.8](../04-tdd/01-sim-core-and-m0.md))の区画が増える

## 12. M0 での検証項目

[GDD01 §6](01-trust-and-conversation.md) と重複しない、**経済側の**検証項目。

| # | 検証内容 | 判定基準 |
| - | -------- | -------- |
| 1 | 価格が安定するか | 信用なし条件で長期実行し、全品目の価格が外部市場の帯(§10.3/§10.4)の内側に収まり続ける |
| 2 | 貨幣が枯渇しないか | 困窮状態(§6.3)の**世帯**が全体の一定割合を超えない(困窮は世帯単位、§6.2.1) |
| 3 | 生産チェーンが止まらないか | 各レシピの生産停止(§5.1)が常態化しない。**一時的な停止は仕様**(§4) |
| 4 | **摩擦が残っているか** | **都市生産品(§2.4 の7品目)の区画間の価格差が消えない。** 消えていれば §4 の摩擦が実装されていない。1次産品は農村世帯が中心区画でのみ売るので対象外(§2.4) |
| 5 | 原価下限が効いているか | 原価を下回る提示価格が**継続**しない(§8.1。投げ売りによる一時的な下回りは正常) |
| 6 | **自動調節が働くか** | 税率を上げても貨幣量が枯渇に向かわず、**貿易収支が黒字方向に振れる**(§10.7) |
| 7 | 貿易依存品が枯れないか | 塩(必需・輸入のみ)が長期に品切れしない(§6.1) |

**#4 が本書固有の判定である。** 価格が安定していても区画差が消えていたら、それは「プレイヤーのいらない経済」であり、**経済として成功でもゲームとして失敗**である。

**#6 は §10.7 の機構が机上の理屈で終わっていないかを見る。** 自動調節を設計に組み込んだ以上、それが実際に働くことを確かめないと、税率が調整不能な地雷になる。
