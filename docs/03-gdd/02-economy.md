## 1. 設計方針

1. **経済は摩擦のためにある。** これが第一原理である。NPC が完璧に動く経済ではプレイヤーの価値がゼロになる。[idea/008](../idea/008-NPCと職業.md) §3.1 の「AI職人は工房から動かない」を**仕様として明文化する**(§3)
2. **観測可能性を最優先する。** The Guild 3 化(観測不能な複雑さ)の回避は企画段階からの制約である。プレイヤーが「なぜこの価格なのか」を追えなくなった時点で、経済の精巧さは価値を失う。**追えなくなる複雑さは、面白さの有無に関わらず入れない**
3. **閉じた経済にしない。** 都市の外を明示的にモデル化する(§9)。閉じた系は貨幣量が固定され、価格の絶対水準が動かせない。外部との接続が、価格の上下限と貨幣の出入りを同時に与える
4. **NPC は満足化する。最適化しない。** 最適化する NPC はプレイヤーの介在余地を消し、かつ挙動が読めなくなる。NPC は「足りなければ買う、余れば下げる」程度の局所規則で動く
5. **数値は初期値。** 構造と依存関係だけを固定する

## 2. 品目とレシピ

### 2.1 深さの方針(**要判断**)

[idea/008](../idea/008-NPCと職業.md) §1.4 は 3〜4段の加工連鎖を挙げている(薪→木炭、木炭+鉄鉱石→鉄、鉄→工具/武器)。一方 [TDD01 §3.6](../04-tdd/01-sim-core-and-m0.md) の M0 仮経済は **5品目・1段**である。

| 案 | 構成 | 利点 | 欠点 |
| -- | ---- | ---- | ---- |
| **A(推奨)** | **3層 × 各5品目 = 15品目、最大2段** | 「原料を買って加工品を売る」が成立する最小構成。連鎖が2段なら価格の因果をプレイヤーが追える | 職人の種類が限られ、都市の賑わいが薄い |
| B | 4層以上、20品目超 | idea/008 の職業一覧に近い。都市が生きて見える | **段が深いほど価格の因果が追えなくなる。** 方針2に正面から反する |
| C | M0 の 5品目1段のまま v1.0 へ | 確実に制御できる | 「加工して売る」商人の面白さが出ない |

**推奨は A。** ただし**深さと品目数は別軸**である点に注意する。品目数が増えても段が浅ければ因果は追える。逆に段が深いと品目数が少なくても追えない。**制約すべきは段のほうである。**

### 2.2 品目表(案)

| 層 | 品目 | 産出 | 備考 |
| -- | ---- | ---- | ---- |
| 1次 | 穀物 | 農民 | 季節性が最も強い(§8) |
| 1次 | 羊毛 | 羊飼い | 季節性あり(春の毛刈り) |
| 1次 | 木材 | きこり | 通年 |
| 1次 | 鉄鉱石 | 鉱夫 | 通年。都市外からの搬入が主 |
| 1次 | 皮 | 肉屋の副産物 | 肉屋の生産に従属 |
| 中間 | 小麦粉 | 水車小屋番(穀物→) | |
| 中間 | 毛糸 | 紡ぎ手(羊毛→) | |
| 中間 | 薪 | 木材加工(木材→) | **燃料。多くの生産の入力になる** |
| 中間 | 木炭 | 木炭職人(薪→) | 2段目。鉄の入力 |
| 中間 | なめし皮 | 皮職人(皮→) | |
| 最終 | パン | パン屋(小麦粉+薪→) | **全 NPC の日次消費財** |
| 最終 | ビール | 醸造(穀物+薪→) | 消費財。嗜好品 |
| 最終 | 衣服 | 仕立て屋(毛糸→) | 耐久財。摩耗で需要 |
| 最終 | 靴 | 靴職人(なめし皮→) | 耐久財 |
| 最終 | 工具 | 鍛冶(木炭+鉄鉱石→) | **生産設備。職人が要る** |

**薪が多くのレシピの入力になっている**のは意図的である。単一の隘路があると、そこの供給不安が都市全体に波及し、プレイヤーの介入余地が生まれる。季節(冬の暖房需要)とも噛み合う。

> **M0 での縮退**: M0 は上表のうち **穀物・小麦粉・パン・羊毛・毛糸** の5品目のみを使う(1〜2段)。TDD01 §3.6 の「品目5種」をこの部分集合として読み替える。M0 で検証したいのは価格機構であって品目の多さではない。

### 2.3 レシピの形

```
レシピ = { 出力品目, 出力数量, 入力[(品目, 数量)], 所要労働 }
```

- **1レシピ1段**。中間財を経ずに原料から最終財を作る近道は置かない
- 数量はすべて int。歩留まり・端数は**切り上げ**([GDD01](01-trust-and-conversation.md) §2.3 の全体規約)
- 職業とレシピは1対1に近いが、**1職業が複数レシピを持つことは許す**(木材加工が板と薪を作る)

## 3. 摩擦 — プレイヤーの価値の源泉

**本書で最も重要な節。** [idea/008](../idea/008-NPCと職業.md) §3.1 を仕様化する。

| 摩擦 | NPC の制約 | プレイヤーの機会 | 実装上の要点 |
| ---- | ---------- | ---------------- | ------------ |
| **空間** | 職人は工房のある区画から動かない。生産物は自分の区画にしか並ばない | 区画をまたぐ運搬でサヤを抜く | World の9区画([TDD01 §3.2](../04-tdd/01-sim-core-and-m0.md))を価格差の単位にする。**区画ごとに価格が違う** |
| **時間** | 職人が買い出しに行くのは1日1回・決まった時刻だけ。入力が切れても即座には補充しない | 「今すぐ要る」に応えて割増で売る | 生産システムは入力不足で**停止する**。停止は Need を生む |
| **情報** | NPC は自分が観測した価格しか知らない([GDD01 §4.1](01-trust-and-conversation.md)) | 相場を知っていること自体が資本 | 既に GDD01 が設計済み。**02 はそれを経済的に意味あるものにする側** |

### 3.1 摩擦を消してはならない

**この3つを効率化する施策は、すべて本作の価値を削る。** 具体的には以下を作らない:

- NPC 同士の自動的な物流(きこりが鍛冶屋へ木炭を届ける)
- 全 NPC が共有する市場価格表(中央の板)
- 入力切れを即座に解消する自動発注

**逆に言えば、経済の「効率が悪い」ことは不具合ではなく仕様である。** レビューや調整でここを「改善」しないよう、本節を根拠として参照すること。

### 3.2 ただし、詰みは作らない

摩擦が強すぎて都市が餓死しては困る。**下限として、都市外の行商 NPC が最低限の流通を担う**(§9.2)。プレイヤーが何もしなくても都市は回るが、**遅く・高く回る**。プレイヤーはその差分を取る。

## 4. 生産

### 4.1 日次の生産

各生産者は日次で、自分のレシピについて:

1. 入力在庫が足りるか判定する
2. 足りれば生産量ぶん消費して出力を在庫に加える
3. 足りなければ**停止**し、不足している入力について Need を生成する(§7.2)

生産量は `min(入力から作れる量, 生産能力)`。生産能力は職人の腕・設備・雇用人数で決まる(§6)。

### 4.2 労働力

**労働は入力の一種として扱う。** レシピの `所要労働` に対して、その工房の労働力(親方 + 職人 + 徒弟)が足りなければ生産量が下がる。

これにより「労働力不足」が [GDD01 §3.2](01-trust-and-conversation.md) の Need 種別として自然に発生する。

### 4.3 設備の摩耗(**要判断**)

工具が最終財として存在する(§2.2)以上、**摩耗して買い替えが要る**のが自然である。しかし摩耗率という調整軸が1つ増える。

| 案 | 内容 |
| -- | ---- |
| **A(推奨)** | 摩耗を入れる。ただし**確率ではなく決定的に**(生産N回で1個消費)。乱数を増やさないぶん因果が追える |
| B | 摩耗を入れない。工具は都市外への輸出品としてのみ存在する |

**推奨は A。** 耐久財の需要が内生的に湧く経路は、経済の自立性にとって重要である。

## 5. 消費と家計

### 5.1 日次消費

| 品目 | 消費者 | 量 | 備考 |
| ---- | ------ | -- | ---- |
| パン | 全 NPC | 家族規模に比例 | **切らすと困窮**(§5.3) |
| 薪 | 全 NPC | 季節で変動 | 冬に急増(§8) |
| ビール | 全 NPC | 階層で変動 | 嗜好品。買えなければ我慢する |
| 衣服・靴 | 全 NPC | 摩耗したとき | 耐久財 |

**必需(パン・薪)と嗜好(ビール)と耐久(衣服・靴)を分ける。** 必需は価格が上がっても買う(需要が硬直的)、嗜好は諦める(弾力的)。この差が価格形成に効く。

### 5.2 家計

```
日次:  流動資金 += 販売収入 − 仕入支出 − 生活費
週次:  流動資金 −= 給金(雇用している場合)
季節次: 流動資金 −= 税
```

- **すべて int**。税率・給金は千分率(‰)の整数([ADR-0002](../adr/0002-time-model-and-determinism.md))
- 税は領主・教会へ。**都市外へ出る貨幣のシンクである**(§9)

### 5.3 困窮と破産(**要判断**)

流動資金が尽き、必需品が買えなくなったらどうするか。

| 案 | 内容 | 利点 | 欠点 |
| -- | ---- | ---- | ---- |
| **A(推奨)** | **段階的**。①嗜好品を諦める ②在庫を投げ売る ③掛けで買う(信用が要る)④廃業して他所に雇われる | 信用システム([GDD01](01-trust-and-conversation.md) 効果2「与信」)が経済的に意味を持つ。**プレイヤーが救う余地がある** | 段階が多く、挙動が複雑になる |
| B | 破産したら退場、新規 NPC が流入 | 単純 | プレイヤーが関わる余地が消える。信用の意味も薄い |
| C | 破産しない(資金は負にならず、単に買えない) | 最も単純 | 経済的な緊張が生まれない |

**推奨は A。** ③で [GDD01](01-trust-and-conversation.md) の掛け売りと接続し、④で雇用(§6)と接続する。**破産は退場ではなく職業の変更である** — これは中世都市のリアリティでもある。

> **④はプレイヤーの店の従業員供給源にもなる**(分冊04)。

## 6. 雇用

### 6.1 構造

**親方 / 職人 / 徒弟** の3階層([idea/008](../idea/008-NPCと職業.md) §1.4.1 のギルド構造)。

- 工房を持てるのは親方のみ
- 職人は週次で給金を受け取る。徒弟は食住のみ(給金なし)
- 労働力: 親方1.0 / 職人0.8 / 徒弟0.3(初期値)

### 6.2 雇用の増減

- 生産が需要に追いつかない状態が続くと、親方は職人を雇おうとする(Need「労働力不足」)
- 資金が続かなければ解雇する。解雇された職人は §5.3 ④の供給プールに戻る

### 6.3 スコープ(**要判断**)

雇用は面白いが、**M0 の検証項目には無い**。

| 案 | 内容 |
| -- | ---- |
| **A(推奨)** | v1.0 の目標仕様としては本節を採るが、**M0 では雇用を実装しない**。生産能力は固定値。M0 で見たいのは価格機構であり、雇用は変数を増やすだけ |
| B | M0 から入れる。労働市場も価格機構の一部である |

**推奨は A。** ただし**データモデルには雇用関係を最初から持たせる**(後付けは World の区画追加になり、決定論ハッシュの更新が要る)。

## 7. 価格形成

### 7.1 提示価格(**要判断**)

売り手が「いくらで並べるか」。妥結価格は分冊06。

| 案 | 式 | 利点 | 欠点 |
| -- | -- | ---- | ---- |
| A | **在庫圧力のみ**(M0 の現状)。目標在庫を上回れば下げ、下回れば上げる | 最も単純。M0 で検証済みになる | **原価割れが止まらない。** 生産チェーンが深いと下流が赤字で回り続ける |
| **B(推奨)** | **在庫圧力 + 原価下限**。`提示価格 = max(原価 × (1 + 最低利幅), 在庫圧力調整後の価格)` | 段が深くても価格が積み上がる。**原価が下限を与えるので発散しにくい** | 原価の定義が要る(移動平均か直近仕入値か) |
| C | B + 相場観(自分の `PriceObservation` を参照して他店に追随) | 情報の摩擦が価格に直結する。**GDD01 §4.1 が経済的に意味を持つ** | 追随が振動を生みうる。M0 の安定性判定を通せるか未知 |

**推奨は B を v1.0 の基準線とし、C を実験的な差し替え点として置く。** C は [TDD01 §3.7](../04-tdd/01-sim-core-and-m0.md) の「差し替え可能点」に追加する形が自然である。

**原価の定義は移動平均を推奨する。** 直近仕入値だと一度の高値づかみで提示価格が跳ねる。

### 7.2 需要の表現

**需要曲線は作らない。** NPC は「必要量」と「払える上限」を持つだけで、価格に応じて量を連続的に変えることはしない(方針4)。

- 必需品: 必要量は固定。払える上限まで買う。買えなければ §5.3 へ
- 嗜好品: 払える上限を超えたら**買わない**(量は0か固定量)
- 耐久財: 摩耗したときだけ需要が立つ

これで十分に価格は動く(在庫が捌けなければ売り手が下げる)。**需要関数を導入すると、価格の因果が式の中に隠れて追えなくなる**(方針2)。

### 7.3 Need への接続

不足は [GDD01 §3.2](01-trust-and-conversation.md) の Need として表面化する。**Need が経済とコアループの結節点である。**

| 発生源 | Need 種別 | 理由コード |
| ------ | --------- | ---------- |
| 生産の入力切れ(§4.1) | 在庫不足 | 生産停止 |
| 必需品が買えない(§5.3) | 金銭不足 | 困窮 |
| 労働力不足(§6.2) | 労働力不足 | 増産できない |
| 設備の摩耗(§4.3) | 在庫不足 | 工具切れ |

> **これが [TDD01 §3.6](../04-tdd/01-sim-core-and-m0.md) の仮決め「`Need.TypeCode` / `ReasonCode` を enum にする」への答えである。** 上表の左2列が種別、右列が理由コードの初期集合になる。§12 参照。

## 8. 季節との接続

[GDD03 §2](03-seasons-and-city.md)(季節が経済に効く形)は未着手。**本書が先に決めると GDD03 と二重管理になる。**

| 何を | どちらが持つか |
| ---- | -------------- |
| 季節係数の**構造**(どのレシピ・どの消費が季節に依存するか) | **本書**(経済の一部) |
| 季節係数の**値**と、季節そのものの定義 | **GDD03** |

構造だけ本書で決める:

- **生産の季節性**: 1次産品のみ季節係数を持つ。中間財・最終財は持たない(工房は屋内)
- **消費の季節性**: 薪のみ季節係数を持つ
- 係数は千分率の整数。**GDD03 が値を持つ**

> 穀物が秋にしか穫れないなら、冬〜夏は在庫を食いつぶす。**保存と投機がゲームになる。** これは本作の商人像と非常に相性がよいが、1年=120日(30日/季)という短さで成立するかは要検証。

## 9. 貨幣と都市の外(**最重要・要判断**)

### 9.1 なぜここが最重要か

[GDD01 §6](01-trust-and-conversation.md) の M0 検証項目2 は「36,000日(300ゲーム年)実行して価格が発散・硬直しないか」である。**この判定を通せるかは、貨幣のソースとシンクの設計でほぼ決まる。**

- **完全に閉じた系**(貨幣総量が一定): 価格の絶対水準は動かせない。相対価格だけが動く。**硬直はしないが、経済成長も不況も表現できない**
- **シンクだけがある系**(税が都市外へ出るのみ): 貨幣が枯渇し、やがて全 NPC が困窮する。**300年もたない**

**つまり税を入れた時点で、対応するソースが必須になる。** ここを設計せずに W2 を実装すると、36,000日実行が必ず失敗する。

### 9.2 提案:都市外を「外部市場」としてモデル化する

| 案 | 内容 | 利点 | 欠点 |
| -- | ---- | ---- | ---- |
| **A(推奨)** | **都市外を、固定価格帯で無限に売買する相手として置く。** 行商 NPC が都市外との窓口になり、都市内の価格が帯を外れると裁定が働く | ①貨幣のソース兼シンクになる ②**価格に上下限を与える**ため発散しない ③M0 の「価格が帯内に収まる」判定と直接噛み合う ④行商 NPC は [idea/008](../idea/008-NPCと職業.md) §1.5 に既にある | 外部価格という「神の値」が入る。ただし**それは都市の外が広いという事実の表現**であって恣意ではない |
| B | 領主が徴税分を都市内で支出する(閉ループ) | 外部の神の値が要らない | 領主の支出先の設計が要る。**価格の上下限が無いので発散を止める仕組みが別に要る** |
| C | 貨幣を持たない(物々交換) | シンク・ソースの問題が消える | 商人ライフシムとして成立しない |

**推奨は A。** 加えて **B を併用**してよい(領主の支出は都市内の需要を作る)。

### 9.3 外部市場の性質(A を採る場合)

- **買値 < 売値**(スプレッド)。外部と取引すると必ず損をする。**だから都市内で取引したほうが得であり、プレイヤーの仲介に価値が出る**
- 外部価格は季節でゆっくり動く。**急変させない**(プレイヤーが読めなくなる)
- 品目ごとに帯の幅が違う。鉄鉱石は外部依存が強く帯が狭い、パンは都市内財で帯が広い

**このスプレッドが、§3.2 の「詰みは作らないが遅く・高く回る」の実装でもある。**

## 10. NPC の一生(**要判断**)

### 10.1 36,000日 = 300年 をどう解釈するか

**重要な整理**: [GDD01 §6](01-trust-and-conversation.md) 検証項目2 の 36,000日は、**300年の物語ではなく価格機構の耐久試験である。** ここを混同すると、人口動態の設計が M0 のスコープに引きずり込まれる。

| 案 | 内容 |
| -- | ---- |
| **A(推奨)** | **M0 では NPC は不死。世代交代は v1.0 の課題として §13 に置く。** 36,000日は耐久試験と明示する |
| B | 最初から寿命と世代交代を入れる | 
| C | 検証地平を短くする(例: 3,600日 = 30年) |

**推奨は A。** ただし **C も一考に値する** — 300年ぶんの計算は価格機構の検証としては過剰かもしれない。**発散・硬直が起きるなら数十年で兆候が出る**はずである。地平を短くすれば実験の反復が速くなり、W2 の調整サイクルが回りやすい。**これは TDD01 §5.4 の判定基準に触れるため、設計セッションで決めること。**

### 10.2 世代交代を入れる場合の波及(参考)

v1.0 で入れるなら、以下が連動する。**M0 では触らない。**

- 信用([GDD01 §2.1](01-trust-and-conversation.md))は死亡でリセットされる。長期の信用関係が失われる痛みがゲームになる
- 相続で資産と工房が引き継がれる。徒弟→職人→親方の昇格が生きる
- 決定論ハッシュ([TDD01 §3.8](../04-tdd/01-sim-core-and-m0.md))の区画が増える

## 11. M0 での検証項目

[GDD01 §6](01-trust-and-conversation.md) と重複しない、**経済側の**検証項目。

| # | 検証内容 | 判定基準 |
| - | -------- | -------- |
| 1 | 価格が安定するか | 信用なし条件で長期実行し、全品目の価格が外部市場の帯(§9.3)の内側に収まり続ける |
| 2 | 貨幣が枯渇しないか | 実行を通じて、困窮状態(§5.3)の NPC が全体の一定割合を超えない |
| 3 | 生産チェーンが止まらないか | 各レシピの生産停止(§4.1)が常態化しない。**一時的な停止は仕様**(§3)であり、常態化だけを見る |
| 4 | 摩擦が残っているか | 区画間の価格差が消えない。消えていれば §3 の摩擦が実装されていない |
| 5 | 原価下限が効いているか | どの品目も、原価を下回る提示価格が継続しない(§7.1 案B の検証) |

**#4 が本書固有の判定である。** 価格が安定していても区画差が消えていたら、それは「プレイヤーのいらない経済」であり、経済としては成功でもゲームとしては失敗である。
