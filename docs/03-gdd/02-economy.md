## 1. 設計方針

1. **経済は摩擦のためにある。** これが第一原理である。NPC が完璧に動く経済ではプレイヤーの価値がゼロになる。[idea/008](../idea/008-NPCと職業.md) §3.1 の「AI職人は工房から動かない」を**仕様として明文化する**(§4)
2. **観測可能性を最優先する。** The Guild 3 化(観測不能な複雑さ)の回避は企画段階からの制約である。プレイヤーが「なぜこの価格なのか」を追えなくなった時点で、経済の精巧さは価値を失う。**追えなくなる複雑さは、面白さの有無に関わらず入れない**
3. **閉じた経済にしない。** 都市の外を明示的にモデル化する(§10)。閉じた系は貨幣量が固定され、価格の絶対水準が動かせない
4. **NPC は満足化する。最適化しない。** 最適化する NPC はプレイヤーの介在余地を消し、かつ挙動が読めなくなる
5. **数値は初期値。** 構造と依存関係だけを固定する

## 2. 品目とレシピ

### 2.1 構成(**決定**)

**3層・最大2段。** 層と段を区別する:

- **層** = 品目の位置(1次産品 / 中間財 / 最終財)。**3層に固定する**
- **段** = 1次産品からの変換回数。**制約すべきはこちら**。段が深いほど価格の因果が追えなくなる(方針2)

品目数を増やしても段が浅ければ因果は追える。逆に段が深いと品目数が少なくても追えない。**したがって制約するのは段であり、段は2に抑える。**

> **段は「品目をどの層に置くか」で調整できる。** 木炭は当初 `木材→薪→木炭` の中間財としたため工具が3段になったが、**1次産品(炭焼き)に置き直すと工具は1段になる**(§2.2)。史実に沿わせた結果として制約も満たした例である。

**都市の賑わいは、品目ではなく職業で出す。** 生産以外の職業(サービス業・物流業・貿易商)を置くことで、レシピを増やさずに都市の味が出る。**M0 では採らない**(§13)。

### 2.2 品目表(**決定**)

**M0 は9品目。品目 Id は下表の順に 0〜8** — 品目に対する決定論の列挙順はこの採番による([ADR-0002](../adr/0002-time-model-and-determinism.md) の列挙順規約)。

| Id | 層 | 品目 | レシピ | 分類 | 供給 |
| -- | -- | ---- | ------ | ---- | ---- |
| 0 | 1次 | 穀物 | — | 生産の入力 | **都市外市場**(§10) |
| 1 | 1次 | 木材 | — | 生産の入力 | **都市外市場** |
| 2 | 1次 | 鉄鉱石 | — | 生産の入力 | **都市外市場** |
| 3 | 1次 | 木炭 | — | 生産の入力(金属加工専用) | **都市外市場** |
| 4 | 中間 | 小麦粉 | 穀物 → | 生産の入力 | 水車小屋番 |
| 5 | 中間 | 薪 | 木材 → | **必需**(家庭の暖房)+ 生産の入力(パン・ビール) | 木材加工 |
| 6 | 最終 | パン | 小麦粉 + 薪 → | **必需** | パン屋 |
| 7 | 最終 | ビール | 穀物 + 薪 → | **嗜好** | 醸造 |
| 8 | 最終 | 工具 | 鉄鉱石 + 木炭 → | **耐久**(摩耗する、§5.3) | 鍛冶 |

**この9品目が、§8.2.1 の予算の4つの決まり方をすべて実行する** — 派生需要(1次〜中間)、相場基準(パン・薪)、予算比率(ビール)、`min` の耐久(工具)。**どれか1つでも対応する品目を落とすと、その式が W2 で一度も実行されない。**

> **削ってよい下限は「4つの決まり方がすべて実行されること」である。** **5品目まで削ると上の4つのうち少なくとも1つが実行されない** — 最も残せる選び方(鉄鉱石・木炭・工具・木材・薪)でも嗜好の予算比率が落ち、パン系列を残す選び方なら予算比率と耐久の2つが落ちる。**[企画書 §6](../02-project-proposal.md) の M1 は当初「品目5種」だったが、[ADR-0007](../adr/0007-m1-scale-follows-economic-model.md) で9種へ改訂した** — 5という数は本書の予算の構造が決まる前に置かれた見積もりだった。**[ADR-0006](../adr/0006-issue-driven-task-management.md) が問題にした M0 > M1 の順序反転は、品目数・NPC 数とも等号で解消している。**

**燃料は2系統ある。用途が分かれ、故障モードも分かれる。**

| 燃料 | 用途 | 供給 | 止まる条件 |
| ---- | ---- | ---- | ---------- |
| **薪** | 家庭の暖房、食品加工(パン・ビール) | **都市内**(木材加工が木材から作る) | 木材の価格が跳ねる / 木材加工が止まる |
| **木炭** | **金属加工のみ**(工具) | **都市外**(炭焼き) | 都市外市場の価格が跳ねる(= 季節性、§9) |

**故障モードが違うことに価値がある。** 単一の隘路より、2つの独立した供給不安があるほうが、プレイヤーの介入機会が多様になる。冬の暖房需要(§9)は薪だけを圧迫し、木炭には効かない。

#### 木炭は1次産品である(**決定**)

**中世の炭焼きは森の奥深くで原木を蒸し焼きにする作業であり、都市内の工房で行うものではない。** したがって木炭は、木材や鉄鉱石と同じく**都市の外から持ち込まれる1次産品**として扱う。

**この置き方が3つの問題を同時に解く**:

1. **史実性。** 製鉄・鍛造には木炭が要る。薪では温度が足りず不純物も多い。「炭が切れた鍛冶屋」は [idea/008](../idea/008-NPCと職業.md) §3.1 が挙げた場面そのものである
2. **段数。** 中間財(`木材→薪→木炭`)に置くと工具が3段になるが、**1次産品に置けば `鉄鉱石 + 木炭 → 工具` は1段**である。§2.1 の制約を満たす
3. **対称性。** 金属加工は `鉄鉱石 + 木炭` で揃う

> **旧版では木炭を廃し、金属加工の燃料を薪に統一していた。** 廃した理由は「段が3になる」「燃料が2種で対称性が崩れる」だったが、**どちらも木炭を中間財に置いたことの帰結**であり、1次産品に置き直すと両方とも消える。**却下理由の前提が、置き場所を変えたことで崩れた**([process/03](../process/03-corrections.md) 規則6)。

### 2.3 レシピの形

```
レシピ = { 出力[(品目, 数量)], 入力[(品目, 数量)], 所要労働 }
```

- **出力は複数を許す**(M0 の5レシピはいずれも単一出力だが、構造としては許す)
- **1レシピ1段**。中間財を経ずに原料から最終財を作る近道は置かない
- 数量はすべて int。歩留まり・端数は**切り上げ**([GDD01 §2.3](01-trust-and-conversation.md) の全体規約)
- **入力を持たないレシピを許す。M0 には該当する職業が無い**(1次産品はすべて都市外市場から来る)が、構造としては残す — §8.1.1 の原価の分岐がこれに対応し、[GDD11](11-external-trade.md) の貿易商と [GDD12](12-countryside-and-fairs.md) の農村職業が戻ったときに発火する

### 2.4 規模 — 職業・世帯・NPC(**決定**)

**都市5職業 × 2世帯 = 10世帯、1世帯2人、NPC 20体。** 9区画に1〜2世帯で収まる。

| Id | 職業 | レシピ |
| -- | ---- | ------ |
| 0 | 水車小屋番 | 穀物 → 小麦粉 |
| 1 | パン屋 | 小麦粉 + 薪 → パン |
| 2 | 醸造 | 穀物 + 薪 → ビール |
| 3 | 木材加工 | 木材 → 薪 |
| 4 | 鍛冶 | 鉄鉱石 + 木炭 → 工具 |

**職業 Id は上の表の順に 0〜4。** §6.3 と [GDD08 §9](08-household-and-decision.md) の「同値なら職業 Id 昇順」はこの採番による。

**規模を決めているのは「1品目につき売り手2世帯を別区画に置けること」である。** `Market` は「品目 × 売り手 → 提示価格」なので、**売り手が1人なら市中価格が1つしか存在せず、§12-4「区画間の価格差が消えない」が消えるのではなく最初から存在しない**。[GDD06 §3](06-trade-and-negotiation.md) の店の選択も比較対象を持たない。

**同じ職業の2世帯は必ず別の区画に置く。これは値ではなく構造の制約である。** §4.3 の密度(1区画1〜2世帯)だけでは同居を防げず、同居すると当該品目の売り手が1区画に集まって区画差が消える。

**§4.3 の密度(1区画1〜2世帯・空区画を作らない)は、情報の摩擦の側にも効いている。** 10世帯を9区画に上限2・下限1で置くと配置は「8区画に1世帯・1区画に2世帯」しかあり得ず、**中心に隣接する4区画(Id 1/3/5/7)は必ず埋まる**。隅の区画(Id 0/2/6/8)はいずれもそのうち2つと隣接するので、**隅の世帯にも「買いに行く先」が必ず存在する** — これが §4.2 の観測の広がりの前提である。

> **これでも「必ず観測する」にはならない。** 隣接区画に売り手が居ても、その売り手が扱う品目をその世帯が買わない日は移動が起きない。**構造が排除できるのは「行く先が無い」配置までであり、残りは §12-7 が測る。**

**初期配置はマスターシードから振る。** 上の構造制約(同職業は別区画・密度)を満たす配置は一意ではなく、どの世帯がどの区画に入り、どの世帯がどの職業に就くかは `RandomStream.WorldGen` から決まる。**同一シードなら同一配置、違うシードなら違う配置になる。** [TDD01 §4.1](../04-tdd/01-sim-core-and-m0.md) の「条件あたり10反復」はこれにより実際に10通りの地理を見ることになり、§12-4(区画間の価格差が消えない)が特定の1つの配置の産物ではなくなる。ADR-0002 の共通乱数法により、A/B の2条件は同一シードなら同一配置で揃う。

#### 世帯構成と NPC 数(**決定**)

**世帯構成は親方1・徒弟1の2人を初期値とする。** [GDD08 §2.1](08-household-and-decision.md) が世帯に含めうる役割(親方・主婦・子ども・徒弟)を定めているが、**M0 で何人置くかは本書が初期値として持つ**(構造は GDD08、値は本書という分け方は §9 季節係数と同じ)。

| | 世帯数 | NPC数(2人 × 世帯数) |
| -- | -- | -- |
| 都市 | 10 | **20** |

**親方と徒弟の2人に絞るのは、M0 が労働力について見たいのが「階層で係数が違うこと」だけだからである**(§5.2)。主婦は家事の外部化([GDD08 §3.2](08-household-and-decision.md))と、子どもは世代交代(§11)と対になって意味を持つ役割であり、どちらも M0 のスコープ外である。**職人は自分の家計を持つ別世帯であり**([GDD08 §2.1](08-household-and-decision.md))、雇用([GDD10](10-employment.md))とともに M0 の外に出る。

> **人数は調整対象である。** ただし「世帯が複数の階層を含む」という構造は GDD08 §2.1 の決定であり、動かさない。世帯内で流動資金を共有すること(§6.2)と、買い物に行く者の機会費用が階層で違うこと([GDD06 §2](06-trade-and-negotiation.md))は、2人でも成立する。

## 3. 職業

### 3.1 職業一覧の正は本書が持つ

[idea/008](../idea/008-NPCと職業.md) は**原典のアイデアメモ**であって仕様ではない。**M0 の職業一覧の正は本書 §2.4 が持ち、拡張で加わる職業は各分冊が持つ**(貿易商・運送労働者は [GDD11](11-external-trade.md)、農村職業は [GDD12](12-countryside-and-fairs.md)、サービス業・質屋・武器職人などは §13)。**どの分冊にも属さない職業は置かない。**

**理由**: 職業 = レシピ + 家計 + 労働力であり、3つとも本書の §2・§5・§6 が持つ。レシピを持たない職業(商業・サービス・物流)も、**経済における役割**として定義される以上ここに属する。

**境界**:

| 何を | どこが持つか |
| ---- | ------------ |
| 職業の一覧・役割・レシピ | **本書 §2.4** |
| 個体の1日の行動(いつ買いに行くか) | **本書 §4**(時間の摩擦の仕様) |
| 親方 / 職人 / 徒弟の**雇用関係** | [GDD10](10-employment.md)。**M0 では雇用を実装しない** |
| 貿易商 | [GDD11](11-external-trade.md) |
| 農村の職業 | [GDD12](12-countryside-and-fairs.md) |
| ギルド・教会・領主という**組織** | 分冊07。**職業とは別の軸**である(鍛冶職人はギルドの一員だが、ギルドは職業ではない) |
| プレイヤーの店と従業員 | 分冊04 |

### 3.2 粒度(**決定**)

**経済的な役割が異なるものだけを分ける。** [idea/008](../idea/008-NPCと職業.md) はより細かい区分を挙げている(海上貿易商とスパイス貿易商の分離、金銀細工師、道化師など)が、経済的役割が重複するものは統合する。

**職業の追加は品目の追加より安い。** レシピを持たない職業(サービス・物流・商業)は品目数も段数も増やさないため、方針2の観測可能性を損なわない。**粒度を上げる拡張は、M0 後の「賑わいが足りない」という所感に応じて足す**(§13)。

## 4. 摩擦 — プレイヤーの価値の源泉

**本書で最も重要な節。** [idea/008](../idea/008-NPCと職業.md) §3.1 を仕様化する。

| 摩擦 | NPC の制約 | プレイヤーの機会 | 実装上の要点 |
| ---- | ---------- | ---------------- | ------------ |
| **空間** | 職人は工房のある区画から動かない。生産物は自分の区画にしか並ばない | 区画をまたぐ運搬でサヤを抜く | **都市を 3×3 の9区画に分け**、価格差の単位にする(§4.3)。**区画ごとに価格が違う** |
| **時間** | 職人が買い出しに行くのは1日1回・決まった時刻だけ。入力が切れても即座には補充しない | 「今すぐ要る」に応えて割増で売る | 生産システムは入力不足で**停止する**。停止は Need を生む |
| **情報** | NPC は自分が観測した価格しか知らない([GDD01 §4.1](01-trust-and-conversation.md)) | 相場を知っていること自体が資本 | 既に GDD01 が設計済み。**02 はそれを経済的に意味あるものにする側** |

### 4.1 摩擦を消してはならない

**この3つを効率化する施策は、すべて本作の価値を削る。** 具体的には以下を作らない:

- NPC 同士の自動的な物流(木材加工へ木材が自動で届く)
- **全 NPC が共有する市場価格表(中央の板)。M0 には例外を1つも置かない。** 都市外市場(§10)も中心区画に並ぶ1つの売り手として扱い、視界半径([GDD06 §3.1](06-trade-and-negotiation.md))の外からは見えない
- 入力切れを即座に解消する自動発注

**逆に言えば、経済の「効率が悪い」ことは不具合ではなく仕様である。** レビューや調整でここを「改善」しないよう、本節を根拠として参照すること。

> **例外を1つも置かないことが、M0 でのこの節の強さである。** 例外は「一貫性のために」他へ広げたくなる圧力を常に持つ。[GDD11](11-external-trade.md)(定期市の周知)や [GDD12](12-countryside-and-fairs.md)(季節市)が例外を必要とするなら、**それは各分冊が自分の理由で正当化する。**

### 4.2 ただし、詰みは作らない

摩擦が強すぎて都市が餓死しては困る。**M0 の下限は都市外市場(§10)が担う。** 中心区画には1次産品が常に並び、都市生産品の余剰は常に引き取られる。**プレイヤーが何もしなくても都市は回るが、遅く・高く回る** — 窓口は中心にしか無いので移動費が乗り、しかも売値と買値の開きが大きい(§10.2)。プレイヤーはその差分を取る。

**下限を担うもう一方は [GDD06 §3.1](06-trade-and-negotiation.md) の観測の広がりである。** 「その日に居た区画から距離 R 以内」で観測が生まれるので、**買い物に行くこと自体が知識を外へ広げる**。隅の区画(Id 0/2/6/8)の世帯は、隣接区画へ買い物に行った日に中心を観測する(2回の移動で届く)。Need(遠方在庫)は立つが、**M0 では履行する主体を置かない**([GDD11](11-external-trade.md) の行商人・運送労働者は M0 の外)。

> **観測の広がりは「必ず届く」保証ではない。** 観測が生まれるのは**その日に実際に居た区画**からであり、[GDD06 §3.1](06-trade-and-negotiation.md) の店選択は「知っている店」が空なら移動そのものを起こさない。**したがって、視界 R=1 の中に一度も買う相手が現れない世帯は、中心を永久に観測しない。**
>
> **構造が保証するのは「買いに行く先が必ず存在する」ことまでである**(§2.4。§4.3 の密度から、中心に隣接する4区画は必ず埋まる)。**残りは §12-7 が測る失敗モードである** — 「知っている店が0件」の世帯の割合が高止まりするなら、この下限が働いていない。

### 4.3 区画と距離(**決定**)

**9区画を 3×3 のグリッドとして扱い、区画間の距離はマンハッタン距離とする。**

```
距離(a, b) = |行(a) − 行(b)| + |列(a) − 列(b)|      ← 0〜4
移動時間   = 距離 × 1区画あたりの移動時間(初期値 1時間) × 2   ← 往復
```

- **区画 Id は行優先で 0〜8。** Id から行・列が定まるので、距離表というデータを持たない
- 距離は**視界半径 R** にも使う([GDD06 §3.1](06-trade-and-negotiation.md))。**起点は「その日に居た区画」であって自宅とは限らない**。**R は値ではなく構造であり、実データを見て調整する軸ではない**
- 距離は実質コストに乗る([GDD06 §2](06-trade-and-negotiation.md))。**これが空間の摩擦の唯一の数値表現である**
- 買い手の区画は世帯の区画、店の区画は売り手の工房の区画。**都市外市場の区画は中心(Id 4)に固定する**(§10)

> **隣接グラフや 9×9 の距離行列を持たないのは、調整軸を増やさないためである**(方針2)。距離行列なら36個の軸が増え、**区画間の価格差が「機構の帰結」か「距離表の設定」かを切り分けられなくなる** — §12-4 がまさにその価格差を判定に使う以上、これは致命的である。
>
> 城壁・川・門といった不整形をグリッドで表せないのは承知の上である。**M0 の目的は価格機構の検証であって都市の地理ではない。** 複数都市(§13)へ進むときに再訪する。

#### 世帯は区画を移らない(**決定**)

**世帯の区画は初期配置で決まり、以後変わらない。**

- **世帯密度は 1区画あたり1〜2世帯。** 同じ職業が1区画に詰まって競合することがなく、かつ空区画も出ない薄さである
- 世帯の区画Id は不変。`Household` の定数であって状態ではない

> **移住を許すとホテリングの法則で全世帯が中心区画に集まる。** 中心は全区画への距離が最小なので実質コスト([GDD06 §2](06-trade-and-negotiation.md))で有利になり、周辺に留まる動機が無い。**都市外市場が中心にあること(§10)がこの圧力をさらに強める。** 集まった瞬間に §4 の空間の摩擦が消滅し、§12-4「区画間の価格差が消えない」が構造的に不通過になる。
>
> **決定論の側でも効く。** 区画Id が不変なら「どの世帯がどこに居るか」は状態ではなくなり、移動判定の順序やタイミングが状態ハッシュ([TDD01 §3.8](../04-tdd/01-sim-core-and-m0.md))に乗らない。§12-4 は**価格機構の帰結だけ**を見ることになる。

> **立地のコントラストは、v1.0 では徒弟の移動で表す** — 立地の良い工房は徒弟を集め、条件の悪い工房は徒弟を手放す。**動くのは世帯ではなく人手**である。これは雇用の一部なので [GDD10](10-employment.md) が持つ。**M0 では初期配置で徒弟数を固定し、立地の差は価格差としてのみ現れる。**

## 5. 生産

### 5.1 日次の生産

各生産者は日次で、自分のレシピについて:

1. 入力在庫が足りるか判定する
2. 足りれば生産量ぶん消費して出力を在庫に加える
3. 足りなければ**停止**し、不足している入力について Need を生成する(§8.4)

生産量は `min(入力から作れる量, 生産能力)`。生産能力は労働力と設備で決まる(§5.2・§5.3)。

### 5.2 労働力(**決定**)

**労働は入力の一種として扱う。** レシピの `所要労働`(**レシピ1回の実行**に必要な労働力‰。1000‰ = 親方1人日相当)に対し、その工房に従事する世帯構成員の**労働力係数‰の合計**(労働力合計‰)が生産量の上限を決める。

> **「出力1単位あたり」ではなく「レシピ1回の実行あたり」である。** §2.3 が**複数出力を許す**と決めているので、多出力レシピでは「出力1単位」が指すものが無い。単一出力でも同じで、木材加工(`木材1 → 薪3`、§2.4)を出力1単位あたりと読むと生産能力1が薪1個を指すことになり、**木材 1/3 個**という存在しない入力を要求する。§2.3 は数量をすべて int と決めているので、この読みは成立しない。

**労働力係数‰(初期値)**:

| 階層 | 係数‰ | M0 |
| ---- | ----- | -- |
| 親方 | 1000 | **居る**(各世帯1) |
| 徒弟 | 300 | **居る**(各世帯1) |
| 職人 | 800 | 居ない([GDD10](10-employment.md)。職人は別世帯) |
| 主婦 | 300 | 居ない(§2.4) |
| 子ども | 100 | 居ない(§2.4) |

**M0 の世帯の労働力合計‰は 1300 で固定である**(親方1000 + 徒弟300)。雇用が無いので構成員が増減せず、階層も変わらない。**M0 では家事・時間配分を分けて計算しない**([GDD08 §9](08-household-and-decision.md))ため、家業に振り向けられる時間の按分を行わず、**構成員全員の労働力係数‰をそのまま合算する。** これは M0 限定の単純化であり、時間配分を入れる v1.0 では [GDD08 §4.2](08-household-and-decision.md) のとおり実際に家業へ充てた時間の比率を乗じる形に戻す。

```
労働力合計‰         = Σ( その工房を持つ世帯の構成員の労働力係数‰ )
生産能力(実行回数)   = floor( ApplyPermille(労働力合計‰, 設備係数‰(§5.3)) ÷ 所要労働‰ )
入力から作れる回数   = min_j( floor( 工房在庫[入力j] ÷ 必要数量_j ) )
                       入力が0件のレシピ(§2.3)は、この項では制約しない
生産量(実行回数)     = min( 入力から作れる回数, 生産能力(実行回数) )

  工房在庫[入力j] −= 必要数量_j × 生産量
  工房在庫[出力o] += 出力数量_o × 生産量
```

**この除算は切り下げる。** [GDD01 §2.3](01-trust-and-conversation.md) の全計算式切り上げの原則の**意図的な例外**である — 端数の労働力ではレシピを1回完成できないため、切り上げると存在しない労働力で生産したことになる。**`入力から作れる回数` の除算も同じ理由で切り下げる** — 端数の入力では1回ぶんに届かない。

**これにより [GDD08 §4.2](08-household-and-decision.md)「1時間あたり出力」の式は M0 では使わない。** あの式はレシピに無い `標準出力/時間` を要求し、かつ時間配分(M0 では入れない)を前提にしている。GDD08 §4.2 は熟練度・時間配分を入れる v1.0 のための式として残し、**M0 の生産量は本節の式が正**とする。

これにより「労働力不足」が [GDD01 §3.2](01-trust-and-conversation.md) の Need 種別として自然に発生する(労働力合計‰ が所要労働‰ に満たない場合)。

> **`ApplyPermille(労働力合計‰, 設備係数‰)` は切り上げヘルパーであり、上の「切り下げる」という明記と向きが逆である。** 設備係数が二値(1000/0)の M0 では乗じても値が変わらないので実害は無い。**摩耗を連続化する v1.0 では、この内側の丸めも切り下げへ直す必要がある**(§13)。

### 5.3 設備の摩耗(**決定**)

**摩耗を入れる。ただし確率ではなく決定的に**(生産N回で工具1個を消費)。乱数を増やさないぶん因果が追える。

**設備係数‰(§5.2)は M0 では二値とする。** 稼働可能な工具在庫が1個以上あれば 1000‰、無ければ 0‰(生産停止。Need「工具切れ」、§8.4)。**摩耗度に比例して連続的に下がる形は v1.0 の拡張とする** — 段階を増やすと調整軸が増え、方針2(観測可能性)に対して M0 では過剰である。

**`N = 30`(初期値)。** レシピを30回実行するごとに工房の工具在庫が1個減る。**摩耗は世帯ごとに累積し、工具1個ぶんに満たない端数は次の工具へ持ち越す** — 日ごとに端数を捨てると、1日1回しか実行しない工房(M0 の初期値がこれ、§13.2)の工具が永久に減らない。

**工具在庫が尽きたときに残った摩耗は捨てる。** 在庫を負にせず、足りなかったぶんを繰り越さない(§6.1 の消費の規則と同じ扱い)。繰り越すと、**次に買った工具が買ったその日に壊れうる**。

> **摩耗の累積は在庫から復元できないので、世帯の状態として持つ。** 「工具在庫 × N − 累積摩耗」が §8.2.1 の言う**耐久値**であり、耐久財の目標在庫はこの導出値を見る。

耐久財の需要が内生的に湧く経路は、経済の自立性にとって重要である。工具を買えない工房は生産能力が落ち、それが Need になる(§8.4)。

> **摩耗する耐久財を工具のみに限っている**のは意図的なスコープ制約である。農具・ツルハシ・厨房設備なども同型に扱えるが、品目と調整軸が増える(§13)。
>
> **工具を買えない鍛冶が工具の供給を止める、という自己参照の経路がある。** 鍛冶2世帯がともに資金不足に陥ると工具の生産が細り、設備係数がやがて全工房で 0‰ に落ちうる。**都市外市場(§10)が鉄鉱石と木炭を常に売るので、入力切れの原因は「供給が無いこと」ではなく「資金が無いこと」か「中心の売り注文を観測できていないこと」(§4.2)に絞られる。** これは §12-3 が観測すべき失敗モードであり、**先回りして救済経路を置かない**(§6.3)。

## 6. 消費と家計

### 6.1 日次消費

| 品目 | 消費者 | 量 | 分類 |
| ---- | ------ | -- | ---- |
| パン | 全 NPC | 家族規模に比例 | **必需** |
| 薪 | 全 NPC | 季節で変動 | **必需**(冬に急増) |
| ビール | 全 NPC | 階層で変動 | **嗜好** |
| 工具 | 工房 | 生産で摩耗(§5.3) | **耐久** |

**必需・嗜好・耐久の分類が価格形成に効く**(§8.2)。必需は価格が上がっても買う(需要が硬直的)、嗜好は諦める(弾力的)。**奢侈の分類も式としては持つ**(§8.2.1)が、**M0 に該当する品目は無い** — ワイン・香辛料は [GDD11](11-external-trade.md) が持つ。

#### 1日消費量(初期値)

**1人1日あたりの個数。階層ごとに持つ。** 上表の「家族規模に比例」は構成員ぶんを足すこと、「階層で変動」は行が階層で違うことを指す。

| 品目 | 親方 | 職人 | 徒弟 | 季節係数 |
| ---- | ---- | ---- | ---- | -------- |
| パン | 1 | 1 | 1 | 掛からない |
| 薪 | 2 | 2 | 2 | **掛かる**(§9。値は [GDD03 §2](03-seasons-and-city.md)) |
| ビール | 1 | 1 | 0 | 掛からない |

- **減らすのは世帯在庫であって工房在庫ではない。** 薪は消費財でも生産の入力でもある(§2.2)ため、2本の在庫([TDD01 §3.2](../04-tdd/01-sim-core-and-m0.md))のどちらから引くかを決めておく必要がある。生産の入力としての薪は §5.1 が工房在庫から引く
- **徒弟のビールが0なのは、徒弟が給金を持たないためである**([GDD10 §1](10-employment.md)。嗜好は諦められる、§8.3)。職人は M0 に居ない(§2.4)が、階層の行は先に埋めておく
- **職人・主婦・子どもを含む階層の一覧は §5.2 が持つ。** 本表が持つのは M0 の `NpcRank` の3階層だけである

**季節係数は構成員ごとに適用して切り上げ、それから世帯で合計する。** 丸めが入るので順序が結果を変える。例: 親方+徒弟の世帯が夏(400‰)に消費する薪は `ApplyPermille(2, 400) = 1` の2人ぶんで **2** である。

> **M0 の初期値ではどちらの順序でも一致する**(基礎量2が偶数で、係数を掛けた積が 1000 で割り切れるか、切り上げが同じ側に倒れるため)。**一致しなくなるのは基礎量が奇数のとき** — 基礎量1・係数500‰・2人なら、構成員ごとなら 1+1 = **2**、世帯合計に先に掛けると `ApplyPermille(2, 500) = 1` である。**基礎量は §13.2 の調整対象なので、いま一致していることに頼らない。**

**在庫が足りないときの消費の規則**: **在庫は 0 で下げ止まり、負にならない。** 足りなかったぶんは繰り越さず、その日の不足として §8.4 の Need(在庫不足)になるだけである。**M0 では飢餓・健康・死亡をモデル化しない**(NPC は不死、§11)ので、不足が蓄積する変数を持たない。

> **この規則が無いと §8.2.3 が壊れる。** 在庫が負に振れると `購入量 = max(0, 到達在庫 − 予想在庫)` が負在庫の絶対値ぶん膨らみ、それが §6.2 の資金上限で毎日切り詰められて**破産中フラグが恒久的に立つ**。(§8.2.2 の在庫圧力‰ は目標在庫以下で 1000‰ に張り付くので、そちらは発散しない。)

### 6.2 家計(**世帯単位**)

**家計の主体は個人ではなく世帯である**([GDD08 §2](08-household-and-decision.md))。

```
日次: 流動資金 += 販売収入 − 仕入支出 − 生活費
```

- **流動資金と帳簿(取引履歴)は世帯が持つ。** 帳簿は**資金の増減と一致するため**、個人別に持つと突合できない
- **すべて int**。比率係数は千分率(‰)の整数([ADR-0002](../adr/0002-time-model-and-determinism.md))
- **`生活費` は必需の消費のための支出そのものである。** 別建ての固定費ではなく、`Trade` で必需品を買った代金を指す
- **週次の給金は M0 に無い**(雇用は [GDD10](10-employment.md))。**季節次の税も M0 に無い**([GDD09](09-treasury-and-tax.md))

> **W1 の `World` は流動資金を `NpcState` に持たせている**([TDD01 §3.2](../04-tdd/01-sim-core-and-m0.md))。**世帯単位へ移すのは W2 の作業であり、決定論ハッシュ([TDD01 §3.8](../04-tdd/01-sim-core-and-m0.md))の区分が変わる。** 区分の設計は [TDD01 §3.2「経済主体は世帯である」](../04-tdd/01-sim-core-and-m0.md)が持つ。

#### 6.2.1 購入の資金上限と走査順(**決定**)

**どの購入も、支払額が世帯の流動資金を超えてはならない。**

```
買える数量 = min( §8.2.3 の購入量 , FloorDiv( 流動資金 , その店の実効単価 ) )
             ← 切り下げる。切り上げると1単位多く買えて流動資金が負に落ちる
切り詰めた結果 1単位も買えなかった購入を「資金不足で買えなかった」と呼ぶ

世帯内の購入は次の順に決済する(流動資金を共有するので順序が結果を変える。ADR-0002):
    必需 → 生産の入力 → 耐久 → 嗜好    同じ用途の中では 品目 Id 昇順(§2.2)
```

**走査順を固定するのは、資金が世帯内の共有資源だからである。** §8.2 の予算は**単価の上限**であって総額の上限ではない(§8.2.5)。**資金の上限がある以上、どの購入が切り詰められるかが順序で決まり、それが破産中フラグ → ②の値付け → ④の付け替え → §12-2 の判定まで波及する。**

**必需を先に決済するのは、フラグの意味を保つためである。** 嗜好品を先に買って必需品が切り詰められる順序を許すと、「資金不足で必需品が買えなかった」が**買い物の順序の関数**になり、困窮の指標として読めなくなる。

**「高すぎて買わなかった」は資金不足ではない。** §8.2.3 が `実質コスト > 基礎値` で購入量を 0 にした場合は、そもそも切り詰めが起きていないので上の定義に当たらない。**フラグが拾うのは「買う判断をしたが払えなかった」だけである** — ここを緩めると、価格が跳ねた日に全世帯のフラグが立ち、②が一斉に発動する**価格ショックの検出器**になってしまう。

#### 6.2.2 破産中フラグ(**決定**)

```
破産中フラグ(世帯の状態。1ビット):
    立つ:  前日、必需品を「資金不足で買えなかった」購入が1つ以上あった
    降りる: 前日、そのような購入が1つも無かった

②(投げ売り)と④のゲートは、どちらもフラグが立っている「状態」で駆動する
```

**評価するのは前日の購入結果である。** 購入が起きるのは `Trade`([TDD01 §3.3](../04-tdd/01-sim-core-and-m0.md) 順5)で、フラグの更新は `Household`(順3)、すなわちその日の購入より前にある。**当日の結果で立てようとすると、②(順5 の値付けでフラグを読む)が同一 tick 内で循環する。** [GDD08 §6.3](08-household-and-decision.md) の1日遅延の成層化・[GDD06 §3.1](06-trade-and-negotiation.md) の「予算は当日の観測を反映しない」と同じ扱いにする。

**「流動資金が尽きた」を残高 0 とは読まない。** 上の規則のとおり、**必需品を1単位も買えない**ことがその意味である。**§12-2 が測る「困窮状態」は、このフラグが立っている状態を指す。**

> **「店を1つも知らないから買えなかった」は破産ではない。** それは [GDD06 §3.1](06-trade-and-negotiation.md) が **在庫不足 / 遠方在庫**の Need に割り当てた状態である(§8.4 の理由コードも「金銭不足 / 困窮」と別である)。**上の条件が資金の項だけを見ているので、これは自動的に除かれる** — 店を知らなければ購入そのものが起きず、切り詰めも発生しない。

**破産しても世帯は解体しない。** §6.3 の段階はすべて世帯の行動であり、④の職業付け替えでも構成員はそのまま残る。

> **②の投げ売りの対象は販売在庫である。** 在庫は世帯在庫(消費財)と工房在庫(生産の入出力)の2本に分かれる([GDD08 §2.2](08-household-and-decision.md) / [TDD01 §3.2](../04-tdd/01-sim-core-and-m0.md))。**世帯在庫の食料と薪まで投げ売ると翌日に困窮が深まるだけ**であり、換金の対象にならない。**工房在庫のうち②が届くのは、売り注文が出ている分(= 販売在庫、§8.1.1)だけである** — ②は提示価格の分岐なので、売りに出していない生産の入力には効かない。

### 6.3 困窮と破産(**決定**)

資金の不足で必需品が買えなくなったとき(**判定の規範は §6.2.2 の破産中フラグ**)、**段階的に対応する**:

| 段階 | 行動 | M0 での形 |
| ---- | ---- | --------- |
| ① | 嗜好品・奢侈品を諦める | **§8.2.1 の余剰資金の帰結。** 規則としては実装しない(下記) |
| ② | **在庫を投げ売る**(最低利幅を諦めて) | **`Trade`(順5)の提示価格の分岐**(§8.1.1) |
| ③ | **掛けで買う**(信用が要る) | **M0 スコープ外。**[GDD01](01-trust-and-conversation.md) 効果2「与信」/ [GDD06 §6](06-trade-and-negotiation.md) |
| ④ | 廃業して職業を変える | **`Household`(順3)の職業付け替え**(下記) |

**破産は退場ではなく職業の変更である。** これは中世都市のリアリティであると同時に、**プレイヤーが救う余地を残す**設計である。v1.0 では③で信用システムが経済的な意味を持ち、④が雇用([GDD10](10-employment.md))と接続する。

> **①は規則ではない。** §8.2.1 の余剰資金(流動資金 − 必要運転資金)が嗜好・奢侈の予算の母数なので、**流動資金が必要運転資金に近づくだけで嗜好の予算は 0 へ向かう**。困窮の判定を待たずに支出が絞られるので、①を別の処理として実装する必要はない。表に残しているのは段階の並びを示すためである。

#### ①〜④の実行位置(**決定**)

**`Household`(順3)で実行するのは ④ だけである。**

```
Trade(順5)の提示価格の決定(§8.1.1)の中で:
    破産中フラグが立っている売り手は、原価下限を「外す」のではなく 500‰ に下げる
        提示価格 = max( ApplyPermille( 原価 , 500 ) ,
                        ApplyPermille( 相場基準 , 価格係数‰ ) )
        通常時の第1項は ApplyPermille(原価, 1000 + 最低利幅‰)(§8.1.1)

Household(順3)の日次処理。
  **手順ごとに全世帯を Id 昇順で回す。世帯ごとに 1→2 を回すのではない。**
  **TDD01 §3.3 順3 の固定支出(仕入)の支払いを済ませてから 1 を始める** —
  流動資金が確定していないと 余剰資金 も破産の判定も決まらない。

  1. 破産中フラグの更新(§6.2.2。前日の購入結果から)

  2. ④へ進む条件(3つすべて):
       a. 破産中フラグが立っている
       b. 販売在庫(§8.1.1)が尽きている      ← ②の投げ売りで換金できるものが無い
       c. 生産が再開できない                  ← 生産停止(§5.1、入力切れまたは工具切れ)
        → 下記「④の付け替え」を実行する

     ※ b だけでは足りない。販売在庫 0 は「売れ残りが尽きた」だけでなく
       「その日完売した」にも成立するので、**完売した健全な世帯が1日の資金不足で廃業する**。
       c が「立ち直れないこと」を表す
     ※ b を工房在庫にしてはならない。生産の入力は売り注文に出ていないので ② では現金化できず、
       工房在庫でゲートすると「鉄鉱石を抱えたまま木炭を買えない鍛冶」が永久に ④ に到達しない
```

**②を順3 の手順にしてはならない。** 投げ売りは `Market` への書き込みであり、順5 の値付け(§8.1.1、全売り手ぶんを一括で書く)と**同じ場所に二重に書くことになる**。順3 で書くと、順5 の `max(原価下限, …)` が同日中に上書きして投げ売りが無効化されるか、[TDD01 §3.2](../04-tdd/01-sim-core-and-m0.md) が「更新前の `Market` の値が**前日の提示価格**である」と宣言した値が当日の投げ売り価格に化けて §8.1.1 の `相場基準` の入力を汚す。**フラグを読んで値付け側で分岐すれば、書き込みは1か所のままである。**

> **「段階的に対応する」を手順の並びで表さない。** フラグが立った世帯に ①〜④ を一息に適用すると、**最初の破産日に必ず廃業まで到達し**、②で立ち直る余地が構造的に消える。§6.3 冒頭が「段階的に対応する」と書き、下の註記が「付け替えが頻発するなら価格機構が働いていない兆候である」と観測に意味を与えているのは、**破産がただちに廃業を意味しない**ことが前提である。
>
> **段階を進める条件に新しい調整軸を足していない。** 3条件はいずれも既にある状態である — フラグ(§6.2.2)、販売在庫(§8.1.1)、生産停止(§5.1)。**「N日連続で困窮したら廃業」とすると閾値が1つ増える**ので採らなかった。

> **投げ売りに床を置くのは、原価下限を完全に外すと提示価格が 1 まで崩落するためである。** `相場基準` には自分の前日の提示価格が入る(§8.1.1)。投げ売りする売り手は在庫が捌けずに積んでいる側なので `価格係数‰ = 500` であり、他の売り手の価格を Q とすると `P[t] ≈ (P[t-1] + Q) / 4` で**不動点が Q/3**、同一品目の売り手が同時にフラグを立てれば毎日半減して `ApplyPermille` の切り上げが効く 1 まで落ちる。**§8.1.1 が「原価下限が消えて半減ループに歯止めがなくなる」と警告した状態を、②が自ら作ることになる。**
>
> **床の 500‰ は新しい係数ではない。** §8.1.1 の `価格係数‰` の clamp の下限と同じ値を使う。**「投げ売りとは、最低利幅を諦めて原価の半分まで下げること」**という意味になり、§12-5(原価を下回る提示価格が**継続**しない)は引き続き「困窮が長引いていないか」を測る指標として働く — 数値的な崩落ではなく経済的な理由で落ちる。

#### ④の付け替え(**決定**)

**M0 では雇用を実装しない**([GDD10](10-employment.md))ため、「他所に雇われる」接続先が存在しない。**M0 に限り、破産した世帯の職業を、担い手の最も薄い職業へ付け替える。**

```
その職業の担い手が自世帯だけなら → 付け替えない(職業を維持する)
そうでなければ:
    候補 = 都市5職業(§2.4)から自職業を除いたもののうち、
           破産世帯の区画に既に同職業の世帯が無いもの(§2.4「同職業2世帯は別区画」を破らない候補)
    候補が空なら → 候補 = 除外前の全職業(区画の重複を許容する。品目の供給停止のほうが優先度が低いため)
    付け替え先 = argmin( その職業の担い手世帯数 )  over 候補
                 同値のときは職業 Id 昇順
```

**「最後の1世帯は付け替えない」が供給の消滅を構造的に防ぐ。** §2.4 は「1品目につき売り手2世帯」を M0 の成立条件としているが、**付け替えを無条件にすると両方の木材加工世帯が離脱して薪の売り手が消え、パンとビールが同時に止まる** — §2.4 が「最初から存在しない」と警告した状態を、破産処理が実行時に作ってしまう。担い手の薄い職業へ流す `argmin` と併せて、職業分布は均等へ戻る方向に働く。

**ただし防いでいるのは担い手 0 だけであり、2 → 1 への減少は防がない。** 担い手が1世帯になった品目は市中価格が1つしか存在しなくなるので、**§12-4(区画間の価格差)はその品目について偽陰性を返す**(§2.4 と同じ理由)。**§12-4 は職業分布と併せて読む** — 差が消えたのか、比べる相手が居なくなったのかを区別する必要がある。

**候補を区画で絞るのは §2.4 の構造制約を保つためである。** 担い手世帯数だけで付け替え先を選ぶと、破産世帯の区画にたまたま既に同職業の世帯があった場合、**§2.4 が成立しないと言った配置(同職業2世帯が同一区画)を実行時に作ってしまう** — §12-4 がその品目について偽陰性を返す。候補が尽きたときだけ例外的に許容する。

**価格や原価から決めない。** 一見「最も儲かっている職業へ」が自然だが、整数除算では比が潰れて `argmax` が事実上「職業 Id 昇順」に退化する。**担い手世帯数は `World` から直接数えられ、除算も価格観測も要らない。** これは NPC の意思決定ではなく、**空いた親方の座を割り当てる世界側の処理**である(史実ではギルドが親方昇格を統制していた → 分冊07)。

- **世帯は解体しない。** 世帯主の職業が変わるだけである。**販売在庫は②の投げ売りで既に現金化されているが、生産の入力として抱えていた工房在庫は残る**(②は売り注文にしか効かない、§6.2.2)。M0 では旧職業の入力を売りに出す経路が無いので滞留する
- **流動資金は補填しない。** 貨幣量を外から増やすと §10 の自動調節と §12-6 の判定が濁る
- 同値の処理を Id 昇順で固定するのは列挙順規約([ADR-0002](../adr/0002-time-model-and-determinism.md))による

> **M0 に救済経路を置かないのは、置くと測定器が濁るからである。** §12-2(困窮世帯の割合)と §12-6(貨幣総量)は、「経済が回っているか」ではなく「救済の強さ」の関数になりうる。**M0 の目的は測定であって救済ではない。**「資金が尽きた鍛冶が止まり §12-3 が落ちる」ことは、**W2 で得たい観測そのものである。**
>
> **v1.0 では③(掛け売り)と質屋・両替商が再建の役割を担う。** 与信と雇用が揃えば、別途の救済機構は要らない。
>
> 職業分布が動くため §12-3(生産チェーンが止まらないか)の観測が豊かになる。**逆に付け替えが頻発するなら、価格機構が働いていない兆候である。**

## 7. 雇用 → [GDD10](10-employment.md)

**M0 では雇用を実装しない。** 親方 / 職人 / 徒弟の3階層、給金、雇用の増減、解雇された職人の行き先は [GDD10](10-employment.md) が持つ。

**M0 で固定されるのは労働力である** — 雇用の増減が無いので世帯の構成員と階層が変わらず、労働力合計‰ が 1300 で動かない(§5.2)。M0 で見たいのは価格機構であり、雇用は変数を増やすだけである。

> **設備は固定しない。** 工具は摩耗し(§5.3)、設備係数が動くので生産量も動く。**工具は M0 で唯一の耐久財**であり、耐久の予算(§8.2.1 の `min`)と「工具切れ」の Need(§8.4)を検証する唯一の経路なので、ここを固定すると M0 の検証項目が1本落ちる。

**ただしデータモデルには雇用関係を最初から持たせる。** 後付けは `World` の区分追加になり、決定論ハッシュの更新([TDD01 §3.8](../04-tdd/01-sim-core-and-m0.md))が要るため。

## 8. 価格形成

### 8.1 提示価格(**決定**)

売り手が「いくらで並べるか」。妥結価格は分冊06。

**在庫圧力 + 原価下限**を基準線とする:

```
提示価格 = max( ApplyPermille(原価, 1000 + 最低利幅‰) , 在庫圧力調整後の価格 )
```

- **原価は移動平均**とする。直近仕入値だと一度の高値づかみで提示価格が跳ねる
- **初期配置で与えるのは、初期在庫の取得原価である。** 移動平均なので初日は標本が無い。**取得原価を与えれば移動平均の初期値が決まり、初日の提示価格は原価下限になる**(§8.2.7)。**与えないと初日の原価が 0 になり、§8.1.1 が「0 が恒久に固定される」と警告している経路を初日に踏む。** 初期価格そのものを別に決める必要は無い

#### 8.1.1 更新式(**決定**)

```
在庫比‰   = CeilDiv( 1000 × 販売在庫 , 出荷目標在庫 )
価格係数‰ = clamp( 1500 − CeilDiv(在庫比‰, 2) , 500 , 1500 )
提示価格  = max( ApplyPermille(原価, 1000 + 最低利幅‰) ,
                 ApplyPermille(相場基準, 価格係数‰) )

原価 = 財の投入がある職業 → CeilDiv( Σ_j(入力 j の仕入れ移動平均単価 × 必要数量_j) , 出力数量 )
       財の投入が無い職業 → ApplyPermille( 機会費用_親方(1時間あたり) × 可処分時間T, 所要労働‰ )
```

**M0 の5職業はすべて「財の投入がある職業」である。** 下の分岐は [GDD11](11-external-trade.md) の貿易商と [GDD12](12-countryside-and-fairs.md) の農村職業が戻ったときに発火する。**それでも本書に置くのは、値付けの式を分冊間で割らないためである**([process/03](../process/03-corrections.md) — 同じ主張が複数層に散ると訂正が届かなくなる)。

**財の投入がある職業の原価は「出力1単位あたり」に正規化する。** 複数入力(パン=小麦粉+薪、ビール=穀物+薪、工具=鉄鉱石+木炭)は仕入れ移動平均単価 × 必要数量の合計を、出力数量で割って1単位分に均す。**この除算は切り上げる**([GDD01 §2.3](01-trust-and-conversation.md) の原則どおり。切り上げても提示価格が上がる方向にしか効かず、§8.1「原価は移動平均」の保守性と整合する — §5.2・派生需要の「保証を守るため切り下げる」例外とは向きが逆であることに注意)。

**財の投入が無い職業の原価は、投入した労働の機会費用である。** レシピに入力を持たない職業は、財の移動平均としての原価が **0** になる。素直に適用すると提示価格が 0 になり、**その品目の売り手が全員そうなら `相場基準` も 0 にしかならず、0 が恒久に固定される** — そこから下流の原価が移動平均で 0 へ向かい、原価下限が消えて `相場基準 × 500‰` の半減ループに歯止めがなくなる。機会費用は職業 × 階層の定数([GDD08 §9](08-household-and-decision.md))で**必ず正**なので 0 にならず、所要労働はレシピが持つ(§2.3)。**代表値は親方(階層係数1000‰)を採る** — GDD08 §9 の機会費用は職業別の基準値に階層係数を掛ける形であり、親方は階層係数1000‰なので「職業別の基準値」と一致する。`所要労働‰`(§5.2、1000‰ = 親方1人日相当)と単位を揃えるため、機会費用(1時間あたり)に**可処分時間T**([GDD08 §3.1](08-household-and-decision.md)、初期値12時間)を掛けて「1人日あたりの金銭価値」に変換してから `ApplyPermille` で所要労働ぶんに按分する。

| 販売在庫 | 価格係数‰ | 意味 |
| -------- | --------- | ---- |
| 0 | 1500 | 品薄。相場の1.5倍 |
| 出荷目標在庫 | 1000 | **相場どおり** |
| 出荷目標在庫 × 2 以上 | 500 | 溢れている。相場の半値 |

> **`価格係数‰` の式は減算の中に `CeilDiv` を持つため、式全体としては切り下げ方向になる(在庫比‰ が奇数のとき係数が1‰小さくなる)。これは意図的である。** 在庫比を切り上げてから引くことで、品薄側(在庫比が小さいとき)ではなく充足側(在庫比が大きいとき)に1‰の誤差が寄る。値付けが**品薄側へ偏る**ほうが §4.1(情報の摩擦)・§8.2.4(不当価格が起き得る場所)の設計意図に沿うため、[GDD01 §2.3](01-trust-and-conversation.md) の「全計算式切り上げ」の原則をここでは字面どおり在庫比‰ の算出にだけ適用し、係数全体には及ぼさない。

##### 相場基準(**決定**)

**`相場基準` は、その品目についての有効な観測(`PriceObservation`)から作る。** 売り手の値付け(§8.1.1)と買い手の予算(§8.2.1)は同じ規約で作る。

- **誰の観測かは世帯主(親方)である。** 知識は個人が持つ([TDD01 §3.2](../04-tdd/01-sim-core-and-m0.md) は `Knowledge` を **NpcId 別**とする)ので、世帯の誰の観測を読むかを決めないと値が定まらない。**買い物に行くのが徒弟でも、値付けと予算に使うのは世帯主の観測である**
- **売り手ごとに最新の1件だけを採る。** 有効な記憶([GDD06 §3.1](06-trade-and-negotiation.md))には同じ売り手の複数日ぶんが入るので、レコード単位で平均すると**よく見る売り手ほど重みが増す**。**下の交互振動の導出も、前日の値だけで決まる1次の差分方程式であることに立っている**
- **平均の規約: 合計を件数で割り、[GDD01 §2.3](01-trust-and-conversation.md) の原則どおり切り上げる**(`CeilDiv`)
- **有効な観測が0件なら相場基準は立たない**(§8.2.7 のフォールバックへ落ちる)。**0 を平均に混ぜるのではない**

**売り手の値付けに限り、自分の前日の提示価格を観測とは別に1件として加える。ただし他の売り手の観測が1件以上あるときに限る**([GDD06 §3.1](06-trade-and-negotiation.md))。**自分の前日の提示価格が存在しない日(初日、前日に売り注文を出していない日)は、集合に加えないだけである — 0 を足すのではない。** 買い手側の予算(§8.2.1)には混ぜない。

> **自分を除くと、売り手2世帯のあいだに交互振動モードが残る。** 互いの前日価格だけを錨にすると遷移行列の固有値が ±√(k_A·k_B) になり、**高値の日と安値の日が交互に続く**。自分を含めると行列の行が同一になり、この固有値が 0 に落ちる。**旧版はこれを「入れると複利で発散する」として却下していたが、その理由は誤っていた** — 自分を除いても両者が品薄なら同じく1日1.5倍で複利発散する。自分を除いて得られていたのは交互振動モードだけだった。
>
> **ただしこの導出は線形近似の下でのみ成り立つ。** 両売り手の `価格係数‰` が同一で、その日在庫が動かないという近似に立っている。実際の係数は在庫で毎日動くので、**残留する交互成分がどれだけあるかは実測でしか分からない**(§12-1)。
>
> **「他の売り手の観測が0件のときは自分も使わない」が、旧版の懸念の有効な部分である。** R = 1 では相手の売り手が見えない日が普通に起きる。そこで自分だけを錨にすると**純粋な自己ループ**が本当に成立する。そのときは相場基準を立てず、原価下限をそのまま提示価格にする(§8.2.7)。

##### 販売在庫と出荷目標在庫(**決定**)

**`販売在庫` は、工房在庫のうち売り注文として `Market` に出している分である。生産職では自分のレシピの出力在庫の全量がこれにあたる**(出力を手元に残す規則を M0 では置かない)。 在庫は世帯在庫(消費財)と工房在庫(生産の入出力)の2本に分かれる([GDD08 §2.2](08-household-and-decision.md) / [TDD01 §3.2](../04-tdd/01-sim-core-and-m0.md))が、**販売在庫はそのどちらとも別の切り口であり、工房在庫の部分集合である** — 生産の入力として抱えている分は売りに出ていない。§6.3② の投げ売りも④のゲートも §10.2 の輸出も、**届くのは販売在庫だけである**。

**`出荷目標在庫` は品目 × 職業ごとの定数とする**(初期値。§13「値として残っているもの」)。生産量や定格から導出しない。

> **導出にすると定義依存と零除算が同時に来る。** 生産が停止している工房(§5.1)では導出元が 0 になり、在庫比‰ の分母が消える。**定数にすれば、停止中の工房も「まだ目標に届いていない」と正しく判定される。**

### 8.2 予算(**決定**)

**予算は需要だけで決まる。** 店ごとの事情(距離・信用・提示価格)は入れない — それは**実質コスト**であり、分冊06 が持つ(§8.2.5)。

```
予算 = 用途別の基礎値 × 買い手の在庫圧力‰ ÷ 1000
```

**予算は1つ。実質コストは店ごとに異なる。** 買うのは「実質コストが最も安い店」で、かつ「その実質コストが予算以下」のときである。

#### 8.2.1 用途別の基礎値と目標在庫

| 用途 | 基礎値 | 目標在庫(初期値) | M0 の該当品目 |
| ---- | ------ | ------------------ | ------------- |
| **生産の入力** | **派生需要**(出力の見込み売値から逆算) | 1日分の使用量 × 仕入れ間隔(日) | 穀物・木材・鉄鉱石・木炭・小麦粉・薪 |
| **必需の消費** | **相場基準**(§8.1.1 の平均の規約 × 許容乖離‰) | 薪: 1週間分(1日消費量は季節変動、§9)<br>パン: 3日分 | パン・薪 |
| **嗜好・奢侈の消費** | **予算比率**(**余剰資金** × 比率‰。階層で変える。下記) | ビール: 1日分 | **ビール**(奢侈は M0 に無い) |
| **耐久の消費** | **min(相場基準, 予算比率)**(予算比率の母数は**流動資金**) | 工具: **耐久値の500‰ × 階層係数** | 工具 |

**基礎値の意味**:

- **生産の入力**: 利益が出る値段でしか買わない
- **必需**: 余程の急騰でない限り相場に追随し、目標在庫まで買う。安ければさらに買い溜める
- **嗜好・奢侈**: 余剰があるときだけ買う
- **耐久**: **`min` を取ることが要点である。** 相場を知っていても資金がなければ買えず、資金があっても相場より高くは買わない

> **耐久財に予算比率を入れたのは、徒弟が自分の財布を持たないためである**([GDD08 §2.1](08-household-and-decision.md))。世帯の流動資金の一定比率(初期値10‰)までなら買える、とすることで**下の階層にも耐久財が届く**。同じ条件を全階層に適用する。

**耐久財の在庫は「個数」ではなく「耐久値」である。** 時間経過と生産で摩耗し(§5.3)、在庫が減る。目標在庫が `耐久値の500‰ × 階層係数` なので、**最下層の NPC は製品寿命の半分で目標在庫に達し、在庫圧力が 1000‰ になる**。階層が高いほど複数個を持とうとする。

##### 運転資金と余剰資金(**決定**)

**嗜好・奢侈の予算の母数は流動資金ではなく余剰資金である。** 流動資金をそのまま母数にすると、**明日の仕入に要る金がそのまま遊興費の原資になり、黒字倒産(資金繰りだけを原因とする破産)が起きる。**

```
必要運転資金 = Σ_(用途,品目) ( 目標在庫[用途,品目] × 相場基準[品目][前日] )
               走査するのは (生産の入力, 品目) と (必需の消費, 品目) の組すべて
               相場基準が無い品目は加算しない(下記)

余剰資金     = max( 0 , 流動資金 − 必要運転資金 )

嗜好・奢侈の基礎値 = ApplyPermille( 余剰資金 , 用途別の予算比率‰ )
```

- **新しい調整軸は1つも増えない。** `目標在庫` は上の表が既に用途 × 品目ごとに持っており、**そこに「何日ぶん持ちたいか」が入っている。必要運転資金は「持ちたい在庫を今の相場で買い揃えるのに要る額」である**
- **走査の単位は品目ではなく(用途, 品目)の組である。** `目標在庫` は用途別にしか定義されていない。**薪はパン屋・醸造にとって生産の入力であると同時に家庭の必需でもあり、在庫も2本に分かれている**([TDD01 §3.2](../04-tdd/01-sim-core-and-m0.md))。品目単位で畳むとどちらの目標在庫を採るかが実装任せになり、**生産用の薪が運転資金から丸ごと落ちて、この規則が防ぐはずの黒字倒産が生産世帯でだけ戻る**
- **現在の在庫は差し引かない。** 「これから買い揃えるのに要る額」にすると、在庫が満ちた日に必要運転資金が 0 に落ちて余剰資金が跳ね、嗜好に流れ、翌日の仕入で資金が尽きる — **黒字倒産が周期的に戻る**。必要運転資金は毎日の差額ではなく、**在庫を回し続けるために常時寝かせておく額**である
- **前向きの量であることが要点である。** 過去 N 日の実支出の移動平均で定義すると、**支出できていない世帯ほど必要額が小さく出る** — 困窮して仕入を止めた世帯ほど「運転資金は要らない」と判定され、**余剰資金が大きく出て嗜好に回る**。目標在庫は実績に依存しないのでこの縮退が起きない
- **前日の相場基準を使う。** 当日の値を使うと、予算が当日の支出に依存し、その支出が予算から決まる日内の循環になる([GDD08 §6.3](08-household-and-decision.md) の1日遅延の成層化)。**本書のすべての `相場基準` は前日までの有効な観測から作る**
- **相場基準が無い品目は加算しない。§8.2.7 のフォールバックを使ってはならない。** フォールバックは `ApplyPermille(流動資金, 比率‰)` なので、**必要運転資金が流動資金の関数になり、`余剰資金 = 流動資金 − 必要運転資金` が自己参照する**。加算しないぶん必要運転資金は小さめに出るが、**それは「相場を知らない品目のぶんは取り置かない」という素直な意味になる**
- **除算は現れない。** 目標在庫(整数)× 相場基準(整数)の総和であり、丸めの向きを決める必要が無い
- **必需(§8.2.7 のフォールバック 50‰)と耐久(`min` の予算比率側 10‰)の母数は流動資金のままである。** ここを余剰資金に倒すと、**困窮した世帯が食料を買えなくなり、困窮した鍛冶が工具を買えず設備係数(§5.3)が 0 に落ちて恒久停止する。守りたいのは「生産と生活の継続」であり、工具はその継続そのものである**
- **生産の入力(派生需要)も母数を持たない**(下記のとおり出力の見込み売値から逆算する)ので影響を受けない

> **この規則は嗜好の需要を構造的に細らせる。** `必要運転資金` は**現在の在庫を差し引かない**ので、在庫が満ちた健全な世帯でも同じ額が恒久的に控除される。**都市世帯のビールの買い手が細ると、§12-3(生産チェーンが止まらないか)が醸造について実質的に不通過になりうる。** 自明な対策(現在在庫ぶんを差し引く)は上記のとおり採らない。残る調整手段は嗜好の予算比率‰ と目標在庫の値であり、**W2 で醸造が成立するかを実測する**(§12-3)。

##### 派生需要の算出(**決定**)

**生産の入力の基礎値は、出力の見込み売値から逆算した「利益が出る上限単価」である。** レシピが複数入力を持つ場合(パン=小麦粉+薪、ビール=穀物+薪、工具=鉄鉱石+木炭)、その上限を入力どうしでどう配分するかを定義する。

```
見込み収益        = 提示価格_出力[前日] × 出力数量
許容原価合計       = floor( 見込み収益 × 1000 ÷ (1000 + 最低利幅‰) )

観測が無い入力 j(相場基準_j[前日] が計算できない)には、按分に加える前に
    派生需要(入力 j の基礎値) = ApplyPermille( 流動資金, 必需の予算比率‰ )    ← §8.2.7 のフォールバックそのもの
    フォールバック仕入見込み_j = 派生需要(入力 j の基礎値) × 必要数量_j
を確定し、按分の対象から外す。

残余原価合計 = max( 0, 許容原価合計 − Σ_{フォールバックに落ちた j} フォールバック仕入見込み_j )
    ← フォールバック入力のぶんを先に差し引く。按分対象(J)に全額を渡さない

残った(観測がある)入力の集合を J とする:
    入力 j∈J の見込み単価配分 = 相場基準_j[前日] × 必要数量_j
    入力 j∈J の配分予算       = floor( 残余原価合計 × 見込み単価配分_j ÷ Σ_{k∈J} 見込み単価配分_k )
    派生需要(入力 j の基礎値)  = floor( 入力 j の配分予算 ÷ 必要数量_j )

J が空(全入力が観測無し、または提示価格_出力[前日] 自体が無い)なら、
全入力についてフォールバックのみを使う(按分の式を評価しない。残余原価合計も使わない)。
```

- **フォールバック入力のぶんを先に差し引くのは、按分に残った入力へ全額を渡さないためである。** 差し引かないと、観測できた入力だけが「本来2入力で分けるはずだった上限」を丸ごと受け取り、その日の入力購入の合計に事実上の上限が無くなる — `最低利幅‰` の保証が、観測が部分的に欠けた日にだけ破れることになる
- **入力が1つしかないレシピ**(水車小屋番・木材加工)で J が非空なら `Σ_{k∈J} = 見込み単価配分_j` なので、`派生需要 = floor(残余原価合計 ÷ 必要数量)` に一致する(このケースはフォールバック対象が無いので `残余原価合計 = 許容原価合計`)
- **すべての除算を切り下げる。** `floor(A × w_j ÷ W)` を J 内で合計すると必ず `A` 以下になる(整数の性質)。J 内の合計とフォールバック入力の合計を足しても `許容原価合計` を超えない。**途中で ‰ 表現の按分比を経由すると、切り上げヘルパー `ApplyPermille` が入力ごとに端数を切り上げてしまい、合計が `許容原価合計` を超えうる**(実現利幅が `最低利幅‰` を下回る)。§5.2 と同じ「保証を壊さない側に丸める」例外であり、**ここでは中間に ‰ を挟まず直接比例配分する**ことで二重丸めを避けている
- **前日の観測を使うのは §8.2.7・[GDD08 §6.3](08-household-and-decision.md) と同じ1日遅延の成層化である。** 当日の価格を参照すると同一tick内で循環する
- **観測が無い入力を按分から外すのは、零除算(`Σ_{k∈J} = 0`)と恒久停止を同時に塞ぐためである。** 視界半径 R=1([GDD06 §3.1](06-trade-and-negotiation.md))では、パン屋から見て水車小屋番・木材加工がともに距離2以上に居ることが普通に起きる。全入力が観測無しなら按分そのものを評価せず、**初日に限らずいつでも**フォールバックへ倒す
- 新しい調整軸は増えない。**`最低利幅‰` は既存(§8.1)、配分予算は完全に導出値、フォールバックは §8.2.7 の必需の予算比率‰ を流用する**

> **派生需要は正のフィードバック経路を1本作る** — 派生需要 → 仕入値 → 原価の移動平均 → 提示価格 → 翌日の派生需要。**§12-1 の安定性検証で、売り手の共通モード(下記)と併せて見る。**

##### 目標在庫の「N日分」は先読みで数える(**決定**)

**目標在庫は「N日 × 現在の1日消費量」ではなく、「今後 N 日に消費する予定の量の合計」とする。**

```
目標在庫 = Σ( 消費量[d] )      d = 今日 … 今日 + N − 1
```

**`消費量[d]` は日ごとに季節係数を適用して切り上げた整数であり、それを足す。** 合計してから切り上げるのではない。薪のように季節係数が掛かる品目では、丸め順で結果がずれる。

- **季節の境をまたぐと自然に前倒しで積み上がる。** 冬が近づくにつれ薪の目標在庫が滑らかに上がり、在庫圧力が上がり、予算が増える — **冬支度が規則ではなく帰結として現れる**
- 季節変動しない品目(パン)では `N × 1日消費量` と一致する。**式が分岐しない**

> **§8.2.2 が現在庫の側で既に採っている「買い物に行く時点で予想される在庫」と、同じ発想を比較の反対側(目標)に当てたものである。** 両側が先読みになっても**調整軸は増えない** — 変わるのは N の意味だけで、N は元から品目ごとの調整軸である。
>
> **当日の季節の消費量をそのまま使うと、冬に入った瞬間に全世帯の目標在庫が同時に跳ねる。** §8.2.3 が警告する「売り手と買い手の在庫圧力が同位相で動く」振動を、季節が毎年4回叩き込むことになる。

#### 8.2.2 買い手の在庫圧力(**決定**)

**上限倍率は2倍固定とする。**

```
在庫 ≤ 目標在庫:
    在庫圧力‰ = 1000

目標在庫 < 在庫 ≤ 目標在庫 × 2:
    在庫圧力‰ = CeilDiv( 1000 × (2 × 目標在庫 − 在庫) , 目標在庫 )

在庫 > 目標在庫 × 2:
    在庫圧力‰ = 0
```

変動幅は **0〜1000‰**。目標在庫までは 1000‰ で据え置き、そこから線形に 0 まで落ちる。

> **上限を 1000‰ に固定し、目標在庫まで据え置くことが重要である。** 基礎値を「安定して機能する信頼できる値」に保つため。
>
> **1000‰ を超えられるようにすると**、原材料では派生需要(利益が出る上限)を超えて買うことになり、**赤字の原価で仕入れが発生する**。奢侈品でも予算比率が後から変動してしまう。**基礎値の意味が壊れる。**

**これは §8.1 の売り手側在庫圧力の鏡像である。** 売り手は在庫が多ければ提示価格を下げ、買い手は在庫が多ければ予算を下げる。**両側で1つの概念**であり、調整軸は品目ごとの目標在庫だけで済む(上限倍率は固定なので軸にならない)。

##### 買い物に行く時点の予想在庫を使う

**在庫圧力の計算には、現時点の在庫ではなく「買い物に行く時点で予想される在庫」を使う。**

```
予想在庫 = 現在庫 − (買い物までに予定されている消費・生産投入)
```

> **これが時間の摩擦(§4)の正しい表現である。** 買い物に行くまでに食事や生産を予定しているなら、そのぶん予想在庫が減り、在庫圧力が上がり、予算が増える — **「在庫を切らす前に店へ行けない」状況が、緊急性として自然に価格へ現れる。**
>
> **待ち時間を費用として数えてはならない。** 待っている間は他の仕事ができるので、実際に時間が奪われるわけではない。摩擦は**偽の費用**ではなく**本物の緊急性**として表す。

#### 8.2.3 複数単位を買う場合

**判定基準はその商品を買う**前**の在庫量である。** 2単位目以降は、直前までの購入分を加えた在庫量で在庫圧力を算出する。

**ただし式は線形なので、反復せずに一度で購入量を解ける。** 実装はこちらを推奨する:

```
実質コスト > 基礎値            → 購入量 0
実質コスト ≤ 基礎値:
    到達在庫 = 2 × 目標在庫 − CeilDiv( 目標在庫 × 実質コスト , 基礎値 )
    購入量   = max( 0, 到達在庫 − 予想在庫 )
```

検算:

| 実質コスト | 到達在庫 | 意味 |
| ---------- | -------- | ---- |
| = 基礎値 | 目標在庫 | 相場どおりなら目標在庫まで買う |
| = 基礎値 × 1/2 | 目標在庫 × 1.5 | **安ければ買い溜める** |
| > 基礎値 | — | 買わない |

**最終的な購入量は §6.2.1 の資金上限でさらに切り詰められる。**

##### 需要曲線は創発する。書かない

各買い手の予算が在庫で下がるなら、**集計レベルの需要曲線は自動的に右下がりになる** — 価格が下がれば「買う人」も「1人あたりの量」も増えるためである。

**したがって個体に需要関数を持たせない。** 個体の意思決定は上の線形解だけで、方針4(満足化)と方針2(観測可能性)を保てる。**需要曲線を仮定するのではなく創発させるのが、エージェントベースの正しい使い方である。**

##### 得られるものと代償

| 利点 | 内容 |
| ---- | ---- |
| **買い溜めと買い控え** | **商人ゲームの中核行動が NPC 側にも生まれる。** プレイヤーの投機(§9)に市場が応答する |
| 概念が増えない | 売り手側(§8.1)と同じ機構 |
| **価格の安定** | 必需品の需要が完全非弾力だと供給不足時に価格が青天井になる。**在庫のある者が買い控えることで需要が自動的に減る** |
| 貯蔵性が意味を持つ | 貯まる品目(薪)と貯まらない品目(パン)の差が経済に効く |
| 会話の素材 | 「うちはまだ薪があるからね」。**買わない理由をプレイヤーに説明できる** |

| 代償 | 対応 |
| ---- | ---- |
| 溜め込みの縮退 | **上限倍率2倍で在庫圧力が 0 になる。** 腐敗を明示的に入れずに済む(§13) |
| 在庫を置く場所が要る | 世帯在庫と工房在庫の2本([GDD08 §2.2](08-household-and-decision.md) / [TDD01 §3.2](../04-tdd/01-sim-core-and-m0.md))。**W1 の `NpcState.Inventory` は W2 で廃止**し、`HouseholdState` へ移す |
| **振動の増幅** | 売り手と買い手の在庫圧力が同位相で動くと「安い→買い溜め→在庫増→買い控え→売れない→さらに安く」が起きうる。**§12-1 の安定性検証で見る** |

#### 8.2.4 不当価格はどこで成立するか

予算を相場基準にすると、NPC は相場から離れた値を「買わない」だけになる。では [GDD01 §4.5](01-trust-and-conversation.md) の不当価格はどこで起きるか。**2つの経路が残る**:

1. **相場観が古い、または無い**(情報の摩擦、§4)。新しく来た NPC、久しく買っていない品目では `PriceObservation` が薄い。そのとき高値を掴み、**後から相場を観測して「あれは不当だった」と気づく** — §4.5 の「取引tick近傍の観測入手による気づき」そのものである
2. **在庫が尽きかけて予算が最大(1000‰)になっている**。これは**正当な緊急性**であり、プレイヤーが「足元を見る」余地でもある

**1が誤爆の源であり、2は仕様である。** [GDD01 §6](01-trust-and-conversation.md) 検証項目5 の誤爆率は、**2を1と誤判定する率**として測る。

> **不当価格が「困窮という異常時」ではなく「情報の非対称という平常時の構造」から生まれることが重要である。** 本作の USP「情報を足で稼ぐ」に直結する。

#### 8.2.5 予算と実質コストの役割分担(**重要**)

**便益と費用を分ける。**

| | 予算(払える上限) | 実質コスト |
| -- | ------------------ | ---------- |
| **何を表すか** | **便益**。その品をどれだけ欲しいか | **費用**。手に入れるのに実際いくらかかるか |
| **決まり方** | 需要のみ(基礎値 × 在庫圧力) | 提示価格 + 信用による割引 + 移動の機会費用 |
| **いくつあるか** | **1つ** | **店ごとに1つずつ** |
| **どこが持つか** | **本書 §8.2** | **分冊06** |

**購入条件**:

```
信用を考慮した実質コストが他のどの店よりも安く、
かつ その実額が予算以下 であるとき、その店で買う
```

> **旧版は機会費用による上乗せを予算の側に入れていた。誤りである。** 実質コストにも機会費用が入るため**二重計上**になり、かつ「店ごとに異なるもの」を「1つしかない予算」に混ぜていた。**便益と費用の分離が正しい**([process/03](../process/03-corrections.md) 規則6 — 却下理由ではなく設計そのものの訂正)。
>
> **時間の摩擦は §8.2.2 の予想在庫へ、空間の摩擦は分冊06 の移動の機会費用へ**、それぞれ1か所だけに置く。
>
> **予算には流動資金が入っていない。** 資金の制約は §6.2.1 が購入量の側で掛ける。**「予算が足りない」と「資金が足りない」は別の事象であり、§6.2.2 の破産中フラグが拾うのは後者だけである。**

#### 8.2.6 M0 でどこまで実装するか(**決定**)

**機会費用は職業 × 階層の固定値とする**(算出方式は [GDD08 §5](08-household-and-decision.md)、M0 スコープと階層係数は [GDD08 §9](08-household-and-decision.md))。

構造(予算と実質コストの分離、在庫圧力、線形解)は M0 から入れる。**構造を先に固定し、値の由来を後から差し替える**のは §9(季節係数)と同じやり方である。

#### 8.2.7 相場観が無いときの予算(**決定**)

**相場基準は有効な観測の平均から出る**(§8.1.1)。観測が1件も無ければ計算できない。**これは初日だけの問題ではない** — 保持期間を過ぎた品目、久しく買っていない品目でも起きる(§8.2.4)。したがって初期観測を配るのではなく、**規則として定義する**。

```
相場基準が計算できないとき:
    基礎値 = ApplyPermille( 流動資金 , 用途別の予算比率‰ )
```

| 用途 | 観測ゼロ時の基礎値 |
| ---- | ------------------ |
| 生産の入力 | **入力ごとに、その入力の観測が無ければ影響を受ける**(§8.2.1「派生需要の算出」)。初日(出力自体の前日価格が無い)はすべての入力がこれに該当する |
| **売り手の提示価格**(§8.1.1) | **原価下限がそのまま提示価格になる。** `max` の第2項が消えるだけで式は分岐しない |
| 必需の消費 | **予算比率へフォールバックする**(初期値 50‰) |
| 嗜好・奢侈の消費 | **影響を受けない。** 元から予算比率(母数は**余剰資金**、§8.2.1) |
| 耐久の消費 | `min(相場基準, 予算比率)` の相場基準側が落ち、**予算比率のみになる**(既存の 10‰。母数は**流動資金**、§8.2.1) |

**新しい機構を持ち込んでいない。** 既に §8.2.1 の表にある「予算比率」へ倒すだけであり、増える調整軸は必需品の比率‰ の1つである。

> **この規則は §8.2.4 の不当価格の発生源そのものである。** 相場を知らない NPC は「流動資金の範囲でなら払ってしまう」ので、**高値を掴み、後から相場を観測して気づく**。フォールバックを穴埋めとしてではなく、**情報の摩擦が価格に現れる正規の経路**として置いている。
>
> **初期観測を配らないのはこのためである。** 配ると初日だけ穴が塞がり、保持期間で観測が失効した NPC が後から同じ穴に落ちる。**規則にすれば初日を特別扱いせずに済む。**

**買い手がそもそも店を1つも知らない場合は、予算ではなく Need になる** → [GDD06 §3.1](06-trade-and-negotiation.md)。

### 8.3 需要の表現

**需要曲線は作らない。** NPC は「必要量」と「払える上限」(§8.2)を持つだけで、価格に応じて量を連続的に変えることはしない(方針4)。

- 必需品: 必要量は固定。払える上限まで買う。買えなければ §6.3 へ
- 嗜好・奢侈品: 払える上限を超えたら**買わない**(量は0か固定量)
- 耐久財: 摩耗したときだけ需要が立つ

これで十分に価格は動く(在庫が捌けなければ売り手が下げ、買い手は在庫が満ちれば買い控える)。**個体に需要関数を導入すると、価格の因果が式の中に隠れて追えなくなる**(方針2)。

**集計レベルの需要曲線は §8.2.3 の在庫圧力から創発する。書かない。**

### 8.4 Need への接続

不足は [GDD01 §3.2](01-trust-and-conversation.md) の Need として表面化する。**Need が経済とコアループの結節点である。**

| 発生源 | Need 種別 | 理由コード |
| ------ | --------- | ---------- |
| 生産の入力切れ(§5.1) | 在庫不足 | 生産停止 |
| 必需品が買えない(§6.3) | 金銭不足 | 困窮 |
| 労働力不足(§5.2) | 労働力不足 | 増産できない |
| 設備の摩耗(§5.3) | 在庫不足 | 工具切れ |
| 区画をまたぐ運搬が要る(§4) | 在庫不足 | 遠方在庫 |

> **これが [TDD01 §3.6](../04-tdd/01-sim-core-and-m0.md) の仮決め「`Need.TypeCode` / `ReasonCode` を enum にする」への答えである。** 上表の左2列が種別、右列が理由コードの初期集合になる。

## 9. 季節との接続

**本書が値を持つと二重管理になる。** 値は [GDD03 §2](03-seasons-and-city.md) が持つ — **消費側(薪)は §2.1 で確定済み、生産側(外部価格)は未着手**である。

| 何を | どちらが持つか |
| ---- | -------------- |
| 季節係数の**構造**(どのレシピ・どの消費が季節に依存するか) | **本書** |
| 季節係数の**値**と、季節そのものの定義 | **GDD03** |

構造だけ本書で決める:

- **消費の季節性**: 薪のみ季節係数を持つ
- **生産の季節性**: M0 に1次産品の生産者は居ない(§2.2)ので、生産側に季節係数は掛からない。**季節性は都市外価格(§10)が担う**
- 係数は千分率の整数。**GDD03 が値を持つ**

> **1次産品の季節性を「価格」として表すのは、M0 で供給側が抽象化されていることの帰結である。** 穀物が秋に安く春に高いなら、**次の収穫までの在庫繰りがゲームになる。保存と投機**は本作の商人像と非常に相性がよい。**供給量の季節変動として表す形は [GDD12](12-countryside-and-fairs.md) が持つ**(農村 NPC が季節に一度だけ売りに来る)。

## 10. 都市外市場 — 価格の錨と貨幣の出入り(**決定**)

### 10.1 なぜ閉じた経済にしないか

[GDD01 §6](01-trust-and-conversation.md) の M0 検証項目2 は「長期実行して価格が発散・硬直しないか」である。**この判定を通せるかは、貨幣のソースとシンクの設計でほぼ決まる。**

- **完全に閉じた系**(貨幣総量が一定): 価格の絶対水準が動かない。錨が無いので、すべての価格が相互参照だけで決まり、**どこへ漂流しても「安定している」と読めてしまう**
- **シンクだけがある系**: 貨幣が枯渇し、全 NPC が困窮する

**M0 は都市外市場を1つだけ置くことで、錨とソースとシンクを同時に得る。**

### 10.2 M0 の都市外市場

**`World` 側の主体である。世帯ではない。** 在庫・帳簿・流動資金・家計を持たず、**無限の相手方**として振る舞う。区画は**中心(Id 4)に固定**する。

**売り注文を `Market` に実体化しない(決定)。** [TDD01 §3.2](../04-tdd/01-sim-core-and-m0.md) の `Market` のキーは売り手**世帯**であり、**都市外市場は世帯ではないのでそこには入らない**。代わりに、**買い手の店選択([GDD06 §3.1](06-trade-and-negotiation.md))が、中心区画について外部価格から候補を1件合成する。**

- **`Market` の型と決定論ハッシュの契約が動かない。** 外部価格は設定と暦から決まる定数であって状態ではないので、レシピ表や距離と同じくハッシュの対象外である([TDD01 §3.8](../04-tdd/01-sim-core-and-m0.md))。**実体化すると「`Market` は含める / 窓口は含めない」という二重定義が生まれ、しかもどちらに実装しても同一設定の2回実行は一致するので CI が検出しない**
- **売り手 Id を予約する。ただし `PriceObservation` に売り手の欄はまだ無い。** [GDD01 §4.1](01-trust-and-conversation.md) の定義は `item / location / price / observedAt / source` で、`location` は**区画**であって売り手ではない。**§8.1.1 の「売り手ごとに最新の1件」も [GDD06 §3.1](06-trade-and-negotiation.md) の「有効な記憶」も売り手の同定を要求するので、欄を足す必要がある**([TDD01 §3.6](../04-tdd/01-sim-core-and-m0.md) の仮決め表が引き継ぐ)。**足したうえで、既存の世帯 Id と衝突しない非負 int を1つ、どの世帯 Id よりも大きい値で窓口に予約する**
- **走査順は [GDD06 §3.1](06-trade-and-negotiation.md) の売り手 Id 昇順に従い、合成した候補は最後に来る。** したがって**実質コストが同値なら都市内の売り手が選ばれる** — 窓口は最後の手段であるという下記の位置づけと一致する
- **[GDD11 §2](11-external-trade.md) の行商人はこの解では済まない。** 行商人は**区画を巡回する**ので居場所が状態になり、設定からの合成では表せない。そちらは分冊が自分で解く

| | 都市外市場の振る舞い | 貨幣 |
| -- | -------------------- | ---- |
| **1次産品**(穀物・木材・鉄鉱石・木炭) | **外部売値**で無制限に**売る**。中心区画の売り手の候補として常時現れる(上記のとおり `Market` には実体化しない) | 都市の**外へ出る**(輸入) |
| **都市生産品**(小麦粉・薪・パン・ビール・工具) | **外部買値**で無制限に**買う** | 都市の**中へ入る**(輸出) |

**外部価格(初期値。季節係数が掛かる、§9)**:

| 品目 | 外部売値(都市が買う) | 外部買値(都市が売る) |
| ---- | ---------------------- | ---------------------- |
| 穀物 | 10 | — |
| 木材 | 8 | — |
| 鉄鉱石 | 14 | — |
| 木炭 | 12 | — |
| 小麦粉 | — | 11 |
| 薪 | — | 9 |
| パン | — | 24 |
| ビール | — | 22 |
| 工具 | — | 29 |

#### 買う側(輸入)は、通常の店選択がそのまま働く

**合成された候補は、中心区画に居る1人の売り手とまったく同じに扱う。** 買い手側に分岐は入らない:

- 買い手は [GDD06 §3](06-trade-and-negotiation.md) の店選択をそのまま適用する。**移動費(中心までの距離)が乗る**
- 観測(`PriceObservation`)も通常どおり生まれる。**視界半径の例外は置かない**(§4.1)。隅の区画の世帯は、隣接区画へ買い物に行った日に中心を観測する([GDD06 §3.1](06-trade-and-negotiation.md))
- **在庫圧力(§8.1.1)は適用しない。** 提示価格は外部売値そのものであり、無限在庫なので在庫比が定義できない

**外部売値が1次産品の価格の天井になる。** 都市内に1次産品の売り手は居ないので、天井は同時に**実勢価格**でもある。

#### 売る側(輸出)は1行で足りる

```
日次の Trade(順5)で世帯間の取引が確定したあと、売り手ごとに:
    超過分 = max( 0 , 販売在庫 − 出荷目標在庫(§8.1.1) )
    外部買値 ≤ 原価(§8.1.1) なら売らない          ← 損切りはしない
    そうでなければ 超過分を外部買値で売る
        流動資金 += 外部買値 × 超過分
        販売在庫 −= 超過分
```

**意味は「最低利幅を諦めて在庫を掃く」である。** §6.3② の投げ売り(原価の半分まで下げる)と同じ譲歩の系列にあり、**その一段手前**にあたる。

> **外部買値の置き場所が §12-6 の成否を構造的に決める。**
>
> ```
> 原価 < 外部買値 < ApplyPermille(原価, 1000 + 最低利幅‰)      ← 構造の制約
> ```
>
> **1次産品の仕入単価は外部売値に固定されるので、都市生産品の原価には床がある。** 外部買値をその床より低く置くと**輸出が一度も発火せず**、輸入だけが残って貨幣が流出し続ける — §12-6 が構造的に不通過になる。逆に原価下限より高く置くと、**売れ残りが毎日確実に利益に変わる** — 出荷目標在庫を超えた分が毎日そのまま換金されるので、**貨幣が過剰に流入して予算が膨らみ、§12-1(価格の発散)と §12-6 の逆向きの破れとして現れる。上の不等式は値の調整範囲ではなく、成立条件である。**

> **世帯間の取引が消えるわけではない。** 輸出規則は世帯間の取引が**確定したあと**に走り、対象は**出荷目標在庫を超えた分だけ**である。都市内の買い手は毎日その手前にアクセスできるので、外部買値をいくら上げても都市内の売買は残る。**提示価格(§8.1.1)も外部買値を参照しない**ので、§12-4(区画間の価格差)は引き続き測れる。**破れは価格差ではなく貨幣量に出る。**
>
> **上の表の初期値はこの不等式を満たすように置いてある**(例: パンの原価 ≈ 小麦粉12 + 薪10 = 22、原価下限 ≈ 27、外部買値 24)。**原価は移動平均で動くので、W2 では不等式が実行時に破れていないかを併せて観測する。**

#### 裁定者にしないための制約

**中央の板と同じ危険がある** — 窓口が最安値を毎日浚えば、§12-4 が判定する区画間の価格差を窓口自身が消してしまう。**抑えているのは次の2つである**:

1. **窓口は能動的に買わない。** 上の輸出規則は**売り手が余剰を持ち込む**形であり、窓口が店を選んで回ることはない。**これが主たる歯止めである**
2. **窓口が買うのは出荷目標在庫を超えた分だけである。** 都市内の買い手が先にアクセスできる範囲は毎日残る(上記)

**輸入の側は、窓口が中心区画にしか無いことで抑えられている。** 移動費([GDD06 §2](06-trade-and-negotiation.md))が乗るので、近所の店と競合するのは中心付近だけである。

> **輸出の側には距離が効かない。** 輸出規則には区画も移動費も現れないので、**隅の売り手も中心の売り手も同じ外部買値で同じ上限まで毎日均される**。窓口が区画間の在庫圧力を平準化する側に働く可能性が残っており、**§12-4 はこれを込みで読む必要がある**(W2 で実測する)。

### 10.3 自動調節(price-specie-flow)

```
輸入(1次産品の仕入)で貨幣が流出
  → 都市内の流動資金が減る
  → 予算(§8.2)が下がり、都市生産品が売れ残る
  → 販売在庫が出荷目標在庫を超える
  → 輸出が発火し、貨幣が流入する
```

**これは正貨流出入メカニズム(price-specie-flow)そのものである。** 歴史的にも実在した調節機構であり、**外部価格という「神の値」を、経済的に正当な錨として使える**ことを意味する。

**均衡は「都市内価格が輸出の閾値のあたりに落ち着く」点にある。** 貨幣が余れば都市内で捌けるので輸出が止まり、貨幣が減れば輸出が増えて戻る。**§12-6 はこの機構が実際に働くかを測る。**

> **v1.0 では、この窓口が [GDD11](11-external-trade.md) の港・行商人・貿易商に置き換わる。** 構造(外部価格帯が錨であり、輸出入が貨幣の出入りである)は同じで、**担い手が世界側の抽象から NPC へ変わる。** スプレッド(外部売値と外部買値の差)が都市内の貿易商の利益として残るのが、そのときの拡張である。

## 11. NPC の一生(**決定**)

**M0 では NPC を不死とし、世代交代を実装しない。**

**根拠となる整理**: [GDD01 §6](01-trust-and-conversation.md) 検証項目2 の 36,000日は、**300年の物語ではなく価格機構の耐久試験である。** 混同すると人口動態が M0 のスコープに引きずり込まれる。耐久試験に人口動態は要らない。

**検証地平は 36,000日のまま据え置く**([TDD01 §5.4](../04-tdd/01-sim-core-and-m0.md) の判定基準を変更しない)。

> **短縮は残された調整弁である。** 発散・硬直が起きるなら数十年で兆候が出るはずなので、原理的には 3,600日(30年)でも検証は成立する。**W2 の調整サイクルが実測で遅すぎた場合に限り、短縮を再検討する。** 先回りして基準を緩めない。

**世代交代を入れるなら以下が連動する**(M0 では触らない): 信用([GDD01 §2.1](01-trust-and-conversation.md))は死亡でリセットされる / 相続で資産と工房が引き継がれ、徒弟→職人→親方の昇格([GDD10](10-employment.md))が生きる / 決定論ハッシュ([TDD01 §3.8](../04-tdd/01-sim-core-and-m0.md))の区画が増える。

## 12. M0 での検証項目

[GDD01 §6](01-trust-and-conversation.md) と重複しない、**経済側の**検証項目。

| # | 検証内容 | 判定基準 |
| - | -------- | -------- |
| 1 | 価格が安定するか | 信用なし条件で長期実行する。**判定対象は都市生産5品目である** — 1次産品の提示価格は外部売値そのもの(§10.2。都市内に売り手が居ない)なので、外れようがない。**(a) 5品目の約定価格に [TDD01 §5.2](../04-tdd/01-sim-core-and-m0.md) の発散・硬直の判定関数を適用する**(閾値の定量化はそちらが持つ)。**(b) あわせて、§10.2 の構造の制約 `原価 < 外部買値 < 原価下限` が実行時に保たれているかを見る** — 原価は移動平均で動くので破れうる。`外部買値 ≤ 原価` に落ちれば**輸出が一度も発火せず**貨幣が流出し続け、`外部買値 ≥ 原価下限` に上がれば**売れ残りが毎日確実に利益に変わり**貨幣が過剰に流入する。**どちらも #6 に出る。破れの向きが、#6 がどちら向きに落ちたかの説明になる** |
| 2 | 貨幣が枯渇しないか | 困窮状態の**世帯**が全体の一定割合を超えない。**困窮は §6.2.2 の破産中フラグが立っている状態を指す** |
| 3 | 生産チェーンが止まらないか | 各レシピの生産停止(§5.1)が常態化しない。**一時的な停止は仕様**(§4)。**醸造が成立するか**(§8.2.1 の余剰資金が嗜好需要を細らせないか)をここで見る |
| 4 | **摩擦が残っているか** | **都市生産5品目(小麦粉・薪・パン・ビール・工具)の区画間の価格差が消えない。** 消えていれば §4 の摩擦が実装されていない。**1次産品は都市外市場が中心区画でのみ売るので対象外**(§10.2) |
| 5 | 原価下限が効いているか | 原価を下回る提示価格が**継続**しない(§8.1。投げ売り(§6.3②)による一時的な下回りは正常) |
| 6 | **自動調節が働くか** | **貨幣総量(= Σ世帯の流動資金)が長期的に減少し続けない。**(§10.3)。**減り続けるなら外部価格の不等式(§10.2)が破れているか、輸出が発火していない** |
| 7 | **知識が広がるか** | **「知っている店が0件」の世帯の割合が、初期の過渡期を過ぎて高止まりしない**([GDD06 §3.1](06-trade-and-negotiation.md))。M0 は行商人も運送労働者も置かないので、**観測の広がりが摩擦の下限の一方を担う**(§4.2) |

**#4 が本書固有の判定である。** 価格が安定していても区画差が消えていたら、それは「プレイヤーのいらない経済」であり、**経済として成功でもゲームとして失敗**である。

**#6 は §10.3 の機構が机上の理屈で終わっていないかを見る。** 自動調節を設計に組み込んだ以上、それが実際に働くことを確かめないと、外部価格が調整不能な地雷になる。

### 13.1 M0 の外に置いた品目と職業(**参考**)

| 層 | 品目 | レシピ | 担い手 | 外した理由 |

**レシピを持たない職業**: 酒場の主人(パン+ビール+肉 → 即時消費)/ 宿屋(薪+パン+ビール → 即時消費)/ 質屋・両替商。**サービス業は「最終財を買って在庫にしない」ことに意味がある** — 都市内に最終財の需要の受け皿ができ、生産が家計消費だけに依存しなくなる。**品目としては持たない**ので品目数も段数も増えない。ただし [GDD08 §3.2](08-household-and-decision.md) の家事の外部化が需要源なので、**主婦を置かない M0 では買い手が存在しない。**

**M0 の中で採らなかった拡張**(品目・調整軸が増えるため):

- 上の品目を戻す。**靴と衣服は「全 NPC 共通の耐久財」という役割を持つ** — M0 では耐久の予算(`min`)が生産職の工具でしか検証されず、「徒弟も靴を買える」(§8.2.1)が確かめられない
- 耐久財を工具以外へ広げる(農具・ツルハシ・厨房設備)。**現在工具のみに絞っているのはスコープ膨張の回避であって、リアリティ上の判断ではない**
- **1回の移動で運べる数量の上限。** [GDD11 §5.1](11-external-trade.md) が持つ。**運送労働者とプレイヤーの荷運びに優位性を与える前提**であり、運び手と同時にしか入れられない。**採るときは §10.2 の輸出規則を運搬として書き直す必要がある**(現行は移動も費用も持たない)
- 職業の粒度を [idea/008](../idea/008-NPCと職業.md) に近づける。**レシピを持たない職業は段数を増やさないので安い**
- 腐敗。パンと肉は本来腐る。M0 では §8.2.2 の在庫上限倍率で代用している
- 設備係数の連続化(§5.3)。あわせて §5.2 の `ApplyPermille` を切り下げへ直す
- 複数都市。§10.3 の分業の利益は、都市ごとの性格づけに繋がる
