## 1. 便益と費用を分ける

**取引の意思決定は2つの量の比較である。**

| | 予算 | 実質コスト |
| -- | ---- | ---------- |
| 何を表すか | **便益**。その品をどれだけ欲しいか | **費用**。手に入れるのに実際いくらかかるか |
| 決まり方 | 需要のみ(基礎値 × 在庫圧力) | 提示価格 + 信用 + 移動 |
| いくつあるか | **1つ** | **店ごとに1つずつ** |

```
買う条件:
  ① 実質コストが、比較したどの店よりも安い
  ② その実質コストが予算以下である
```

**①だけでは「一番マシな店でとにかく買う」になり、②だけでは「どこでもいいから予算内なら買う」になる。両方が要る。**

## 2. 実質コスト

```
実効価格_店   = 提示価格_店 × (1 − α‰ × 信用 ÷ 100 ÷ 1000)      ← GDD01 効果1
移動費_店(1単位あたり) = CeilDiv( 移動時間_店 × 委託先の機会費用 , max(目標在庫, 1) )
実質コスト_店 = 実効価格_店 + 移動費_店(1単位あたり)
```

- **実効価格は品目1単位あたりの値であり、実質コストもそれに揃える。** 移動時間 × 機会費用は「その店まで行って帰るのに要した費用」であり1回の来店に対する値(1単位あたりではない)なので、**目標在庫**([GDD02 §8.2.1](02-economy.md)。その品目・その用途で決まっている既存の値)**で割って1単位あたりに割り戻す**。「1回の来店で目標在庫ぶんを買う」ことを基準にした配分であり、実際の購入量が目標在庫からずれても配分そのものは変えない(単純化)。**新しい調整軸は増えない** — 目標在庫は既に §8.2.1 が持つ値である
- **`max(目標在庫, 1)` は零除算を塞ぐためである。** 生産の入力の目標在庫は「今後 N 日に消費する予定の量」([GDD02 §8.2.1](02-economy.md)「目標在庫の N 日分は先読みで数える」)なので、入力切れで生産が停止している工房([GDD02 §5.1](02-economy.md))では目標在庫が 0 になりうる。0 のまま割ると停止した工房は入力を買い直せず永久に止まる — [GDD02 §8.1.1](02-economy.md) が出荷目標在庫を定数化して塞いだのと同じ穴を、こちらは下限1で塞ぐ
  > 割らずに1回あたりの値のまま store選択に使い、購入量の式([GDD02 §8.2.3](02-economy.md))には実効価格だけを渡す案も検討したが、**移動費が「行けば1回だけ払う固定費」であることを実装が忘れやすく**、目標在庫という既存の値で割り戻すほうが式が1本で済む
- **耐久(工具)の目標在庫は耐久値で数えているので、割る前に個数へ直す**([GDD02 §8.2.1](02-economy.md)「M0 での目標在庫の持ち方」)。`max( CeilDiv(目標在庫, 1個あたりの耐久値), 1 )` で割る。**実効価格は1個あたりの値なので、耐久値のまま割ると移動費が「1個あたりの耐久値」ぶん小さく出て、空間の摩擦が耐久財についてだけ消える**
- **移動時間**は買い手の区画と店の区画の距離で決まる。**距離は 3×3 グリッドのマンハッタン距離**(0〜4)であり、定義は [GDD02 §4.3](02-economy.md) が持つ。**往復で数える**(片道の2倍) — 買いに行った者は帰ってくる
- **委託先の機会費用**は実際に行く者のもの([GDD08 §7.2](08-household-and-decision.md))。徒弟が行くなら安く、親方が行くなら高い
- **信用は §5 の「店の信用」を使う**(店主と応対店員の平均)

### 2.1 待ち時間は費用に入れない

**待ち時間を実質コストに加えてはならない。**

買い物に行くまでの時間には他の仕事ができるので、**実際に時間が奪われるわけではない**。待ちを費用として数えると、存在しないコストを二重に課すことになる。

**時間の緊急性は予算の側に入る。** [GDD02 §8.2.2](02-economy.md) が、在庫圧力を「買い物に行く時点で**予想される**在庫」から計算する。行くまでに食べてしまうなら予想在庫が減り、在庫圧力が上がり、予算が増える。

> **摩擦は「偽の費用」ではなく「本物の緊急性」として表す。** 空間の摩擦は実質コストへ(移動は実際に時間を奪う)、時間の摩擦は予算へ(緊急性が便益を上げる)。**それぞれ1か所だけに置く。**

## 3. どの店で買うか

```
選択 = argmin( 実質コスト_店 )   over 買い手が知っている店
ただし 実質コスト_選択 ≤ 予算 でなければ買わない
```

**「買い手が知っている店」であることが重要である。** NPC は自分が観測した範囲しか知らない([GDD01 §4.1](01-trust-and-conversation.md))。**情報の摩擦**([GDD02 §4](02-economy.md))が、比較対象の集合そのものを制限する。

**帰結**:

| 現象 | なぜ起きるか |
| ---- | ------------ |
| 遠い店は不利 | 移動時間 × 機会費用が乗る |
| **信用の高い店は「行く価値がある」** | 効果1 の割引が実効価格を下げる |
| **通りすがりの信用0のプレイヤーは選ばれにくい** | 割引が無いので実質コストで負ける |
| **地道に信用を上げれば逆も成立する** | 遠くても選ばれるようになる |
| 機会費用の低い者を使うと選択肢が広がる | 徒弟に行かせれば遠い店も候補に入る |


**在庫の無い店は候補に入らない。** `Market` に売り注文が出ていること自体は「その日の朝の販売在庫が1以上だった」ことしか意味しない([GDD02 §8.1.1](02-economy.md))。**同じ日のうちに先に来た買い手が買い尽くす**ので、`argmin` の対象は**その時点で販売在庫が残っている売り注文**だけとする。

**選ぶ店は1つで、足りなくても次善の店へは回らない。** 買える数量は `min( 購入量(§4), 資金上限([GDD02 §6.2.1](02-economy.md)), その店の残りの販売在庫 )` で切り詰め、その日はそこで終わる。**移動費(§2)が「1回の来店で目標在庫ぶんを買う」ことを基準に1単位あたりへ割り戻されている**以上、2店目を回ると費用の前提そのものが崩れる。**買い足せなかったぶんは翌日の在庫圧力が拾う**([GDD02 §8.2.2](02-economy.md)) — 在庫が減ったまま翌日を迎えるので予算が上がり、遅れて届く。

### 3.1 「知っている店」の定義(**決定**)

**知っている店は観測だけで決まる。視界は「観測がどこで生まれるか」の規則である。**

```
知っている店 = 今日の知覚 ∪ 有効な記憶

今日の知覚 = 自区画から距離 R 以内に出ている売り注文
有効な記憶 = 保持期間内の PriceObservation がある売り注文(前日まで)

観測(PriceObservation)が生まれる範囲
           = その日に居た区画すべてから距離 R 以内の売り注文
             居た区画 = { 自区画 } ∪ { その日に買い物で訪れた区画 }
             生まれた観測は翌日から「有効な記憶」になる

R = 視界半径(初期値 1)
```

**知覚と記憶を分けることが、日内の相互参照を切る。** 「訪れた区画」は店の選択で決まり、その選択は「知っている店」に依存する。**同日内で観測の生成と参照が循環する**ので、生成した観測を当日使えることにすると、初日は全世帯が0件になって誰も買い物に行かず、下の「これで初日が動く」が空振りする。

- **今日の知覚は当日すぐ使える。** 近所の店先は目の前にあるので、初日から自区画まわりで買える
- **記憶は前日まで。** [GDD08 §6.3](08-household-and-decision.md) が機会費用に採った1日遅延の成層化と同じ扱いである
- **保持期間は「その品目が売られる間隔より長い」。これは構造の制約である。** 間隔以下だと**次に売られる前に `相場基準` が消えて** [GDD02 §8.1.1](02-economy.md) の値付けが原価下限に落ちる。**「N日以上」ではなく「間隔より長い」と定義する**のは、境界で失効の判定が包含/排他の取り方に依存する余地を無くすためである
  - **M0 で「間隔」が確実に1日なのは1次産品だけである**(都市外市場が中心区画に常時並べる、[GDD02 §10.2](02-economy.md))。**都市生産品の売り手は各2世帯しか無く、生産停止・投げ売り・職業付け替えで売り注文が途切れる日がある**ので、間隔は実行時に決まる。**保持期間を短く振ると、途切れた品目から順に §8.2.7 のフォールバックが常態化する** — 調整するときは §12-1 と併せて見る
  - 季節に一度しか売られない品目を入れる [GDD12](12-countryside-and-fairs.md) では、来訪間隔(1季 = 30日)が下限として効く

- **距離の起点は「その日に居た区画」であって自宅だけではない。** ここが要点である。自宅を起点に固定すると、知識は永久に自宅の R 以内に閉じる
- **自区画と隣接区画は毎日見える。** 近所の店先は目に入る。**知識を配っているのではなく、知覚の範囲を定義している**
- **知識は実際の移動で外へ広がる。** 隅の区画(0,0)は R=1 で (0,1) を知り、そこへ買い物に行った日に (0,1) から距離1の**中心(1,1)を観測する**。2回の移動で都市の反対側に届く
- **広がった知識は保持期間で失効する。** 行かなくなった区画の相場は忘れる。**これが情報の摩擦の実体**であり、知識が単調に増えて中央の板になることを防ぐ
- **∪ の重複は現在の売り注文を採る。** 実質コストは `Market` の現在の提示価格から計算する
- **どの構成員の観測で決めるかは世帯主(親方)に固定する。** 帰宅時共有([GDD08 §8.1](08-household-and-decision.md))で世帯内の観測は同一になるので情報量は減らない。**固定しないと、買いに行く者が誰かで候補集合が変わる** — [GDD02 §8.2](02-economy.md) が予算について同じ理由で世帯主に固定したことが、店の選択の側から破れる
- **走査は売り手世帯 Id 昇順、`argmin` の同値は Id 最小を採る**([ADR-0002](../adr/0002-time-model-and-determinism.md) の列挙順規約)
- **観測は「見た」時点で生まれる。** 買わなくても、視界に入った売り注文は記録される
- **M0 に視界半径の例外は1つも無い**([GDD02 §4.1](02-economy.md))。**都市外市場([GDD02 §10.2](02-economy.md))は `Market` に実体を持たないが、店の候補としては中心区画(Id 4)に居る1人の売り手と同じに扱う** — 距離 R の外からは見えず、移動費も観測も通常どおり生じる。**売り手 Id はどの世帯 Id よりも大きい予約値**なので、上の Id 昇順の走査では最後に来る。**定期市を視界の例外にする規則は [GDD12 §2.2](12-countryside-and-fairs.md) が持つ** — 例外を必要とする分冊が、自分の理由で正当化する
- **自分の売り注文は自分の観測(`PriceObservation`)に入れない。** 観測は「他人の売り注文を見た記録」である。**ただし [GDD02 §8.1.1](02-economy.md) の売り手の値付けは、観測とは別に自分の前日の提示価格を相場基準に混ぜる** — **他の売り手の観測が1件以上あるときに限る**。買い手側の予算([GDD02 §8.2.1](02-economy.md))には混ぜない
  - **旧版はこれを「入れると複利で発散する(品薄の売り手が毎日1.5倍を掛ける)」として全面的に却下していたが、この理由は誤っていた。** 自分を除いても売り手2世帯の遷移行列の固有値は ±√(k_A·k_B) であり、両者が品薄なら**同じく1日1.5倍で複利発散する**。自分を除いて得られていたのは交互振動モードだけだった(導出は [GDD02 §8.1.1](02-economy.md))
  - **「他の売り手の観測が0件のときは自分も使わない」が、旧版の懸念の有効な部分である。** R = 1 では相手の売り手が見えない日が普通に起きる。そこで自分だけを錨にすると、**純粋な自己ループ**が本当に成立する。そのときは相場基準を立てず、原価下限をそのまま提示価格にする([GDD02 §8.2.7](02-economy.md))

> **視界半径 R は値ではなく構造である。** R = 0 なら「他区画の店は観測で知る / 観測は自区画からしか生まれない / 世帯は区画を移らない([GDD02 §4.3](02-economy.md))」が閉ループになり、**誰も他区画の店を知れない**。`移動時間` が常に 0 になって実質コストの第2項が消え、[GDD08 §7.4](08-household-and-decision.md) の「信用インフレを止める唯一の絞り」が恒偽になる。R = 2 なら中心区画の世帯が最初から全区画を見通す。**「誰が何を知りうるか」が R で変わるので、W2 の実データで調整する値として扱ってはならない。**

**これで初日が動く。** 全世帯が視界内の売り注文を見て買い、観測が生まれる。**初日の予算は [GDD02 §8.2.7](02-economy.md) の予算比率フォールバックによる。**

> **予算は当日の観測を反映しない。前日までの観測から計算する。** そうしないと「見た瞬間に相場基準が立つ」ため初日にフォールバックが発火せず、§8.2.7 が初日を規則で抜ける設計そのものが空振りする。**[GDD08 §6.3](08-household-and-decision.md) が機会費用に対して採った1日遅延の成層化と同じ扱いであり**、情報の摩擦の一形態でもある。

#### それでも0件のとき

**視界の中に売り手が居ない品目では、知っている店が0件になる。** M0 では品目ごとの売り手が2世帯しかない([GDD02 §2.4](02-economy.md))ので、**どちらも距離2以上に居る世帯からは見えない**日が普通に起きる。1次産品も同様で、都市外市場は中心区画にしか無い([GDD02 §10.2](02-economy.md))。このとき買わずに **Need を立てる**:

| 条件 | Need 種別 / 理由コード |
| ---- | ---------------------- |
| 知っている店が0件で、予想在庫が目標在庫を下回る | **在庫不足 / 遠方在庫**([GDD02 §8.4](02-economy.md)) |

**新しい Need 種別を足していない。** [GDD02 §8.4](02-economy.md) の表は既に「区画をまたぐ運搬が要る → 在庫不足 / 遠方在庫」を持っている。

**これは [GDD08 §7.4](08-household-and-decision.md) のゲートの特例である。** §7.4 は `min(世帯内の機会費用) × 所要時間 > 外注コストの見込み` を Need の唯一の絞りとするが、**店を1つも知らなければ所要時間が定義できず、式が評価できない**。知っている店が0件のときは §7.4 を通さずに Need を立てる。

> **M0 ではこの Need を履行する主体を置かない。** 行商人も運送労働者も [GDD11](11-external-trade.md) へ出してある。**0件は一時的である** — 買い物に行けば観測が外へ広がり、隅の区画からでも2回の移動で中心に届く([GDD02 §4.2](02-economy.md))。Need は「まだ届いていない」という信号として立つだけでよく、v1.0 で行商人と運送が履行する。
>
> **区画に役割は無い。** [GDD02 §4.3](02-economy.md) の9区画はいずれも同格であり、**中心(Id 4)が特別なのは距離が最小であることと都市外市場がそこに居ることだけである**([GDD02 §10.2](02-economy.md))。[GDD11](11-external-trade.md) で港を入れるときも「港区画」は作らず、貿易商がどこに居るかだけが効く。

## 4. いくつ買うか

**式は [GDD02 §8.2.3](02-economy.md) の線形解による。** 本書が持つのは、その入力に**どの店の実質コストを使うか**である:

```
購入量 = f( 選ばれた店の実質コスト, 予想在庫, 目標在庫, 基礎値 )
```

**店を選んでから量を決める。** 逆順(量を決めてから店を選ぶ)にはしない — 実質コストが店ごとに違う以上、量は店に依存するためである。

## 5. 店に対する信用

信用は個人が持つ([GDD01 §2.1](01-trust-and-conversation.md))ので、「あの店は信用できる」を表すには導出が要る。

```
取引時の信用 = ( 親方(店主)への信用 + 応対した店員への信用 ) ÷ 2
```

- **信用の変化も両方に効く。** 良い取引は店主と店員の双方の信用を上げる
- **実体を持たせない。** これは導出値であり、`TrustScore` は個人間のままである

**帰結**: 店主や番頭が大口取引に出る理由が生まれる([GDD08 §3.3](08-household-and-decision.md))。店主が応対すれば信用は店主に二重に乗る。

> **プレイヤーの店にも同じ規則が適用される**(分冊04)。従業員を雇うと、**その従業員への信用がプレイヤーの店の信用を薄める**。誰に応対させるかが判断になる。

## 6. M0 のスコープ

| 要素 | M0 | v1.0 |
| ---- | -- | ---- |
| 予算と実質コストの分離(§1) | **入れる** | |
| 実質コスト(§2)、店の選択(§3)、購入量(§4) | **入れる** | |
| 店の信用(§5) | **入れる** | |
| **妥結価格** | **提示価格をそのまま妥結価格とする** | 交渉を入れる |

| 掛け売りの運用 | **入れない**(困窮時の与信は [GDD02 §6.3](02-economy.md)③ が概念だけ持つ) | §7 |

> **M0 で妥結を作らないのは、価格機構の検証に不要だからである。** [GDD02 §12](02-economy.md) が測るのは価格の安定・貨幣の循環・摩擦の残存であり、いずれも提示価格で成立する。**交渉を入れると調整軸が増え、価格が動いた原因が機構か交渉かを切り分けられなくなる。**
