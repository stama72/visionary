## 1. 時間の進み方

### 1.1 ゲーム内1日の長さ

**ゲーム内1日 = 実時間10分。初期値であり、テストプレイで変える。**

| ゲーム内 | 実時間      |
| -------- | ----------- |
| 1 tick(1時間) | **25秒** |
| 1日(24 tick)  | **10分** |
| 1季(30日)     | 5時間    |
| 1年(120日)    | **20時間** |

シム側の時間の真実は `Tick` であり(ADR-0002)、ここで決めるのは**実時間からゲーム時間への変換率だけ**である。この値を変えてもシムの決定論と検証地平(TDD01 §3.1)には影響しない。

### 1.2 10分を初期値にした理由

暦を1年120日にした判断([ADR-0003](../adr/0003-calendar-structure.md))は「プレイヤーが四季を一巡できること」を根拠にしている。その一巡に必要な実時間は1日の長さで決まるため、両者は整合していなければならない。

- 10分なら**1年 = 20時間**で、v1.0のプレイ時間目標10〜20時間([企画書](../02-project-proposal.md) §2)の上端で四季を一巡できる
- 1 tick がちょうど25秒の整数になる(15分では37.5秒)

### 1.3 15分も候補として残す

**次点は15分(1年 = 30時間)。** 以下を重視するなら15分に寄せる:

- **1日のうちに街の端から端まで行ける取引のダイナミズム。** 1日が短すぎると、移動そのものが機会費用として重くなりすぎ、「歩いて情報を集める」というUSPが窮屈になる
- **のんびり自由に遊べるゲーム性。** 時間に追われる感覚が強いと、ライフシム側のアイデンティティ(生きた都市で生きた暮らし)と衝突する

一方で1年30時間はプレイ時間目標を超えるため、**四季の一巡を「1周目で必ず体験するもの」から「やり込むと届くもの」に格下げする**ことを意味する。このトレードオフはテストプレイ(M0 W6 / M1)で判断する。

### 1.4 時間が止まる場面

会話中・取引UI表示中はゲーム時間を止める(M0の暫定仕様。TDD01 §3.5)。会話が実時間を消費すると「話しかけるコスト」が生まれ、会話を目的にもするという設計方針(GDD01 §1-1)と衝突するため。
