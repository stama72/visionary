## 1. 時間の進み方

### 1.1 ゲーム内1日の長さ

**ゲーム内1日 = 実時間10分。初期値であり、テストプレイで変える。**

| ゲーム内 | 実時間      |
| -------- | ----------- |
| 1 tick(1時間) | **25秒** |
| 1日(24 tick)  | **10分** |
| 1季(30日)     | 5時間    |
| 1年(120日)    | **20時間** |

シム側の時間の真実は `Tick` であり(ADR-0002)、ここで決めるのは**実時間からゲーム時間への変換率だけ**である。この値を変えてもシムの決定論と検証地平(TDD01 §3.1)には影響しない。

### 1.2 10分を初期値にした理由

暦を1年120日にした判断([ADR-0003](../adr/0003-calendar-structure.md))は「プレイヤーが四季を一巡できること」を根拠にしている。その一巡に必要な実時間は1日の長さで決まるため、両者は整合していなければならない。

- 10分なら**1年 = 20時間**で、v1.0のプレイ時間目標10〜20時間([企画書](../02-project-proposal.md) §2)の上端で四季を一巡できる
- 1 tick がちょうど25秒の整数になる(15分では37.5秒)

### 1.3 15分も候補として残す

**次点は15分(1年 = 30時間)。** 以下を重視するなら15分に寄せる:

- **1日のうちに街の端から端まで行ける取引のダイナミズム。** 1日が短すぎると、移動そのものが機会費用として重くなりすぎ、「歩いて情報を集める」というUSPが窮屈になる
- **のんびり自由に遊べるゲーム性。** 時間に追われる感覚が強いと、ライフシム側のアイデンティティ(生きた都市で生きた暮らし)と衝突する

一方で1年30時間はプレイ時間目標を超えるため、**四季の一巡を「1周目で必ず体験するもの」から「やり込むと届くもの」に格下げする**ことを意味する。このトレードオフはテストプレイ(M0 W6 / M1)で判断する。

### 1.4 時間が止まる場面

会話中・取引UI表示中はゲーム時間を止める(M0の暫定仕様。TDD01 §3.5)。会話が実時間を消費すると「話しかけるコスト」が生まれ、会話を目的にもするという設計方針(GDD01 §1-1)と衝突するため。

### 1.5 NPC の1日の時間割(**決定**。M0)

**NPC の経済の判断は日次のままである。** 朝0時に値付けと外出の計画を決め、夕方18時に買い物が約定する([TDD01 §3.3](../04-tdd/01-sim-core-and-m0.md))。画面に出る1時間単位の行動は、朝に決まった外出の計画を時間割へ展開したものである。**時間割はシムが持ち、描画は1 tick の中の移動を補間するだけである**([TDD01 §3.9](../04-tdd/01-sim-core-and-m0.md))。

| 時刻 | どこに居て、何をしているか |
| ---- | -------------------------- |
| 0〜5時・18〜23時 | 自区画の家で休む(睡眠・食事) |
| 6〜17時 | 自区画の工房で家業に就く。**外出の委託先**([GDD08 §7.2](08-household-and-decision.md))だけは、家業の後に外出し、18時に帰り着く |

**外出**(委託先だけ):

- その日の外出を [GDD06 §3](06-trade-and-negotiation.md) が決めた順に1回ずつ行う。1回の外出は「自区画 → 行き先 → 自区画」の往復である。片道の時間は `距離 × 1区画あたりの移動時間`([GDD02 §4.3](02-economy.md))
- **出発の時刻は、最後の外出がちょうど18時に帰り着くように逆算する。** 出発 = 18時 − その日の往復時間の合計。買い物の約定(18時)に、店を訪れる時刻を近づけるためである([#249](https://github.com/stama72/visionary/issues/249) 決定6)
- 行き先には着いた時刻に居て、そのまま帰る。待ち時間は外出の費用に入れない([GDD06 §2.1](06-trade-and-negotiation.md))ので、時間割にも置かない
- 輸出のための中心行きが別の外出になる日([GDD02d §2.3](02d-external-market-and-money.md))は、買い物の外出の後に行う
- 往復時間の合計は T(可処分時間 12)以下である([GDD06 §3](06-trade-and-negotiation.md))。そのため、出発は6時より前にならない。**6〜17時の12時間は [GDD08 §3.1](08-household-and-decision.md) の T と同じ長さに揃えてある**

**プレイヤーは NPC の買い物(18時)より先に取引できる。** 取引と会話は6〜17時に、相手の世帯の区画で行う([GDD06 §6.4](06-trade-and-negotiation.md))。日中に NPC と売買した結果は、その日の18時の買い物に入る([#249](https://github.com/stama72/visionary/issues/249) 決定4・5)。**時間割そのものは経済に関与しない。** そのため、NPC が店を訪れた時刻と在庫が動く時刻(18時)はずれる。訪れた後でも、18時より前ならプレイヤーは同じ在庫を買える。

**時刻(6時・18時)は初期値であり、W5 で触って直す。** プレイヤーの取引の時間帯も同じ定数を読むので、一緒に動く([GDD06 §6.4](06-trade-and-negotiation.md))。**外出中の委託先とは、その場で話せない** — 行為の条件は時間割を読まず、世帯の区画で判定する(同節)。

## 2. 会話UI・会話UX

未着手。メニュー型 vs RPG風の動的ネスト構造([idea/007](../idea/007-会話UX.md))の採否をここで決める。**本作最大のリスク。**

### 2.1 感謝の見せ方(**決定**。M0)

**画面に出すのは所持金と、数値の無い感謝の記録である。** 感謝([GDD01 §3.6](01-trust-and-conversation.md))は価格にも取引相手の選好にも効かない。そのため、見え方そのものが報酬になる。

- **取引の場では、台詞と、表情・効果音程度の演出で伝える。** 台詞は感謝の3段階で分ける([GDD01 §3.3](01-trust-and-conversation.md))
- **感謝された取引は日誌に1行ずつ残す。** 誰の、どの困りごとを解き、どの段階の感謝だったか(「鍛冶屋〇〇の工具切れを救った — 深く感謝された」)。段階の名前は台詞と同じ粒度にとどめる
- **感謝を数値やポイントで表示しない。** 数値にすると感謝が2つ目の通貨になり、プレイヤーはそれを最大化しに行く。そうなると、M0 のプレイテストで「吹っかけたか」([GDD01 §6.2](01-trust-and-conversation.md) #1)を観察しても、測れるのは最小構成要素ではなく UI の誘導になる。数値の差から段階の境目と予算も読まれやすい
- **所持金だけにもしない。** 観察の条件としては最も厳しいが、楽しさが無いのか、感謝が消えて見えないだけなのかを切り分けられない。M0 では貨幣の使い道がほぼ仕入れだけで、所持金もスコアとしてしか働かない。そのため、何を画面に残すかで、稼ぐか感謝されるかの選好が UI の側から動く

決定の経緯は [#245](https://github.com/stama72/visionary/issues/245) の決定2・3。

### 2.2 M0 の会話 UI(**決定**。M0)

**M0 はメニュー型の最小形にする。** 動的ネスト構造([idea/007](../idea/007-会話UX.md))は M0 では作らない。M0 の台詞は6種類で([GDD01 §3.3.1](01-trust-and-conversation.md))、入れ子にする話題が無いからである。最終形の採否は §6 に残し、M1 で信用 Tier の話題が増えるときに決める。

- **話しかけると、挨拶 → 世間話 → 開示(Need が無ければ困りごとは無い)が続けて流れる。** プレイヤーが選ぶ操作は挟まない。順は GDD01 §3.3.1 のとおりである。**理由: M0 には、選ぶと何かが変わる話題が無い。** 世間話を飛ばせる形にしても、クリックが1回増えるだけである。会話疲れ(§0)の元を、選択肢の無い場面に置かない
- **流れ終わると、商談のメニュー(売る・買う・立ち去る)が残る。** 売買は §3.1。売った結果は取引の成立・不成立の台詞で返る(GDD01 §3.3.1)
- **話しかけられるのは、6〜17時に相手の世帯の区画に居るときだけである**([GDD06 §6.4](06-trade-and-negotiation.md))。画面の横に、居る区画の世帯の一覧(職業名)と、中心区画なら窓口を出す。外れたときは会話を開かず、断られた理由(取引時間外など)だけを出す
- **相手は世帯の代表(構成員の最小 NpcId)である。** 取引の相手は世帯なので(GDD06 §6.1)、話し手も世帯につき1人にする。**代償: 代表が外出中でも代表が話す**([TDD01 §3.10](../04-tdd/01-sim-core-and-m0.md))
- **会話と取引の間は時間が止まり(§1.4)、地図をクリックしても移動しない。** 立ち去ると時間が動き出す

### 2.3 時間を止めたまま遊べること(M0 の代償)

会話を開いている間は時間が止まるので、1回の会話の中では何度売り買いしても時刻は進まない。**同じ (世帯, 品目) に値を出せるのは1日1回まで**([GDD06 §6.1](06-trade-and-negotiation.md))なので、止めた時間の中で予算を絞り込むことはできない。窓口で買って世帯へ売る往復には移動が要り、移動の間は時間が動く。

## 3. 取引UI

交渉の提示・応答の見せ方は分冊06と対で決める(M1 以降)。

### 3.1 M0 の取引 UI(**決定**。M0)

**会話の商談メニューと、中心区画の窓口で売買する。** どちらも、コマンド([TDD01 §3.4](../04-tdd/01-sim-core-and-m0.md))を1つ出して結果を出すだけの形である。交渉は無い([GDD06 §6](06-trade-and-negotiation.md))。

| 場面 | 出すもの | 入れるもの |
| ---- | -------- | ---------- |
| 世帯へ売る | 所持品のうち1個以上ある品目と所持数 | 単価と数量。**単価の既定値は、その品目をこの起動で最後に買った単価**(無ければ 1)。数量の既定値は所持数 |
| 世帯から買う | **その世帯の**売り注文(品目・提示価格・販売在庫) | 数量(既定値 1) |
| 窓口から買う | 窓口の売値(全品目) | 数量(既定値 1) |
| 窓口へ売る | 窓口の買値(都市生産品のうち、1個以上持っているもの) | 数量(既定値は所持数) |

- **相場の目安・予算・評価額は出さない。** 予算を見せない理由(値踏みの読み合い。[GDD01 §6.1](01-trust-and-conversation.md))と同じである。**売値の既定値を仕入れ値に置くのは、画面の側から値付けを誘導しないためである。** 相場や窓口の値を既定値にすると、M0 のプレイテストで「吹っかけたか」([GDD01 §6.2](01-trust-and-conversation.md) #1)を観察しても、測れるのは既定値の誘導になる(§2.1 と同じ懸念)。**穴: 仕入れ値も錨にはなる。** 「仕入れ値に上乗せする」は商人の素の考え方なので許す。W6 のプレイテストで見る
- **出す売り注文は、居合わせた世帯のものだけである。** 街じゅうの提示価格の一覧は出さない(§4。全知の相場表を持たない)
- **窓口の値は出す。** 窓口は NPC と同じ値で両方向に取引する公開の口である([GDD06 §6.3](06-trade-and-negotiation.md))
- **成立した売買は、地の文で品目・数量・単価を出す。** 感謝の段階の名は出さない。段階は取引の成立の台詞で伝える(§2.1)。日誌は [#283](https://github.com/stama72/visionary/issues/283) が作る
- 数量は、売り手の在庫・所持金・所持品・Need の数量でシムが切る(GDD06 §6.1〜§6.3)。画面の側では切り直さない
