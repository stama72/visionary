## 0. この文書の位置づけ

**本書は「今の仕様」を持つ。** なぜその仕様を選んだかは ADR が持つ(CLAUDE.md「ADRとGDDの境界」)。

暦について言えば、ADR-0003 は「なぜ1年を120日にしたか」「なぜ28日でなく30日か」という**選択肢と理由**の記録であり、そこで役割を終えている。季節の名称・順序・エポック・年中行事の基準といった**仕様**は本書が持つ。M0 の段階では仮仕様でよいが、実装コメントや ADR に仕様を溜めない。

§1 と §2.1 以外は見出しのみのスタブである。

## 1. 暦と季節

### 1.1 暦の構造

**1年 = 4季 × 30日 = 120日。月の概念を持たない。**(理由は [ADR-0003](../adr/0003-calendar-structure.md))

1 tick = ゲーム内1時間、1日 = 24 tick([ADR-0002](../adr/0002-time-model-and-determinism.md))。

### 1.2 季節の順序とエポック

| 項目           | 仕様                                       |
| -------------- | ------------------------------------------ |
| 季節の順序     | **春 → 夏 → 秋 → 冬**                   |
| 内部の数値割当 | 春 = 0 / 夏 = 1 / 秋 = 2 / 冬 = 3          |
| 年             | **1始まり**                                |
| エポック       | **1年 春1日 0時**(`Tick.Zero` がこれにあたる) |

**この順序と割り当ては仕様である。** 実装(`Season` / `GameDate`)はこれに従う。変更したい場合は本節を改訂したうえでコードを直す — 逆順(コードを直して文書を放置)をしない。

**エポックを動かすと、同一マスターシードで生成される世界の中身がすべて変わる。** M0 の比較実験([TDD01](../04-tdd/01-sim-core-and-m0.md) §5)の結果は取り直しになるため、W2 以降の変更は実験計画への影響を確認してから行う。

#### 春始まりを選んだ理由

- **降誕祭を冬25日(通算115日、年末の5日前)に置ける。** 現代のプレイヤーが持つ「クリスマス ≒ 年末」という感覚と一致する。中近世の実際の年始(3月25日や12月25日)という設定の厳密さより、プレイヤーの理解しやすさを取る
- 春始まりは**農業年**としても自然で、収穫を秋に置ける
- Stardew Valley 型であり、プレイヤーの学習コストが低い

### 1.3 週

**週は暦の一部ではない。単なる7日周期として扱う。** ADR-0003 の「週は暦とは独立」を踏襲する。

- 30日は7で割り切れないため、週は季節の境界をまたいで漂う。これは許容する(中世都市の実態としてむしろ自然)
- スケジューラの `Weekly` cadence は **`dayIndex % 7 == n` の日**と定義する([TDD01](../04-tdd/01-sim-core-and-m0.md) §3.1)
- **`GameDate` にも `Calendar` にも曜日を持たせない。** 曜日を表す型も作らない。市場日・安息日を導入するまで曜日は必要にならないため

将来「市の立つ日」「教会の安息日」を導入するときの基準として、**エポック(1年 春1日)は月曜日とする**。現時点で実装には一切現れない、基準の予約である。

> **注意**:.NET の `System.DayOfWeek` は `Sunday = 0` から始まる。本作の基準(エポック = 月曜日)と食い違うため、将来この概念を実装するときは標準型を使わず、名前もずらして混同を防ぐこと。

### 1.4 年中行事(未確定)

降誕祭を冬25日に置くこと(§1.2)以外は未定。祭礼・市・収穫期の配置は §2 とあわせて決める。

## 2. 季節が経済に効く形

**本節が持つのは係数の値である。構造(どの消費・どの価格が季節に依存するか)は [GDD02d §5](02d-external-market-and-money.md) が持つ。** 分担はあちらが決めており、本書が構造を書くと二重管理になる。

**係数はすべて千分率の整数**([ADR-0002](../adr/0002-time-model-and-determinism.md))。季節の順序と値(春0 / 夏1 / 秋2 / 冬3)は §1.2。

### 2.1 消費の季節係数(**M0 の仮仕様**)

**薪だけが季節係数を持つ**([GDD02d §5](02d-external-market-and-money.md))。基準は秋の 1000‰ である。

| 季節 | 係数‰ | 由来 |
| ---- | ----- | ---- |
| 春 | 800 | 残寒。暖房は要るが冬ほどではない |
| 夏 | 400 | 暖房が要らず、調理ぶんだけが残る |
| 秋 | 1000 | **基準** |
| 冬 | 2000 | 暖房需要が倍になる。[GDD02 §2.2](02-economy.md)「冬の暖房需要は薪だけを圧迫し、木炭には効かない」が指しているのがこの行である |

- **1日消費量の基礎値(1人あたり何個か)は [GDD02b §1](02b-consumption-and-household.md) が持つ。** 本表は係数だけを持つ
- **適用の順序も [GDD02b §1](02b-consumption-and-household.md) が持つ** — 構成員ごとに切り上げてから世帯で合計する
- **目標在庫は「今後 N 日に消費する予定の量の合計」として、日ごとにこの係数を当てて数える**([GDD02c §2.1](02c-price-and-budget.md))。冬が近づくと薪の目標在庫が滑らかに上がり、**冬支度が規則ではなく帰結として現れる**
- **値は初期値であり調整対象である**([GDD README](README.md) 執筆ルール)。固定したいのは「薪だけが季節で動く」という構造のほう

**生産と外部価格の季節性はまだ値を持たない。** M0 に1次産品の生産者は居ない(GDD02 §2.2)ので、季節性は都市外価格が担う([GDD02d §5](02d-external-market-and-money.md))。**どの品目の外部価格が季節で動くかの列挙と、その値は、都市外市場を実装する時点で本節に足す。**

年周期のイベント(年貢・決算・祭礼)を単年周期にするか複数年周期にするかは、まだ決めていない。1年が120日と短いため、単年だと体感で頻繁になる。
