# Visionary(仮題)ドキュメント体系

個人開発だが、チーム開発の意思決定プロセスを模して文書を運用する。
各文書は「誰が・何を判断するための文書か」を明確にして書く。

## 文書一覧

| # | 文書 | 状態 | 目的(想定読者) |
|---|------|------|------------------|
| 01 | [コンセプトシート](01-concept-sheet.md) | ドラフト | 企画のGO/NO-GO判断(プロデューサー視点) |
| 02 | [企画書](02-project-proposal.md) | ドラフト | 市場性・スコープ・スケジュールの妥当性判断(事業視点) |
| 03 | GDD(ゲームデザイン仕様書) | 未着手 | 実装の設計図。システム別に分冊(開発者視点) |
| 04 | TDD(技術設計書) | 未着手 | アーキテクチャと技術リスクの潰し込み(開発者視点) |
| 05 | マイルストーン計画 | 未着手 | 進捗判定基準と縮小プラン(PM視点) |
| 06 | リスク管理表 | 未着手 | リスク/影響度/対策の一覧(PM視点) |
| ADR | [adr/](adr/) | 運用中 | 技術的意思決定の記録(1決定1ファイル) |

## 運用ルール

- 文書は Markdown で管理し、Git で変更履歴を残す
- 大きな技術的決定は必ず ADR に「背景・選択肢・決定・理由」を記録する
- GDD/TDD は「育てる文書」。マイルストーンごとに実態と乖離していないか見直す
- 各マイルストーンの完了判定は 05 に定義した Exit Criteria で行う
