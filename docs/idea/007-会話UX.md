# 会話UX

(GDD 01 §3.1 の会話構造に対する原案メモ。採否・詳細設計は分冊05(UI/UX)で行う)

## 0. 前提:会話疲れが最大のリスク

このゲームは会話が多いので、プレイヤーが疲れたり飽きてしまうリスクが最大のリスクである。会話UXの設計は最重要。

## 1. 二段階の会話体験

会話を目的別に二段階に分け、体験を変える:

1. **会話自体が目的**:ただの挨拶やクエスト関係の情報収集。何も考えずにぽちぽちクリックして読み飛ばしていい
2. **商売が目的**:取引やコアな情報収集。意識的に操作して取引する

読み飛ばせる部分と、意識的に操作する部分を明確に分けることで、会話量の多さが疲労に直結しないようにする。

## 2. メニュー画面を出すか、RPG風にするか

そもそもメニュー画面を出すのかが重要な論点。**プレイヤー側の発言する文章を選択肢として選ばせるRPG風の形**にする案がある。

- メリット:没入感の高い直感的な会話体験になる
- 選択肢をネスト構造にして依頼に関するものを聞きやすくすれば、メニュー画面と同じ機能性を維持しながら、自然言語駆動型の体験を提供できる

## 3. 動的ネスト構造

プレイヤーが一番選びそうなホットトピックを第一階層に出し、それ以外は「ところで…」の第二階層以降に格納する。

例:一つの会話テーマが終わった後の3択:

- 「ところで…」
- 「◯◯(現在の依頼対象の人/もの)について聞きたいんだけど…」
- 「ありがとう、じゃあね」

第三階層以降もある。人の噂を聞く場合:

```
「ところで…」
  → (人について)
      → 「奥さんは元気?」
      → 「子どもは元気?」
      → 「弟子の◯◯は仕事に馴染んできた?」
      → (仕事相手について)
      → (近所の人について)
      → (都市の人たちについて)
          → 「◯◯通りの…」
              → 「◯◯屋の…」
                  → 「◯◯さんって知ってる?」
```

英語なら "By the way…" → (about someone) → (about citizens) → (\<district\>) → (\<profession\>) → "Have you heard of \<someone\>…?" の順が良い。

- 「(人について)」のような、**キーワード自体は会話の発言に含めないカテゴリ名**も使うことで、内部の堅牢なネスト構造と自然言語によるUIを一対一でリンクさせられる

## 4. コンテキストによるショートカットと動的変化

- 相手の家族など、聞く可能性が高い候補は上の階層に優先配置する。相手や自分のコンテキストに合わせて、上の階層構造にショートカットを作る
- **ネスト構造の判断基準は「現実の会話として自然かどうか」**
- 相手の家族について話したことが一度もなければ、第三階層に「奥さん」「子ども」などの候補はなく、代わりに「家族は何人いるの?」という一段広いスコープの質問が置かれる(GDD 01 §4.2 人物知識の有無から生成)
- どの階層も状況に応じて動的に変わる
