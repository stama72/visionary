# ADR-0007: M1 の品目数を経済モデルの要求に合わせて広げる

- 日付: 2026-09-14
- ステータス: 承認
- 決定者: stama

> **レビュアーエージェントを3巡かけ、[process/01](../process/01-review.md) の停止則(前巡の修正が原因のブロッカーが2巡続いたら打ち切る)に到達したので打ち切った。** 3巡目の指摘は全件を反映したうえで凍結している — **ADR は後から本文を直せないため、「打ち切って実装へ渡す」が使えない種類の文書だからである。** 残る指摘([issue #55](https://github.com/stama72/visionary/issues/55))は註記の対象にならない運用の話である。

## 背景

[issue #8](https://github.com/stama72/visionary/issues/8) で M0 のスコープを切り分けた結果、M0 は **9品目・都市5職業・10世帯・NPC 20体**になった。[GDD02](../03-gdd/02-economy.md) から財政・雇用・交易・農村 NPC を4分冊へ出し、貨幣のソースとシンクを都市外市場1つに畳んだ結果である。

[ADR-0006](0006-issue-driven-task-management.md) の背景が測定した「**M0 が M1 より大きくなった**」という順序反転は、**NPC 数では解消した**(80 → 20 で [企画書 §6](../02-project-proposal.md) の M1「NPC20体」と並んだ)。**品目数では解消していない** — M1 は「品目5種」であり、M0 の 9 はこれを上回る。

**5品目まで削れない理由は、値の好みではなく式の本数である。** [GDD02 §8.2.1](../03-gdd/02-economy.md) の予算は用途によって4通りの決まり方を持つ:

| 決まり方 | M0 で対応する品目 |
| -------- | ----------------- |
| 派生需要(出力の見込み売値から逆算) | 穀物・木材・鉄鉱石・木炭・小麦粉・薪 |
| 相場基準(観測の平均 × 許容乖離‰) | パン・薪 |
| 予算比率(余剰資金 × 比率‰) | **ビール** |
| `min(相場基準, 予算比率)`(耐久) | **工具** |

**対応する品目を落とすと、その式は W2 で一度も実行されない。** 最も残せる5品目の選び方(鉄鉱石・木炭・工具・木材・薪)でも予算比率が落ち、パン系列を残す選び方なら予算比率と耐久の2つが落ちる。**工具は M0 で唯一の耐久財なので、落とすと耐久の予算(`min`)に加えて設備の摩耗([§5.3](../03-gdd/02-economy.md))と Need「工具切れ」([§8.4](../03-gdd/02-economy.md))の経路も同時に消える** — [§12](../03-gdd/02-economy.md) の7項目そのものが減るのではなく、**#1 と #4 の判定対象が都市生産5品目から4品目へ痩せ、検証の経路が1本消える**([GDD02 §7](../03-gdd/02-economy.md) の註が、設備を固定した場合について「M0 の検証項目が1本落ちる」と書いているのと同じ経路である)。

## 論点: M0 の9品目と M1 の5品目のどちらを動かすか

### 検討した選択肢

- **A. [企画書 §6](../02-project-proposal.md) の M1 を「品目9種」に広げる**
- **B. W2 の検証範囲を狭める。** 予算の4つの式のうち2つを W3 以降へ回し、M0 を5品目にする
- **C. 現状維持。** M0 ≤ M1 は NPC 数で満たしたとみなし、品目数の逆転は許容する
- **D. 企画書 §6 から規模の数値を外す。** M1 の定義を定性的な Exit Criteria(「コアループが通しで遊べる」「第三者が15分遊んで『もっと遊びたい』と言う」)だけにし、規模は issue が持つ

### 決定

**A を採る。企画書 §6 の M1 垂直スライスを「1地区・品目9種・NPC20体」に改訂する。**

**あわせて、「上位文書を広げてよい条件」を一般則としては定めない**(下記)。上の判断は個別のものである。

### 理由

- **「品目5種」は経済モデルが存在する前に置かれた見積もりである。** [TDD01 §3.6](../04-tdd/01-sim-core-and-m0.md) も当初「品目5種・職業3類型」を仮置きしていた。**その後 GDD02 が「予算の決まり方は4種類ある」という構造を確定した。**5という数はその構造を知らずに置かれた数であり、**構造と衝突したときに守るべき側ではない**
- **B は M0 の目的そのものを毀損する。** W2 のゲートは「信用なしで価格が安定する経済」([TDD01 §5.4](../04-tdd/01-sim-core-and-m0.md))であり、価格機構の4分の1〜2分の1を動かさずに通したゲートは、W3 以降の比較実験の土台にならない。**削るのが安いのは検証項目ではなく実装量である**
- **C は数え方で問題を回避するだけである。** ADR-0006 の背景が測ったのは「マイルストーンの順序が反転している」ことであって NPC 数ではない。1つの軸で満たして他を黙らせると、**同じ計測が次に効かなくなる**
- **D は今回の食い違いを検出する手段を失う。** 規模の数値が企画書 §6 に無ければ「M0 > M1」は測れず、[ADR-0006](0006-issue-driven-task-management.md) の背景が書けない。**順序反転を検出できたのは、上位文書が定量の目標を持っていたからである。** 二重管理に見えるが、企画書 §6 が持つのは **M1 の目標値**、[GDD02 §2.2](../03-gdd/02-economy.md) が持つのは **M0 の現在値**であり、別の量である

### 「膨張ではなく発見である」と言える一般則は、書かない

**本 ADR を起案する過程で2度、上位文書を広げてよい条件を一般則として書こうとし、2度とも [ADR-0006](0006-issue-driven-task-management.md) が測った膨張を落とせなかった。** 却下した2案とその反例を残す。

| 案 | 反例 |
| -- | ---- |
| **①「要求が『検証項目が落ちる』という形で述べられ、その検証項目が数値を広げる前から文書にあること」** | **膨張の代表例そのものがこれを満たす。** 「9区画・1品目につき売り手2世帯」は、**「売り手が1人なら §12-4 が最初から存在しない」**という形で正当化されており(`b4ce60e` 時点の GDD02 §2.4)、その **§12-4 は初版 `f04f5de` から存在する**。当時これを適用すれば「M1 を 9区画・11品目・NPC80 に広げてよい」が通る。<br>**※ 検証項目が常に先にあるわけではない** — §12 は初版5件で、#6・#7 は後から足された。**①に識別力が無いのではなく、識別できない事例がある**ということである |
| **②「その変更が、下位のスコープを縮める作業の一部であること」** | **膨張の途中にも縮小差分は存在する。** `df65f03` 時点の GDD02 は「酒場の撤回で都市の職業数が7→6、世帯数が22→20、NPC数が88→80に変わった」と記録している。②が問うのは「縮める作業に同梱されているか」であって「膨張前の基準まで戻したか」ではないので、**膨張させてから一部を戻し、残差を上位へ写す**経路を塞がない |

**したがって本 ADR は一般則を定めない。上の決定は個別の判断である。**

> **膨張を止めるのは論証の形式ではない。** ①も②も「どう正当化されたか」を問う試みであり、正当化は後からいくらでも形を整えられる。
>
> **[ADR-0006](0006-issue-driven-task-management.md) が置いた器は、膨張を止めたのではなく巻き戻せるようにした。** 器(スコープを持つ issue、[process/01](../process/01-review.md) のスコープの関門、停止則)は膨張の**後**に置かれたものであり、ADR-0006 の背景自身が「W2 は器が無いまま膨張した」と書いている。**器が実証したのは検出と巻き戻しであって、予防ではない。** 予防を規則に委ねられると期待してはならない — **次に上位文書を広げる判断が要るときも、判定するのは規則ではなくその3つを通した人間である。**

### 9 は、既にある構造制約から出てくる下限の近傍である

**本 ADR が論拠にした「予算の4つの決まり方」は、[GDD02](../03-gdd/02-economy.md) §8.2.1 が本 ADR より前から持っている**(初出は `c5897d5`「予算と実質コストの役割分担を確定し、GDD06 を新設する」。GDD02 は v1.0 で変更履歴の行を落としたので、版番号ではなくコミットで指す)。

**予算の4つの式だけを条件にすると、9 より小さい構成がありうるように見える。** しかし **[GDD02 §4.3](../03-gdd/02-economy.md) の密度と §2.4 の売り手2世帯が、独立に下限を課している**:

```
9区画 × (1〜2世帯、空区画を作らない)        → 世帯は最低 9
同じ職業の2世帯は必ず別の区画              → 都市職業は最低 5(5職業 × 2 = 10世帯)
5職業がそれぞれ1品目を売る                  → 都市生産品は 5
その入力のうち都市で作られないもの           → 1次産品(M0 の構成では 4)
                                            合計 9
```

**したがって M0 の9品目は、予算の式からではなく規模の構造制約から出ている。** 例えば4つの決まり方だけを満たす7品目の構成(`木材・薪・穀物・ビール・鉄鉱石・木炭・工具`)は**都市3職業・6世帯にしかならず、9区画に空区画が出るので §4.3 に反する。**

> **「4」が1次産品の最小であることは論証していない。** 別の5職業の組み方でもっと少ない1次産品で済む可能性は残る。したがって主張できるのは **「9 は下限の近傍であり、5 には遠く届かない」**までである。**削る判断をするときの条件は「予算の4つの決まり方」だけでなく、§2.4・§4.3 の規模の構造制約も含む。**
>
> さらに削れるかは W2 の実測後に再訪する([issue #50](https://github.com/stama72/visionary/issues/50))。

## 帰結(引き受けるトレードオフ)

- **M1 の実装量が増える。M0 ≤ M1 は品目数について等号で成立する**
- **「増分は Godot 側に寄る」は仮説である。** 品目・レシピ・価格機構は M0 の成果をそのまま使うので、増えるのは表示と売買 UI だけのはず、という予測であり、**[企画書 §6](../02-project-proposal.md) の M1 の期限(2026-12末)を据え置いた判断はこれに乗っている。**
  - **判定: W5(グレーボックス)の完了時点で、`Visionary.Sim` 側に品目起因の未完タスクが残っているか。** 残っていれば外れである。W5 は M0 の最終段階なので、**M1 の期日まで約2か月を残して判定できる**。判定は [issue #50](https://github.com/stama72/visionary/issues/50)(Exit 判定と実態合わせ)で行う
  - **外れたときの戻し先は、品目数ではない。** 上記のとおり M1 の品目数は M0 と等号で、**M0 の 9 は §2.4・§4.3 の規模の構造制約から出ている**。品目を引くには先に区画数か密度を動かすことになり、**それは §12-4(区画間の価格差)を測れなくする** — M0 のやり直しである。**したがって引けるレバーは (a) M1 の期日、(b) M1 のグレーボックスの作り込み(表示・売買 UI の範囲)の2つに絞られる**
- **ADR-0006 の背景の一部が、本 ADR によって「解消済み」ではなく「基準を動かして解消した」になる。** [運用ルール](README.md)は本文の文言を変えないことだけを求めており、**日付つきの註記は書き換えに含めない** — 足さないと崩れた前提の上に決定だけが残るためである。**したがって ADR-0006 の背景に本 ADR への註記を足し、[ADR README](README.md) の状態欄にも読み替えを書いた**(ADR-0004 の「憲章リストは 0005 で棄却 / WIP と状態一覧は 0006 で読み替え」と同じ形)。**ADR-0006 の決定(issue 駆動・粒度・WIP・停止則)は一つも覆っていない。覆したのは背景の測定値である**
- **区画については未解決のまま残る。** 企画書 §6 の M1 は「1地区」、[GDD02 §4.3](../03-gdd/02-economy.md) のシムは 3×3 の9区画である。**「地区」(歩ける範囲)と「区画」(価格差の単位)は別の単位であり、本 ADR は比較していない。** 両者の関係は W5 でグレーボックスを作るときに決める([issue #48](https://github.com/stama72/visionary/issues/48))
- **縮小プランの「品目数」は、M0・M1 については独立したレバーではなくなった。** [コンセプトシート](../01-concept-sheet.md)「社会規範システム → 従業員AI深度 → 品目数 → 都市イベント」の順序は変えないが、**M0 の9品目は §2.4・§4.3 の規模の構造制約から出ており、引くには区画数か密度を動かすことになる**(上記)。**このレバーが独立に効くのは M1 より後**(品目を戻す段階、[GDD02 §13.1](../03-gdd/02-economy.md))である
