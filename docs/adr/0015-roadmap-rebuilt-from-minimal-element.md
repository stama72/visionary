# ADR-0015: ロードマップを最小構成要素から組み直し、信用を M1 へ移す

- 日付: 2026-09-30
- ステータス: 承認
- 決定者: stama

## 背景

M0 の GO 判断は3項目あり、その1つが「**信用を経済シミュレーションに組み込んでもバランスは制御可能か**」だった([コンセプトシート](../01-concept-sheet.md) 旧版)。この問いに答えるため、M0 は「信用なしで価格が安定する経済」(W2)を土台に、信用システム(W3)と信用あり/なしの比較実験(W4)を積む構成になっていた([TDD01 §5.4](../04-tdd/01-sim-core-and-m0.md) 旧版)。**土台の W2 のゲートは 36,000日の耐久試験だった**([GDD02 §7](../03-gdd/02-economy.md) 旧版)。

2026-09-30 時点で、W2 のゲートは通っていない。

- **経済の不安定は、校正ではなく構造の問題と診断された**([#244](https://github.com/stama72/visionary/issues/244))。在庫から価格を探す側は成り立っているが、価格 → 生産量・価格 → 消費量・資金 → 支出の3本の帰還路が無い。帯 `[床, 天井]` の中に内点の均衡が無く、床に張り付く売り手日が約 50%、ビールは天井に固定される
- **3本の帰還路を足すのは、M0 の残り期間に収まる作業ではない見込みである。** 36,000日のゲートを M0 に置いたままでは、W3・W4 の比較実験は土台の無いまま待ち続ける
- **一方で、30日なら都市は死ななくなった。** [#210](https://github.com/stama72/visionary/issues/210) が処方を置き、[#173](https://github.com/stama72/visionary/issues/173) の生存検出器が全5シード・30日で通っている

同じ日の対話で、コアループのさらに下に置く**最小構成要素「困りごとを取引で解決し、感謝される」**を定めた。ゲームとしては取引、プレイ体験としてはニーズを聞き出して満たし、感謝される会話である。**この最小のゲームは取引と会話だけで完結し、信用を必要としない。** 信用は、これを繰り返しゲームへ発展させる要素である。

決定の経緯と、各論点の開発者の判断は [#243](https://github.com/stama72/visionary/issues/243) の決定ログが持つ。

## 論点1: M0 で何を検証するか

> ステータス: 承認

### 検討した選択肢

1. **最小構成要素だけを M0 に置き、信用・約束・信用によるコンテンツ解放・困窮からの再出発を M1 へ移す**
2. 信用を M0 に残す(現行。W3・W4 を M0 の中で回す)

### 決定

**選択肢1。** M0 の GO 判断は「最小構成要素が楽しいか」と「テンプレート台詞の品質」の2つになり、「信用の制御可能性」は M1 の GO 判断へ移る(#243 決定6)。約束(期限と履行のライフサイクル)は信用を増減させる道具なので、信用と一緒に M1 へ移る(#243 決定12)。M0 の納品は、困りごとを聞き、後で持ってきて売る通常の取引で果たす。

### 理由

- **最小構成要素が楽しくなければ、何を足しても失敗する。** 信用は最小構成要素を繰り返しゲームへ育てる要素であり、面白さの源泉ではなく増幅器である。[GDD01 §5](../03-gdd/01-trust-and-conversation.md) は信用を会話とニーズ解決の「骨格」と書いていたが、それは繰り返しゲームの完成形の記述である。M0 の会話は信用 Tier を持たず、開示の水準を固定する(#243 決定11)。増幅器の制御可能性を、増幅する対象より先に確かめる順序は逆である
- **選択肢2 は、経済の再設計の前提として、M0 の完了を必要とする。** 信用あり/なしの比較は「信用なしで価格が安定する経済」を前提とする([TDD01 §5.2](../04-tdd/01-sim-core-and-m0.md)「信用あり/なしの比較」)。その前提が #244 の再設計待ちである以上、W3・W4 は M0 の期日の中で意味のある答えを返せない
- **失うものがある。** M0 の取引は一回限りのゲームになり、吹っかける戦略(タカ)が支配戦略になりうる。吹っかけを咎める既存の経路([GDD01 §4.5](../03-gdd/01-trust-and-conversation.md) の不当価格)は帰結が信用の減点だけなので、M0 では働かない。感謝の側で釣り合わせるかは [#245](https://github.com/stama72/visionary/issues/245) が決める。**プレイテストでプレイヤーが吹っかけたかを記録する**(GO 判断①の観察項目)。記録は [#243](https://github.com/stama72/visionary/issues/243) が閉じたあと、W6 のプレイテストの issue が持つ

## 論点2: M0 の経済の検証地平

> ステータス: 承認

### 検討した選択肢

1. **30日・5シード**(プレイテストの1季)
2. 36,000日のまま据え置く(旧 GDD02 §7)
3. 360日(3年。[#244](https://github.com/stama72/visionary/issues/244) が M1 の Exit に挙げる初期値)

### 決定

**選択肢1。** 36,000日の耐久試験と年単位の経済の安定は、M1 以降の経済の再設計([#244](https://github.com/stama72/visionary/issues/244))へ移す。

### 理由

- **M0 の経済が支えるのはプレイテストである。** ゲーム内1日は実時間10分([GDD05 §1](../03-gdd/05-ui-ux.md))で、1時間のプレイテストはゲーム内の約6日になる。暦のエポックは春1日なので、30日は季節をまたがない。**プレイテストの間に都市が死なないことは、M0 の経済の必要条件である**(十分条件ではない。30日の生存は [#210](https://github.com/stama72/visionary/issues/210) が出荷日数を 3 → 1 にして得たもので、代わりに価格が床に張り付きやすくなった)
- **選択肢2 を却下する理由は、36,000日が不要だからではない。** 旧 GDD02 §7 は「36,000日は価格機構の耐久試験である」と正しく書いていた。却下するのは、**耐久試験が通らない原因(帰還路の欠落)が M0 の外の再設計にある**と分かったからである。旧 §7 は「短縮は W2 の調整サイクルが実測で遅すぎた場合に限り再検討する。先回りして基準を緩めない」と書いていた。今回の短縮は、その条件(調整の遅さ)によるものではない。**検証する対象(信用の比較実験の土台)が M0 から出た**ことによる
- **選択肢3 は季節をまたぐ。** 冬の薪の需要が天井を超える経路は未検証のまま M1 にある。季節をまたぐ地平を M0 に置けば、M1 の作業を M0 に引き戻すことになる
- **これは仮説を含む。** 「30日で死なない都市は、最小構成要素の面白さを判定するのに足りる」は予測であり、W6 のプレイテストで検証する。プレイテストの所感が経済の破綻(品切れが続く・価格が張り付いて差が見えない)を理由に判定不能になれば外れである。**外れの記録先は W6 の Exit 判定の issue である**

## 論点3: プレイヤー自身に生産させるか

> ステータス: 承認

### 検討した選択肢

1. **させない。プレイヤーがやることは人と人、需要と供給をつなぐことに限る**
2. 生産を入れる(工房・畑を持つ)

### 決定

**選択肢1。** 業態の拡大ルートは「行商人(零細小売り)→ 店舗(小売り・卸売り)→ 大商会(小売り・卸売り・貿易・金融・不動産)」であり、生産職にはならない。

### 理由

- **これを貫く限り、ライフシム側の要素を入れても芯が崩れない。** 友好度・プレゼント・季節行事・納品(Stardew 系)も、告解・救貧・海外貿易・ギルド・参事会(ハンザ都市)も、「つなぐ」行為の相手や場として入る
- **選択肢2 は二つの点で差別化を失う。** 生産を入れると農場・工房経営のライフシムと同じ土俵に立ち、ビジュアルの品質で競うことになる([企画書 §3.4](../02-project-proposal.md))。そして経済シム側では、プレイヤーが NPC の生産者と競合する。「NPC のニーズを満たす」立場から「NPC の市場を奪う」立場へ動く。
- **フェッチクエストを正面から面白くする。** プレイヤーが提示すれば通常の取引になり、NPC が提示すればニーズというクエストになる。生産を持たないことで、クエストの達成手段は常に「誰かから手に入れて、誰かに渡す」になる。その手段を生きた経済と生きたコミュニティが支える

## 論点4: EA 時点の「成長」の到達点

> ステータス: 承認

### 検討した選択肢

1. **自分の店と従業員(仕事は店番のみ)を M2〜EA に入れる**
2. EA を行商人だけで出す(店舗・従業員は EA 後)

### 決定

**選択肢1。**

### 理由

- **選択肢2 では、EA に「成長」(世界観設定書 [§1.1](../02b-world-setting.md) の b)の到達点が無い。** 02b は b を「お金を稼ぐ、店を持つ」と定義し、ハイコンセプトは「行商人から豪商へ」を掲げる。EA の中身が行商人で止まると、差別化の軸(b × c)より愛着(d)に配分が寄る
- **従業員の仕事を店番に限るのは、従業員の AI に深さを要求しないためである。** 仕入れ・交渉・配達まで任せる従業員は、NPC の意思決定をプレイヤーの代理として作り直すことになる
- **代わりに d の側を削る余地を持つ。** 削減の第一候補は季節ごとのビジュアル変化である(素材の量が4倍になる)。港と海の描写は、海沿いの都市であることと海上貿易が世界観の芯なので残し、M2 に入ってから判断する。どちらも [コンセプトシート](../01-concept-sheet.md) の縮小順序が持つ

## 決定(まとめ)

| 論点 | 決定 |
| ---- | ---- |
| 1 M0 の検証 | 最小構成要素だけを置く。信用・約束・コンテンツ解放・再出発は M1 へ |
| 2 M0 の経済の地平 | 30日・5シード。36,000日と年単位の安定は M1 以降の経済の再設計へ |
| 3 プレイヤーの生産 | させない。業態は行商人 → 店舗 → 大商会 |
| 4 EA の成長 | 自分の店と店番のみの従業員を M2〜EA に入れる |

## 帰結(引き受けるトレードオフ)

- **M0 の比較実験の資産(W3・W4 の設計)は M1 まで寝かせる。** [GDD01 §6](../03-gdd/01-trust-and-conversation.md) の検証項目と TDD01 §5.2・§5.3 の判定の設計は捨てず、M1 で使う。寝かせる間に経済の再設計(#244)が前提を変えるので、M1 で読み直すコストを払う
- **M0 の取引は信用の無い一回限りのゲームになる。** 吹っかけが支配戦略になるなら、M0 のプレイテストは「楽しさ」ではなく「搾取の爽快さ」を測ってしまう。観察項目で切り分ける(論点1)
- **M0 のプレイテストは、値を読む側をほとんど測れない。** 出荷日数 1 の下では、希少性は価格ではなく品切れに出る(論点2)。USP①「情報を足で稼ぐ」の価格の側は M1 で検証する
- **36,000日の検証が無いまま M1 の設計に入る。** 価格機構が長期で発散するかは、M1 の再設計の後にしか分からない。**M0 の成果物(Visionary.Sim)を M1 がそのまま土台にできる保証は、今より弱くなる。** 許容するのは、36,000日を M0 に置いても通らない見込みだからである(現行コードが通らないのは実測で、M0 の期間で直せないのは見込み)
- **M0 の中に、1時間単位の行動描写という新しい作業が入る。** 現行の Sim は全システムが0時に1回だけ動く。日次の判断を時間割に展開する層が要る。W5 の負荷は上がる
- **[ADR-0007](0007-m1-scale-follows-economic-model.md) の仮説「M1 の増分は Godot 側に寄る」は、実測を待たずに外れる。** 本 ADR が信用・約束・経済の再設計・年単位の安定を M1 へ入れたためである。ADR-0007 は M1 の期限を据え置いた判断をこの仮説に乗せていたので、M1 の中身と期日の釣り合いは [#246](https://github.com/stama72/visionary/issues/246) で判断し直す。ADR-0007 の決定(M1 は品目9種)は覆らない
