# ADR(アーキテクチャ決定記録)一覧

技術的意思決定の記録。**1決定1ファイル**。「背景・検討した選択肢・決定・理由・帰結」を必ず書く。

ADRの価値は決定そのものより、**却下した選択肢とその理由**が残ることにある。後から「なぜこうなっているのか」を再検討するコストを消すために書く。

## 運用ルール

- 承認済みADRは原則として**書き換えない**。決定が変わったら新しいADRを起こし、古い方の状態を「棄却(ADR-XXXXで置き換え)」に変える
- 実装がADRと食い違ったら、コードを直すかADRを改訂するかを必ずどちらか選ぶ。放置しない
